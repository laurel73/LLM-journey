## 2. 写代码的正确工具：文本编辑器 [00:00]

### 2.1 代码就是文本 [00:00]

Malan 打开的程序叫 **Visual Studio Code**，简称 **VS Code**，是当下非常流行的写代码工具。

但这里有个很重要的认知：**你并不是非用 VS Code 不可**。归根到底，我们唯一需要的是一个"写文本的程序"——也就是**文本编辑器（text editor）**。为什么？**因为代码本身就是文本**。

### 2.2 终端 / 命令行界面（CLI） [00:00]

VS Code 界面大致分两部分：

这个终端是你和底层计算机（你的 Mac、PC，甚至云端某台服务器）打交道的地方。我们后面所有"运行程序"的动作，都是在这里敲命令完成的。

敲完回车后，屏幕上方出现了编辑区：

## 3. 运行程序：`python hello.py` 与解释器 [00:05]

### 3.1 为什么不能双击图标？ [00:05]

平时在 Mac、PC 甚至手机上，我们习惯**双击图标**或**点一下屏幕**来运行程序。但这里看不到任何图标——因为我们的界面只有 CLI 这一种。

Malan 坦白说：这看起来像是从"菜单、按钮、图标"倒退了一步。但你会发现，CLI 最终是一个**强大得多**的界面，而且在现实世界的程序员中极其流行。

### 3.2 第二个命令，`$` 提示符的含义 [00:05]

光标移回屏幕下方的终端，之前已经跑过一条命令（`code`），现在可以输入第二条了。你会看到**第二个美元符号 `$`**。

> 重点：**这个 `$` 不是货币符号，不代表钱**。它只是一个通用的**提示符（prompt）**——命令行界面用它来告诉你"把命令敲在这儿"。

### 3.3 运行命令 [00:05]

```bash
python hello.py
```

为什么是这么写？

我们写的 Python 代码当然存放在 `hello.py` 这个文件里，但**计算机需要有人一行一行、从左到右地去"解读"（interpret）它**，才知道要做什么。

### 3.4 计算机只懂 0 和 1 [00:05]

这里 Malan 补了一段底层原理：

你可能听过，**计算机只认识 0 和 1**，也就是所谓的**二进制（binary）系统**。那么问题来了：像 `print`、括号、`"hello, world"` 这种东西，显然不是 0 和 1，**必须被翻译成 0 和 1**，计算机才看得懂。

好消息是：只要你提前安装好，**Python 既是一门语言，也是一个程序**。这个程序就是所谓的**解释器（interpreter）**——你可以免费安装在自己的 Mac、PC 或云服务器上。

于是整个过程是这样的：

1. 你运行解释器程序 **python**
2. 把文件名（这里是 `hello.py`）作为**输入**传给解释器
3. 解释器负责**从上到下、从左到右**读取你的文件
4. 把它"翻译"成计算机能懂的 0 和 1

### 3.5 第一个输出 [00:05]

Malan 敲下回车，如果没写错，终端里出现了：

```
hello, world
```

## 4. 函数（Function）与参数（Argument）[00:10]

现在退一步，看看刚才到底做了什么、屏幕上都是些什么。

### 4.1 函数是"动词 / 动作" [00:10]

几乎所有编程语言都会提供所谓的**函数（function）**。

> 函数就像是一个**动作（action）**或者**动词（verb）**，它让你能在程序里"做某件事"。

一般来说，**任何一门语言都会自带一批预先定好的函数**——一批最基本的动作，计算机（更准确地说，是这门语言）**已经知道该怎么做了**。你作为程序员，可以随意调用这些函数，让计算机去干活。

我们的 `hello.py` 只用了**一个函数**，你应该能猜到是哪个——就是 `print`。

### 4.2 参数（argument） [00:10]

`print` 这个函数并不是打印某句"注定的话"，它打印的是**你想让它打印的东西**。

这就引出了编程世界的另一个术语：**参数（argument）**。

> **参数就是传给函数的输入，它会影响函数的行为。**

发明 Python 的人当然不可能预知你我到底想在屏幕上打印什么，所以他们把 `print` 设计成：**用括号接收一个输入**——这个输入可以是一串文本（英文或任何人类语言），函数最终就会把这串文本打印到屏幕上。

在我们的例子里，`"hello, world"` 就是传给 `print` 的参数。

### 4.3 副作用（side effect） [00:10]

程序最终在屏幕上做了什么？它在**打印**，它把 `hello, world` 显示在了屏幕上。

> 这在编程里被统称为**副作用（side effect）**。它可以是视觉上的，也可以是听觉上的。本例中它是"出现在屏幕上的东西"。

所以：**函数是可以有副作用的**。作为"动词/动作"，它能做的事情之一就是——把你想看的字显示在屏幕上，这就是一种副作用。

## 5. Bug：犯错是常态 [00:10]

第一个程序一切顺利，Malan 自我感觉良好，没犯任何错。但他马上话锋一转：

> 学编程的时候你会犯错，**哪怕学成之后很多年，你依然会犯错**。

> **Bug 就是程序里的一个错误（mistake）**，它有千千万万种形态。

请放心：接下来的几周里，你会犯**大量**错误，你的代码里会有**大量** bug——**就像我当年一样，就像我现在依然一样**。

那些 bug 本身，就是**等着你去解决的问题**。接下来的课程会给你很多工具——既有思维上的，也有技术上的——来解决它们。

> 讲师的口头强调：**如果你的程序第一次就没跑通，别灰心。** 随着时间、练习和经验的积累，它是会通的。

### 5.1 故意制造一个 bug [00:10]

Malan 现在**故意**犯一个他刚才其实有可能不小心犯的错误：把行尾的**右括号删掉**。

代码几乎是对的，"99% 都对了"，但既然被指出来了，你就看得很清楚：少了那个 `)`。

> 关键认知：像这种**看似微不足道的小细节**——你我作为人类根本不会在意，发邮件、发短信时它就只是个笔误，没什么大不了——**对计算机来说却是天大的事**。

### 5.2 语法错误（syntax error） [00:10]

清一下终端屏幕，重新运行：


这次没有出现 `hello, world`，而是屏幕上出现了错误——所谓的**语法错误（syntax error）**，意思是"我在键盘上敲错了"。

值得庆幸的是，这次的报错相当直白，它明明白白地告诉你：**那个左括号一直没有被关上**。这很符合直觉。要做的当然就是把它补回去。

> **讲师的提醒**：不幸的是，接下来几周我们会看到的一些报错信息，**可就没这么友好了**。但同样地，**随着练习和经验积累，你会越来越擅长调试（debug）这类程序。**

## 6. 让程序变得可交互：`input` 函数 [00:15]

### 6.1 目标：不要只会说 hello, world [00:15]

现在来改进这个程序，让它**更有交互性**——不要假定所有人都想被一句笼统的 `hello, world` 问候，而是能说出 `Hello, David`、`Hello, Jeremiah`、`Hello, Horatio` 之类，**用到用户真实的名字**。

### 6.2 第一次尝试：`print` + `input` 分开写 [00:15]

Malan 回到 `hello.py`，在最上面加了一行，大致意思是先打印一句提示：

```python
print("What's your name? ")
input()
print("hello, world")
```

思路是：先用 `print` 向用户提问，然后需要**另一个函数**来真正拿到用户的输入。巧的是，**Python 自带一个就叫 `input` 的函数**。

调用 `input()`（一对空括号）会**提示用户输入**，光标会闪烁着等你敲东西。

### 6.3 改进：查文档发现 `input` 自己就能带提示语 [00:15]

但 Malan 说，他去读了 `input` 函数的文档后发现：**`input` 本身就接收一个参数**！

也就是说，**不需要先用 `print` 提问、再单独调用 `input`**。可以直接简化：

```python
input("What's your name? ")
print("hello, world")
```

他把同一个字符串从 `print` 里拿出来，**作为参数塞给 `input`**，然后把那行 `print` 整个删掉。

> 而且原来那个 `print` 还会**额外输出一个换行**呢。现在的效果就是：光标停在同一行的提示语后面闪烁，问用户"What's your name?"。

### 6.4 运行：输入了，但没被用上 [00:15]

```bash
python hello.py
```

终端提示 `What's your name?`，Malan 输入 `David` 并回车。

**结果：程序并没有拿这个名字做任何事**，它只是照旧输出 `hello, world`。

### 6.5 假装修好：硬编码（hardcode） [00:15]

当然，"修"起来很容易——回到第 2 行，把 `world` 改成 `David`：

```python
input("What's your name? ")
print("hello, David")
```

再运行，输入 David，回车，看起来一切正常了。

### 6.6 但这根本没修好 [00:15]

> **讲师明确指出：这当然算不上"按预期工作"。**

Malan 演示了一遍：这次他假装自己是同事 **Carter**，输入 `Carter`，回车，看到的当然是——`Hello, David`？不，输出的是 `hello, David`（因为写死的是 David）。总之就是不对。

原因：他把名字**硬编码（hardcode）**了——也就是**把名字字面写死在了字符串里**。

所以我们需要一种方式，能**把用户输入的东西拿回来（get back）**，并拿它去做点什么。

### 6.7 返回值：让函数把东西"交还"给你 [00:15]

为此，我们要用到函数的另一个特性：**函数可以有返回值（return value）**。

Malan 用了一个非常形象的比喻：

> 把 `input` 想象成一个动作、一个动词——你甚至可以把它**拟人化**成你的一个朋友。你**拜托这个朋友去问别人一个问题**："去问问那个人叫什么名字"。
>
> 那么，如果你的朋友问回来了、知道了那个人的名字，**他把这个名字交还给你，岂不是很好？**
>
> 这就正是我们需要这个函数做的事情：**拿到用户的输入，然后把它交还给我**，这样我（程序员）才能拿它去做点什么。

## 7. 变量（Variable）与赋值 [00:15]

### 7.1 为什么需要变量 [00:15]

如果值要被"交还"给我，我就得**找个地方把它放起来**，这样才能之后把它喂给 `print` 函数。

> 类比：相当于**拿出一张纸或一张便利贴（Post-It note）**，把用户说的话写在上面，然后我才能把它作为输入交给 `print` 函数。

为此，我们需要编程的另一个特性：**变量（variable）**。

大多数人应该都熟悉数学课上的变量——`x`、`y`、`z` 之类。编程也有同样的能力：**在计算机的内存里创建一个变量**（不只是纸上），这个变量可以**存储一个值**——一个数字、一段文本、甚至一张图片或一段视频。

> **变量就是计算机里（或者说你自己的程序里）装某个值的容器（container）。**

### 7.2 起个好名字：`name` 而不是 `x` [00:15]

Malan 说，他要引入一个**名字比 x、y 更有意思的变量**。他本可以写 `x = input(...)`，但他选择直接把变量叫 **`name`**。

为什么？**因为在编程里，我面前有一整块键盘，我可以用更具描述性的词来说明我在写什么。**

```python
name = input("What's your name? ")
print("hello, world")
```

### 7.3 重点：`=` 不是"等于"，是"赋值" [00:15]

现在要仔细看一个语法细节。我们已经见过括号、见过引号，它们都是**给函数传参时必需的**。但 `name` 和 `input(...)` 中间这个**等号**很重要：

> 严格来说，它**并不是"等号"**。它表示的**不是相等（equality），而是赋值（assignment）**。
>
> 在 Python 和很多编程语言里，**单个等号是赋值运算符（assignment operator）**。

它的具体含义是：**把右边的东西赋给左边**。

更准确地说：`=` 会**从右往左拷贝**——把右边那个函数的**返回值**拷到左边。

所以：

1. `input(...)` 显然会从用户那里拿到输入（这就是为什么我能敲进自己的名字或 Carter 的名字）
2. 同时，它在幕后**把那个值、那个返回值，交还给我这个程序员**
3. 只要我用一个等号加一个变量（**不管这个变量叫什么名字**），我就能把这份输入**存进那个变量**，以便之后复用

于是，**在计算机内存的某个地方，现在有一个容器，里面装着 `"David"`，或者 `"Carter"`，或者用户敲进去的任何东西。**

### 7.4 经典错误：把变量名放进引号里 [00:15]

> **这里是本讲第一个最容易踩的坑，讲师专门停下来演示了。**

假设你想把这个名字打印出来，凭直觉你可能会这样写：

```python
name = input("What's your name? ")
print("hello, name")
```

运行，输入 `David`——

**输出的是 `hello, name`。** 注意，是**字面量** `hello, name`，不管用户输的是什么名字，它都这么说。

Malan 在敲回车前还特地问了聊天区："你们猜会输出什么？"——聊天区答对了：它大概率会**原样输出 `hello, name`**。

**原因**：引号意味着"字面打印这几个字符"。引号里的 `name` 就是四个字母 n-a-m-e，不是变量。

### 7.5 改进版：去掉引号，传变量本身 [00:15]

再换个方式试。先把事情简化，至少保证 `Hello, ` 这部分能出来，然后**另起一行打印 `name`**：

```python
name = input("What's your name? ")
print("hello,")
print(name)
```

> 注意这次的"小聪明"：**`name` 没有加双引号**。我们前面已经看到，加双引号会**字面打印 n-a-m-e**。这次我去掉引号，希望：**把名为 `name` 的变量传给 `print` 函数，它会去打印这个变量里的内容，也就是它的值（value）。**

运行并输入 `David`：

```
What's your name? David
hello,
David
```

> 讲师自评：这不是最好的程序，我算是走了点捷径——`Hello, David` 被拆到了两行上。**既不优雅、也不好看，从英语语法上说也不如一口气说完来得体面**。但至少问题解决了，只是**解决得还不够好**。

### 7.6 学生提问：`input` 只能接收文字吗？ [00:15]

**学生**：`input` 函数对任何类型的信息都有效，还是只对文字有效？

**Malan**：很好的问题。根据它的文档（我们很快就会更正式地看文档），**`input` 期望的是一个字符串（string）**——也就是**一串文本**，可以是英文或任何人类语言。它用来提示用户的确实就是文本。

（注：这里说的是 `input` 的**提示语参数**是字符串；后面讲 `int` 时会进一步看到，**`input` 的返回值也总是文本**。）

## 8. 注释（Comments）[00:20]

### 8.1 为什么需要注释 [00:20]

到这里，Malan 停下来铺垫一个面向未来的习惯：

> 我们的程序**不会永远只有一行、两行、三行**——它们最终会变成**几十行、甚至几百行**。所以现在就要为将来打好基础。

Python 和很多语言都支持所谓的**注释（comment）**。

> 注释是**你在代码里写给自己的笔记（notes to yourself）**。在 Python 里，注释用**井号 `#`**（hash symbol）来标记。

它的好处是：**让你可以写一段给自己看的说明，同时又不会把代码弄坏**。

> **计算机会完全忽略你的注释。** 它只为你而存在，也为你把代码分享出去的对象——老师、同事——而存在。

### 8.2 给 `hello.py` 加注释 [00:20]

回到 VS Code，Malan 在程序最上方加了注释，把原来的代码往下挪了挪：

```python
# Ask user for their name
name = input("What's your name? ")

# Say hello to user
print("hello,")
print(name)
```

几点说明：

1. 注释里的文字**不一定要用英文**，你可以用**任何人类语言**写。
2. VS Code 默认会把注释**灰掉（gray out）**——它们不再是蓝色的，也没有别的颜色。**这只是因为它们是你写给自己的笔记，计算机最终会忽略它们。**
3. 现在的写法是：**每一块（一行或几行）值得说明的代码，上面配一条注释。**

### 8.3 为什么值得这么做？ [00:20]

Malan 给了一个很实际的理由：

> 明天早上我睡了一觉醒来，早就忘了昨天干了什么。有了注释，我就能**直接用英文（或你自己的语言）看出这个程序在干什么**，而不必一行行去读代码本身。
>
> 更好的是：**如果将来出了错，你可以先读注释看到"我当时想干什么"，再看代码，判断代码现在是不是真的在做你当初想做的事。**

当然，对于眼下这种一两三行的小程序，注释**并不是必需的**，直接读代码和读注释一样快。但**养成这个习惯总体是好事**——每写一行或几行代码，就配注释，提醒自己和别人：你的**意图（intent）**是什么、你的代码在做什么。

> **补充**：注释还有一个用途——它可以充当**你的待办清单（to-do list）**。这就引出了下一节的伪代码。

### 8.4 学生提问：怎么写多行注释？ [00:20]

**学生**：我想写多行的注释，怎么做？

**Malan**：如果没听错的话，你是问"怎么写多行注释"？——很简单，**就一直这么写**，在**每一行前面都加一个井号**。

> 另外还有另一种写多行注释的技巧：用**三个双引号** `"""`，中间的内容都是注释。用单引号也可以。
>
> 但用三引号这种方法**在 Python 里往往有特殊的含义**，Malan 说"这个我们改天再讲"，本讲不展开。

## 9. 伪代码（Pseudocode）[00:20]

### 9.1 什么是伪代码 [00:20]

编程里有这样一个概念：**伪代码（pseudocode）**。

> **伪代码不是一个形式化的东西，也不是某一种具体的语言。** 它只是**用英文（或你自己的语言）简洁地、有条理地、带有算法味儿地把你的想法表达出来**。

正因为伪代码既不是 Python、也不必是英文，它就让你可以**在动手之前先把程序的大纲列出来**。

### 9.2 用伪代码写 `hello.py` [00:20]

举例：假如 Malan 今天其实**不确定这个程序该怎么写**，但**知道自己想干什么**，他可以先在 `hello.py` 里只写几条注释，一行代码都不写：

```python
# Step 1: ask user for their name

# Step 2: say hello to user
```

然后，一旦用伪代码把程序大纲列好，就可以逐条往里填：

- 好，怎么问用户的名字？——我可以用 `input("What's your name? ")`；然后在左边放一个变量，把值赋给它。
- 好，怎么向用户问好？——我知道可以用 `print` 在屏幕上说话。那就先说 `hello,`，然后再打印这个人的名字。

最终代码：

```python
# Ask the user for their name
name = input("What's your name? ")

# Print hello
print("hello,")

# Print the name inputted
print(name)
```

> **伪代码的价值**：它是**组织待办清单的好办法，尤其在你完全不知道代码该怎么写的时候**——因为它能把一个大程序**拆成一个个一口能吃下的小任务（bite-sized tasks）**。

## 10. 进一步改进：把输出并到一行 [00:25]

### 10.1 问题：换行太丑 [00:25]

现在程序"有点让人失望"——`Hello,` 在一行、名字在下一行，这个"抄近路"的结果不好看。你手机和电脑上的绝大多数程序，当然都会把文字放在一行。那我们该怎么做到？

> **讲师的强调**：这里的重点**不是为了解决这一个问题**，而是要**展示并强调一件事**——在编程（Python 和别的语言都一样）里，**同一个问题往往有非常多种解法**。

### 10.2 解法一：用 `+` 拼接字符串 [00:25]

```python
# Ask the user for their name
name = input("What's your name? ")

# Print hello and the inputted name
print("hello, " + name)
```

> 注意 `+` 的用法很有意思：它**不是加法**，我显然不是在把数字相加，但我的确**想把用户的名字"加到" `Hello, ` 这串文本上**。

运行，输入 `David`：

```
What's your name? David
hello,David
```

> 比之前好了，**但有个小 bug**——虽然只是审美层面的：**少了一个空格**。

凭直觉修：既然逗号后面少了空格，那就手动加一个呗：

```python
print("hello, " + name)
```

（在 `"hello,"` 的引号里，逗号后面补一个空格。）再运行，`hello, David`——从英语语法上看顺眼多了。

### 10.3 顺带解释：提示语末尾为什么有个空格 [00:25]

> 这里 Malan 回头解释了一个之前被略过的小细节：为什么 `"What's your name? "` 里**问号后面、右引号前面有个空格**？
>
> 那**纯粹也是为了好看**：他想**把用户的光标往右挪一格**，这样用户打字时，名字就不会紧贴着那个问号。

### 10.4 解法二：`print` 可以接收多个参数 [00:25]

事实证明，**有些函数（包括 `print`）其实可以接收多个参数**。

> 只要用**逗号**把给函数的输入（即参数）隔开，你就可以传入**不是一个，而是两个、三个、四个、五个……**个参数。

于是可以写成：

```python
# Ask the user for their name
name = input("What's your name? ")

# Print hello and the inputted name
print("hello, ", name)
```

第一次看可能有点晕，因为现在**有两个逗号**：

- **第一个逗号在引号里面**——那只是英语语法里的逗号，是字符串内容的一部分
- **第二个逗号在引号外面**——它隔开了**传给 `print` 的两个参数**：第一个参数是 `hello, `（含空格），第二个参数是变量 `name` 本身

运行，输入 `David`：

```
What's your name? David
hello,  David
```

> **讲师的翻车现场**：**我算是矫枉过正了——现在不知怎么出现了两个空格。**

### 10.5 关键机制：`print` 会自动插入空格 [00:25]

> 这件事很微妙，但很重要：**当你给 `print` 传多个参数时，它会自动帮你插入一个空格。**

为什么之前没暴露？因为之前我们是用 `+` 运算符，**一次性把一整个参数**传给了 `print`；而这次由于用了逗号，我们传的是**两个**参数，于是 `print` 自动插入的空格 + 我们自己写的空格 = 两个空格。

所以，**如果我不想要那个多余的空格，我自己就不用写**：

```python
# Ask the user for their name
name = input("What's your name? ")

# Print hello and the inputted name
print("hello,", name)
```

再运行，输入 `David`，输出 `hello, David`——语法上正是我们想要的样子。

### 10.6 两种写法到底哪个好？ [00:25]

| 写法 | 传了几个参数 | 机制 |
| --- | --- | --- |
| `print("hello, " + name)` | **1 个** | 先用 `+` 拼接（concatenation），再把结果作为唯一参数传进去 |
| `print("hello,", name)` | **2 个** | 直接传两个参数，`print` 自动在中间插一个空格 |

关于 `+` 版本，Malan 详细解释了计算机是怎么做的：**就像数学家一样，先算括号里的**。

- 括号里你有：字符串 `hello, `（还要把空格加回来）
- 然后一个 `+`，**这里的意思不是加法，而是拼接（concatenation）**——把左边的东西和右边的东西连起来
- 于是它变成英语短语 `hello, David`
- 然后**作为唯一的参数**传给 `print`

而且它是**动态完成的**——不像之前那样是我偷偷把 David 敲死在代码里，它是**先拼接、算出那个值，再作为参数传给 `print`**。

### 10.7 学生提问：函数可以反复用吗？`+` 和逗号到底啥区别？[00:30] [00:30]

**学生 1**：我们能多次使用同一个函数，去解决代码里反复出现的问题吗？

**Malan**：可以，你可以**在不同的地方多次使用同一个函数**来解决某类问题。不过我们很快就会看到：**如果你发现自己在用同样的方式一遍又一遍地解决同一个问题**，那么你就可以**做出你自己的函数**，这样就不必一直重复用语言自带的那几个基础函数了。

**学生 2**：我想问逗号和加号。加号后面只能给一个变量吗？逗号后面可以给多个变量吗？区别是什么？

**Malan**：好问题。在字符串（string）的语境下——我一直用这个词，**"字符串"是编程语言里的技术术语，意思是"一串文本"**：可以是一个字符、一个单词，甚至整整一段话。

- **`+` 运算符在 Python 里不只是用来做加法**（像我们纸上做的那样），**它也被用来拼接（concatenate）左右两个字符串**。
- 如果你想连起来的不只是左右两个字符串，而是第三个、第四个，你**完全可以一直用 `+` 串下去**，就像数学里那样。
- 但**到某个点它就会开始变得难看（ugly）**，尤其是当你的代码行变得很长的时候。所以**有更好的办法，我们马上就会看到**。

## 11. `str` 类型与 `print` 的官方参数 [00:30]

### 11.1 `str` 就是 string 的缩写 [00:30]

回到代码，Malan 指出：我们一直在讨论的其实**就是字符串**——但在 Python 里，字符串有个专门的**技术称呼**，叫 **`str`（S-T-R）**，就是 string 的缩写。

> 如果你学过别的语言就会知道，发明编程语言的人**喜欢非常简洁、直奔主题**，所以我们倾向用很短的词来描述东西，而不一定是完整的单词。
>
> 所以你口头可以说 "string"，但在 Python 里，**我们说的这串文本，技术上就是 `str`。** 这是**程序里一种真正的数据类型（type of data）**。

### 11.2 换个思路：不放弃两次 `print` [00:30]

Malan 说他喜欢"所有内容都在同一行"这个成果，但还有没有别的办法？

答案是**有**：其实**我们完全不必放弃用两次 `print`**。

倒回之前的版本——那时候我还不知道怎么解决，就用了一次 `print` 输出 `hello, `，再用一次 `print` 输出 `name`。严格说这不算差，但**有个我不喜欢的视觉副作用（visual side effect）**：两行文字被拆开，看起来很丑。

**但有另一种修法。**

### 11.3 去官方文档里找答案 [00:30]

显然，`print` 函数会**自动输出一个换行**——它会自动把光标移到下一行，这就是为什么 Hello 在一行、David 在下一行、再下面是我的 `$` 提示符。

**但你可以覆盖（override）这个行为。** 再次强调：**函数接收影响其行为的参数，你只需要知道这些参数叫什么。**

于是我们去查 Python 官方文档：

- Python 所有官方文档都在 **docs.python.org**
- 在里面翻可以找到**所有内置函数（built-in functions）**的清单与文档
- 再精确一点，还能找到 **`print` 函数专属的那一页**

Malan 没有在浏览器里打开，而是**只摘了那页文档里的一行**——他坦白说，**这是目前为止我们看到的最晦涩（cryptic）的东西**：

```
print(*objects, sep=' ', end='\n', file=sys.stdout, flush=False)
```

> 而且我也要说：**Python 的文档对初学者、新手来说并不一定是最容易读的**。这同样**需要练习**。所以如果你看不懂眼前的文档，**别慌、别被淹没**。

### 11.4 形参（parameter）vs 实参（argument）—— 本讲重点术语 [00:35]

Malan 用这行文档讲清了一个容易混淆的术语区别：

- 函数名当然是 `print`
- 然后有一个左括号和一个右括号，**括号里的所有东西都是这个函数的参数**
- **但是**，当我们像这样**在文档里**看这些"参数"时，技术上应该用另一个词——**形参（parameter）**

> **形参和实参说的是同一件事，只是你看问题的方向不同：**
>
> - 当你讨论**这个函数能接收什么**、这些输入叫什么名字时 → 叫**形参（parameter）**
> - 当你**真正使用这个函数**、往括号里传入具体的值时 → 这些值叫**实参（argument）**

### 11.5 逐个拆读这行文档 [00:35]

**`*objects`**

语法很晦涩，但现在只需知道：**一个星号/星花后面跟 `objects`，意思是 `print` 函数可以接收任意数量（any number）的对象**。你可以传入 0 串文本、像我之前那样传 1 串、像后来那样传 2 串，**技术上讲，你真想的话传无限多个都行**（虽然那代码会很难看）。

**`sep=' '`**

接下来看到一个逗号，然后是一个叫 **`SEP`** 的参数，是英文 **separator（分隔符）** 的缩写。注意那个等号和**单引号包着的一个空格**。所以我们看到了一个线索——**它的默认值是一个空格**。

**`end='\n'`**

`print` 函数还有一个叫 **`end`** 的参数，从等号和引号来看，它的**默认值是 `\n`**。

> **`\n` 是什么？** 如果你以前写过程序，你多半见过它；如果你从没写过，它可能看起来相当晦涩。
>
> **反斜杠 n 的意思是"换行"（new line）**——它是一种**文本化的表达方式**，用来告诉计算机"我希望你把光标移到下一行、另起一行"。

所以，读文档得到的结论是：**`print` 函数默认会在每一行的结尾加上 `\n`。** 你**并不会真的看到 `\n` 这三个字符**，你看到的是一个新行，你看到光标跳到了下一行。

### 11.6 回头解释前面的"两个空格"之谜 [00:35]

按同样的逻辑倒推：**`sep`（separator）的默认值是一个空格**。

我们在哪儿见过？——回想之前那个例子：我给 `print` 传了**不只一个而是两个**参数，结果它们**神奇地中间多了一个空格**。事实上，**那个空格是 `print` 加的，加上我自己写的空格，所以我后来把自己的空格删掉了**。

所以文档告诉我们的就是：

> **当你给 `print` 传多个参数时，默认它们之间会用一个空格分隔。**
> **默认情况下，你传给 `print` 的参数，整串输出结束时会以换行结尾。**

### 11.7 实战：用 `end=""` 干掉换行 [00:35] [00:35]

Malan 说：文档里 `print` 还能做更多事，但我们**先只聚焦 `sep` 和 `end`**，来解决最初的那个问题——**我不喜欢 `Hello, David` 被拆成两行**。

为什么会拆行？**因为 `print` 会自动输出一个新行。那就告诉它别这么做。**

做法：给**第一个 `print`** 传第二个参数，写上 `end=""`——**不是默认的 `\n`，而是"空空如也"**。**覆盖默认值，让它后面不换行，后面什么都没有。**

```python
# Ask the user for their name
name = input("What's your name? ")
print("hello,", end="")
print(name)
```

运行，输入 `David`：

```
What's your name? David
hello,David
```

一切都在同一行了。原因：

- 第 5 行会打印 `hello,` 加一个空格，**但末尾什么都不加**，因为我把 `end` 改成了空字符串
- 第 6 行会打印名字 `David`（或用户输入的任何名字），**并且它后面会把光标移到下一行**，因为**我没有覆盖那里的 `end` 值**——它还是默认的 `\n`

### 11.8 用一个"丑"例子看清楚 `end` 到底干了什么 [00:35]

为了看得更明白，Malan 故意写了个很怪的东西：**往 `end` 里塞三个问号**：

```python
# Ask the user for their name
name = input("What's your name? ")
print("hello,", end="???")
print(name)
```

运行，输入 `David`：

```
What's your name? David
hello,???David
```

> 结果**真的很丑，但你 literally（字面地）看到了发生了什么**：`hello,` + 空格 + 三个问号（这就是那个 `end`），然后才是 `David`。
>
> 这不是个好结果，但它**展示了我们在这里拥有多大的控制权**。

### 11.9 实战：用 `sep` 覆盖默认分隔符 [00:35]

再倒回另一个版本——当时我传了 `hello,` 和 `name`，它们被**一个空格**隔开，运行 `python hello.py`，输入 `David`，一切正常。

**那如果我们覆盖 `sep`（separator）的值呢？** 把它从一个空格改成三个问号，好让自己搞明白这是怎么回事：

```python
# Ask the user for their name
name = input("What's your name? ")
print("hello,", name, sep="???")
```

运行，输入 `David`：

```
What's your name? David
hello,???David
```

你会看到：这两个输入——`hello,` 和名字——**现在被三个问号丑陋地分隔开了**，因为**我覆盖了 `sep` 的默认行为**。

> 注意：**虽然文档里用的是单引号，但我一直习惯用双引号。**
>
> **在 Python 里两者都可以用。严格来说无所谓，但你应该保持一致（be consistent），而我一般用双引号。**
>

### 11.11 位置参数 vs 命名参数 [00:35]

讲到这里，Malan 给刚才见过的两类参数正式命名：

**位置参数（positional parameters）**

> 到目前为止，我们给 `print` 传的那些值，叫**位置参数**。
>
> "位置"的意思是：**你传给 `print` 的第一个东西，第一个被打印；逗号之后的第二个东西，第二个被打印；以此类推。**

**命名参数（named parameters）**

> 而我们刚才看到的 `sep`（separator）和 `end`（E-N-D，行尾）这类，叫**命名参数**。
>
> 为什么叫"命名"？因为：一、**它们是可选的**，你可以在 `print` 语句的末尾传入；二、**你可以用名字来使用它们**。

## 12. 一个小麻烦：引号里面还想放引号 [00:40]

### 12.1 学生提问 [00:40]

### 12.2 翻车：`print("hello, "friend"")` 是非法语法 [00:40]

假设我们想输出的不是用户名，而是带点讽刺意味的一句：

```python
print("hello, "friend"")
```

（想把 friend 这个词放在"手指引号 / 空气引号"里。）

**这行不通。** 因为你既想用引号把 `friend` 括起来表示讽刺，**又想用引号结束这句话**——解释器会彻底混乱。

运行 `python hello.py`，你会看到：**这是非法语法（invalid syntax）**，而且**报错信息还会误导你**：

> `SyntaxError: invalid syntax. Perhaps you forgot a comma?`

> **讲师的提醒**：这其实**有点烦人**——**有时你看到的报错信息是具有误导性的**。计算机、这门语言**并不真的知道发生了什么**，所以它只能给出**最好的猜测**，但**这个猜测不一定正确**。

### 12.3 解法一：外层改用单引号 [00:40]

回忆一下刚说过的：**只要保持一致，你可以用双引号也可以用单引号**。所以：

```python
print('hello, "friend"')
```

**外层用单引号，内层就可以用双引号，而且它们会被原样显示出来。**

运行 `python hello.py`：

```
hello, "friend"
```

### 12.4 解法二：用反斜杠转义（更常用） [00:40]

如果你**坚持用双引号**（为了保持一致），你可以再次使用那个**反斜杠字符**。

我们之前见过 `\n`：**它表示"我不想要一个字面的 n，我想要一个换行"**。

> 所以，**反斜杠代表所谓的转义字符（escape character）**——这个概念指的是：**某个你没法在键盘上直接敲一下就打出来的字符，你需要用多个字符组合来表达它。**

于是可以在内层那两个双引号前面各加一个反斜杠，让计算机明白：**哦，等等，这两个引号不是用来结束或开始句子的，它们是字面意义上的引号。**

```python
print("hello, \"friend\"")
```

再运行，同样工作正常，输出 `hello, "friend"`。

> **转义（escaping）是一种通用技巧**，可以让我们做到这件事。

## 13. 格式化字符串：f-string [00:45]

### 13.1 还有最后一种（最优雅的）解法 [00:45]

事实证明，我们还有**另一种方式**来解决"把变量塞进字符串"这个问题，而且它**大概是现在最常用的、至少是在为后面更长的字符串用法铺路时最优雅的方式**。

### 13.2 先试错的中间态 [00:45]

首先，**你不能直接把变量名写进字符串**——我们已经看过这是错的，那样你会字面看到 `hello, name`。

那如果**给变量名套上花括号（curly braces / curly brackets）**呢？

```python
name = input("What's your name? ")
```

> 注意 VS Code 会**很微妙地改变它的颜色**——VS Code 察觉到这里有有意思的事情发生了。

**显然不是我们想要的**——因为**我还没有告诉 Python 这是一个特殊的字符串**。

### 13.3 加上 `f` 前缀 [00:45]

这就是所谓的**格式化字符串（format string）**，或者叫 **f-string**，是 Python **近几年新增的一个特性**，它告诉 Python：**请以一种特殊的方式来格式化这个字符串里的内容**。

> 用来触发它的符号**有点怪，但这就是全世界选出来的方案**：**在字符串的开头、也就是第一个引号的前面，放一个 `f`**。这就是给 Python 的一个线索："哦，这是一个特殊的字符串，让我用特殊的方式为你格式化它。"

```python

print(f"hello, {name}")
```

```

```

**终于得到了我们这一路追求的目标。**

Malan 提出一个非常现实的问题：

### 14.3 演示：用户乱输入会怎样 [00:50]

### 14.4 `strip()`：去掉两端的空白 [00:50]

我们可以清理它。**事实证明，字符串里内置了"对字符串做点什么"的能力。**

```python
# Ask the user for their name
name = input("What's your name? ")

# Remove whitespace from the str
name = name.strip()

# Print the output
print(f"hello, {name}")
```

来看 `name = name.strip()` 这行：

**右边发生了什么？**

1. 右边我写了变量名 `name`
2. 然后用了一个**点号（period / dot）**
3. 然后看起来像是在调用一个函数——**凡是函数，我们都见过这个模式：函数名 + 左括号 + 右括号**，这里正是如此

**但这次我是在用一种略有不同的方式使用函数——在这个语境下，它被称为方法（method）。**

> **什么是方法（method）？** 如果 `name` 是一个字符串（也就是 `str`），那么根据文档，**Python 里有一大堆函数是"跟着字符串一起来的"**。你可以通过这样的方式访问这些功能：**字符串的名字（这里字面就是 `name`）+ 一个点 + 函数名 + 左括号 + 右括号**（括号里可以有参数，但这里不需要任何参数）。

我的诉求很简单：**把用户输入左边和右边的空白去掉。**

**但光调用还不够，我得记住这个结果**——所以这里**又用了等号**。再次强调：**它不表示相等，它表示从右往左赋值。**

当 `name.strip()` 这行代码**返回（return）**给我一个**返回值**时，它返回的是**用户输入的同样内容，但左边和右边都没有空白了**。于是**赋值运算符把这个值从右拷到左，从而更新了我 `name` 变量里的值**。

> **重要结论**：你不仅可以给变量赋值，你还可以**改变变量的值**——**只要反复使用赋值运算符（等号）**，它就会**一遍又一遍地从右往左拷贝新的值**。

再运行，输入 `     david  `：

```
What's your name?      david  
hello, david
```

比之前好了——**首字母大写还没解决**（第一个 D 还是小写），**但多余空格全被剥掉了**。

> 讲师自评：这是个超小的细节，不算多激动人心，但它**说明了一行代码能有多大的能量**。

### 14.7 `title()`：每个单词首字母都大写 [00:50]

还有另一个跟着字符串来的函数，叫 **`title`**，它做的是**标题式（title-based）的大写**，就像一本书的标题或一个人的名字那样——**把每个单词的首字母都大写**。这能帮我们多干点活。

### 14.9 链式调用：`name.strip().title()` [00:55] [00:50]

那我的代码呢？现在**有八行代码，其中四行是注释、四行是真正的代码**——真的需要这么多吗？

**不一定。** 看还能怎么干：

```python
# Ask the user for their name
name = input("What's your name? ")

# Remove whitespace from the str and capitalize the first letter of each word
name = name.strip().title()

# Print the output
print(f"hello, {name}")
```

**我可以把这些函数串起来（chain）**——把 `title` 加到后面。

**现在发生了什么？** 对于这样一行代码，**先看等号右边，再看左边**：

1. 取 `name` 变量的值，比如 `david malan`
2. **去掉左边和右边的空白**——这一步**会返回一个值**：没有前后空白的 `david malan`
3. 你想拿这个返回值做什么？**让 Python 对它做标题化处理（title case）**，也就是**遍历结果字符串里的每一个单词，修正第一个单词的首字母、第二个单词的首字母……**
4. 最后，**把整个结果从右往左拷回同一个 `name` 变量里**

### 14.10 再进一步：压成一行 [00:55]

而且，**我还可以再进一步**。为什么不把 `strip` 和 `title` 全都放到第一行去：

```python
# Ask the user for their name, remove whitespace from the str and capitalize the first letter of each word
name = input("What's your name? ").strip().title()

# Print the output
print(f"hello, {name}")
```

这样**我们从八行代码缩减到了四行**——**紧凑多了、整洁多了**。而且**尽管讲道理的人可能会有不同意见，但可以说它更好，因为更容易读**。**代码行数越少，犯错的机会越少**，它让我能赶紧去解决下一个问题。

### 14.13 `split()`：把全名拆成名字和姓氏 [00:55]

字符串还有很多别的方法，其中有一个叫 **`split`**——顾名思义，**它能把一个字符串拆成多个更小的子字符串（substrings）**。

举例：如果用户习惯输入**名 + 空格 + 姓**，而你想**只用名字来问候他**，那么我们就可以**利用名和姓之间那个空格，把字符串拆成两个更小的子字符串**。

```python
# Ask the user for their name
name = input("What's your name? ")

# Split user's name into first name and last name
first, last = name.split(" ")

# Print the output
print(f"hello, {first}")
```

要点：

1. 先主动加一行注释，说明我们要**把用户的名字拆成名和姓**
2. 然后取出那个 `name` 变量（里面大概是 `David Malan`），调用 `split`，**并传入一个空格作为参数**，以此表明"我就是想按这个字符来切"
3. **`split` 会返回一串值（a sequence of values）**，理想情况下是名字和姓氏
4. 在 Python 里，我们可以**一次性把这一串值同时赋给多个变量**：`first, last = ...`——效果是**从右往左，把第一个值放进第一个变量、第二个值放进第二个变量**
5. 最后一行，不再是向全名问好，而是 `hello, {first}`

运行，输入 `David Malan`：

```
What's your name? David Malan
hello, David
```

**这就是 Python 的交互模式。** 你现在**正在运行 Python 解释器**，而且**每敲入一行代码，它就会立刻执行**——你不必一遍又一遍地重新运行 `python`。

## 16. 浮点数（float）基础 [01:15]

### 16.1 什么是 `float` [01:15]

我们能用的不只是整数。现在从整数过渡到**又一种数据类型**——**float（浮点数）**。

- 字符串（string）是一串文本
- `int` 是像 -1、0、1 这样的整数
- **`float` 是带小数点的数，正式名称叫浮点值（floating point value）**

> 你可以把那个**小数点（floating point）想象成可以飘到这边、也可以飘到那边**，左边或右边可以有任意多位数字。**数学上，它是一个实数（real number），一个里面带小数点的数。**
>
> **这是 Python 支持的第三种数据类型。**

### 16.2 让计算器支持小数 [01:15]

眼下我们的计算器**有点天真地假设用户只会输入整数**。但如果我们也想支持浮点值，我想只要做几处小改动就行。

回到 VS Code，**把第 1 行和第 2 行的 `int` 改成 `float`**：

```python
# Get the user's input
x = float(input("What's x? "))
y = float(input("What's y? "))

print(x + y)
```

运行，输入 `1.2` 和 `3.4`：

```
What's x? 1.2
What's y? 3.4
4.6
```

得到最终答案 `4.6`。**如果我只期待整数，这是行不通的**；但既然我现在期待浮点值并做了适配，就能做浮点运算了。

### 16.3 `round()`：四舍五入到最近整数 [01:20] [01:15]

但假如我**不希望最终答案是 `4.6` 这样的浮点值**——我只想**四舍五入到最近的整数**，那就很高兴了。也就是说：**我允许用户输入带小数点的浮点数，但最终我只想把结果四舍五入到最近的整数。**

Python 里也内置了这个功能。回到之前那个"列出所有 Python 内置函数"的 URL，里面有一个叫 **`round`** 的函数，它做的事情正如我们所料：**接收一个数字作为输入，然后替我们四舍五入**，比如舍入到最近的整数。

但如果我们凑近看那份文档，会看到这样一行（Malan 摘录了一段）：

```
round(number[, ndigits])
```

这和之前看 `print` 文档的感觉类似——**它不仅显示函数名，还显示可用的参数（parameters），也就是我们使用这个函数时可以提供的输入**。但它也有点晦涩，还加了一些语法。

**逐个拆读：**

1. 这个函数的名字当然是 `round`
2. 它的**第一个参数是一个数字（number）**
3. **注意这次没有星号**——不像 `print` 那里有 `*objects`。**`round` 函数的第一个参数就只接收一个数字，句号。这是它的位置参数（positional parameter）。**
4. **注意这个语法**：在编程（以及更广义的技术领域）里，这是一个约定——**当你在文档中看到方括号（square brackets）时，它的意思是"你即将看到的东西是可选的（optional）"**。
5. 所以它的意思是：**如果你想更精确地指定要舍入到几位数字，你可以在这里加个逗号和一个数字来指定。**

换句话说，读文档可知：

- **如果你不指定位数，只指定了要舍入的数字，它就舍入到最近的整数**
- **如果你想舍入到十分位、百分位（也就是小数点后一位或两位），你可以额外传入 `, 1` 或 `, 2` 来更精确**

### 17.1 做除法 [01:25]

### 17.2 解法一：用 `round(x / y, 2)` 保留两位小数 [01:25]

既然做好了简单的除法，就来**舍入**它。把那个很长的 `0.6666666……` 舍入到**两位小数**会很棒。


```

What's y? 3

```

**于是我们看到了一种舍入方式**——**不只是舍入到最近的整数，而是舍入到指定的位数**。

### 17.3 解法二：用 f-string 的 `:.2f` [01:25]

**但还有另一种做法。** 而且它再次唤起了我们的 f-string 例子。改一下：

步骤和之前一样：

2. **在开头加 `f`**
3. **同样，这还没意思——它只是打印 `z`，而我为了把它变成 f-string 反而加了很多复杂度**
4. **但注意，我可以在变量名后面、冒号之后做点别的**：如果这是个大整数，我可能想用之前的逗号来给每三位数字加逗号；但**这次我不这么做，我要用另一串字符——`.2f`**

> 这也是那种**非常晦涩、连我自己都得不断去查的东西，因为不常用就会忘**。所以**如果它看起来特别怪，别被吓到**——但**根据文档，这就是用 f-string 指定"你想打印几位小数"的方式**。

运行，输入 `2` 和 `3`：

```

What's y? 3
0.67
```

**得到了完全相同的结果。**

> **讲师再次强调**：这**只是又一次印证了我的主张——在编程里，我们非常非常频繁地可以用多种方式解决同一个问题**。这就是**用 f-string 解决同一个问题的方案**。

**那哪个更好？** **看情况（It depends）。** 在这个例子里，它们**基本等价**。但你可以想象：

- **有时候用函数会更有用**，因为你可以**传入一个参数（比如 `ndigits`）作为第二个参数**
- 或者你可以想象**你事先就决定好要 `.2f`，然后直接这么写**

### 18.5 参数化：让 `hello` 接收一个参数 [01:30]

那我们考虑一下：**能不能把这个函数参数化（parameterize）？** 也就是说，**能不能定制 `hello`，让它接收用户的名字作为输入**，这样我们就能**在一行里、一口气说出不仅是 hello，还有那个人的名字**？

在括号里**自己想一个参数名**——**这完全由我选**。Malan 说他把参数叫 **`to`**：

> 为什么？**因为我希望我的函数听起来像它所代表的那个动词——`hello`。但你想向谁说 hello 呢？** 我把这个函数的参数叫 `to`，纯粹是因为**在英语里它听着很顺**：hello **to** whom?（向谁问好？）**这就是我叫它 `to` 而不是更简单的 `x`、`y`、`z` 的原因。**

```python
# Create our own function
def hello(to):
    print("hello,", to)

# Output using our own function
name = input("What's your name? ")
hello(name)
```

其中 `print("hello,", to)` 里那个逗号只是**为了语法好看**（英语里的逗号），然后把 `to` 作为 `hello` 的第二个参数放在后面。

> 当然还有别的写法（我们已经见过太多了），但**这一版在我看来比较清楚**。

2. 我**使用那个我命名为 `to` 的参数的值**，把它塞进 `print`，这样我不只看到 hello，还看到那个人的名字
3. 第 5 行：和往常一样，我只是拿到用户的名字
4. 第 6 行：**我不仅调用 `hello`，还把 `name` 变量作为输入（实参）传进去**，这样它就被传进了 `hello`
5. **这里本质上发生的是**：**虽然这个变量在这里叫 `name`，但当函数被调用时，计算机假定同一个值现在叫 `to`。** 所以 **`name` 实际上是被拷贝到了另一个叫 `to` 的变量里**，这样在 `hello` 的语境里，我就可以向那个变量说 hello 了
6. **稍后我们会看到，如果不把这些名字分清楚，会发生什么**

### 18.6 默认参数值：`def hello(to="world")` [01:35] [01:30]

- 第 6 行：获取名字

> **讲师的点题**：于是我们看到，**用相对简单但全新的语法，你就能实现与 `print` 函数自动提供给我们的功能非常相似（in spirit）的东西**。而现在，**控制权在你自己手里了。**

> **Python 解释器会按字面理解你；如果你要使用一个函数，那么在你调用它的时候，它必须已经存在。**

### 18.8 约定：定义 `main` 函数 [01:35]

那怎么修？看来不能那么做——**我必须把所有想用的函数都定义在文件的最顶端**。但那也会带来麻烦：**如果我总是得把函数定义在使用它的位置之上，那你等于在"倒着写代码"**——你得不停地把函数往上写、往上写、往上写，**而不是按逻辑从上往下写**。

所以，**用一种更标准的方式来修**：

1. **一般来说，你确实希望把代码的主要部分放在文件的顶部**
2. 而且 Malan 会进一步：**定义一个叫 `main` 的函数**——**这不是强制要求，而是一种约定（convention）**，它只是**向读者传达"这是我程序的主要部分"**

```python
def main():

    # Output using our own function
    name = input("What's your name? ")
    hello(name)

    # Output without passing the expected arguments
    hello()

# Create our own function
def hello(to="world"):
    print("hello,", to)
```

现在**去掉空的 `hello()` 调用**，只保留带参数的那一版——然后**在下面几行再定义我的 `hello` 函数**。

### 18.9 翻车：什么都没发生 [01:35]

**不幸的是**，既然我按这个顺序重排了函数（**主代码在上、`hello` 在下**，这样我的逻辑就能从上往下流动），运行 `python hello.py` 时——

**什么都没发生。**

再运行一次——**还是什么都没发生。**

> **这到底是为什么？**
>
> **仅仅因为我定义了一个叫 `main` 的函数、定义了一个叫 `hello` 的函数，并不意味着我真的调用（call）了、也就是使用了它们中的任何一个。**
>
> 是的，**我在 `main` 里面用了 `hello`，但没有任何人告诉 Python 去真正使用或调用 `main`。**

### 18.10 修复：在文件末尾调用 `main()` [01:35]

为了收尾，**我要在这份文件里做的最后一件事，就是真的调用我的 main 函数**：

```python
def main():

    # Output using our own function
    name = input("What's your name? ")
    hello(name)

    # Output without passing the expected arguments
    hello()

# Create our own function
def hello(to="world"):
    print("hello,", to)

main()
```

> **而且，以这种方式调用 `main` 还能把我从麻烦里解救出来**——因为现在：
>
> 1. **我先定义 `main`，但我还没调用 `hello`**
> 2. **接着我定义 `hello`，但我还是没有调用 `hello`**
> 3. **我只在文件的最后才调用 `main`**——它的效果是：先运行上面这段代码，而这段代码又会运行下面那段代码
>
> **于是它让我可以用任意顺序组织我的文件、排列我的函数**，包括**把 `main` 放在最顶端**，并且**最终解决了"Python 不知道发生了什么"的那个问题**。

### 18.11 作用域（scope）的大坑 [01:40] [01:40]

现在有一个重要的事情要注意：**我把 `hello` 函数定义为接收一个参数 `to`**，然后**把"我想向之问好"的那个变量的值传进这个函数**——也就是那个叫 `name` 的变量。

**因为，假设我刚才的做法略有不同呢？** 假设：

- **我没有把 `hello` 定义成接收参数**，也就是**去掉 `to` 以及它的默认值 `"world"`**
- 然后回到 `main` 函数，**只调用 `hello` 本身，不传任何参数**
- 并且**再犯一个（技术上的）错误**：**天真地在 `hello` 函数里直接打印 `name` 的值**

```python
def main():
    name = input("What's your name? ")
    hello()

def hello():
    print("hello,", name)

main()
```

明确一下现在的情况：

- 在 `main` 函数的第 2 行：**我定义了叫 `name` 的变量**，并把 `input` 函数从用户那里得到的返回值赋给它
- 然后**我只是调用 `hello`**
- 在**现在不再接收任何参数的 `hello` 函数里**：我调用 `print`，传入 `hello,`，紧接着传入 `name` 这个变量（就是那个装了用户输入的变量）

**但问题在于：`name` 现在只存在于 `main` 里面。**

运行这一版：

```
What's your name? David
```

然后——

```
NameError: name 'name' is not defined
```

> **事实证明，这其实是所谓作用域（scope）的问题。**
>
> **作用域指的是：一个变量只存在于你定义它的那个语境（context）中。**
>
> **既然我是在 `main` 函数里定义这个变量 `name` 的，那我就只能在我的 main 函数里使用这个变量。我不能像刚才那样在 `hello` 函数里使用它——它在那个所谓的作用域里并不存在。**

**所以这就是为什么**：如果我们把所有改动都撤销，你会看到**我是刻意地从 `main` 函数把值传给 `hello` 函数的**。

**而现在在 `hello` 函数里，它在技术上有了个不同的名字——在那个语境里它叫 `to`，但没关系。** **每个函数都有完全的自由度来给自己的变量、自己的参数起名字**；而**这是一种把那个变量的值交到 `hello` 函数手里的方式**，这样它也能被 `hello` 打印出来。

## 19. 返回值（`return`）[01:45]

### 19.1 副作用之外，函数还应该能"交还"值 [01:45]

**最后我们还可以再加一笔**。

既然我们已经实现了 `hello`，你会注意到：**`hello` 只有一个所谓的副作用（side effect）——它只是往屏幕上打印了点东西。**

**那如果我还希望我的函数不要只有副作用，而是真的交还（hand back）一个值给我呢？**

回忆一下：

- **`input` 函数会返回一个值**——用户输入的那个字符串
- **`int` 函数会返回一个值**
- **`float` 函数会返回传给它的那个值（转换后的）**

那么**你可以用最后一个关键字，字面就叫 `return`，来显式地自己返回一个值**。

回到 VS Code，把注意力转回 `calculator.py`，看看能不能**实现另一个版本的 `calculator.py`，让它有一个我们自己的、甚至还能返回值的函数**。

### 19.2 先假设 `square` 存在——然后报错 [01:45]

打开 `calculator.py`，这次把之前的东西全部扔掉，**开始践行我们刚刚宣讲的做法**：

```python
def main():
    x = int(input("What's x? "))
    print("x squared is", square(x))

main()
```

- 定义一个叫 `main` 的函数，它将成为我程序的主要部分
- 声明一个变量 `x`，把它赋值为"询问用户 `What's x?` 之后转换过的用户输入"——又是一行我们写过的那种代码
- 现在假设我们想**把这个值平方（square）**：**把用户输入的数字提升到 2 次幂**（2 的平方是 4，3 的平方是 9，4 的平方是 16，等等）

那怎么实现一个**字面上叫 `square`、但 Python 并不自带**的函数？

**先假设它存在**，然后这么写：`print("x squared is", square(x))`，也就是把 `square` 函数的返回值作为 `print` 的第二个参数传进去。

> **但 `square` 并不存在，我来演示给你看**：在文件底部调用 `main()`，然后运行 `python calculator.py`——输入 `x` 为 2，然后会看到**一大堆错误**，以及 **`NameError: name 'square' is not defined`**。

**这不是笔误，只是这个函数确实不存在。**

### 19.3 用 `return` 实现 `square` [01:45]

我想我可以让它存在。来定义另一个函数叫 `square`：

```python
def main():
    x = int(input("What's x? "))
    print("x squared is", square(x))

def square(n):
    return n * n

main()
```

- 这个函数接收一个数字，Malan 把它**泛化地叫 `n`**（很多程序员都会这么干），用来表示**任意一个数**
- 那我要做什么来求 `n` 的平方？**一个数的平方其实就是它自己乘自己**，所以写 `n * n`
- **但光自己做这个乘法 `n * n` 是不够的**——**你必须 `return`（返回）真正的 `n * n` 这个值**，这就是我们的新关键字

运行：

```
What's x? 2
x squared is 4
```

再试一次，输入 3：

```
What's x? 3
x squared is 9
```

**于是我实现了我自己的、返回一个值平方的函数。** 而且**因为我用了 `return` 关键字，这保证了我可以像使用 `input`、`int`、`float` 的返回值那样，把这个函数的返回值传给另一个函数（比如 `print`）**。

### 19.4 同一个问题的多种解法 [01:45]

> **而且这里也有非常多种解决同一个问题的方法**：
>
> - 我可以真的**把 `n` 提升到 2 次幂**——我们没见过这个语法，但如果用**两个星号**（`**`），**它就把左边的东西提升到右边的幂**：`n ** 2`
> - 或者，**Python 里其实有一个叫 `pow`（power）的函数**用来做乘方，**它接收两个参数：第一个是数字，第二个是指数（exponent）**：`pow(n, 2)`
>
> **所以同样，解决同一个问题就是有这么多种办法。**

```python
def square(n):
    return n ** 2

def square(n):
    return pow(n, 2)
```

## 本讲易错点

1. **`=` 不是"等于"，是赋值，方向是从右往左。** `name = input(...)` 是把右边函数的返回值拷进左边的变量。理解反了，后面所有代码都会读不懂。

2. **加了引号的变量名就是普通文字。** `print("hello, name")` 会字面输出 `hello, name`；要打印变量的值必须**去掉引号** `print(name)`，或者用 f-string `print(f"hello, {name}")`。

3. **`input()` 返回的永远是字符串，哪怕用户敲的是数字。** 所以 `x = input(...)` + `y = input(...)` 之后写 `x + y`，做的是**字符串拼接**：输入 1 和 2 会得到 `12` 而不是 `3`。必须用 `int()` / `float()` 做类型转换。

4. **`print` 用逗号传多个参数时，会自己插一个空格。** 所以 `print("hello, ", name)` 会出现**两个空格**。要么把末尾空格删掉，要么改用 `+` 拼接。同理，`print` 默认以 `\n` 结尾（自动换行），用 `end=""` 可以覆盖。

5. **只写 `{name}` 没有用，必须在引号前加 `f`。** `print("hello, {name}")` 会原样输出花括号；必须是 `print(f"hello, {name}")`。

6. **引号里想放同种引号会直接语法错误。** 而且报错信息可能误导你（"Perhaps you forgot a comma?"，其实你忘的是转义）。两种修法：外层换单引号，或者用 `\"` 转义。

7. **`capitalize()` 只大写第一个字母，`title()` 才大写每个单词。** 处理 `david malan` 这种全名时必须用 `title()`。另外 `strip()` 只去**两端**空白，中间的空格去不掉（那需要别的方法；`lstrip` / `rstrip` 分别只处理左 / 右）。

8. **函数必须先定义、再调用。** 把 `def hello()` 挪到调用它的代码下面，会直接 `NameError: name 'hello' is not defined`。

9. **只 `def main()` 不写 `main()`，程序什么都不做。** 定义了函数 ≠ 调用了函数。文件末尾那行 `main()` 是让程序真正跑起来的开关。

10. **函数里的变量有作用域（scope）。** 在 `main` 里定义的 `name`，不能在 `hello` 里直接用，会 `NameError: name 'name' is not defined`。正确做法是**通过参数把值传进去**，函数内部用自己的参数名（比如 `to`）来接收。

11. **自己写的函数如果只想"交还"一个值，必须写 `return`。** 只写 `n * n` 不算返回；要写 `return n * n`，调用方才能把结果传给别的函数（比如 `print`）。

12. **不要把代码炫技式地压成一行。** `print(int(input("What's x? ")) + int(input("What's y? ")))` 虽然只有一行，但嵌套太多、可读性差、容易出错——讲师明确不推荐。可读性和简单性优先。

13. **float 不能无限精确。** 因为计算机内存有限，`2 / 3` 只能得到 `0.6666666666666666`。这是浮点数的固有问题（后面会再讲）；而 Python 的 `int` 则没有大小上限。

14. **不要指望用户配合。** 多余空格、全小写、输入非数字（比如 `cat`）——这些都是现实。本讲的解法是 `strip()` / `title()`；如何处理"输入了非数字"这种错误，本讲故意留到后面几周。
