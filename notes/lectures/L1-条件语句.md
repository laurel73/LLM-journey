## 1. 为什么要学条件语句 [00:00]

到目前为止（第 0 讲我们学了函数与变量），我们写的程序都是**从上到下一路执行到底**的：第一行、第二行、第三行……没有任何"选择"。

但真实世界的程序几乎都需要做决定。David 用了一个非常形象的说法：条件语句让我们在代码里遇到"**岔路口**"（forks in the road）——往左走还是往右走，取决于我们问出的那个问题的答案。

更正式一点说：**条件语句（conditional statements）就是"提问并根据答案做决定"的能力**。问出一个问题，如果答案是真（true），就执行这一段代码；如果是假（false），就执行另一段（或者干脆什么都不执行）。

### 1.1 Python 里用来提问的符号 [00:00]

Python 内置了一批"运算符"（operators），专门用来问数学类的问题。David 说，我们从数学问题入手，只是因为例子简单，后面会问更复杂的问题。

这一讲会用到的符号：

- `>`：大于（greater than）
- `>=`：大于等于（greater than or equal to）。注意，我们在纸上写"≥"是一个符号，但键盘上没有，所以编程语言里统一写成 `>=`
- `<`：小于（less than）
- `<=`：小于等于（less than or equal to）
- `==`：等于（equals）——**两个等号**
- `!=`：不等于（not equal to）——感叹号（也叫 bang）加等号

### 1.2 一个等号 vs 两个等号：本讲第一大坑 [00:00]

这里 David 专门停下来解释了一个"历史遗留问题"。

在第 0 讲里，我们用**一个等号** `=` 给变量赋值。David 强调：那个等号**不代表"相等"**，它代表"赋值"（assignment）——把右边的东西复制一份给左边，方向是**从右往左**。

这个设计很好用，但它留下了一个麻烦：既然一个等号被"占用"了，那我们想**比较两个东西是否相等**时怎么办？

答案是在 Python（以及很多语言）里用**两个等号** `==`：

- `=` ：赋值，把右边的值复制给左边
- `==`：比较，问左边和右边是否相等

最后是 `!=`，感叹号加等号，表示"不等于某个值"。

> 记住这一对，它是本讲最容易出错的地方。后面 David 自己就在现场写错了一次（见 2.4 节）。

## 2. 第一个程序：compare.py [00:05]

要用这些符号提问，我们还需要一个新关键字。和英语一样，这个关键字就是 **`if`**。

### 2.1 创建文件并获取用户输入 [00:05]

David 打开 VS Code，在终端里输入：

```bash
code compare.py
```

`code` 命令会在 VS Code 里新建一个文件（如果文件已存在则打开它）。文件名是 `compare.py`，因为它的目标就是"比较数值并根据比较结果做决定"。

先获取两个来自用户的整数。为什么要用用户输入？因为我们希望程序能对**事先不知道值**的数字做出判断——如果值都是写死的，那判断就没有意义了。

```python
x = int(input("What's x? "))
y = int(input("What's y? "))
```

这里的套路第 0 讲见过：`input()` 弹出提示并等待用户输入，返回字符串（str）；`int()` 把这个字符串转换成整数（integer）；最后赋值给变量 `x`。`y` 同理。

### 2.2 第一版：三个独立的 if【初始版本】 [00:05]

现在开始提问。David 写的第一个版本是三个**各自独立**的 `if`：

```python
x = int(input("What's x? "))
y = int(input("What's y? "))

if x < y:
    print("x is less than y")
if x > y:
    print("x is greater than y")
if x == y:
    print("x is equal to y")
```

运行：

```bash
python compare.py
```

```text
What's x? 1
What's y? 2
x is less than y
```

输入 1 和 2，程序打印出 `x is less than y`，符合预期。

David 自己也说，这个程序目前"没什么意思"——它只是把显而易见的数学事实又说了一遍。但它的价值在于让我们看清**新语法长什么样**。

### 2.3 语法拆解：布尔表达式、冒号、缩进 [00:05]

我们逐行拆开看：

- 第 4 行的 `if` 是关键字，放在行首
- 紧跟其后的是**问题本身**：`x < y`。左边一个变量 `x`，右边一个变量 `y`，中间是数学比较符号
- `x < y` 这一整块，技术上叫做**布尔表达式**（Boolean expression）

**什么是布尔表达式？** 它以数学家 Bool（布尔）命名，指的就是"一个只有是/否两种答案的问题"，或者更技术地说，答案是 **true（真）或 false（假）** 的问题。

只有两种可能答案，这件事非常方便——无论是对人还是对计算机，决策都变得极其简单：做，还是不做。

接下来是两个 Python 的关键细节：

**细节一：不需要括号。** 如果你从 C、C++、Java 转过来，可能会觉得问题应该被括号包起来，比如 `if (x < y)`。David 明确指出：**在 Python 里这些括号不是必须的**（至少在这个场景下不是）。

**细节二：行末必须有冒号 `:`。** 这是必须的，不是风格问题。

**细节三（最重要）：下一行必须缩进。** David 说，他在新的一行开头**打了缩紧**——按四次空格键，或者按一次 Tab 键（VS Code 会自动把 Tab 转成四个空格）。

**这个缩进就是 Python 的全部"分块"机制**：缩进告诉 Python，第 5 行（也就是 `print` 那行）**只有**在第 4 行的答案为真时才执行。

换句话说：

```python
if x < y:          # 提问
    print("...")   # 缩进 → 归 if 管，只有答案为真才执行
print("done")      # 没缩进 → 跟 if 无关，无论如何都会执行
```

### 2.4 翻车现场：David 写成了 `if x = y` [00:05]

在写第三个条件时，David 现场口述的是 "if x equals y"（如果 x 等于 y），然后**他自己立刻发现了问题**：

> "if x equals y，然后——等等，我刚才写错了什么？"

他马上纠正：我**不想**把 y 赋值给 x。要表达"相等"，必须写 `if x == y`。

这就是 1.2 节那个坑的现场演示：如果你在这里写了 `if x = y`，Python 会直接报语法错误（syntax error），因为 `if` 后面需要的是一个能求值的表达式，而不是一条赋值语句。

**修正后的完整第一版：**

```python
x = int(input("What's x? "))
y = int(input("What's y? "))

if x < y:
    print("x is less than y")
if x > y:
    print("x is greater than y")
if x == y:
    print("x is equal to y")
```

## 3. 流程图与控制流：把逻辑画出来看 [00:10]

代码跑通了，但 David 接下来做了一件对初学者特别有价值的事：**把这段代码画成流程图（flow chart）**，理由是"如果你是一个更依赖视觉的学习者"。

流程图就是程序逻辑的图示。更技术地说，它展示的是程序的**控制流**（control flow）——也就是你在代码里**控制程序走向**的能力，程序默认是从上往下流的，而条件语句可以改变这个流向。

### 3.1 怎么读这张图 [00:10]

- 最上面是一个**椭圆**，里面写着 `start`（开始）。不管图长什么样，你读图的起点永远是它
- 从 `start` 出发有一根箭头，指向一个**菱形**。菱形里放的是一个**问题**（布尔表达式），比如 `x < y`
- 菱形的意思就是：**根据答案，往左走还是往右走**。答案 true 走一边，答案 false 走另一边
- 矩形框代表"做点什么"，比如打印一句话
- 最后是 `stop`（结束）椭圆

### 3.2 跟着输入 1 和 2 走一遍 [00:10]

`x = 1`、`y = 2`：

1. 第一个菱形问 `x < y`？1 小于 2，答案是 **true** → 打印 `x is less than y`
2. 但代码往下还有两个 `if`。所以还要问第二个问题：`x > y`？1 大于 2？**false**
3. 还要问第三个问题：`x == y`？1 等于 2？**false**
4. 走到 `stop`

注意关键的一点：**无论前面的答案是 true 还是 false，箭头最后都会汇合到下一个菱形**。也就是说——

**这个程序不管什么情况，永远要问满三个问题。**

这也是为什么屏幕上只打印了一行：后面两个问题的答案都是 false，它们分支上没有 `print`。

### 3.3 代码"正确"不等于"设计得好" [00:10]

David 在这里提出了本讲的核心方法论，非常值得记下来：

> 你写的代码**正确**、能实现你想要的功能，这**还不够**。随着程序越来越长、越来越复杂，你还必须让它**设计良好**（well-designed）。

他当场问学生：这个程序虽然正确，但"设计上"哪里不好？

学生 **Khalid** 回答：

> "if 用得太多了，有点重复。我们可以让代码更简洁（concise）一些。"

David 完全同意：确实显得啰嗦，`if` 这个、`if` 这个、`if` 这个。而从逻辑上讲，**一旦我搞清楚了其中一个问题的答案，后面那些问题的答案我其实已经知道了**。

回到图上就很清楚：不管走左边还是走右边，三个菱形一个都跑不掉，永远要问三个问题。

那怎么改进？

## 4. elif：让条件互斥 [00:10]

改进的办法是给 Python 词汇表再加一个关键字：**`elif`**。

`elif` 是 "else if" 的缩写（一个连词式的合并写法）。它的作用是：**问一个"会考虑前面问题的答案是真是假"的问题**。

### 4.1 第二版：if / elif / elif【改进版本】 [00:10]

```python
x = int(input("What's x? "))
y = int(input("What's y? "))

if x < y:
    print("x is less than y")
elif x > y:
    print("x is greater than y")
elif x == y:
    print("x is equal to y")
```

区别只在于把后两个 `if` 换成了 `elif`。但逻辑变了：这些条件现在是**互斥的**（mutually exclusive）——一旦某个答案为真，后面的问题就**不再问了**。

用英语去想这段逻辑就非常自然：

- 如果 x 小于 y → 打印 `x is less than y`，**然后就完事了**
- 否则，如果 x 大于 y → 打印 `x is greater than y`
- 否则，如果 x 等于 y → 打印 `x is equal to y`

David 强调：**不要继续问那些你在逻辑上已经知道答案的问题**。

### 4.2 运行结果看不出差别，但这是在为将来打地基 [00:10]

```bash
python compare.py
```

```text
What's x? 1
What's y? 2
x is less than y
```

行为完全一样。David 很坦率地说：说实话，我运行的时候**没感觉到任何差别**。因为现在的电脑、手机都太快了，这种改进在小程序上根本感觉不出来。

**但是**，这是在为我们以后写更大、更复杂的程序**打地基**（laying the foundation）。

> 官方 Notes 补充了一个很好的视角：你的电脑可能察觉不到速度差异，但想象一下，一台在线服务器每天要跑几十亿、几万亿次这样的计算，一个小小的编码决定就会产生实实在在的影响。

### 4.3 新版流程图 [00:10]

`if / elif / elif` 版本的流程图长这样（用文字描述）：

```text
start
  │
  ├─ 问：x < y ?
  │     ├─ True  → 打印 "x is less than y"    → stop
  │     └─ False ↓
  ├─ 问：x > y ?
  │     ├─ True  → 打印 "x is greater than y" → stop
  │     └─ False ↓
  └─ 问：x == y ?
        ├─ True  → 打印 "x is equal to y"     → stop
        └─ False → stop
```

关键在于：**一旦某条分支为真，就直接连到 `stop`，不再往下问**。

- 输入 1 和 2：问第 1 个问题，为真，打印，**结束**。只问了 1 个问题
- 输入 2 和 1：第 1 个问题为假，问第 2 个问题，为真，打印，**结束**。问了 2 个问题
- 只有 x 恰好等于 y 时，才会一路走到最后那个 `elif`

David 还补充了一个细节：最后一个 `elif` 在图上仍然画了 false 分支，是为了让程序"定义完整"（well-defined）；但**逻辑上我们根本不该走到那里**——因为 x 与 y 的关系必然是小于、大于、相等三者之一。

## 5. else：兜底分支 [00:15]

David 停下来问：对这段代码或者这张流程图，有什么问题吗？

学生马上问：

> **"我们是不是应该在最后加一个 else？"**

David：问得好，这正好是我的第三种也是最后一种写法，我们立刻切过去。

### 5.1 为什么连第三个问题都不用问 [00:15]

回到代码，看高亮的 `elif x == y`：

问这个问题本身**没有错**。如果你想特别严谨（thorough），检查"小于 / 大于 / 等于"三种情况完全合理。

**但为什么不需要问这第三个问题？**

学生（David 称她为 Hope）回答得非常漂亮：

> "我们不需要再问 x 是否等于 y 了。因为从逻辑上说，如果前两个条件都求值为假，那么只剩下一个条件会为真——那就是 x 等于 y。"

David 确认：完全正确。我们对数学和比较都很熟悉，x 要么小于 y，要么大于 y，要么等于 y。**一旦排除了前两种可能，逻辑上 x 必然等于 y**。如果不是这样，那它就一定是小于或者大于。

### 5.2 第三版：if / elif / else【最终版本】 [00:15]

```python
x = int(input("What's x? "))
y = int(input("What's y? "))

if x < y:
    print("x is less than y")
elif x > y:
    print("x is greater than y")
else:
    print("x is equal to y")
```

注意 `else` 的用法：**它后面不跟任何问题**。它就是一个"兜底"（catch-all）：前面所有条件都为假时，直接假设 x 等于 y，然后打印。

### 5.3 三种输入全部验证 [00:15]

```bash
python compare.py
```

```text
What's x? 1
What's y? 2
x is less than y
```

```text
What's x? 2
What's y? 1
x is greater than y
```

```text
What's x? 1
What's y? 1
x is equal to y
```

三种情况全部正确。

### 5.4 用 else 之后的流程图 [00:15]

```text
start
  │
  ├─ 问：x < y ?
  │     ├─ True  → 打印 "x is less than y"    → stop
  │     └─ False ↓
  └─ 问：x > y ?
        ├─ True  → 打印 "x is greater than y" → stop
        └─ False → 直接打印 "x is equal to y" → stop
```

第三个菱形**消失了**。

David 总结这个演进：

- 第一版：图又长又拖沓，问了大量不必要的问题
- 第二版：短了一些
- 第三版：更短了

而**代码行数越少，你犯错的概率就越低，别人读起来也越容易**。所以这种"可读性"和"简化"，总的来说是好事。

## 6. or：一次问多个"或者"关系的问题 [00:20]

接着再增加一个能力。就像英语里你可以问"是这个**或者**是那个"，Python 里也可以，用的就是字面意义上的单词 **`or`**。

### 6.1 换个更"粗"的问题 [00:20]

这次我们不关心"到底是大于还是大于等于"，只想问一个更粗粒度（coarser）的问题：**x 和 y 相等，还是不相等？**

第四版：

```python
x = int(input("What's x? "))
y = int(input("What's y? "))

if x < y or x > y:
    print("x is not equal to y")
else:
    print("x is equal to y")
```

逻辑是什么？

- 如果 x 小于 y，那显然**不相等**
- 如果 x 大于 y，那也显然**不相等**
- 所以这两种情况都可以得出"x 不等于 y"
- 否则（用上 Hope 提议的 `else`），逻辑上它们**必然相等**

### 6.2 运行验证 [00:20]

```bash
python compare.py
```

```text
What's x? 1
What's y? 2
x is not equal to y
```

```text
What's x? 2
What's y? 1
x is not equal to y
```

```text
What's x? 1
What's y? 1
x is equal to y
```

### 6.3 对应的流程图 [00:20]

```text
start
  │
  └─ 问：x < y ?
        ├─ True  → 打印 "x is not equal to y" → stop
        └─ False ↓
           问：x > y ?
             ├─ True  → 打印 "x is not equal to y" → stop   ← 复用同一个 print
             └─ False → 打印 "x is equal to y"     → stop
```

David 在这里特别指出一个"看图"的心法：因为用了 `or`，两条 true 分支**可以复用图里同一个部件**（同一个 `print` 框）。

> 我们不需要为了每种情况都新增箭头和方框。就像代码里可以复用同一行代码一样，图上也可以复用同一块。

## 7. 还能更好吗：用 != 只问一个问题 [00:20]

### 7.1 第五版：用 !=【最终简化版】 [00:20]

David：完美。回想一下开头那张符号表——我们不仅可以问小于、大于、等于，**我们还可以直接问"不等于"**。

```text
start

```

### 7.2 也可以反过来写 [00:20]

如果你更喜欢从"相等"的角度思考，而不是"不相等"，那完全可以反过来——这是你的自由。

if x == y:

else:

改动时注意：把 `!=` 换成 `==` 之后，**两条 `print` 的顺序必须反过来**——原来 `if` 里那句要挪到 `else`，原来 `else` 里那句要挪到 `if`。

程序同样只问一个问题，同样简洁。

> 官方 Notes 在这里再次强调：`==` 判断左右两边是否相等，**两个等号非常重要**。如果你只写一个等号，解释器（interpreter）会抛出错误。

一张图总结本节的演进：随着代码越来越紧凑（字符越来越少），流程图也越来越小——这就是"相对简化"的可视化体现。

## 10. 继续收紧 grade.py [00:30]

### 10.1 改进一：把变量放中间，然后链式比较 [00:30]

首先，这些符号可以换着方向用。`score >= 90` 完全可以写成 `90 <= score`。

```python
score = int(input("Score: "))

if 90 <= score <= 100:
    print("Grade: A")
elif 80 <= score < 90:
    print("Grade: B")
elif 70 <= score < 80:
    print("Grade: C")
elif 60 <= score < 70:
    print("Grade: D")
else:
    print("Grade: F")
```

现在重点来了。David 特意强调：

> **这在 C、C++、Java 以及其他语言里是做不到的。**

原本我们问了两个问题（两个布尔表达式）：`90 <= score` **并且** `score <= 100`。而 Python 允许你把这两个比较**嵌套、串起来**（nest / chain them together），就像你在纸上做数学题时写的那样：

```python
score = 95

if 90 <= score <= 100:      # 链式比较：等价于 90 <= score and score <= 100
    print("Grade: A")
```

好处：

- 更干净一点（cleaner）
- 代码更紧凑
- 敲的键更少，打得更快
- 以后读起来更容易

David 的评价：这个改进**主要是审美层面（largely aesthetic）的**——它问的问题数量没变，只是表达得更简洁了。但这也算更好。

### 10.2 改进二：只问下界【最终版本】 [00:30]

还能再进一步吗？

David 的思路是：**每次判等级，我其实不必问两个问题**。不需要既问"是否大于 90"又问"是否小于 100"，也不需要既问"是否大于 80"又问"是否小于 90"。**重新想一遍逻辑**，可以做得更好。

假设（此处做一个假设）输入一定在 0 到 100 之间，那我们可以这样写：

```python
score = int(input("Score: "))

if score >= 90:
    print("Grade: A")
elif score >= 80:
    print("Grade: B")
elif score >= 70:
    print("Grade: C")
elif score >= 60:
    print("Grade: D")
else:
    print("Grade: F")
```

**为什么这样就够了？** David 解释得很细：

- 分数 ≥ 90，那显然是 A
- 走到 `elif score >= 80` 这一句时，说明**前面的 `>= 90` 已经是假的了**。所以如果这里为真，你**隐含地**就知道分数落在 80~89 这个区间
- 同理，`>= 70` 为真时，隐含地说明它不在 80 以上，所以在 70~79
- 再往下同理

也就是说：`elif` 的"前面为假才问"这个特性，**自动帮我们划出了上界**。

这是一个**小优化**，但它让我们问的问题更少，代码也更有可读性、更简洁，长期来看更好维护（maintainable）。

## 12. 取模运算符 % 与 parity.py [00:35]

现在换一个完全不同的思路，用一个我们到目前为止还没机会用的符号。

新程序叫 `parity`。在数学里，**parity（奇偶性）**指的是一个数是偶数还是奇数。判断用户输入的数是奇还是偶，在很多应用里都很有用。

创建文件：

```bash

```

### 12.1 认识取模运算符 `%` [00:35]

回顾一下算术符号：加、减、乘、除我们都熟。但列表里一直还有最后一个——**百分号 `%`**。

David 特别提醒：**在 Python 里作为运算符使用时，它不表示"百分比"**。

它表示的是**取模运算符**（modulo operator），用于模运算（modular arithmetic）。就我们现在的用途而言，它用来计算**一个数除以另一个数之后的余数（remainder）**。

举例（除以 3）：

- 1 ÷ 3：3 除不进 1，余数 = **1**
- 2 ÷ 3：余数 = **2**
- 3 ÷ 3：整除，余数 = **0**
- 4 ÷ 3：能除进 1 次，还剩 1，余数 = **1**
- 5 ÷ 3：余数 = **2**

所谓"余数"，就是**除完之后还剩下多少**。

> 官方 Notes 的对应说法：`4 % 2` 结果是 0（能整除）；`3 % 2` 不能整除，结果是**非零**的数。

### 12.2 偶数的定义是什么？ [00:35]

代码先获取用户输入的数：

```python

```

那么，怎么用"余数"这个新积木来判断奇偶？

> "偶数是可以被 2 整除的数。比如 2、4、6、8、10，还有……"

David：完美，我们可以一直数下去，因为偶数有无穷多个。但她把定义**表述成了一个我们可以明确提问的问题**，这非常好：

> **这个数能被 2 整除吗？** 也就是：除以 2 的余数是不是 0？

这正好和 `%` 对上了——`%` 回答的就是"余数是多少"。于是我们只要检查**余数是 0 还是 1**：是有剩余，还是没有剩余。

## 13. 自定义函数 is_even 与布尔类型 [00:40]

还能怎么改进？

注意这里：即使我还**完全不知道**这个判断奇偶的函数该怎么实现，我也先"天真地"（naively）假设有个函数叫 `is_even`，然后**闭着眼睛调用它**。

### 13.2 实现 is_even，认识 bool 类型 [00:40]

```python
def main():
    x = int(input("What's x? "))
    if is_even(x):
        print("Even")
    else:
        print("Odd")


def is_even(n):
    if n % 2 == 0:
        return True
    else:
        return False


main()
```

要点逐个说明：

- 用 `def` 定义函数，函数名 `is_even`
- 参数叫 `n`（number 的缩写，通用的"一个数"）。为什么不叫 `x`？因为 `main` 里已经有个 `x` 了，David 不想把自己搞混——**参数名和外部的 `x` 不冲突，换成 `n` 更清楚**
- 关键来了：David 说"**这里是魔法**"——作为程序员，你**可以返回布尔值（Boolean values）**

**关于 bool 类型：**

我们已经见过 Python 的几种数据类型：`str`（string，字符串）、`int`（integer，整数）、`float`（floating point，浮点数）。

现在加第四种：**`bool`（布尔值）**。

bool 的好处在于：**它只能取 `True` 或 `False` 两个值**。对比一下：`int` 可以是无穷多个数中的任意一个；而 `bool` 只有两种可能。

> **大小写很重要**：写这两个值的时候，必须是**大写的 T 和大写的 F**，也就是 `True` 和 `False`。

回到 `is_even` 的逻辑：如果 `n % 2 == 0`（n 除以 2 余数为 0），按 Elena 的定义它就是偶数，于是 `return True`；否则，我知道它不是偶数——数学上余数必然是 1，但这不重要——我直接 `return False`。

### 13.4 这段代码真正在做的事 [00:40]

David 总结：我想造一个叫 `is_even` 的函数来替我回答"奇还是偶"。现在我不光能在这个程序里用它，**以后写别的程序也能用**，甚至**可以分享给别人**。

最值得注意的一点在 `main` 里这一行：

```python
def main():

```

这里**没有任何比较运算符**。我的布尔表达式不是 `x < y` 这种显式的比较，而是**一个函数调用**。

这完全没问题，因为：

- 这个函数是我写的，我知道它返回 `True` 或 `False`
- 而 `if` 需要的全部东西，就是一个能判断真假的布尔表达式

## 15. Pythonic：把四行变成一行 [00:45]

回到 `parity.py`。老问题：**设计还能再改进吗？**

能。David 说要展示一种在 Python 世界里被称为 **Pythonic** 的写法。

**什么是 Pythonic？** 这是 Python 圈子里的一个行话（term of art）：如果一件事"就是 Python 里的那种做法"，就说它是 Pythonic。

意思是：解决同一个问题有很多很多种写法，而在 Python 程序员社区里，**有些写法比另一些更受推崇**（smiled upon）。这些写法往往和"只有 Python 有、别的语言没有"的特性有关。

### 15.1 Pythonic 写法一：三元表达式 [00:45]

`is_even` 现在是四行（`if` / `return True` / `else` / `return False`）。在 Python 里，你可以把它**压缩成一行**：

```python
def main():
    x = int(input("What's x? "))
    if is_even(x):
        print("Even")
    else:
        print("Odd")


def is_even(n):
    return True if n % 2 == 0 else False


main()
```

语法是：`结果A if 布尔表达式 else 结果B`。

David 的评价：有编程经验的人可能会觉得这挺酷——四行变一行。而 Python 流行的原因之一，就是**它读起来很像英语**。

它虽然还不像自然语言那么友好，但这一行确实几乎在"说你想说的话"：

> **Return true if n 除以 2 余数为 0，else false.**

这已经非常接近你用英语描述这段逻辑时会说的话了。

运行验证，行为完全一样：输入 2 → `Even`，输入 3 → `Odd`。

### 15.2 Pythonic 写法二：直接返回布尔表达式本身 [00:45]

还能再精炼。

看这行里的 `n % 2 == 0`——**这就是我的布尔表达式**，它会求值成 `True` 或 `False`。n 除以 2 的余数是不是 0？**这本身就是一个"是/否"问题，本身就是一个布尔表达式**。

那关键的一问来了：

> **如果你的布尔表达式自己就有 true / false 的答案，那你为什么还要再问一遍？为什么还要 `if`？为什么还要 `else`？** 直接把布尔表达式的值返回就行了！

于是最紧凑、同时依然可读的版本是——**把整行都删掉**，直接：

```python
def main():
    x = int(input("What's x? "))
    if is_even(x):
        print("Even")
    else:
        print("Odd")


def is_even(n):
    return n % 2 == 0


main()
```

为了帮助理解，David 临时加了括号：

```python
def is_even(n):
    return (n % 2 == 0)
```

括号里的内容会**先算**。n 除以 2 要么余 0，要么不余 0：余 0 结果就是 `True`，否则就是 `False`。

**所以：直接把"这个问题"返回回去就行了，不需要再用 `if` 和 `else` 包一层。**

而且，因为**运算符优先级**（order of operations）的关系，**连括号都不需要**。这就是实现这个想法最优雅的方式。

### 15.3 那到底哪种更好？ [00:45]

David 给了一个非常中肯的评价，值得记下来：

- `return n % 2 == 0` 这一版非常好，因为它极其简洁，你很难挑它的毛病
- **但是**，写成 `if` + `else` 那四行**同样完全正确，也完全可以**

如果那四行能让你把代码想得更清楚，也能帮别人读懂，那就用四行。

> **可读性和简洁性之间要做权衡，"能跑"和"优雅"之间也要做权衡。不要为了炫技牺牲清晰度。**

## 16. match 语句与 house.py：分院程序 [00:50]

还有**另一种**实现条件逻辑的语法：根据布尔表达式的答案，**可选地**做某件事。

这个关键字在**较新版本的 Python** 中可用，叫做 **`match`**。

David 说明：如果你以前写过代码，`match` 在精神上类似于其他语言里的 **`switch`** 语句。

### 16.1 场景：哈利波特分院 [00:50]

先关掉 `parity.py`，新建 `house.py`：

```bash
code house.py
```

目标：提示用户输入名字，然后输出他在哈利波特的世界里属于哪个学院（house）。

### 16.2 第一版：传统的 if / elif / else [00:50]

```python
name = input("What's your name? ")

if name == "Harry":
    print("Gryffindor")
elif name == "Hermione":
    print("Gryffindor")
elif name == "Ron":
    print("Gryffindor")
elif name == "Draco":
    print("Slytherin")
else:
    print("Who?")
```

- Harry（哈利）、Hermione（赫敏）、Ron（罗恩）都在 Gryffindor（格兰芬多）
- Draco（德拉科·马尔福）在 Slytherin（斯莱特林）
- 如果不是这些名字，就打印 `Who?`（谁？），表示我们**没有为这个名字硬编码（hard-coded）任何回答**

运行：

```bash
python house.py
```

```text
What's your name? Harry
Gryffindor
```

```text
What's your name? Draco
Slytherin
```

```text
What's your name? Padma
Who?
```

Padma 这个名字我们没有写对应的 `elif`，所以走到 `else`，输出 `Who?`。

### 16.3 第二版：用 or 合并同名结果 [00:50]

这里明显有**冗余**（redundancy）：Harry、Hermione、Ron 三个人都在检查，结果打印的都是同一句。用我们已经学过的 `or` 就能收紧：

```python
name = input("What's your name? ")

if name == "Harry" or name == "Hermione" or name == "Ron":
    print("Gryffindor")
elif name == "Draco":
    print("Slytherin")
else:
    print("Who?")
```

删掉了两个 `elif` 块，把三种情况**合并进一个 `if` 语句**。Draco 仍然单独一个 `elif`（因为他不在格兰芬多），最后保留 `else` 兜底。

验证：输入 Hermione → `Gryffindor`；输入 Ron → `Gryffindor`。都正确。

### 16.4 第三版：改用 match / case [00:50]

David 指出一个现实问题：如果名单不止 Harry、Hermione、Ron 三个，而是格兰芬多、斯莱特林以及其他所有学院的一大堆名字，那这段代码**很快就会变得非常笨重（unwieldy）**。

`match` 就是另一种能让代码**不那么冗长（less verbose）**的技术。

```python
name = input("What's your name? ")

match name:
    case "Harry":
        print("Gryffindor")
    case "Hermione":
        print("Gryffindor")
    case "Ron":
        print("Gryffindor")
    case "Draco":
        print("Slytherin")
```

语法要点：

- 用关键字 `match`，后面跟你想匹配的**变量或值**（这里是 `name`）
- 然后**加冒号 `:`
- 下面用关键字 `case`，每个 `case` 后面是要匹配的值。因为名字是字符串，所以要加引号
- **每个 `case` 行的末尾也要有冒号 `:`
- 再往下一层缩进，写这个 case 命中时要做的事

运行：

```text
What's your name? Harry
Gryffindor
```

```text
What's your name? Hermione
Gryffindor
```

```text
What's your name? Draco
Slytherin
```

### 16.5 漏掉的 case 会怎样？翻车演示 [00:50]

现在输入一个没有对应 `case` 的名字：

```text
What's your name? Padma
```

（**没有任何输出**）

David 的点评：我们**直接被忽略了**（we're just ignored）。因为**没有给 Padma 写 case**，所以什么都不打印。

这暴露了 `match` 和 `if/elif/else` 的一个重要区别：`else` 是天然的兜底，`match` **不会**自动兜底。

### 16.6 case _：match 里的"兜底" [00:50]

当然你可以回去专门给 Padma 加一个 case。但如果我们想像 `else` 那样，写一个"**处理所有没被显式列出的名字**"的兜底，该怎么写？

语法是：仍然写一个 `case`，但值用**单个下划线字符 `_`**。

（这个下划线在 Python 的其他场景里也有别的用途，但在这里它的意思是"**所有还没被处理的情况**"。）

```python
name = input("What's your name? ")

match name:
    case "Harry":
        print("Gryffindor")
    case "Hermione":
        print("Gryffindor")
    case "Ron":
        print("Gryffindor")
    case "Draco":
        print("Slytherin")
    case _:
        print("Who?")
```

再运行一次，输入 Padma：

```text
What's your name? Padma
Who?
```

这次至少得到了一个明确的回应（`Who?`），而之前是什么都没有。

### 16.7 第四版：用 | 合并 case [00:50]

David 又发现"我们退步了一点"：刚才用 `or` 已经把 Harry、Hermione、Ron 合并到一行了，现在又变回三个 `case` 了。

`match` 里也能合并，但**语法不一样**：用**单竖线 `|`**。

```python
name = input("What's your name? ")

match name:
    case "Harry" | "Hermione" | "Ron":
        print("Gryffindor")
    case "Draco":
        print("Slytherin")
    case _:
        print("Who?")
```

操作是：删掉中间那两个 `case`，在 `Harry` 后面、冒号之前，加上一个单竖线 `|` 加 `"Hermione"`，再加一个 `|` 加 `"Ron"`。

这就是用相对较新的 `match` 语句表达"Harry **或** Hermione **或** Ron"的方式，而且**比用 `if` 更简洁**。

最后一次完整验证：

```text
What's your name? Harry
Gryffindor
```

```text
What's your name? Hermione
Gryffindor
```

```text
What's your name? Ron
Gryffindor
```

三个都还在格兰芬多。

### 16.8 match 的几个注意事项（非常重要） [00:50]

David 在这一段集中说了几条，都是高频考点：

- **`match` 不需要 `break`。** 如果你以前用过其他语言的 `switch`，可能习惯了到处写 `break`。**在 Python 的 `match` 里不需要**
- **也不需要用 `default` 之类的显式关键字。** 兜底就是 `case _`
- **`case _` 必须放在最后。** 它表示"前面都没匹配上的情况"
- **命中即停止。** `match` 会把 `match` 关键字后面的值，依次和每个 `case` 后面的值比较；**一旦找到匹配，就执行对应缩进块里的代码，然后停止匹配**（不会发生"贯穿"到下一个 case）

> 官方 Notes 的原文总结：`match` 语句把 `match` 后面的值与各个 `case` 后面的值比较。一旦找到匹配，就执行相应的缩进代码段，程序**停止匹配**。

### 16.9 到底用 if/elif/else 还是 match？ [00:50]

David 的态度很开放：在 Python 和编程里，**永远有多种解法**。`match` 只是你工具箱里的又一件工具。

- 它确实收紧了代码
- 它也许可读性更好一点，因为**语法更少、重复更少**——不用到处写 `==`、`elif`、`elif`、`elif`
- 但用 `if / elif / else` 来实现**同样是正确的**

另外他提到：`match` 还能做**更强大的匹配形式**（不只是简单的值相等比较）。本讲只是用它复刻了 `if / elif / else` 的效果。

    ...

    ...

if x < y or x > y:     # 满足其一即可
    ...
if score >= 90 and score <= 100:    # 必须同时满足
    ...

# ---------- 链式比较（Python 特有） ----------
if 90 <= score <= 100:
    ...

False       # 大写 F

def is_even(n):

        return True
    else:
        return False

def is_even(n):
    return True if n % 2 == 0 else False   # 三元表达式

def is_even(n):

# ---------- match / case ----------
match 变量:
    case 值1:
        ...
    case 值2 | 值3:     # 单竖线表示"或"
        ...

## 本讲易错点

1. **一个等号 `=` 和两个等号 `==` 混淆。** `=` 是赋值（从右往左复制），`==` 才是比较。David 自己在写 `if x = y` 时当场翻车并纠正。在 `if` 条件里写单个等号会直接报语法错误。

2. **忘记缩进。** 在 Python 里缩进是**强制的**，不是美观问题。不缩进程序直接不工作。缩进决定了某一行"归谁管"。

3. **忘记冒号 `:`。** `if`、`elif`、`else`、`match`、每个 `case` 的行末都必须有冒号。

4. **把 `if / if / if` 当成 `if / elif / else` 用。** 这是本讲破坏性最大的错误：`grade.py` 全用 `if` 时，95 分会同时打印 A、B、C、D。因为 95 同时满足 `>= 90`、`>= 80`、`>= 70`、`>= 60`。**必须用 `elif` 让条件互斥。**

5. **`True` / `False` 的首字母必须大写。** 写成 `true` / `false` 是错的。

6. **多余的提问。** 排除了"小于"和"大于"之后，"相等"是逻辑必然，不需要再问一次——直接用 `else` 兜底。同样，`grade.py` 里有了 `elif` 就不需要再检查上界。

7. **本末倒置的三元表达式。** `return True if 条件 else False` 属于绕远路，直接 `return 条件` 就行。但也别走极端——如果 `if / else` 四行让你和别人更容易读懂，用四行也没错。

8. **`match` 没有自动兜底。** 没匹配到任何 `case` 时**什么都不执行、什么都不打印**（输入 Padma 时静悄悄）。需要兜底就显式写 `case _`，且必须放在最后。

9. **`match` 里不要写 `break`。** 从 C / Java 的 `switch` 转过来的同学容易手滑。Python 的 `match` 命中即停止，不需要 `break`，也不需要 `default` 关键字。

10. **假设用户输入一定合法。** `grade.py` 最终版依赖"输入在 0~100 之间"这个假设；官方 Notes 也提醒"永远不要信任用户会输入正确的信息"。如果输入 1000，最终版会给出 A。

11. **把 `%` 当成百分号。** 在 Python 里它是取模运算符，求的是**余数**。

12. **对自己定义的函数乱用字符串方法。** `is_even` 返回 `bool`，而布尔值没有 `strip` / `capitalize` 这些概念。只有当函数返回字符串时，才能接着用点运算符调这些方法。
