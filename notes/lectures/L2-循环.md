## 2. `while` 循环 [00:05]

### 2.1 一个坏设计的自白 [00:00]

David 画了流程图：椭圆（开始）→ 三个 meow 矩形 → 椭圆（结束）。图完全正确，代码也"能用"，但他问全班：**这段代码为什么设计得不好？**

学生 Alex 回答：重复做同一件事，三遍甚至更多，不是好习惯。

David 肯定了这个回答，并把它推到极端来让你自己判断：

- 如果我想喵**四次、五次、五十次、五百次**呢？
- 就算你从没写过代码，你也会觉得"一直复制粘贴"不像是正经解法。
- 更致命的是**改起来**：假设我改主意了，不想做猫，想做狗，那得把 50 处的 `meow` 全改成 `woof`。虽然可以用查找替换，但——"拜托，我们现在是程序员了，肯定有更好的办法。"

**这一段的真正教训**：判断代码好坏，永远问一句"如果规模放大 100 倍会怎样"。这是本讲反复出现的一根线。

### 2.2 用 `while` 提问 [00:05]

于是引入关键字 `while`（当……时）。它的思路是：**反复问一个问题，只要答案为真（true），就一直执行**。所谓"问题"，就是我们前面见过的布尔表达式（Boolean expression，结果只有 true / false 的式子）。

David 用"数手指"打比方：我要喵三次，就竖起三根手指，喵一声，放下一根；再喵，再放下一根；再喵，再放下一根。每喵一次就问自己一句"**还有手指竖着吗？**"——答案是 true 就继续，答案是 false 就停下。

翻译成代码：

```python
# cat.py —— while 循环，第一版（有 bug！会无限循环）
i = 3
while i != 0:
    print("meow")
```

几个细节：

- 变量名 `i` 只是 David 的习惯（i 来自 integer 整数），叫什么都行。
- `i = 3` 是**初始化**（initialize），也就是第一次给变量赋值。
- `!=` 是"不等于"。所以 `while i != 0` 读作"当 i 不等于 0 时"。
- **行末的冒号 `:` 必须写**，和函数、条件语句一样。
- **缩进**（indentation）同样关键：缩进的那些行，才属于这个 `while`。

### 2.3 演示现场：故意不按回车 [00:05]

David 摆出这行代码后问全班："如果我现在很鲁莽地直接回车运行，屏幕上会发生什么？"学生 Timo 回答：会一直打印 meow，因为 `i` 永远是 3，`while` 的条件永远为真。

**完全正确。** 解释一下解释器（interpreter）的行为：

1. 第 1 行：`i` 被设为 3；
2. 到第 2 行问：i 不等于 0 吗？——3 当然不等于 0，是真；
3. 执行第 3 行，打印 meow；
4. **回到第 2 行**再问一次……永远如此。

这就是**意外的无限循环**（accidental infinite loop）。注意 David 特意**没有按回车**，因为他不想让电脑失控。

> **救命键：`Ctrl+C`。** 万一你陷进了无限循环，**不需要重启电脑、也不需要关机**。在终端窗口里按 `Ctrl+C`（C 代表 cancel / interrupt，取消 / 中断），大概率就能立刻停下来。这是新手必须记住的第一个快捷键。

### 2.4 修好它：让 `i` 真的在变 [00:05]

修法就是每次循环之后把 `i` 减 1，让它最终能碰到 0：

```python
# cat.py —— while 循环，第二版（正确）
i = 3
while i != 0:
    print("meow")
    i = i - 1
```

运行：

```
$ python cat.py
meow
meow
meow
```

这里出现了一个重要术语：**iteration（迭代）**，意思是"循环转一圈"、"执行一次循环体"。第一次是第 0 次迭代，第二次是第 1 次迭代……编程里数数从 0 开始。

David 又展示了对应的流程图，这一回能**用眼睛看见那个圈**：开始 → `i = 3` → 菱形提问 "i != 0?" → 为真 → 打印 meow → `i = i - 1` → **箭头绕回菱形**再问一次。直到 i 变成 0，问题答案为假，走出循环 → 结束。他强调：你不必养成画流程图的习惯，它只是帮你第一次建立"机器内部在干什么"的直觉。

### 2.5 换一种思路：从 1 数到 3 [00:10]

有人就是不喜欢倒数，喜欢从 1 往上数。完全可以。那代码要改两处：

```python
# cat.py —— while 循环，第三版：从 1 数到 3
i = 1
while i <= 3:
    print("meow")
    i = i + 1
```

David 在这里**故意停下来点名提问**："第 4 行该怎么改？"学生答：改成加 1。

他顺便复述了一个**经典翻车**：如果你从 1 开始，却还在做 `i = i - 1`，那 i 会一路变成 0、-1、-2……**永远不可能大于等于 3**，于是又是一个无限循环。方向搞反，是最常见的低级错误之一。

这里还复习了赋值运算符（assignment operator）：

> `i = i + 1` 从**右往左**读/执行。先算右边的 `i + 1`，再把结果**复制**给左边的 `i`。数学上 "i 等于 i 加 1" 是荒谬的，但编程里它是"取值 → 加一 → 存回去"。

### 2.6 最好从 0 开始数 [00:10]

"大多数程序员和计算机科学家**习惯从 0 开始数**。"这不只是癖好，它在 Python 里确实有好处。于是：

```python
# cat.py —— while 循环，第四版：从 0 开始
i = 0
while i < 3:
    print("meow")
    i = i + 1
```

**注意这个坑**：如果你只把 `i = 1` 改成 `i = 0`，却忘了把条件从 `<=` 改成 `<`，程序立刻就"有 bug 了"——猫会喵**四次**！因为 0、1、2、3 都满足 `<= 3`。

所以配套的口号是：

> **从 0 开始数，上到但不穿过（up to but not through）目标值。**

`i < 3` 意味着 i 取 0、1、2 三个值，正好三次。虽然一开始不习惯（日常生活我们数 1、2、3），但**现在就养成这个习惯**。

### 2.7 更简洁的写法：`i += 1` [00:10]

`i = i + 1` 太常见了，所以 Python 给了简写：

```python
i += 1   # 完全等价于 i = i + 1，只是少敲几个键
```

同理还有 `i -= 1`。纯粹的约定，读起来更快。

> **来自 C / C++ / Java / JavaScript 的同学注意**：Python **没有** `++` 和 `--`。写 `i++` 会报错。`i += 1` 已经是你能写出的最简洁形式了。

### 2.8 学生提问：能不能用 `for` 循环？ [00:10]

有学生问：能不能像别的语言那样，`for` 循环自带初始化、条件、递增三部分？

David 的回答是：**在 Python 里不行**，Python 没有那种三段式 `for`。但 Python **有另一种 `for` 循环**——马上就讲。

## 4. `for` 循环与 `list` 列表 [00:20]

### 4.1 先认识 `list` [00:20]

要理解 `for`，得先认识一个新数据类型：**`list`（列表）**。

我们已经见过 `str`（string，字符串）、`int`（integer，整数）、`float`（floating point，浮点数）、`bool`（Boolean，布尔值）。现在加上 `list`：

> 列表 = 把**多个值**装在同一个地方、同一个变量里。现实世界的购物清单、待办清单，在 Python 里就是列表。

### 4.2 第一个 `for` 循环 [00:20]

回到 `cat.py`，把 `while` 整个扔掉，写：

```python
# cat.py —— for 循环第一版
for i in [0, 1, 2]:
    print("meow")
```

执行过程是：**Python 自动**把 `i` 依次设成 0、1、2，每设一次就执行一次缩进的代码：

- i = 0 → 打印 meow
- i = 1 → 打印 meow
- i = 2 → 打印 meow
- 列表用完了 → 结束

那个 `[0, 1, 2]` 就是列表，**方括号 `[]`（square brackets）**是它的标志——注意不是圆括号，Python 靠这对符号认出"这是个列表"。

**为什么比 `while` 好？** David 的评价很直接：`while` 版本里"我干了一大堆活"——自己决定 i 是什么、自己写判断条件、自己递增递减，脑子里能看见齿轮在转，非常"机械"。而 `for` 把这些琐事全交给 Python：你只要说"i 依次取这些值"就行了。

### 4.3 极端情况：要是想喵一百万次呢？ [00:20]

"这段代码能跑、喵三次，但从设计上说，它为什么不好？"

学生 Hope 回答：因为我们手写 0、1、2，如果想喵一百万次，就得手写 0、1、2、3……一直写到 999999。

**正中靶心。** 这就是本讲反复出现的思维方式：

> 判断自己的代码（或别人的代码）好不好，**第一眼看着没问题不算数**，要往下推到极端：不是三个，而是一百万个呢？

### 4.4 `range()`：让别人替你生成列表 [00:25]

解法是用 Python 自带的函数 `range`（范围）：

```python
# cat.py —— for 循环第二版：用 range
for i in range(3):
    print("meow")
```

`range(3)` 会"交回"（return）三个值：**0、1、2**。它从 0 开始，同样**上到但不穿过**你给的数字。所以 `range(3)` 给 0、1、2，一共三个。

好处立竿见影：想喵一百万次？写 `range(1000000)` 就够了——不用真的敲出一百万个数字。（David 吐槽：那可真是只愤怒的猫。）

### 4.5 用 `_` 表示"这个变量我不在乎" [00:25]

继续观察上面的代码：虽然 Python 必须用个变量来计数，但**我们人从头到尾没用过 `i`**。

Python 有个约定：如果某个变量只是语法上必须有，而你根本不关心它的值，就把它命名为**一个下划线**：

```python
# cat.py —— for 循环第三版：用 _ 当变量名
for _ in range(3):
    print("meow")
```

**这对程序运行结果零影响**，纯粹是给人看的信号：它告诉未来的你、同事、老师——"这是个变量，但我不用它，你别指望它有意义"。

### 4.6 更"Pythonic"的写法：字符串乘法 [00:25]

"为了让你对 Python 的可能性有个概念，咱们再进一步。"David 说下面这行"如果你以前写过代码，可能会有点被震到"：

```python
# cat.py —— 第四版：字符串乘法
print("meow" * 3)
```

**演示翻车**：运行结果是——

```
$ python cat.py
meowmeowmeow
```

David 打趣说"这只猫大概是饿坏了，叫得特别快"。问题很清楚：三个 meow 连在一起，没有分行。

### 4.7 用 `\n` 换行 [00:25]

怎么修？回忆前面学过的东西：我们用过 `+` 拼接字符串，而 `*` 可以把字符串重复多次。那"换行"怎么表达？

学生答：用转义序列（escape sequence）`\n`。

```python
# cat.py —— 第五版：加换行符
print("meow\n" * 3)
```

运行后"**非常接近了**"——三个 meow 各占一行，但**末尾多了一个空行**。

### 4.8 用 `end=""` 干掉多余的空行 [00:25]

为什么会有空行？因为 `print` 函数默认会在结尾再加一个 `\n`。解法是把这个默认行尾改掉：

```python
# cat.py —— 第六版（最终版）：自定义行尾
print("meow\n" * 3, end="")
```

- `\n`：在每个 meow 后面加换行；
- `end=""`：`print` 的**命名参数**，把默认的行尾从 `\n` 改成"什么都不加"（空字符串），于是最后不多出那个空行。

运行结果：

```
$ python cat.py
meow
meow
meow
```

**David 的重要提醒（别走火入魔）**：这么写虽然酷，但**可读性变差了**——一行里塞了 `\n`、乘 3、`end=""`。你**不必**这么写。用 `for` 循环完全没问题，用 `while` 循环也完全没问题，设计上都站得住。只是"又多了一种写法"，而这是某些语言根本不具备的能力。**原则：如果你自己、老师、同事、朋友读你的代码会费劲，那就不是好事。**

## 5. 用循环改进用户输入 [00:30]

### 5.1 问题的提出 [00:30]

现在让**用户**决定喵几次。但有个前提：我在数数、在喵喵叫，不是在算账，所以用户必须给我一个**正数**。

如果只写一次 `if`，会怎样？

```python
n = int(input("What's n? "))
if n < 0:
    n = int(input("What's n? "))
```

用户要是又输了个负数呢？那就再来一个 `if`……**这个程序永远写不完**。你不可能穷举"用户到底会错多少次"。

### 5.2 `while True`：故意制造无限循环 [00:35]

Python 里有个非常常见的范式（paradigm）：当你想要一个**符合要求**的用户输入时，直接写：

```python
while True:
    ...
```

`while True` 看起来很吓人——问题永远是"True 是真的吗？"，答案永远是真，所以这**必然**是个无限循环。但这一次我们是**故意的**（deliberately）。之前我们见过无限循环是数学上算错导致的意外，而这里是主动诱导。

然后在循环里面做三件事：问用户、检查、不符合就再来一次。

### 5.3 `continue` 与 `break` [00:40]

第一版（用 `continue`）：

```python
# cat.py —— 输入校验，第一版：continue + break
while True:
    n = int(input("What's n? "))
    if n < 0:
        continue      # 回到循环开头，重新问用户
    else:
        break         # 跳出循环

for _ in range(n):
    print("meow")
```

两个新关键字：

- **`continue`**：明确告诉 Python"跳到**下一次迭代**"。在这里的效果就是：回到 `while True` 开头，再次调用 `input`，希望用户这次给个像样的答案。
- **`break`**：**提前跳出**循环，不等它自然跑完所有迭代。`break` 跳出的是**最近开始的那个循环**。

如果 `n` 不小于 0（即 0 或正数），就 `break`，然后程序往下走到 `for`，喵那么多次。

### 5.4 去掉 `continue`：更精简 [00:40]

其实这里的 `continue` 是**多余的**——因为 `if` 不成立时，循环本来就会自己回到开头。而且"允许用户输入 0"也没什么意思（一只一次都不喵的猫没意思）。所以改成"必须是**大于** 0 的数才 break"：

```python
# cat.py —— 输入校验，第二版（更精简）
while True:
    n = int(input("What's n? "))
    if n > 0:
        break

for _ in range(n):
    print("meow")
```

代码逻辑梳理：

- 第 1–4 行：故意构造一个默认情况下会永远跑的无限循环；
- 第 2 行：从用户那里拿一个整数（`int(input(...))`）；
- 第 3–4 行：如果大于 0，就 `break`。注意 `break` 缩进了两层，但它跳出的仍是**最近开始的那个 `while`**；
- 一旦用户给了正数，就走到第 6 行，用 `for _ in range(n)` 喵 n 次（用 `_` 是因为我们不用这个变量，保持 Pythonic）。

运行演示：

```
$ python cat.py
What's n? 3
meow
meow
meow

$ python cat.py
What's n? 10
meow
meow
meow
meow
meow
meow
meow
meow
meow
meow
```

> **本讲最重要的套路之一**：当你想"**一直问，直到用户给出我想要的东西**"时，就用 `while True:` + `if 合乎要求: break`。这是 Python 里极其常见的写法。

## 6. 用函数再进一步：实践我们讲过的东西 [00:45]

David 说："既然我们一直在讲要写自己的函数，那现在就身体力行。"

既然一直在喵，不如有个 `meow` 函数（Python 的发明者可没给我们这个函数）。

**第一步**：先假装它存在，直接调用——

```python
# cat.py —— 函数化，第一版
def main():
    meow(3)


def meow(n):
    for _ in range(n):
        print("meow")


main()
```

`main()` 里写死（hardcode）了 3，所以永远喵三次。

**第二步**：改成向用户要数字。假设存在 `get_number` 这个函数（Python 里当然没有，但**我们可以自己发明**）：

```python
# cat.py —— 函数化，第二版
def main():
    number = get_number()


def get_number():
    while True:
        n = int(input("What's n? "))
        if n > 0:
            return n       # 注意：这里用 return，不再用 break


def meow(n):
    for _ in range(n):
        print("meow")


main()
```

关键变化：这次在循环里用的是 **`return`** 而不是 `break`。因为我们需要把值**交回去**。

- `return` 不仅能让你跳出代码块，还会**把一个值交还给调用者**，就像 `input`、`int`、`float` 那样。
- 这样函数就不只是"有个副作用（side effect，比如打印）"，而是真的**有产出**。

**关于 `break` 和 `return` 的配合**（David 特意讲清楚的一点）：

你也可以继续用 `break` 跳出循环，但跳出之后，你**仍然必须**在函数里写 `return` 才能把值交出去：

```python
def get_number():
    while True:
        n = int(input("What's n? "))
        if n > 0:
            break
    return n      # 用 break 跳出循环后，还要在循环外、函数内 return
```

两种写法效果相同，随你选。用 `return n` 直接返回更短。

**最终版**（把 main 里写死的 3 换成用户给的数）：

```python
# cat.py —— 函数化，最终版
def main():
    meow(get_number())


def get_number():
    while True:
        n = int(input("What's n? "))
        if n > 0:
            return n


def meow(n):
    for _ in range(n):
        print("meow")


main()
```

`meow(get_number())` 是**函数嵌套调用**：先算出 `get_number()` 的返回值，再把它当参数传给 `meow`。

运行：

```
$ python cat.py
What's n? 3
meow
meow
meow

$ python cat.py
What's n? 1
meow
```

## 7. 更多关于 `list`：霍格沃茨 [00:45]

有了循环，就可以处理**更多、更大的数据**了。David 换了个更亲切的例子：霍格沃茨（Hogwarts）。

新建 `hogwarts.py`（`code hogwarts.py`），先硬编码三个学生：

```python
students = ["Hermione", "Harry", "Ron"]

print(students[1])
print(students[2])
```

- 方括号 `[]` 表示"列表来了"；
- 每个名字都带引号，因为它们是 `str`（字符串）；

### 7.1 索引（index）：从 0 开始 [00:45]

问题来了：我不想一次性把三个人都打印出来，我想**一个一个**取出来，怎么办？

答案是**索引进去**（index into）：用**另一对方括号**加数字：

- `students[0]` → `"Hermione"`（第 1 个）
- `students[1]` → `"Harry"`（第 2 个）
- `students[2]` → `"Ron"`（第 3 个）

> Python 的列表是**零索引（zero-indexed）**的：第 1 项在位置 0，第 2 项在位置 1，第 3 项在位置 2。你的脑子会一直"差一个"，但写久了就习惯了。

运行结果：

```
$ python hogwarts.py
Hermione
Harry
Ron
```

### 7.2 用 `for` 遍历列表 [00:45]

手写 0、1、2 显然又有"扩展性"问题：明年霍格沃茨来了新生怎么办？

`for` 循环不只可以数数字，**它可以遍历任何东西**，包括字符串：

```python
# hogwarts.py —— 第二版：用 for 遍历
students = ["Hermione", "Harry", "Ron"]

for student in students:
    print(student)
```

不管是 3 个学生、4 个还是 400 个，**这两行代码全都搞定**。

**关于变量命名的一个强调**（David 特意停下来讲的）：这里我**故意**没用 `_`。因为这次我真的在用这个变量！如果你把变量叫 `_` 又在用它，"你的代码就太晦涩了，你在害人，也在害未来的自己"——**变量就该叫什么是什么**。

- 推荐：`for student in students`（列表叫 students，一个个个体叫 student，单数对复数，非常清楚）
- 也可以偷懒写 `for s in students`，但"何必呢？Python 的卖点就是可读"。

**问**：既然讲了 `break`，那有没有"跳过某一次"的概念？
**答**：有，就是 `continue`（前面已经用过）。

**问**：这个 `for` 循环能用在哈希表（hash table）、数组之类的数据结构上吗？
**答**：能。凡是**可迭代的（iterable）**数据，都可以用 `for` 遍历——后面会见到更多类型。（字典马上就来。）

## 8. `len()`：用数字遍历列表 [00:45]

有人就是喜欢用 `i`、`0、1、2` 这种数字思考，或者你的程序**必须**用到序号。那怎么办？

```python
for i in students:   # 不行！这样 i 会是 "Hermione"、"Harry"、"Ron"，不是数字
    print(i)         # 打印出来的是名字，不是序号
```

而且 `range(students)` 也不行——`range` 要的是**整数**，你给它一个列表它会报错。

**解法**：Python 有个函数 `len`（length，长度），能告诉你列表有多长。把两个小想法**组合（compose / nest）**起来：

```python
# hogwarts.py —— 第三版：用 len + range
students = ["Hermione", "Harry", "Ron"]

for i in range(len(students)):
    print(students[i])
```

拆解这个嵌套调用：

1. `len(students)` 先执行，得到 `3`；
2. 把这个 `3` 作为 `range` 的参数，得到 0、1、2；
3. `students[i]` 里的 `i` 是个变量——**方括号里可以放变量！** 于是动态取到每一个学生。

这就是 David 说的"把小想法不断组合、组合、再组合"。

### 8.1 顺便打印名次 [00:45]

想做个排名（比如格兰芬多前三名），`print` 可以接收多个参数，默认用空格分隔：

```python
students = ["Hermione", "Harry", "Ron"]

for i in range(len(students)):
    print(i + 1, students[i])
```

运行结果：

```
$ python hogwarts.py
1 Hermione
2 Harry
3 Ron
```

注意：如果直接写 `print(i, students[i])`，输出会是 `0 Hermione`——"Hermione 是第 0 名"，这对用户来说很怪。**那是程序的内部计数方式，没必要暴露给人看**，所以加个 `i + 1` 换成人类习惯的 1、2、3。

### 8.2 学生再问一次 `for i in range` [00:45]

有学生请 David 再讲一遍。他倒回去重讲：

- 最初是 `for i in [0, 1, 2]`：Python 自动造出变量 `i`，先给它列表里第 1 个值，再第 2 个，再第 3 个，每次执行缩进的代码；
- 后来发现手写列表不可扩展，引入 `range(3)`，它"交回"一串值，行为**完全一样**；
- 到了霍格沃茨这个例子，`range` 里面要放几？我不想写死 3，我想**动态**知道有几个学生，于是用 `len(students)` 得到 3。**只是把已有的小块拼起来而已。**

## 9. `dict` 字典：键值对应 [00:50]

### 9.1 为什么列表不够用 [00:50]

现在想记录每个学生属于哪个**学院（house）**。用两个列表也能做：

```python
students = ["Hermione", "Harry", "Ron", "Draco"]
houses = ["Gryffindor", "Gryffindor", "Gryffindor", "Slytherin"]
```

（顺便加了德拉科·马尔福，他在斯莱特林，这样有点变化。）

**约定**：students 里第 1 个人对应 houses 里第 1 个学院，第 2 个对第 2 个……

David 的评价：**这招很快就崩**。学生一多、学院一多就乱；更别提如果还想记每个人的**守护神（patronus，魔杖召唤出的那个动物）**，那就得有第三个列表……全靠"自觉对齐"，代码一复杂就完蛋。

### 9.2 字典是什么 [00:50]

于是引入最后一种新数据类型：**`dict`（dictionary，字典）**——一种把**键（key）**和**值（value）**关联起来的数据结构（data structure）。

类比现实中的词典：翻开一本词典，里面是一堆"单词"和"释义"。计算机科学家把它抽象成"**某个东西关联着另一个东西**"。

> 列表是"一堆值"，是一维的；字典是"成对的对应关系"，是**二维的**。

### 9.3 语法：花括号 [00:50]

列表用方括号 `[]`，字典用**花括号 `{}`**。

（David 顺口提了一句：我们之前在 f-string 里也见过花括号，那跟字典**毫无关系**——键盘上的符号就那么些，语言的设计者只好重复使用，这里是**另一种用法**。）

第一版：

```python
# hogwarts.py —— 字典第一版
students = {
    "Hermione": "Gryffindor",
    "Harry": "Gryffindor",
    "Ron": "Gryffindor",
    "Draco": "Slytherin",
}
print(students["Hermione"])
print(students["Harry"])
print(students["Ron"])
print(students["Draco"])
```

- 键在左，值在右，中间是冒号 `:`；
- 写成多行纯粹是**排版美观**，Python 完全允许你为了可读性换行。David 一开始全写在一行，发现"一旦加上 Draco，代码就太长要换行了"，于是改成竖排，键在左、值在右，从上往下一眼能扫完；
- 最后那个"尾随逗号"（trailing comma）留着没问题。

### 9.4 用单词当索引 [00:50]

列表的位置是**数字**（0、1、2），字典的位置是**真正的单词**：

```python
print(students["Hermione"])   # 不是 students[0]
```

这就是"查词典"：知道单词，就查到释义；知道学生名字，就查到学院。

运行结果：

```
$ python hogwarts.py
Gryffindor
Gryffindor
Gryffindor
Slytherin
```

## 11. 一个学生有多条信息：列表套字典 [01:00]

### 11.1 需求升级 [01:00]

现实里，一个学生不只有名字和学院，还有**守护神（patronus）**——魔杖施展某个咒语时召唤出来的动物或实体。也就是说：我们要给一个学生关联**多个**信息。

第一版字典（学生名 → 学院）显然不够。于是换个设计：把键**标准化**成 `name`、`house`、`patronus` 三个词，值才是真正的数据。

### 11.2 语法：列表里装字典 [01:00]

```python
# hogwarts.py —— 列表套字典
students = [
    {"name": "Hermione", "house": "Gryffindor", "patronus": "Otter"},
    {"name": "Harry", "house": "Gryffindor", "patronus": "Stag"},
```

**怎么读懂这段"套娃"？** David 教了一个**看符号**的方法：

1. 最外层是 `[` 开头、`]` 结尾 → 我知道这是个**列表**；
2. 里面每一行是 `{` 开头、`}` 结尾 → 我知道每一项是个**字典**。

于是：这是一个**包含四个字典的列表**，每个学生一个字典。

（哪些信息是他现查的：Hermione 的守护神是水獭 otter——"这个我得查一下"；Ron 的是杰克罗素梗犬 Jack Russell terrier——"这个我也查了"；Harry 的是牡鹿 stag——"这个我知道"。）

### 11.3 `None`：正式的"没有值" [01:00]

有意思的是：**Draco 没有守护神**（书和电影里都没揭示过）。

这是个绝佳的教学时刻。Python 有一个专门的关键字：

> **`None`**（空值），拼写是 N-O-N-E，**首字母必须大写**。它正式地表示"**这里没有值**"。

你可能想偷懒写成 `""`（空字符串）。但那语义含糊——是"我懒得填"还是"确实没有"？写 `None` 就很清楚：**我知道 Draco 没有守护神，这不是我的疏忽。**

### 11.4 遍历这个"列表套字典" [01:00]

```python
# hogwarts.py —— 遍历列表套字典
students = [
    {"name": "Hermione", "house": "Gryffindor", "patronus": "Otter"},
    {"name": "Harry", "house": "Gryffindor", "patronus": "Stag"},
    {"name": "Ron", "house": "Gryffindor", "patronus": "Jack Russell terrier"},
```

- `for student in students`：遍历这个列表，**一共 4 圈**，每一圈的 `student` 是**一个完整的字典**；
- `student["name"]`：就像翻开一本实体字典，查 "name" 这个词，得到它的"释义"；
- 依次打印姓名、学院、守护神，用 `sep=", "` 分隔。

运行结果：

## 12. Mario：把循环用起来 [01:05]

### 12.2 第二版：用循环 [01:05]

```python
# mario.py —— 第二版
for _ in range(3):
    print("#")
```

现在想改高度，**只改一处**（那个 3），而不是改三处或更多。

### 12.3 抽象（abstraction）：`print_column` [01:05]

接下来把"写自己的函数"也整合进来。函数的好处不只是复用，更在于**创造抽象（abstraction）**——把一个可能很复杂的想法**简化**成一个名字。

- 之前的 `hello` 函数：它做的事就是"打招呼"，我不必再想"打印点什么"；
- 之前的 `get_number` 函数：同理。

于是先假设存在这么个函数，直接用：

```python
# mario.py —— 第三版：抽象出 print_column
def main():
    print_column(3)


def print_column(height):
    for _ in range(height):
        print("#")


main()
```

- 参数叫 `height`（高度），不叫 `n` 或 `h`——**名字要能提醒自己它在干什么**；
- 代码其实"变复杂了"，暂时也没多做什么，但它在**为将来解更复杂的问题搭脚手架**；
- 运行结果还是三行 `#`，但我现在拥有了一个**抽象**：`print_column`。

### 12.4 内部实现可以随便换，调用方无感知 [01:10]

函数还有一个巨大的好处：**只要函数名、参数、返回值不变，函数内部怎么改都没人知道**。

比如用前面那个"字符串乘法"的技巧重写 `print_column`：

```python
# mario.py —— 第四版：换掉 print_column 的内部实现
def main():
    print_column(3)


def print_column(height):
    print("#\n" * height, end="")


main()
```

运行还是三行 `#`。

> **重点**：`main` **完全不需要知道** `print_column` 的内部实现变了。就算你的同事、朋友、网上的陌生人在用你的 `print_column`，你也可以随时改进内部实现、修 bug——他们毫无察觉。

（David 也安慰了一句："这个语法你看着不舒服也没关系"，它只是前面见过的那种更"聪明"的写法。）

## 13. 换个维度：`print_row` [01:10]

游戏后面有"天空中的砖块"，马力欧从下面顶一下就变成金币。我们只关注那四个问号——**横向**排列。

```python
def main():
```

## 14. 嵌套循环：打印正方形 [01:15]

### 14.1 思路：打印机模型 [01:15]

假设要打印一个 3×3 的正方形。怎么下手？

David 给了一个**心智模型**：想想老式打字机或打印机——它们是**从上到下**输出的；而在每一行上，是从**左到右**打印的。你的黑白终端窗口也是这样：**从上到下，从左到右**。所以生成正方形也必须按这个顺序。

具体拆解：

- 总共要打印 3 行；
- 每一行里面，要打印 3 块砖。

也就是说：**我在"三件事"里，每一件又是"三个动作"**——**循环套循环**。

### 14.2 第一版：双重循环 [01:15]

```python
# mario.py —— print_square 第一版：嵌套循环
def main():
    print_square(3)


def print_square(size):

    # For each row in square（对于正方形中的每一行）
    for i in range(size):

        # For each brick in row（对于该行中的每一块砖）
        for j in range(size):

            #  Print brick（打印一块砖）
            print("#", end="")

        # Print blank line（打印一个空行）
        print()


main()
```

几个关键点：

- **外层循环**用 `i`：负责每一行，跑 size 次（3 行）；
- **内层循环**用 `j`：负责一行里的每一块砖。为什么不用 `i`？**因为不能把同一个变量用两次，否则计数会乱**。约定俗成是 `i` 然后 `j`，再套一层用 `k`——"但套到第三层你就不该再往下套了"；
- `print("#", end="")`：打印砖块时**不要换行**，否则每块砖都独占一行；
- 那个**孤零零的 `print()`**：在内层循环结束之后、但仍在**外层循环内部**。它的作用是什么？

David 点名提问，学生 Evelyn 答：每打印完一行，需要换到新的一行，所以单独 print 一下换行。

**完全正确。** 当你**不给 `print` 任何参数**时，它只做一件事——输出那个自动的行尾 `\n`，也就是把光标移到下一行。

运行结果（因为字符本身比它宽要高，屏幕上看着不太"方"，但它确实是 3×3）：

```
$ python mario.py
###
###
###
```

**注释（comments）的价值**：David 特意加了三行英文注释——"对于每一行" / "对于每块砖" / "打印砖块"。他说：**注释和伪代码（pseudocode）能帮你和别人解释清楚这几行在干什么**，尤其是这种嵌套循环。

### 14.3 第二版：用字符串乘法消掉内层循环 [01:15]

如果你觉得"循环套循环"烧脑，**内层循环其实不是必需的**。借用前面的字符串乘法：

```python
# mario.py —— print_square 第二版：去掉内层循环
def main():
    print_square(3)


def print_square(size):
    for i in range(size):
        print("#" * size)


main()
```

结果一样，但 `print_square` 变得非常紧凑：只有一个显式循环，一行里的所有井号一次性用乘法打印出来。

### 14.4 第三版：把"打印一行"甩给另一个函数 [01:20]

如果你更在乎抽象、想把代码意图表达得更清楚，那就把事情**甩给别的函数**：

```python
# mario.py —— print_square 最终版：分解到 print_row
def main():
    print_square(3)


def print_square(size):
    for i in range(size):
        print_row(size)


def print_row(width):
    print("#" * width)


main()
```

思路是：

- 在写 `print_square` 时，我**不在乎**"打印一行"具体怎么实现，我只知道**有人**会负责这件事；
- 于是把任务**传下去**（pass the buck）：调用 `print_row(size)`；
- 而 `print_row` 内部可以用 `for` 循环，也可以用字符串乘法——随便。

> **这就是分解（decomposition）**：把一个较大的程序（"这大概是到目前为止我们看过最复杂的一个"）拆成若干小组件，再组装起来，最终实现你的想法。

## 本讲代码速查

```python
# ===== while 循环 =====
i = 3
while i != 0:          # 条件为布尔表达式
    print("meow")
    i = i - 1          # 必须让 i 变化，否则无限循环

i = 0
while i < 3:           # 从 0 开始，上到但不穿过 3
    print("meow")
    i += 1             # 等价于 i = i + 1；Python 没有 ++

# ===== for 循环与列表 =====
for i in [0, 1, 2]:        # 遍历列表
    print("meow")

for i in range(3):         # range(3) 给 0, 1, 2
    print("meow")

for _ in range(3):         # _ 表示"我不关心这个变量"
    print("meow")

# ===== 字符串技巧 =====
print("meow" * 3)              # meowmeowmeow
print("meow\n" * 3)            # 三行，但末尾多一个空行
print("meow\n" * 3, end="")    # 三行，末尾无多余空行；end 自定义行尾

# ===== 用循环校验用户输入（经典范式）=====
while True:
    n = int(input("What's n? "))
    if n > 0:
        break              # 跳出最近开始的循环

while True:
    n = int(input("What's n? "))
    if n < 0:
        continue           # 直接进入下一次迭代
    else:
        break

# ===== 函数里返回值 =====
def get_number():
    while True:
        n = int(input("What's n? "))
        if n > 0:
            return n       # return 既跳出又交回值

# ===== 列表 =====
students = ["Hermione", "Harry", "Ron"]
print(students[0])                  # 索引从 0 开始（零索引）
for student in students:            # 遍历元素本身
    print(student)
for i in range(len(students)):      # 用 len + range 得到数字索引
    print(i + 1, students[i])       # i + 1 换成人类习惯的序号

# ===== 字典 =====
students = {
    "Hermione": "Gryffindor",
    "Harry": "Gryffindor",
    "Ron": "Gryffindor",
    "Draco": "Slytherin",
}
print(students["Hermione"])                       # 用"词"当索引
for student in students:                          # 遍历字典 = 遍历键
    print(student, students[student], sep=", ")   # sep 自定义分隔符

# ===== 列表套字典 + None =====
students = [
    {"name": "Hermione", "house": "Gryffindor", "patronus": "Otter"},
    {"name": "Harry", "house": "Gryffindor", "patronus": "Stag"},
    {"name": "Ron", "house": "Gryffindor", "patronus": "Jack Russell terrier"},
    {"name": "Draco", "house": "Slytherin", "patronus": None},
]
for student in students:
    print(student["name"], student["house"], student["patronus"], sep=", ")

# ===== 嵌套循环与抽象 =====
def print_square(size):
    for i in range(size):          # 外层：每一行
        for j in range(size):      # 内层：该行的每一块砖
            print("#", end="")     # 不换行
        print()                    # 一行结束才换行（无参数 print 只输出 \n）

def print_square(size):            # 用字符串乘法简化
    for i in range(size):
        print("#" * size)

def print_square(size):            # 再抽象一层
    for i in range(size):
        print_row(size)

def print_row(width):
    print("#" * width)
```

## 本讲易错点

1. **`while` 循环里忘了更新变量** → 直接变成无限循环。写 `while` 时第一件事就问自己："哪个量在变？它在变小/变大吗？真的能碰到终止条件吗？"
2. **陷进无限循环时别慌**，按 `Ctrl+C` 中断即可，不用重启电脑。
3. **方向搞反**：从 1 开始数却在 `i -= 1`，数字会越来越负，永远到不了 3。
4. **把起始值从 1 改成 0，却忘了把 `<=` 改成 `<`** → 会多执行一次（猫喵四次）。记住"从 0 开始，上到但不穿过"。
5. **Python 没有 `++` / `--`**，写 `i++` 会报错，用 `i += 1`。
6. **`range(3)` 是 0、1、2，不是 1、2、3**；`range` 要的是整数，不能给它列表（`range(students)` 会报错，要先 `len()`）。
7. **把还需要的变量写成 `_`**：`_` 只用于"语法需要、但我不用"的情况。一旦你要用它，就起个正经名字。
8. **`for student in students` 遍历字典时拿到的是键，不是值**。要拿到值，得再用键索引回去：`students[student]`。
9. **误以为要手动初始化循环变量**：不需要，Python 会自动把 `student` / `i` 依次赋值。
10. **嵌套循环用了同一个变量名**（两层都用 `i`）→ 计数会乱，外层用 `i` 内层用 `j`。
11. **`print()` 的空行陷阱**：`print("x", end="")` 会取消自动换行，所以行末要自己补一个无参数的 `print()`；反过来，如果忘了 `end=""`，每块砖都会独占一行。
12. **`break` 和 `return` 混淆**：`break` 只跳出循环；要从函数里交回一个值，必须 `return`（用 `break` 的话，之后仍要在函数里 `return`）。
13. **`None` 首字母必须大写**，它是关键字，表示"确实没有值"，不要用 `""` 冒充。
14. **列表是零索引**：第 1 项在位置 0。给用户看名次时记得 `i + 1`。
