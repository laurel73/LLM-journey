## 本讲速览

**一句话主题**：到目前为止我们的代码都是"过程式"的（从上往下一步步走）；这一讲教你用**类（class）** 发明自己的数据类型，把相关的数据和功能打包在一起，从而写出更长、更复杂、更不容易出错的程序。

### 本讲知识清单

1. **编程范式（paradigm）**：过程式、函数式、面向对象三种风格的区别，以及为什么需要 OOP
2. **tuple（元组）**：用逗号返回"多个值"的真相，tuple 与 list 的区别（不可变 vs 可变），防御式编程
3. **dict（字典）** 作为折中方案：用键名代替数字下标，语义更清晰
4. **class（类）与 object（对象）/ instance（实例）**：类是蓝图/模具，对象是用蓝图造出来的具体东西
5. **attribute（属性）/ instance variable（实例变量）**：用点号 `.` 存进对象里的变量
6. **`__init__` 方法（Dunder init）**：构造函数 / 初始化方法，对象一创建就被 Python 自动调用
7. **`self`**：Python 偷偷塞给你的"当前这个对象"的引用，永远写在第一个参数位
8. **`__new__` 与 `__init__` 的分工**：构造（造空对象）与初始化（往里填值）
9. **`raise` 关键字**：程序员自己抛出异常，附带自定义错误信息
10. **`__str__` 方法**：让 `print(对象)` 输出人能看懂的内容，而不是内存地址
11. **自定义方法**：类里可以有自己的函数（如 `charm`），这是字典做不到的
12. **Decorator（装饰器）`@property` 与 `@xxx.setter`**：getter（取值器）与 setter（赋值器），把校验逻辑收拢到一个地方
13. **命名冲突与 `_house` 下划线约定**：属性名和方法名不能重名，下划线表示"私有，请别碰"
14. **Python 的"君子协定"（honor system）**：没有真正的 private，只有约定
15. **你一直在用类**：`int`、`str`、`list`、`dict`、`type()` 函数验证
16. **类变量（class variable）与 `@classmethod`**：`cls` 代替 `self`，不需要创建对象就能调用
17. **`@staticmethod`**（本讲只提一句，不讲细节）
18. **继承（Inheritance）**：`class Student(Wizard)`、`super().__init__()`、父类/子类/超类
19. **异常的继承层级**：`BaseException` → `Exception` → `ValueError`，为什么这么设计
20. **运算符重载（Operator Overloading）**：`__add__` 让 `+` 对你的类也能用

## 1. 开场：编程范式与本讲要解决什么问题 [00:00]

David 开场就说：编程世界里存在**不同的"范式"（paradigm）**，也就是解决问题的不同思路。如果你只学过一门语言，一开始很难察觉到这一点；但随着你学的语言变多，你会开始注意到"某些语言有这个能力，某些没有"。

回顾我们到目前为止的历程：

- **过程式编程（procedural programming）**：这是我们的主战场。我们写过程、写函数，代码从上往下一步一步执行，就像你脑子里想的算法那样。
- **函数式编程（functional programming）**：我们也"涉猎"过一点。比如我们可以把函数当作值传来传去，还学过匿名函数（lambda）。这些证据说明 Python 身上带着函数式语言的特性，只是我们只摸到了表面。

而今天要重点讲、也是讲得最细的，是第三种范式——**面向对象编程（Object-Oriented Programming，简称 OOP）**。

David 特意提醒：你们中有些人可能以前学过 Java，Java 从设计上就是一门**从根本上面向对象**的语言；而 Python 给了你很大的灵活性，你可以用不同风格解决同一个问题。但是——

> "随着你的程序越来越长、越来越大、越来越复杂，你会不可避免地遇到某些问题，而面向对象编程是这些问题的一个相当有说服力的解决方案。"

也就是说：OOP 不是一个花架子，它是**为了解决"程序变大之后怎么办"这个问题**而存在的。它建立在我们前几周学过的所有东西之上。

### 本讲的学习方法

David 说得很清楚：我们先写一个非常过程式的程序，然后**一点一点往上加功能**，看看会不会撞上一些"到目前为止我们没有优雅解决方案"的问题。等这些问题暴露出来，再引入 OOP 作为解法，看看代码是不是被清理干净了，是不是为以后写更复杂的程序铺好了路。

所以这一讲的节奏是：**笨版本 → 发现问题 → 改进 → 再发现问题 → 再改进**。每一个中间版本都有存在的意义，笔记里会全部保留。

## 2. 起点：一个纯过程式的 student.py [00:02]

打开 VS Code，新建文件 `student.py`。

我们的目标很简单：在哈利波特的语境下，问用户叫什么名字、属于哪个学院（house），然后打印出"某某来自某某学院"。

### 版本 1：最直白的过程式写法

```python
# student.py —— 版本 1：纯粹从上往下执行
name = input("Name: ")      # 问用户名字
house = input("House: ")    # 问用户学院
print(f"{name} from {house}")
```

运行：

```bash
$ python student.py
Name: Harry
House: Gryffindor
Harry from Gryffindor
```

（`$` 是终端提示符本身，不是你要输入的内容；`python student.py` 才是你敲的命令。）

注意 David 的强调：**现在不做任何错误检查、不做任何修剪（trim）**，就是把用户输入原封不动地吐回来。先让程序跑起来，再谈改进。

### 版本 2：抽象出函数

程序能跑了，但我们来引入第 0 周学过的东西——**写自己的函数**。

David 的原话很关键：

> "不是因为这样能让问题解得更正确——我敢说现在这样已经是对的。而是因为它开始给我们提供积木块（building blocks），我们可以基于这些积木去解决更复杂的程序。"

也就是说，抽函数的价值**不在于正确性，而在于可扩展性**。

```python
# student.py —— 版本 2：抽象出 get_name 与 get_house
def main():
    name = get_name()
    house = get_house()
    print(f"{name} from {house}")


def get_name():
    return input("Name: ")


def get_house():
    return input("House: ")


if __name__ == "__main__":
    main()
```

这里有两个细节值得记：

**细节一：不必要的变量要删掉。** David 一开始写的是：

```python
def get_name():
    name = input("Name: ")
    return name
```

然后他立刻说：第 8 行的 `name` 变量其实不需要，既然马上就要 return 它，不如直接 return `input()` 的返回值。改成 `return input("Name: ")`。功能完全一样，但少一个变量。这是他在整门课里反复强调的习惯。

**细节二：`if __name__ == "__main__":` 不能忘。** 这行代码的意思是：只有当你**直接从命令行运行这个文件**时，才调用 `main()`。这样万一以后这个文件变成一个模块（module）、一个库被别人 import，就不会莫名其妙地把 `main()` 跑一遍。

运行效果和版本 1 完全一样：

```bash
$ python student.py
Name: Harry
House: Gryffindor
Harry from Gryffindor
```

到这一步，问题没有被"更正确"地解决，但我们有了积木块。

## 3. 我想返回"一整个学生"，怎么办？[00:08]

### 3.1 问题的提出

David 提出一个改进方向：`get_name` 和 `get_house` 是能用，但我归根结底是想**从用户那里得到一个学生**——我要的是名字和学院**两个东西**，不是其中一个。

所以更干净的做法是定义一个 `get_student`，让它把两件事都干了。理论上 `get_student` 可以去调用 `get_name` 和 `get_house`，但那两个函数实在太短了，David 认为直接写一个 `get_student` 就够了。

于是问题来了，而且这是个真问题：

```python
def get_student():
    name = input("Name: ")
    house = input("House: ")
    # 我现在有两个变量 name 和 house
    # 但到目前为止，我们 return 的都是"一个值"
    # 我想把两个都返回，怎么办？
```

David 的原话是："我觉得我把自己逼进死角了（I might have painted myself into a corner）。"

### 3.2 学生的两个回答（都正确）

**学生 Muhammad 的回答**：返回一个字典（dictionary / dict），一个键叫 `name`，一个键叫 `house`，值就是这两个变量。

David 的评价：完全可以。但"我担心那样稍微有点复杂了，我想知道有没有更简单的方法"。

**另一个学生的回答**：直接 `return name, house`，两个都返回。

David 很喜欢这个："听起来简单。我不必去纠结字典长什么样。而且就算你以前没见过这个写法，它也是合法的。"

接着 David 点出了本讲反复出现的主题：

> "这里我们又一次看到：同一个问题至少可以用两种方式解决。而且我敢说，我们马上还会看到更多种。"

### 3.3 解包（unpacking）：用逗号返回"多个值"

```python
# student.py —— 版本 3：返回两个值
def main():
    name, house = get_student()      # 左边用逗号"解包"
    print(f"{name} from {house}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return name, house               # 一个逗号，返回两个值


if __name__ == "__main__":
    main()
```

运行：

```bash
$ python student.py
Name: Harry
House: Gryffindor
Harry from Gryffindor
```

这里的机制是：`return name, house` 实际上是返回了一个"序列"，而 `name, house = ...` 是在**解包（unpack）**这个序列。我们以前见过这个技巧。

David 的一个小提醒：左边的变量名不一定非得叫 `name` 和 `house`，你完全可以写成 `n, h = get_student()` 然后 `return n, h`。但那样读代码的人不知道怎么回事，**可读性差**。所以这里故意让 `main` 里的变量名和 `get_student` 里的变量名保持一致（虽然这只是巧合），读起来更清楚。

### 3.4 真相：所谓"返回多个值"是个善意的谎言

David 紧接着戳破：

> "这有点像一个白色的谎言（a bit of a white lie）。"

真相是：当你在 `return` 后面写一个逗号，你其实**并没有返回两个值**，你返回的是**一个值**——一个 **tuple（元组）**。这个 tuple 里面装着两个东西。

tuple 是 Python 里的又一种数据类型，它是一组值的集合，类似 `x, y` 或 `x, y, z`。它跟 list（列表）在精神上很像，**但它是不可变的（immutable）**。

所以：

- `return name, house` —— 靠一个逗号告诉 Python：我要返回一个 tuple
- 更啰嗦但更明确的写法是加括号：`return (name, house)`

### 3.5 把 tuple 存进一个变量

既然本质上是"一个值"，那我们就不必在 `main` 里解包，可以直接存进一个变量，而且可以给这个变量起一个更贴切的名字：

```python
# student.py —— 版本 4：把 tuple 存进 student 变量
def main():
    student = get_student()
    print(f"{student[0]} from {student[1]}")   # 用数字下标取


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return (name, house)      # 显式加括号，强调"这是一个装着两样东西的值"


if __name__ == "__main__":
    main()
```

David 认为这个设计**更好一点**，因为我们开始把"什么是学生"这件事抽象掉了——虽然目前是用一个装着两个值的 tuple 实现的，但至少变量名叫 `student`，是"我想要的那个东西"的名字。

**但这里有个代价（catch）**：现在 `main` 里既没有 `name` 变量，也没有 `house` 变量，又不是字典（没法按键名取）。所以只能**用数字下标**：

- `student[0]` → tuple 里第 0 个位置，也就是名字
- `student[1]` → tuple 里第 1 个位置，也就是学院（因为我们是**从 0 开始数**的）

运行依然正常：

```bash
$ python student.py
Name: Harry
House: Gryffindor
Harry from Gryffindor
```

### 3.6 学生提问：到底什么时候该用 tuple，什么时候该用 list？

> **学生**：tuple 和 list 相比，真正的用例是什么？什么时候你会用 tuple 而不是 list 或类似的东西？

David 的回答非常精彩，值得逐字记住：

> "这是个好问题。当你想**防御式地编程**（program defensively）时——或者更一般地说，当你**知道这个变量里的值不该被改变**的时候，那你为什么要用一个允许它被改变的数据类型呢？那只会招来错误、招来 bug，不管是你自己写的，还是和你协作的同事写的。"

> "所以 tuple 只是你工具箱里的又一件工具，用来提高正确性的概率——方法就是**不让任何人（包括你自己）去改里面的内容**。"

一句话总结：**list 可变，tuple 不可变；不确定就先用 tuple，因为你不需要改的时候，不该给自己留一个能改的口子。**

## 4. tuple 不可变的翻车现场：Padma 的例子 [00:15]

### 4.1 需求：修正电影和原著的不一致

David 先跑一遍程序：输入 Padma（帕德玛）和 Gryffindor，输出 `Padma from Gryffindor`。

然后他说自己"钻了牛角尖"去查了哈利波特的细节：**电影里** Padma 在 Gryffindor，但**原著里**她在 **Ravenclaw（拉文克劳）**。这是电影和书之间的一个不一致。

我们来修掉它：如果用户输入的名字是 Padma，就不管他输的什么学院，强制改成 Ravenclaw。

### 4.2 报错版本（务必记住这个报错）

```python
# student.py —— 版本 5：试图修改 tuple（会报错！）
def main():
    student = get_student()
    if student[0] == "Padma":
        student[1] = "Ravenclaw"          # ❌ 这一行会炸
    print(f"{student[0]} from {student[1]}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return name, house


if __name__ == "__main__":
    main()
```

先跑 Harry，一切正常：

```bash
$ python student.py
Name: Harry
House: Gryffindor
Harry from Gryffindor
```

再跑 Padma —— **屏幕上炸出一堆错误**：

```
TypeError: 'tuple' object does not support item assignment
```

### 4.3 读懂这条报错

David 承认这条报错"表达得有点晦涩（arcanely expressed），对用户不太友好"。但拆开看就懂了：

- `tuple object` → 一个 tuple 对象
- `does not support` → 不支持
- `item assignment` → 给里面的元素赋值

**item assignment 就是"赋值"**，也就是从右往左拷贝的那个动作。所以整句话的意思是：**tuple 不允许你改里面某个位置的值**。

这就是"不可变性（immutability）"的直接体现。你不能改位置 0、位置 1，哪里都不能改。**这是特性，不是 bug，这就是 tuple 被设计出来的目的。**

### 4.4 修复：改用 list

如果确实需要让值能被改（不管是你自己还是同事），那就用另一种数据类型——**list（列表）**。

```python
# student.py —— 版本 6：改用 list（可以修改）
def main():
    student = get_student()
    if student[0] == "Padma":
        student[1] = "Ravenclaw"          # ✅ list 可以改
    print(f"{student[0]} from {student[1]}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return [name, house]                  # 方括号 = list


if __name__ == "__main__":
    main()
```

**唯一的改动**就是把 `return (name, house)` 的圆括号换成**方括号** `[name, house]`。思想完全一样，但 list 是**可变的（mutable）**。

运行结果：

```bash
$ python student.py
Name: Harry
House: Gryffindor
Harry from Gryffindor

$ python student.py
Name: Padma
House: Gryffindor
Padma from Ravenclaw          # 被我们强制纠正了
```

David 的取舍说明：这样确实给了你自己和同事更大的灵活性，但**代价是牺牲了代码的安全性**。既然值可以改，那么跟你合作的人未来就可能改错。

### 4.5 学生提问一：tuple 能像 list 那样嵌套吗？

> **学生**：Python 里能用嵌套的 tuple 吗？就像嵌套 list 那样？

David：绝对可以。list 里可以放 list（外层方括号，内层再来一对方括号），tuple 也一样。**对能放进去的值的类型没有任何限制**。我们这里只是返回了一个装着两个元素的简单 tuple，但你想嵌套完全可以。

### 4.6 学生提问二：方括号到底是不是 list 专属？

> **学生**：我看到方括号的时候，是不是主要就表示 list？

David：这是个**非常好的问题**，答案是"算是，但有个坑"：

- **创建值的时候**：方括号 `[...]` 是 list 的视觉标志；圆括号 `(...)` 是 tuple 的视觉标志。
- **访问元素的时候**：**list 和 tuple 都用方括号**！`x[0]`、`x[1]` 都是方括号，不管是 list 还是 tuple。

所以：**建的时候看括号类型，取的时候一律方括号**。这是初学者最容易混的地方之一。

## 5. 第三种解法：用 dict（字典）[00:20]

### 5.1 为什么 dict 更好

David 提议再来一种解法。回顾一下：**dict（字典）** 是键值对的集合。它最大的优点是**语义更好（better semantics）**。

用 tuple / list 的时候，你必须**假设**名字永远在位置 0、学院永远在位置 1。如果只有两个值还凑合；一旦你有三个、四个、更多值，**早晚有人（包括你自己）会搞混顺序，然后写出 bug**。

dict 更强大，因为你可以**把键（key）——也就是一个小小的描述——和值语义化地绑定在一起**。

### 5.2 版本 7：dict 版

```python
# student.py —— 版本 7：用 dict
def main():
    student = get_student()
    print(f"{student['name']} from {student['house']}")   # 用键名索引


def get_student():
    student = {}                          # 先创建一个空字典
    student["name"] = input("Name: ")     # 加一个键值对
    student["house"] = input("House: ")   # 再加一个
    return student


if __name__ == "__main__":
    main()
```

注意：这里确实是**返回一个东西**，只是这个东西是 dict 而不是 tuple、不是 list。里面有两对键值对（严格说是四样东西，如果把键和值都算上的话）。

### 5.3 一个真实的语法错误：引号套引号

写上面 `main` 里的 f-string 时，David 习惯性地用了双引号：

```python
print(f"{student["name"]} from {student["house"]}")   # ❌ SyntaxError
```

他**故意先不运行**，问台下："谁看出我哪里写错了？"

有学生听出了关键词——**双引号和单引号**。

问题在于：这个 f-string 本身外层就是双引号（带 `f` 前缀），你不能在双引号里面再直接用双引号，Python 会**被搞混**。

运行的结果：

```
SyntaxError: invalid syntax
```

**注意这个错误级别**：程序**根本没能跑起来**，不是运行时错误，而是 Python 压根没读懂你的代码。

修复方法有两个，任选其一：

```python
# 方案 A：内层改用单引号（官方 Notes 用的就是这种）
print(f"{student['name']} from {student['house']}")

# 方案 B：外层改用单引号，内层用双引号
print(f'{student["name"]} from {student["house"]}')
```

**核心原则：保持一致，别让引号嵌套冲突。**

这个坑跟我们今天要解决的核心问题无关，纯粹是 dict 语法的锅，但非常常见。

运行：

```bash
$ python student.py
Name: Harry
House: Gryffindor
Harry from Gryffindor
```

### 5.4 dict 的价值重申

David 说得很直白：用 dict 的好处就是**语义更好**。我不必去记住、去背、去写文档说明"0 是名字，1 是学院"。现在 `"name"` 就是名字，`"house"` 就是学院。**更清晰、更有表现力**。

尤其是当你要存的学生信息不止名字和学院——三个字段、四个、五个、十个——**没有人愿意、也没有能力永远记住哪个是 0、哪个是 1、哪个是 2**。这时候引入名字（键）就非常值得。

### 5.5 版本 8：精简掉不必要的变量

David 的习惯是：**不引入不必要的变量，除非它能让代码更好读**。

严格来说，我们不需要"先建空字典 → 加一个键 → 再加一个键 → 返回这个字典"这四步。可以合并成一条语句：

```python
# student.py —— 版本 8：在 return 里直接创建字典
def main():
    student = get_student()
    print(f"{student['name']} from {student['house']}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return {"name": name, "house": house}    # 一行搞定，边建边返回


if __name__ == "__main__":
    main()
```

`student` 这个中间变量**不再需要存在**了。

David 的诚实评价：

> "这样更好吗？也许好，也许不好。也许第一种写法可读性更好一点——如果变量能提升代码可读性，**创建变量是完全没问题的**。但你要知道，你也可以像这样'随手'（on the fly）创建并返回字典，一行搞定。我觉得在这个例子里，这么做是相当合理的。为什么？因为它很短。如果它越来越长，我大概就不会这么写了，起码会把键值对拆到不同行去。"

这是一个很重要的"分寸感"教学：**代码短不短不是唯一标准，可读性才是**；但短到一定程度，一行确实更清楚。

### 5.6 版本 9：dict 版加回 Padma 特例

dict 和 list 一样是**可变的**，可以改里面的内容。语法稍有不同——不是用位置 0 和 1，而是**用键名**：

```python
# student.py —— 版本 9：dict 版修正 Padma 的学院
def main():
    student = get_student()
    if student["name"] == "Padma":
        student["house"] = "Ravenclaw"      # 用键名改，不是数字下标
    print(f"{student['name']} from {student['house']}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return {"name": name, "house": house}


if __name__ == "__main__":
    main()
```

运行：

```bash
$ python student.py
Name: Harry
House: Gryffindor
Harry from Gryffindor

$ python student.py
Name: Padma
House: Gryffindor
Padma from Ravenclaw
```

**关键对比（David 反复强调）**：

- 索引 list 和 tuple 用的是**数字**
- 索引 dict 用的是**字符串**（键名）

### 5.7 学生提问：tuple 里面装 list，那个 list 能改吗？

> **学生**：如果我们的 tuple 里装着 list，我们能改那个 list 吗？因为 tuple 不可变，但 list 可变？

David：正确。

- list 里的内容可以改，而且你想往里放什么都行——别的 list、字符串、整数，随便。
- tuple 也是一样可以装任何东西，但**一旦创建就不能改**。
- dict 更像 list，是**可变的**，可以改。
- 区别在于索引方式：dict 用**键（字符串）**，list/tuple 用**数字下标**。

## 7. 第一个类：`class Student` [00:30]

### 7.1 版本 10：一个"空壳"类

回到 VS Code，清屏，在文件顶部开始一个"想法先不写完"的写法：

```python
# student.py —— 版本 10：引入 class Student
class Student:
    ...                      # 三个点，占位符，表示"待会儿回来补"


def main():
    student = get_student()
    print(f"{student.name} from {student.house}")    # 点号访问属性


def get_student():
    student = Student()                  # 用类名加括号，创建一个 Student
    student.name = input("Name: ")       # 用点号往里放属性
    student.house = input("House: ")
    return student


if __name__ == "__main__":
    main()
```

几个要注意的地方：

**一、命名约定：类名首字母大写。** 这里用 `Student`（大写 S）。这是 Python 社区的约定，官方 Notes 也强调"by convention that `Student` is capitalized"。

**二、`...` 是合法占位符。** 类体里写三个点，表示"我知道这里要写代码，但先留个位置"。Python 认这个语法，不会报错。David 说这"就足以创造一个类了"。

**三、`student = Student()` 看起来像在调函数。** 没错，它就是在调用一个跟类同名的函数——**只要你定义了一个类，你就自动获得了一个跟类名完全一样（包括大写字母）的函数**。

**四、点号（dot notation）。** 如果还是字典，我们会写 `student["name"]`（方括号 + 字符串）。但这不是字典。**类有我们暂且称之为"属性（attribute）"的东西**，用来在里面放值，语法是**一个点**：

```python
student.name = input("Name: ")     # 放
student.house = input("House: ")   # 放
print(student.name)                # 取
```

我们以前在模块和库里用过点号，这里是"点号"的又一种用法：**从某个东西里取出里面的某个东西**。

## 8. `__init__` 与 `self`：类的核心机制 [00:40]

### 8.1 为什么要升级？

现在看版本 10 的第 12、13 行：手动往对象里塞属性，这有两点问题：

1. **太手工（a little manual）**
2. **太随意（a little reckless）**——我往这个 student 对象里塞什么都行

而类跟字典不一样的地方在于：**类可以进一步标准化（standardize）这些属性可以是什么、可以设成什么样的值**。

### 8.2 版本 11：把参数传进构造函数

先改 `get_student`：不再创建对象后再一个个塞，而是**把值作为参数传进去**：

```python
# student.py —— 版本 11：把 name 和 house 传进 Student()
class Student:
    def __init__(self, name, house):
        self.name = name
        self.house = house


def main():
    student = get_student()
    print(f"{student.name} from {student.house}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    student = Student(name, house)     # 把两个值传进去
    return student


if __name__ == "__main__":
    main()
```

**为什么这一步很重要？** David 解释了很久，核心是：

> "因为我把 name 和 house 传给了 Student 类（这个特定的函数），我就**对数据的正确性有了更大的控制权**。"

这给了我们机会去做错误检查：确保名字有值、不是用户直接按回车；确保学院是 Gryffindor / Hufflepuff / Ravenclaw / Slytherin 之一，而不是用户随便敲的乱七八糟的东西。

**这就是类和字典的根本差别之一：字典你塞什么进去都行；类可以拦截。**

### 8.3 `__init__` 到底是什么

回到类定义，把 `...` 换成真正的代码。

在类的语境里，你不光可以往里放**属性 / 实例变量**，还可以放**方法（method）**——也就是类里面的函数。

有些方法是 Python **约定好会自动调用**的，它们"由 Python 的工作方式天然地具有特殊行为"。我们要定义的第一个就是：

```
__init__
```

读作 **"Dunder init"**（Dunder = Double Underscore，双下划线）。

```python
class Student:
    def __init__(self, name, house):    # 注意第一个参数 self
        self.name = name
        self.house = house
```

### 8.4 `self` 是什么？（本讲最难的点之一）

David 非常坦诚："这里有一大堆奇怪的语法。"他列出了三件让人懵的事：

1. 这个 `__init__` 双下划线方法
2. 突然冒出来的 `self` 参数
3. 新语法 `self.name` 和 `self.house`

他的教学策略是**倒着讲**：

**第一步：看调用的那一行。**

`student = Student(name, house)` 这一行，是在把类名 `Student`（大写 S）**当函数用**，并传入两个值。

这一行**一般被称为"构造函数调用"（constructor call）**——它会为我**构造（construct）**一个 student 对象。用同义词说，它会为我**实例化（instantiate）**一个 student 对象。

**构造的过程**是：用 Student 类作为模板 / 模具，**让每一个学生的结构都一样**——每个学生都有名字，每个学生都有学院。但因为我能往 `Student()` 里传参数，我就能**定制**对象里的内容。

回到造房子的比喻：同一份蓝图造出来的房子长得都一样，但你可以给外墙刷不同颜色、种不同的树，**在细节上做specialization（特化）**。Student 蓝图永远有 name 和 house，但具体是什么名字、什么学院，由你传进去决定。

**第二步：那个函数在哪儿？**

我写了 `Student(...)` 加括号，说明世界上一定有个用 `def` 定义的函数会被调用。

而**按 Python 类的工作方式，永远会被调用的那个函数，就叫 `__init__`（双下划线 init 双下划线）**。

为什么叫这么怪的名字？David 笑说："这是个疯狂的名字，但这就是 Python 的作者们选择的、用来实现对象初始化的方式。"

**第三步：那 `self` 是干嘛的？（关键）**

David 承认"尤其奇怪的是这一点"：

> "如果 init 只有 `name, house` 两个参数，对我来说也清楚得多。到这门课为止，我们定义每个函数都是这么干的：你只要指定你想让函数接受的参数就行了。这也跟我在调用时只传两个东西对上了。"

那为什么非要加个 `self`？

**因为：假设你把 name 和 house 传给了 `__init__`，你打算拿它们怎么办？你到底要把它们放在哪里？**

如果你想为这个学生记住名字和学院，你得**把值存到某个地方**。而问题是：**你怎么把它们存进"刚刚被实例化的那个当前对象"里？**

Python 的作者们定下了一个约定：

> **`__init__` 方法会半秘密地（semi secretly）接受第三个参数，而且这个参数必须排在第一个。**

- 按约定，它叫 `self`；技术上你可以叫它任何名字，但**约定永远是 `self`**。
- `self` 如其名，给你**访问"刚刚创建的那个当前对象"的能力**。

**具体流程是这样的：**

1. 你写 `student = Student(name, house)`，这一行**构造**了一个 student 对象
2. 刚造出来的时候，这个对象**里面是空的**——没有 name，没有 house
3. 但这个对象**已经存在于计算机的内存里了**
4. 现在轮到**你**负责往里填值
5. Python 会**自动调用** `__init__`，并且**自动传入一个引用（reference）**，这个引用代表它刚刚为你在内存里构造好的那个当前对象
6. 于是你在 `__init__` 里可以写 `self.name = ...`，也就是**在这个原本空空如也的对象里创建一个新属性（也就是实例变量）**，把 name 放进去

**David 的原话特别形象：**

> "这就像是在那个原本空空的对象里**安装（installing）**上 name 和 house 这两个值，并把它们存放在对象里**同名**的实例变量中。"

### 8.5 `self.name = name` 的命名可以随便改吗？

可以。你完全可以把它们叫 `n` 和 `h`。但 David 说：

> "那真的太不自解释了（not very self-explanatory）。用 `self.name = name`、`self.house = house` 这种约定好得多。"

**再强调一次：对象就是类的实例（an object is just an instance of a class）。**

### 8.6 学生提问一：`__init__` 和"默认构造函数"有什么区别？

> **学生**：init 方法和 default constructor（默认构造函数）有什么区别？

David 的回答（如果你学过 Java，这段很重要）：

- 在其他语言里（比如 Java），有**明确叫做 constructor 的函数**来构造对象、用值初始化它。
- Python 技术上把 `__init__` 叫做**initialization method（初始化方法）**——它负责**初始化值**。
- 真正"构造"对象的是**另一行代码**（也就是 `Student(name, house)` 那一行）。
- 事实上 Python 里还有**另一个特殊方法叫 `__new__`**，它才真正负责"在内存里为你创建一个空对象"这个流程。但**今天我们不会详细讲它**。

所以严格区分是：

- **`__new__`** → 构造（construct）：在内存里造一个空对象
- **`__init__`** → 初始化（initialize）：往这个空对象里填内容

> "一般来说，作为程序员的你**不需要去摆弄 `__new__`**，它自己会为你工作。你只要定义自己的 `__init__` 就行。技术上有这个区别，但在 Python 的世界里，你基本只需要操心 `__init__`，另一半 Python 替你做了。"

### 8.7 学生提问二：我想存多个名字 / 多个学院怎么办？

> **学生**：如果我们想存不止一个 name 或不止一个 house 呢？

David：这是个好问题，有几种做法：

1. 创建**别的属性**（技术上叫实例变量），比如 `self.name1`、`self.name2`。但我们以前就见过，**这不是好设计**——用一堆变量去存一堆东西。
2. 更好的做法：一个实例变量叫 `self.names`（复数），设成一个**名字的 list**，或者一个学院的 list。

不过 David 也指出：**在这个具体的例子里，这其实没有解决什么问题**。因为我要实现的是**一个**学生（单数），一个人有多个名字（名、中间名、姓另说，见下）或多个学院，本身就说不通。

但**绝对可以这么做**，用我们熟悉的积木（比如 list）就行。

### 8.8 学生提问三：类和对象在内存中是怎么表示的？

> **学生**：类或对象在内存中是怎么表示的？

David：

- **类**技术上**只是代码**——就是我文件顶部那几行，定义蓝图 / 模板的代码。

- **但这件事是 Python 这个程序替你搞定的**。Python 解释器决定把它放在内存的哪里。

## 9. `raise`：让类自己抛异常 [00:55]

### 9.1 问题：创建学生时出错了怎么办？

- 如果用户**没给名字**，直接按了回车怎么办？我不想往内存里放一个"没有名字的假学生对象"。 ideally 我希望**在创建之前就检查出错误**，这样就不会造出一个无名的学生。
- 类似地，我不想让用户随便敲个乱七八糟的字符串当学院。在哈利波特的世界里（至少在霍格沃茨）**只有四个学院**：Gryffindor、Hufflepuff、Ravenclaw、Slytherin。

### 9.2 错误检查应该放在哪里？

David 说：我当然**可以在 `get_student` 函数里做全部校验**——检查名字是否为空、检查学院是否是四个之一。

**但那样就跟"学生"本身脱钩了（rather decoupled from the student itself）。**

`student.py` 文件里，`get_student` 只是我自己写的一个函数；而**类——以及更广义的面向对象编程——鼓励你把一个类的所有相关功能都封装（encapsulate）在类的内部**。

> "如果你想验证名字存在，如果你想验证学院正确，那在根本上就应该属于 Student 这个类本身，而不是你写在别处的某个随机函数里。"

David 强调这是**方法论（methodology）**，不是语法强制：

> "想想看，如果你把跟 name 有关的、跟 house 有关的所有代码都放在 student 里，**把相关的代码放在一起**，组织性就是更好，这很可能会让你以后更成功。这确实是面向对象编程这套方法论的一部分。"

### 9.3 三种错误方案，逐个被否

**方案一：`print("Missing name")`——不够。**

```python
def __init__(self, name, house):
    if not name:
        print("Missing name")     # ❌ 不够！
```

David 的评价：**"This is not good enough. It does not suffice."** 只是打印一句"缺少名字"，然后**让后面的代码继续跑下去**，这不行。

**方案二：`sys.exit("Missing name")`——太粗暴。**

```python
import sys

def __init__(self, name, house):
    if not name:
        sys.exit("Missing name")  # ❌ 太极端！
```

David 的评价非常生动：

> "这是一个相当讨厌的（obnoxious）解决方案。就因为你或者你同事搞砸了、用了个无效的名字调用函数，你就要**退出我整个程序**？这个反应真是极端到极点（really, really extreme）。"

> "如果你的程序正在运行中，你大概不想这么做。你可能想清理一些东西，你可能想保存文件——你总不希望因为输入无效，就在某个随意的行上直接退出程序吧？"

**方案三：`return None`——太晚了。**

```python
def __init__(self, name, house):
    if not name:
        return None              # ❌ 来不及了！
```

为什么不行？David 的解释直指 `__init__` 的本质：

> "太晚了（It's too late）。如果我们滚回创建对象的地方，student **已经被创建出来了**。在内存的某个地方，已经有了一个按 student 结构组织的对象。它只是里面还没有值而已。但**返回 None 已经来不及了，那条船已经开走了（That ship has sailed）**。对象存在就是存在。你不能突然说'不不不，没有对象'——**有对象**。现在轮到**你来发出一个错误信号（signal an error）**。"

**这段是理解 `__init__` 的关键：`__init__` 不能"拒绝创建对象"，它只能"报错"。**

### 9.4 正解：`raise`

既然不能退出、不能返回 None、不能只打印，那就用我们早就见过、但**从来没有自己造过**的机制：**异常（exception）**。

Python 里有一个跟异常相关的关键字，Python 自己就是用它在抛那些我们之前见过的所有异常的。这个关键字就是——**`raise`**。

> "结果证明，你——程序员——也可以 raise（抛出）你自己的异常，当某件事真的出错的时候：错得**不至于**让你想退出整个程序，但又**足够**让你需要以某种方式提醒程序员'出错了'——发生了某种非常糟糕的'异常的'事情，让他们按需去捕获（catch）这个异常。"

### 9.5 版本 13：加上 `raise`

```python
# student.py —— 版本 13：用 raise 做校验
class Student:
    def __init__(self, name, house):
        if not name:
            raise ValueError("Missing name")          # 名字为空就抛异常
        if house not in ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]:
            raise ValueError("Invalid house")         # 学院不合法就抛异常
        self.name = name
        self.house = house


def main():
    student = get_student()
    print(f"{student.name} from {student.house}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return Student(name, house)


if __name__ == "__main__":
    main()
```

几点说明：

**一、`if not name` 是 Pythonic 写法。** 它的意思是"如果 name 为空"，等价于 `if name == ""`，但**更优雅（more elegant）、更 Pythonic**。我们以前见过这种写法。

**二、`raise ValueError("Missing name")`。** 我们以前**意外地制造过** ValueError，也一直在 try 去捕获它们。而异常这个特性的"另一面"是：**程序员也可以在出问题的时候自己抛异常**。

**三、异常可以像函数一样传参数。** 你不必抛一个"笼统的 ValueError 然后让程序员猜哪儿错了"。你可以**把 Python 的所有异常都当成函数用**，给它们传一个解释性的消息：

```python
raise ValueError("Missing name")     # 程序员看到就知道：哦，是我没确保用户有名字
raise ValueError("Invalid house")    # 程序员看到就知道：学院不对
```

**四、调用方可以 `try` / `except` 捕获它。**

```python
try:
    student = Student(name, house)
except ValueError:
    ...    # 出错了我在这里处理
```

David 说"我在这里用手一挥（wave my hand），具体怎么处理先不管"，但机制上：你可以像以前一样用 `try` 和 `except`。


> "所以我们现在工具箱里不只有类了，在异常方面也有了更强的能力——**不只是自己捕获异常，还能自己抛出异常**。"

## 10. `__str__`：让 `print(对象)` 输出人话 [01:05]

### 10.1 问题：直接 print 一个对象，输出是一串天书

到目前为止，在 `main` 里我们还是**很手工地**打印：进到对象里取 `student.name`，再进到对象里取 `student.house`，自己拼出那句话。

但是——**要是能像前几周打印 int、float、str 那样，直接 `print(student)` 该多好？**

试试看：

```python
def main():
    student = get_student()
    print(student)         # 直接打印对象
```

运行：

```bash
$ python student.py
Name: Harry
House: Gryffindor
<__main__.Student object at 0x102733e80>
```

### 10.2 那串天书是什么？

那串 `0x102733e80` 是**内存地址**。

- 如果你在自己的电脑上跑，**看到的数字会不一样**（因为是另一块内存）
- 你真正看到的是：**这个特定对象作为字符串的底层表示（underlying representation）**
- 具体来说，你看到的是**它在计算机内存（RAM）里的位置**

David 的评价：这对我也好、对你也好、一般来说对程序员也好，**都不是什么有意思的信息**。但这只是 Python 在 `print` 时**描述一个东西的默认方式**。

**但我们可以覆盖（override）它。**

### 10.3 `__str__` 方法

Python 里关于类还有别的特殊方法。除了 `__init__`，沿用同样的命名模式，还有：

```
__str__
```

如果你在自己的类里定义了这个方法，**Python 会在任何"别的函数想把你的对象当成字符串看"的时候，自动调用它**。

- `print` 就想把你的对象当字符串看
- 但**默认情况下**，如果你没定义 `__str__`，它就会打印出那个非常丑陋、非常晦涩的样子：`<__main__.Student object at 0x...>`

### 10.4 第一版 `__str__`：返回一句废话

David 先写了个最简版本，只为了演示机制：

```python
class Student:
    def __init__(self, name, house):
        if not name:
            raise ValueError("Missing name")
        if house not in ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]:
            raise ValueError("Invalid house")
        self.name = name
        self.house = house

    def __str__(self):
        return "a student"        # 先不管具体是谁，就返回一句通用的话
```

运行：

```bash
$ python student.py
Name: Harry
House: Gryffindor
a student
```

David 的评价：**更可读了，但没什么信息量（more readable but not very enlightening）。** 到底是哪个学生？

### 10.5 第二版 `__str__`：用 `self` 拼出具体内容

注意：`__str__` 这个方法**永远只接受一个参数**，按约定叫 `self`。这是 Python 作者的设计。当 `print` 触发 `__str__` 时，**Python 会自动把"正在被打印的那个对象的引用"传进去**。

于是我们可以：

```python
class Student:
    def __init__(self, name, house):
        if not name:
            raise ValueError("Missing name")
        if house not in ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]:
            raise ValueError("Invalid house")
        self.name = name
        self.house = house

    def __str__(self):
        return f"{self.name} from {self.house}"    # 用 self 取出属性
```

**这里没有任何新语法**：就是一个 f-string，`f` 开头，两个双引号，两对花括号。但因为 `__str__` 被自动传入了 `self`（当前对象的引用），我就可以**进入那个对象**里取 `name`，再进入那个对象取 `house`。

运行：

```bash
$ python student.py
Name: Harry
House: Gryffindor
Harry from Gryffindor

$ python student.py
Name: Draco
House: Slytherin
Draco from Slytherin
```

**现在输出是针对"具体那个被打印的对象"定制的了。**

### 10.6 学生提问：`__str__` 还能干别的吗？`__str__` 和 `__repr__` 有什么区别？

> **学生**：`__str__` 方法还能做别的事吗？另一个问题是，`str` 和 `repr` 有什么区别？

David 的回答（这是本讲一个重要的扩展点）：

**一、Python 的类里有很多以双下划线开头的方法。** 我们只是**掀开了冰山一角**，今天主要聚焦在 `__init__` 和 `__str__` 这两个（加上后面的 `__add__` 是第三个）。但**还有很多别的**，我们一会儿至少还会看到一个。

**二、其中有一个叫 `__repr__`。** 它是 "representation"（表示）的缩写，表示 Python 对象的"表示形式"。

**三、`__repr__` 和 `__str__` 的分工：**

| 方法 | 面向谁 | 内容 |
|---|---|---|
| `__repr__` | **开发者（developers）的眼睛** | 信息更多，通常还会说明对象的类型，比如 `Student('Harry')` |
| `__str__` | **用户（users）**，也就是程序的使用者 | 更友好，比如 `Harry from Gryffindor` |

**四、两者都可以按你的需要被覆盖。**

## 11. 自定义方法：patronus（守护神）与 `charm` [01:10]

### 11.1 类可以有普通函数（方法）

现在给 Student 加更多功能——**不是 `__init__`、`__str__` 这种"特殊方法"，而是我们自己发明的方法**。

> "因为**类的真正力量和灵活性**就在于此：如果你我作为程序员，能发明出**专属于学生**的新功能。"

背景设定：霍格沃茨的学生会学习施一种咒语——当他们喊 **"Expecto Patronum!"（呼神护卫）** 时，魔杖里会冒出一个东西，通常形似某种动物。这是一个需要反复练习的特殊咒语。

**我们能不能不只存储学生的名字和学院，还存储他们的 patronus（守护神）——也就是他们施这个咒时召唤出来的东西？**

### 11.2 加入 patronus 属性

```python
class Student:
    def __init__(self, name, house, patronus):
        if not name:
            raise ValueError("Missing name")
        if house not in ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]:
            raise ValueError("Invalid house")
        self.name = name
        self.house = house
        self.patronus = patronus        # 新属性
```

David 明确说：**现在先不校验 patronus**（不去对照一个"合法守护神列表"），就盲目地把它赋给 `self.patronus`，让用户随便输。当然以后可以加校验。

### 11.3 自定义方法 `charm`

现在关键的一步——**类不只是能存变量（实例变量、属性），还能有内置的函数，也就是方法（method）**。

## 13. `@property` 与 setter：把校验收拢到一个地方 [01:20]

### 13.1 什么是 property（属性）

> **"property（属性）其实就是一个带有更多防御机制（more defense mechanisms）的 attribute。你多写一点代码，用来防止像你我这样的程序员把这些 attribute 搞坏。"**

再简言之：**property 就是一个你能施加更多控制的 attribute。**

怎么做到？用 Python 的一个特性——

```
@property
```

**技术上，`property` 是 Python 里的一个函数。** 但我们要用的是一种**新的 `@` 语法**，它允许你**装饰（decorate）函数**。

**Decorator（装饰器）** 又是一个术语：

> "在 Python 的世界里，你可以有 decorator（装饰器），它们是**用来修改其他函数行为的函数**。我们就点到为止，不往深了钻。我们通过例子来看看怎么用这些装饰器，**特别是用来定义 property**。"

（顺带记一下：`@` 开头的这行就叫"装饰器"，它写在函数定义的正上方。）

### 13.2 思路：为什么需要 getter 和 setter？

在写代码之前，David 先讲清楚思路：

我们想阻止程序员（包括我自己）**绕过**我为 name 和 house 做的错误检查。怎么做？

> "我们在编程里没有那么多积木。我们有**存数据的变量**，我们有**做动作的函数**。那我们为什么不这么做呢——"
>
> "**为什么不要求：想访问一个属性，你必须经过某个函数？想设置一个属性，你也必须经过某个函数？**"

按约定，这两个函数分别叫：

- **getter（取值器）**：类里的一个函数，用来**获取（get）**某个属性
- **setter（赋值器）**：类里的一个函数，用来**设置（set）**某个值

David 特意说明：这两个术语**在 Java 世界里非常常见**，你们有些人以前学过 Java。但**正如名字所暗示的**，getter 就是"获取某个属性的函数"，setter 就是"设置某个值的函数"。

**为什么用函数？** 因为**一旦有了函数，那些函数就是你自己可以创造的"动作 / 动词"**。因为是自上而下执行的代码，**我可以在这些函数里放任何我想要的错误检查**。

### 13.3 第一版：两个同名函数（有 bug，先别抄）

David 先写了一个"还没写完、里面有错误"的版本，然后逐步修正：

```python
class Student:
    def __init__(self, name, house):
        if not name:
            raise ValueError("Invalid name")
        self.name = name
        self.house = house

    def __str__(self):
        return f"{self.name} from {self.house}"

    # Getter for house
    def house(self):
        return self.house        # ⚠️ 有 bug

    # Setter for house
```

**问题在哪儿？** 两个函数都叫 `house`，但参数个数不同（一个只有 `self`，一个有 `self` 和 `house`）。这在 Python 里是**后者覆盖前者**——后定义的那个会把前面的覆盖掉。所以这个版本根本不能工作。这只是 David 用来讲思路的中间态。

### 13.4 往 setter 里加校验

借用之前的逻辑，不要盲目地 `self.house = house`，而是加上错误检查：

```python
    # Setter for house
    def house(self, house):
        if house not in ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]:
            raise ValueError("Invalid house")
        self.house = house
```

David 说：

> "我刚刚把我的错误检查**拷贝（或者说重打了一遍）**到这个所谓的 setter 函数里。"

**这么做是为了什么？** 关键机制来了：

> "当程序员写下 `student.house = ...` 这样的代码时，Python **不会**让程序员直接访问 `student.house` 这个属性（实例变量）。**它会神奇地、自动地替我调用这个 setter 函数。**"

**Python 怎么知道该这么做？**

> "如果它看到左边是 `self.house`（其中 house 是 getter 或 setter 的名字），然后看到**一个等号**表示赋值——**这个视觉线索就够了**：'等一下，我不会让你直接访问那个属性，我要改用 setter。为什么？因为等号意味着你在试图**设置（set）**、试图从右往左把一个值**赋值**给那个属性。'"

于是 Python 自动调用这个函数。**这很棒，因为现在我可以执行代码——一段算法——去检查"我要不要让用户（程序员）把那个属性设成那个值"。** 如果不行，我就 `raise ValueError`，你就设不了；如果行，我就帮你设上。

### 13.5 加上装饰器（真正能用的版本）

但光写两个函数还不够，我们需要**告诉 Python 把这个方法当成 getter**。这就用到装饰器：

```python
class Student:
    def __init__(self, name, house):
        if not name:
            raise ValueError("Invalid name")
        self.name = name
        self.house = house

    def __str__(self):
        return f"{self.name} from {self.house}"

    # Getter for house
    @property
    def house(self):
        return self._house          # 注意下划线

    # Setter for house
    @house.setter
    def house(self, house):
        if house not in ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]:
            raise ValueError("Invalid house")
        self._house = house         # 注意下划线
```

**装饰器语法规则（David 也吐槽了）：**

- **定义 getter**：在函数上方写 `@property`，然后把函数命名成**你希望这个 property 叫什么名字**——这里是 `house`。
- **定义 setter**：一旦你写了 `@property` 并命名为 `house`，**Python 就自动为你创建了一个新的装饰器，叫 `@house.setter`**。因为你管它叫 house，所以就是 `@house.` + `setter`。
- David 的原话："我希望一个是 `@getter` 一个是 `@setter`，但设计者没这么干。"（事实是：getter 用 `@property`，setter 用 `@xxx.setter`。）

setter 这个函数**名字和 getter 完全一样，都叫 `house`**，但**它接受两个参数**：

1. `self` —— 让你能访问对象里的内容
2. `house` —— 就是从程序员 / 用户 `input()` 返回值那里传进来的字符串，也就是你想设成的那个值

### 13.6 关键修复：为什么是 `_house` 而不是 `house`？

**这是这一节最容易卡住的地方，David 讲得非常细。**

**问题：名字撞车了（I have collided names）。**

- 第 5 行的 `self.name` 是一个**实例变量**（对象里的一个字符串）
- `self.house` 是另一个**实例变量**
- 但如果我有实例变量叫 `name` 和 `house`，**我就不能再有叫 `house` 的函数了**。它们会**撞车（collide）**。Python 会把一个当成另一个，搞混。

**你必须二选一：是想让**变量**叫 house，还是想让**函数**叫 house？不幸的是，不能两个都叫 house。**

**约定俗成的修复方法：**

让 setter **不把**传进来的值存进 `self.house`，而是存进一个**几乎同名、但前面加一个下划线**的变量：

```python
self._house = house       # 前面加一个下划线
```

getter 里也一样：

```python
return self._house        # 前面加一个下划线
```

**于是：**

- 技术上，我的**实例变量**叫 `_house`（带下划线）
- 我的**property**（一种更高级的 attribute）叫 `house`（不带下划线）

David 的感叹："**我知道这是一大堆语法，但它是一个非常强大的特性。这也是为什么你可以从'只用字典'毕业，拥有多得多的功能。**"

### 13.7 `__init__` 里的校验可以删掉了（重要）

现在看 `__init__`：

```python
    def __init__(self, name, house):
        if not name:
            raise ValueError("Invalid name")
        self.name = name
        self.house = house      # 注意：这里没有下划线！
```

**我不再需要 `__init__` 里对 house 的检查了。为什么？**

因为我刚说过：像 `student.house = ...` 这样的代码会让 Python 自动去调用我的 setter。**那么，即使在 `__init__` 里写 `self.house = ...`，也一样会调用我的 setter 方法！**

**这太棒了，因为：**

- 我可以把**所有**错误检查**只保留在 setter 这一个地方**
- 它会在**两种情况**下被调用：
  1. 我第一次创建对象时（`__init__` 里的 `self.house = house` 触发）
  2. 程序员试图绕过 `__init__`、事后改这个属性时（`student.house = ...` 触发）

用 David 的话说：

> "我的 setter 会在**任何时候**我访问 `.house` 的时候被调用。"

### 13.10 学生提问二：getter 一个参数、setter 两个参数，这是规矩吗？

> **学生**：用 getter 时只有一个参数，用 setter 时总是两个参数？这是正常的吗？

**直觉上的解释：**

所以"逻辑上"是 **0 个或 1 个**参数。但**你看到的是 1 个或 2 个**，因为——**类里的任何函数（也就是 method）都会被自动传入 `self`**，让你能访问内存里的那个当前对象。

**如果我改成 `self._house = house`，那就绕过了 setter，`__init__` 里就一点错误检查都没有了。**

David 的感叹：

> "这是一条多么细微的界线（such a fine line）。**横亘在'有错误检查'和'没错误检查'之间的，仅仅是一个下划线的有无。**"

**但这就是约定**。通过**不**在那里用下划线，确保连那次赋值也走 setter，这样：

> "说实话，我就不必把同样的错误检查**复制粘贴到两个地方**了。我可以只把它放在 setter 里。所以这是**更好的设计**——这也解释了为什么我一开始手动重打了一遍，然后又从 `__init__` 里把它删掉了。"

## 14. 给 `name` 也加上 property [01:35]

### 14.1 完整版：name 和 house 都是 property

既然 house 有了，name 也照做。为了保持顺序（跟前面定义的顺序一致），name 的 property 写在 house 前面：

```python
# student.py —— 版本 17：name 和 house 都是 property
class Student:
    def __init__(self, name, house):
        self.name = name        # 会触发 name 的 setter
        self.house = house      # 会触发 house 的 setter

    def __str__(self):
        return f"{self.name} from {self.house}"

    # Getter for name
    @property
    def name(self):
        return self._name

    # Setter for name
    @name.setter
    def name(self, name):
        if not name:
            raise ValueError("Invalid name")
        self._name = name

    @property
    def house(self):
        return self._house

    @house.setter
    def house(self, house):
        if house not in ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]:
            raise ValueError("Invalid house")
        self._house = house


def main():
    student = get_student()
    print(student)


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return Student(name, house)


if __name__ == "__main__":
    main()
```

**注意几点：**

1. **`@name.setter`** —— 之所以是 `name`，是因为我刚创建的 property 叫 `name`。**getter 和 setter 就是这样配合工作的。**
2. setter 这个函数**也叫 `name`**，但**它不是完全相同的函数**——不是"函数名相同且参数个数也相同"。**setter 多一个参数。**
3. 第二个参数你可以叫任何名字，但这里叫 `name`，因为传进来的就是 name。
4. `__init__` **完全不用改**，只要**删掉重复的错误检查**就行。因为：

> "如果我在这里用 `self.name =`（不带下划线）和 `self.house =`（不带下划线），**这两次赋值都会走我的两个 setter 函数**。"


**空名字**（提示名字时直接按回车）：

## 15. 残酷真相：Python 靠的是"君子协定" [01:38]

### 15.1 泼冷水

David 说："**冒着给大家泼冷水的风险（at the risk of bursting everyone's bubble），让你怀疑我们刚才折腾这一大圈到底图什么**——"

先确认一下 setter 确实拦得住：

```python
def main():
    student = get_student()
    student.house = "Number Four, Privet Drive"    # 会被 setter 拦住
    print(student)
```

```bash
$ python student.py
Name: Harry
House: Gryffindor
ValueError: Invalid house          # 拦住了
```

**但是**——如果你已经开始"更 adversarially（对抗性地）"思考了，你会悲剧地发现：

```python

    student = get_student()
    student._house = "Number Four, Privet Drive"   # 加个下划线！
    print(student)
```

```bash
$ python student.py
Name: Harry
House: Gryffindor
Harry from Number Four, Privet Drive        # ⚠️ 溜过去了！
```

**为什么？**

- 实例变量现在叫 `_house`
- property 叫 `house`（不带下划线）
- 但**底层那个以实例变量实现的 attribute 仍然叫 `_house`**
- 所以你直接改 `_house`，**完全绕过了 property 和 setter**

### 15.2 那我们折腾这一圈图什么？

David 的原话（很重要）：

> "那我刚才那么强调要用'正确的方式'、'Pythonic 的方式'去做 getter 和 setter，到底图什么？"

答案是：

> "**不像 Java 那样的语言会直接不让你干这种事，Python 本身允许你指定某些实例变量是 public（公开，任何人都能访问）、protected（受保护），还是 private（私有，其他人不该能改）。但在 Python 的世界里，这只是君子协定（it's just the honor system）。**"

**关键点：**

- **"可见性"（visibility）这个概念——public / private / protected——并没有被内建到 Python 语言本身。**
- 有的只是**约定（convention）**：

> "一般来说，如果一个实例变量**以下划线开头，请不要碰它。真的别碰。** 如果你碰了那个变量并把东西搞坏了，那是你的责任。"

- **下划线意味着"这个按约定是私有的"，但它的真实含义只是"请你别碰这个"。**
- 有时候你会看到**两个下划线**开头，那是程序员在**更强烈地表达"真的别碰这个"**。
- **但从技术上说，没有任何东西能阻止你或我去绕过所有这些机制——这些 property、这些 getter 和 setter。**

**结论：**

> "我们归根结底只是**靠君子协定**，不去碰那些以一个（或甚至两个）下划线开头的实例变量。"

## 16. 你其实一直在用类：int / str / list / dict [01:40]

### 16.1 一个"惊喜"

> "虽然我们可能是在过去几周才第一次听到 OOP 这个名字，但**我们所有人已经用了好几周的类（class）和对象（object）了**。"

### 16.2 `int` 一直是一个类

回想本课程最开始做的事：我们从用户那里拿到整数（integer）。

**但如果你去翻 int 的官方文档，你会发现 `int` 本身——而且好几周以来一直——是一个类。**

`int` 的构造函数签名大致是：

```python
int(x, base=10)     # x 是数字或字符串，base 是进制：10 是十进制，2 是二进制
```

- `int` 这个函数会返回给你一个**类型为 int 的对象**
- 也就是说，**int 是一个类**，是**用来在内存中创建整数的模板 / 蓝图**
- 每当你我把一个字符串转成 int，**你和我就是在创建一个 int 类型的对象**，而这背后显然是在调用 `__init__` 方法（由 Python 的作者写的）

### 16.3 `str` 也一直是类

如果你去查 `str` 的文档，你会发现：当你**实例化（instantiate）**——也就是创建一个 str 时，它接受一个可选参数 `object`，**默认值是 `""`**（空字符串）。

- 任何时候你我用 `str` 函数或者创建 str，你得到的都是**一个 str 类型的对象**
- 任何时候你我用 `str.lower()` 把一个字符串转成小写，**你和我就是在一个 str 类型的对象上调用一个叫 `lower` 的方法**——这个方法是 Python 的作者**内建在 str 类里的**
- 如果你调用过 `strip()` 去掉字符串首尾的空白，你就是在调用**另一个** Python 自带的方法

**所以"方法"这个概念今天根本不算新东西**——我们从第一周就在用了，只是当时没叫它类。

> "虽然我们当时没叫它类，但 str 从头到尾都是一个类。字符串的实例本身就是对象。而这些对象因此自带了这些内置函数——也就是方法——让我们能做诸如转小写、去首尾空白之类的事。"

### 16.4 `list` 也是类

任何时候你创建 list——不管是**用方括号语法** `[]`，还是**字面地写 `list()`**——你都在用一个类。

`list` 类的初始化接受一个**可选的 iterable（可迭代对象）**，比如 `1, 2, 3` 或某个值列表，然后返回一个包含这些值的 list。

**如果你往 list 里 append 过东西，你就是在用一个叫 `append` 的方法**——它来自 list 类。这个方法（按文档里的 `x` 参数）接受一个参数，让你把东西追加到**当前这个 list** 上——**也就是在那个方法的语境里的 `self`**。

### 16.5 `dict` 也是类

## 17. 类变量与 `@classmethod`：hat.py（排序帽）[01:50]

### 17.1 到目前为止的术语回顾

David 特意说明：到目前为止，我**一直在刻意地**把我们所有的变量叫**实例变量（instance variable）**，把所有的方法叫**实例方法（instance method）**。

**但世界上还有别的类型的变量和方法。** 其中一种叫——**类方法（class method）**。

### 17.2 为什么需要类方法？

> "有时候，把一个函数跟'类的对象'关联起来，并不是必需的、也不合理；而是应该把它跟'类本身'关联起来。"

回到那个街区的比喻：

- 一个实例 / 对象是一个**非常具体的化身**（specific incarnation）
- 在那个"所有房子长得都一样，但刷了不同颜色、装饰不同"的街区里——
- **有时候某些功能跟房子无关，它不是任何一栋房子独有的。不管你问的是哪栋房子，这个功能都完全一样。**

OOP 世界同理：**有时候你希望某些功能（动作）跟类本身关联，不管具体对象的实例变量是什么。**

为此，我们有一个关键字：

```
@classmethod
```

这是**另一个装饰器**（其实也是一个函数）。用它来指定：**这个方法默认不是一个能访问 `self`（对象本身）的实例方法，而是一个类方法——它拿不到 `self`，但它知道自己所在的类是哪个。**

### 17.3 排序帽的需求

新建 `hat.py`，实现哈利波特世界里的**排序帽（Sorting Hat）**：

- 书和电影里有一顶**尖帽子**，学生把它戴在头上，它就会**决定**这个学生属于哪个学院
- 我们要做的是：把学生的名字（比如 "Harry"）传给排序帽，它告诉我们这个学生该去哪个学院

### 17.4 第一版：先写"占位符"类（一个好习惯）

David 用了他自己推荐的技巧（不仅在教学时，写代码时也这样）：

```python

```

> "我发现这是个很有用的技巧，不光在教学时，写代码时也如此。**我知道我要一个 Hat 类，我不一定知道我要它干什么，所以我先创建这个占位符 `...`，回头再来补。**"

**然后"假装这个类已经存在"去用它**，从而反推出这个类需要什么功能：


- 我们假定排序帽有一个函数 / 方法叫 `sort`
- `hat.sort("Harry")` 会打印出这个学生该在哪个学院

> "就这些。我要把所有必需的功能**封装**（encapsulate，也就是 tuck away 收起来）到一个 Hat 类里，然后往屏幕上打印出 Harry 属于哪个学院。"

现在让它真的随机选一个学院。

**先要有学院列表，放哪儿？** David 提议：定义 `__init__`，在里面创建一个**实例变量 `houses`（复数）**：

技术细节：

- 注意：Python 的 `print` 可以接受多个参数，用逗号隔开，它会自动用空格连接。所以 `print(name, "is in", random.choice(self.houses))` 会输出 `Harry is in Hufflepuff`。

**为什么把列表放在 `__init__` 里、而不是 `sort` 里面？** David 给了一个通用的工程原则：

> "任何时候你有一个'东西的列表'——天知道，它也许会随时间变化。**像哈佛这样的地方多年来就在建新的 house（学院），所以你可能得改可用学院的列表。** 虽然哈利波特七本书八部电影里没有发生过，但你可以想象霍格沃茨也许最终会有第五个学院。"

**我需要的只是"用一个类来代表排序帽"，但我真的不需要实例化它。为什么？因为它已经存在了。我只需要一个。**

### 17.10 第四版：类变量 + `@classmethod`

**第一步：删掉 `__init__`。**

> "如果我不打算实例化多个帽子，我就真的不需要这个 `__init__` 方法了，因为那是用来从蓝图 / 模板 / 模具**初始化具体对象**的。"

**第二步：类变量（class variable）登场。**

删掉 `__init__` 之后，`self` 就不存在了。**但没关系，因为除了类方法，还有所谓的"类变量（class variable）"。**

> "**类变量存在于类本身之中。而且这个变量对所有对象来说只有一份拷贝。** 如果你愿意这么想的话，它们**共享**同一个变量——不管是 int、str，还是本例中的一个 list。"

```python
import random


class Hat:

    houses = ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]    # 类变量

    @classmethod
    def sort(cls, name):
        print(name, "is in", random.choice(cls.houses))


Hat.sort("Harry")
```

**要点：**

- **不要写 `self`** —— 因为 `self` 指的是**具体的对象**，而 `self` 已经不相关了。我要的是**这个类里的一个变量**，也就是**类变量**，它就等于那个列表。
- 因为它在这个 Hat 类里面，**我可以在任何函数里用这个列表**。我现在只有一个函数 `sort`，但如果我有很多个，它对**所有**方法都可见。

**第三步：`sort` 也改成类方法。**

> "而且，在一个具体的排序帽里做排序也没什么意义，因为再说一遍，我只想要一个。所以我可以指定这是一个类方法，方法是写 `@classmethod`。"

**第四步：`self` 换成 `cls`。**

> "我不再传 `self` 了。按约定，我传入**一个指向类本身的引用，通常写作 `cls`**。"

**为什么是 `cls` 而不是 `class`？**

> "**因为如果你写 C-L-A-S-S，那会跟我们一直在用的关键字 `class` 冲突。** 所以业界意识到：哎呀，我们不能在这里复用同一个词。那就叫它 `cls` 吧。"

**为什么这里 `cls` 有用？**

> "因为现在 `houses` 不再是一个通过 `self.houses` 访问的实例变量，它现在是一个**类变量，通过 `cls.houses` 访问**。"

**第五步：删掉实例化的那一行，直接用类调用。**

```python
Hat.sort("Harry")     # 注意 Hat 大写，因为这是类的名字
```

> "我根本没有费心去实例化一个类型为 Hat 的对象。我只是在用这个类自带的功能。"

**这就是类方法的工作方式：**

1. 你用**类的名字**（大写字母也在）**点**方法名，传入你想要的任何参数
2. **Python 会自动地往那个函数里传入某个变量**，让你能在函数内部引用那个类
3. 这样我就能说："我**不**想要一个叫 houses 的**局部**变量，我想要的那个叫 houses 的变量是**跟当前这个类关联**的那个"，于是我依然能访问到第 6 行定义的那个列表

运行：

```bash
$ python hat.py
Harry is in Hufflepuff
$ python hat.py
Harry is in Hufflepuff
$ python hat.py
Harry is in Gryffindor
```

### 17.11 一个容易困惑的点：没有 `@instancemethod`

David 主动指出：

> "这里至少有一件事有点怪：**尽管有一个叫 `@classmethod` 的装饰器，但并没有一个叫 `@instancemethod` 的装饰器。**"

**规则是：当你定义一个方法而**不带任何装饰器**时，它就自动地是一个所谓的"实例方法（instance method）"。**

### 17.12 学生提问一：类里面能再套一个类吗？

> **学生**：你能在一个类里面再放一个类吗？

David：**可以。** 你可以定义一个类在另一个类里面。**一般来说不这么做**，但在某些情况下会有用，**尤其是对于更大、更复杂的程序**。所以是的，这是可能的。

### 17.13 学生提问二：为什么把 `self.houses` 删了？变量不是自己就创建了吗？

> **学生**：问题关于 `self.houses`。当我们把它删掉、然后传数据时，变量是自己创建的，所以我们为什么要把 `self` 去掉？

**最新版的排序帽**：

> "所以有时候你可以**用这种稍微不同的方式来用面向对象编程**：当你想要某些功能，但它不专属于某一个具体的帽子，而是**专属于'排序帽'这个概念本身**的时候。"

然后他说了一段非常有分量的话：

**而且它不排斥别的方案：**

> "当我们在几周前聚焦库（libraries）的时候，**那也是同一个问题的另一种解决方案**。你可以定义自己的模块或包，把一些数据和/或功能放进去，那也挺好。"

> "**而且有时候该用哪个是有重叠的。** 如果你熟悉韦恩图（Venn diagram），那个重叠区域就意味着：你可以用类；你也可以用模块或包；你也可以就用一个单独的本地文件。**随着时间的推移，你会培养出一种直觉，甚至是一种个人偏好，来决定用哪个工具。**"

## 18. `Student.get()`：用类方法消除"代码异味" [02:08]

### 18.1 回到 student.py，发现设计问题

关掉 `hat.py`，重新打开 `student.py`。David 先做一个简化：**把 properties 全删掉**——不是因为它们有错，而是想让我们**聚焦核心思想**。

```python
class Student:
    def __init__(self, name, house):
        self.name = name
        self.house = house

    def __str__(self):
        return f"{self.name} from {self.house}"


def main():
    student = get_student()
    print(student)


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return Student(name, house)


if __name__ == "__main__":
    main()
```

**现在看这个"错失的机会（missed opportunity）"：**

文件顶部这个 Student 类，**按 OOP 的本质，理论上应该容纳我所有的"跟学生有关的功能"**。

> "也就是说，如果我有跟学生有关的功能和数据，你——我的同事、程序员——会**假定**它们都被打包、被封装在 Student 类里面。"

**但是往下滚一滚，这是什么？**

```python
def get_student():        # 一个就那么存在于文件别处的函数
    name = input("Name: ")
    house = input("House: ")
    return Student(name, house)
```

David 的评价非常克制但精准：

> "**这没错。它能用。而且我们看到它很多次都在正常工作。但是这有点怪（a little weird）**——因为，如果这是一个'帮你得到一个学生'的函数，帮你得到学生的名字和学院，**那这个功能为什么不在类里面？**"

> "毕竟，**随着我的代码越来越复杂、做的事情越来越多，我会去 Student 类里找所有跟学生有关的功能。我不会往下滚，心里想着'哦，也许后面这个文件里别的地方还有点别的学生功能'。**"

**所以这不是对错的（correctness）问题，而是设计（design）问题。**

David 用了一个非常专业的词：

> "这是**代码异味（code smell）** 的一个例子。**这里有点不对劲（Something smells a little off here）。** 把相关的功能拆开，这很可能会给我们找麻烦。"

### 18.2 用 `@classmethod` 修复

**第一步：把 `get_student` 整个删掉**，只剩下 `main`。

**第二步：在 Student 类里定义一个更简单地叫 `get` 的函数。**

按类方法的工作方式，它会接受**类的名字**（或者一个指向它的引用）作为参数：

```python
class Student:
    def __init__(self, name, house):
        self.name = name
        self.house = house

    def __str__(self):
        return f"{self.name} from {self.house}"

    @classmethod
    def get(cls):
        name = input("Name: ")
        house = input("House: ")
        return cls(name, house)        # 用 cls 创建当前类的对象


def main():
    student = Student.get()
    print(student)


if __name__ == "__main__":
    main()
```

**几个关键点：**

**一、"先有鸡还是先有蛋"的问题（chicken and the egg problem）。**

David 说 `@classmethod` **解决了一个潜在的"鸡生蛋蛋生鸡"问题**：

> "如果为了调用 `get`、为了得到另一个 student 对象，你**必须先创建一个 student 对象**，那听起来就很乱。"

> "我们就用一个类方法来得到一个学生吧——**按定义，它不要求你先创建一个 student 对象**。"

就像最终版的 Hat：我们用 `Hat.sort()`，**不需要先创建一顶帽子，我们只是用了类本身**。

**二、`cls(name, house)` 是什么意思？**

David 很坦诚：

> "我承认这个语法看起来有点怪——我现在在调用 `cls` 并传入这些参数。"

- 第 11、12 行跟以前完全一样（就是两个 `input`）
- 新的语法只有 `return cls(name, house)` 这一处
- **但这是 OOP 的一个特性：你现在可以通过传入的 `cls` 来实例化一个 student 对象**
- **技术上我也可以写 `Student(name, house)`（大写 S），但我用的是更约定俗成的写法**，因为这样能解决并避免以后在更复杂的代码中出问题
- **这一行的意思是："创建当前这个类的一个对象。"** 当前类是哪个？**不管 `cls` 是什么。而按这一切的工作方式，`cls` 就是 Student。** 然后像往常一样用 name 和 house 初始化它。

**三、命名：`get` 而不是 `get_student`。**

> "我当然也可以叫它 `get_student`，但**在一个 Student 类里叫 `get_student` 显得有点冗余**，所以我简化了。"

### 18.3 现在的调用方

```python
def main():
    student = Student.get()      # 多清晰！
    print(student)
```

David 的评价：

> "这读起来就很舒服。也许你得慢慢培养出这个品味——而且我说'这读起来很舒服'听起来有点怪——但确实，`Student.get()` 告诉我在干什么：**我要得到一个学生**。我不需要在文件里另写一个我自己的、叫 `get_student` 的函数。**get 这个功能被内建到类里了。我所有跟学生有关的代码现在都在一起了。**"

运行：

```bash
$ python student.py
Name: Harry
House: Gryffindor
Harry from Gryffindor
```

> "我们回到了起点，**但是，但是，但是——现在所有跟学生有关的东西都在这个类里了**。**文件里唯一的其他东西就是 main，以及那个我们一直用来避免在做成模块/包时误执行 main 的条件判断。**"

### 18.4 学生提问一：类必须定义在 main 之前吗？

> **学生（Michael）**：就程序的顺序而言，类必须定义在 main 函数之前吗？

David：**非常好的问题。拿不准的时候，我们就试一下。**

他真的把 `main` 移到了类的**上面**：

### 18.5 学生提问二：能一次性声明类的所有属性吗？

## 20. 继承（Inheritance）：wizard.py [02:20]

### 20.1 继承的地位

David 的开场：

> "也许面向对象编程**最强大的特性**，我们还没有明确使用过——虽然在过去几周里我们其实已经隐式地见过了——就是**继承（inheritance）**这个概念。"

**通过 OOP，你实际上有机会以"层级化（hierarchical）"的方式设计你的类**：你可以让**一个类从另一个类继承（inherit）**——或者说"借用（borrow）"属性（也就是方法或变量）——**如果它们都有这些共同点的话**。

### 20.2 起点：Student 和 Professor 有大量重复

新建 `wizard.py`，先定义 Student：

```python
class Student:
    def __init__(self, name, house):
        self.name = name
        self.house = house

    ...        # 假设这个类里还有别的功能


class Professor:
    def __init__(self, name, subject):
        self.name = name
        self.subject = subject

    ...
```

设定说明：

- 学生有 `name` 和 `house`
- 教授也有名字。**虽然有些教授是院长（heads of houses），但我们假定教授是由"名字"和"他们教的科目（subject）"来标识的**，所以第三个参数叫 `subject`

### 20.3 发现"红色警报"

> "你们在我的 Student 和 Professor 定义里**已经注意到了什么**？"

> "通常我们**不太愿意让代码出现冗余（redundancy）**。而在这里，我觉得我的 `__init__` 为学生接收一个 name，我的 `__init__` 又为教授接收一个 name，而且我还有**一模一样的代码行**，比如 `self.name = name`。"

**而这还只是一个开始——如果我现在去加错误检查，情况会更糟：**

```python
class Student:
    def __init__(self, name, house):
        if not name:
            raise ValueError("Missing name")     # 检查
        self.name = name
        self.house = house

    ...


class Professor:
    def __init__(self, name, subject):
        if not name:
            raise ValueError("Missing name")     # 又复制粘贴一遍！
        self.name = name
        self.subject = subject

    ...
```

David 的原话：

> "而且你知道吗，**如果一位教授缺了名字，我大概得把这段代码复制粘贴到下面去。这就是红旗（red flags）应该竖起来的时候**——**只要你一开始复制粘贴代码，很可能存在更好的办法**，让我们把代码写一次，然后以某种方式复用它。"

**而在这里，面向对象编程也提供了一个解决方案。**

### 20.4 抽出公共父类 Wizard

OOP 支持**继承**，你可以定义多个彼此**有某种关联**的类。**它们不需要像这样平行存在，它们之间可以有层级关系。**

> "比如在魔法世界里，我们可以论证：**学生和教授，归根结底都是 Wizard（巫师）**。"

> "所以也许我们真正应该定义的是**第三个类**，比如叫 `Wizard`，它包含学生和教授**共有的**任何属性。"

目前我们保持简单：**它们唯一共有的就是 name（学生有 name，教授也有 name）。所以我们起码先把这个"析"出来（factor out）。**

```python
class Wizard:
    def __init__(self, name):
        if not name:
            raise ValueError("Missing name")
        self.name = name

    ...        # 也许还有别的功能，但不包括 subject（教授专属），也不包括 house（学生专属）
```

### 20.5 删掉子类里的重复

既然 Wizard 里已经做了，那就在 Student 和 Professor 里把错误检查和 `self.name = name` 都删掉：

```python
class Student:
    def __init__(self, name, house):
        self.house = house        # 只保留自己特有的

    ...


class Professor:
    def __init__(self, name, subject):
        self.subject = subject    # 只保留自己特有的

    ...
```

**但是——虽然它们都在同一个文件里，我还没有告诉 Python：学生是一个巫师、教授是一个巫师。我需要把这两个东西联系起来。**

### 20.6 继承的语法

**规定继承的方式是这样的**（在冒号之前加括号）：

```python
class Student(Wizard):      # Student 继承自 Wizard
    ...


class Professor(Wizard):    # Professor 继承自 Wizard
    ...
```

术语：

- `Student` **继承自（inherit from）** `Wizard`，或者说是 `Wizard` 的**子类（subclass）**
- 反过来说，`Wizard` 是 Student 类的**超类 / 父类（superclass）**

**这句话的意思就是：当我定义 Student 类的时候，顺便把 Wizard 的所有特征也继承过来。**

### 20.7 `super()`：调用父类的 `__init__`

**但有个问题：** 因为 Student 和 Professor 仍然有自己的 `__init__` 方法，**那些才是会被调用的方法**。

> "每当我用代码创建一个 student 或一个 professor，我都得**明确地说**我也想用 Wizard 类里 `__init__` 方法的功能。"

**在 Python 里这么做：**

```python
class Wizard:
    def __init__(self, name):
        if not name:
            raise ValueError("Missing name")
        self.name = name

    ...


class Student(Wizard):
    def __init__(self, name, house):
        super().__init__(name)        # 调用父类（superclass）的 __init__
        self.house = house

    ...


class Professor(Wizard):
    def __init__(self, name, subject):
        super().__init__(name)        # 同样
        self.subject = subject

    ...
```

**拆解 `super().__init__(name)`：**

- **`super()`**（不带参数）——**它是指向"这个类的超类（superclass）"的一个引用**。如果当前类是 Student，那么它的**超类 / 父类**就是 Wizard。所以 `super()` 的作用就是**访问超类**。
- 然后我**明确地调用它的 `__init__` 方法**
- 并且**把传给 Student 的 `__init__` 的 name，传给 Wizard 的 `__init__`**

David 的说明：

- "下面这个（Professor 里的）也是一行复制粘贴，**但我觉得可以接受**，因为它仍然让我把**所有的 name 赋值和错误检查都放在 Wizard 类里**。"

- 关于这行奇怪的语法，David 承认：**"我承认这个语法确实有点离谱（definitely out there）——我们调用 `super` 加括号加点号，左右两边还有双下划线的 init。但它就是这两个想法的组合：`super()` 是一种以编程方式访问当前类的父类 / 超类的方式，而 `__init__` 当然只是指那个类自己的初始化方法。"**

### 20.8 现在各司其职

> "但现在的好处是：**Wizard 作为一个类，负责所有'巫师名字'的赋值**——不管这个巫师是学生还是教授。**它甚至还做了一些错误检查**，确保 name 真的被传进来了。"

> "与此同时，**Student 继承了所有那些功能，并通过调用超类自己的 `__init__` 方法来使用它**。但它**额外**接收那个（ presumably 会传给 student 构造函数的）house，并把它赋给自己的实例变量 `self.house`。Professor 也类似，把传进来的 subject 存进 `self.subject`。"

## 21. 继承与异常：你一直在用的那个层级 [02:30]

### 21.1 异常也是继承

David 指出：我们刚刚才介绍继承，**但我们在使用异常的过程中其实一直在用它**。

如果你去看 Python **异常的官方文档**，你会发现：**不只是我们在课上见过的这些（比如 ValueError），还有很多别的异常**。而且**它们本身就是层级化的（hierarchical in nature）**。

官方的异常层级（这是 Python 内置异常的一个子集）：

```
BaseException
 +-- KeyboardInterrupt
 +-- Exception
      +-- ArithmeticError
      |    +-- ZeroDivisionError
      +-- AssertionError
      +-- AttributeError
      +-- EOFError
      +-- ImportError
      |    +-- ModuleNotFoundError
      +-- LookupError
      |    +-- KeyError
      +-- NameError
      +-- SyntaxError
      |    +-- IndentationError
      +-- ValueError
 ...
```

### 21.2 怎么读这张图

- 最底下有 `ValueError` —— 我们见得可多了
- **从它往上顺着线看**，你会发现 ValueError 有一个**父类 / 超类**叫 `Exception`
- 而 `Exception` 类又有一个父类叫 `BaseException`

（顺带一提，你在这一讲里已经见过里面的好几个了：`AttributeError` —— 在 `__add__` 演示里出现过；`NameError` —— 忘了 `import random` 时出现过；`SyntaxError` —— 引号套引号时出现过。`KeyboardInterrupt` 是用户按 Ctrl+C 时的异常，它在 `Exception` 之外，直接挂在 `BaseException` 下。）

### 21.3 Python 的作者为什么这么设计？

> "为什么 Python 的作者要这么做？"

> "因为事实是：**不管你遇到的是 ValueError 还是 KeyError 还是 AssertionError 还是其他任何一种，它们都有很多共通的功能，是你希望程序员能够使用的。**"

> "所以 Python 的作者们决定：'这么着吧，**我们不要搞出一打甚至更多的类，每个类里面都是复制粘贴来的相似功能**。让我们创建这个层级，这样即使靠近列表底部的那些异常非常精确，**它们起码也可以继承——也就是借用上面那些非常通用的功能。**'"

### 21.4 这对我们写代码意味着什么？

> "所以事实证明，当你在 Python 里使用 `try` 和 `except` 关键字时——**一般来说我们一直试图捕获非常具体的异常**，比如 `ValueError`。"

**但技术上，你也可以捕获某个异常的"父异常"甚至"祖父异常"**，尤其是：

- 你**不确定**会抛出哪一个的时候
- 或者更好：**可能会抛出很多种异常，但你想用同样的方式处理它们**，而你**不想在括号里用逗号把它们一个一个枚举出来**

> "你想说的是：你想**以大体相同的方式处理某个超类下的所有异常**。"

### 21.5 自定义异常的正确姿势

> "而且，**如果你要发明自己的异常，一般来说你不会想从零开始**。你会想**从这些已有的异常之一派生（descend）——也就是子类化（subclass）它**，然后加上你自己的变化、你自己的功能。"

这就回答了前面那个学生的问题：怎么造一个 `EricError`？——**继承一个已有的异常类**（通常是 `Exception` 或更具体的某个），而不是凭空造。

### 22.9 `__add__` 方法

查文档会发现，Python 的类有**这个以及很多别的特殊方法**。我们要看的第三个是：

```
__add__
```

文档里对它的描述**非常笼统**：**它适用于任何对象**，不管是一个 vault 还是一个 str 还是一个 list 还是别的什么。

**按约定，它：**

**含义：**

- **`self`** 实际上指的是**加号左边的那个对象**
- **`other`** 指的是**加号右边的那个对象**

> "这就给了我们一种方式，用代码描述**运算符左右两边的操作数（operand）**——中间是加号这个运算符。"

### 22.10 版本 4：实现 `__add__`

```python
class Vault:
    def __init__(self, galleons=0, sickles=0, knuts=0):
        self.galleons = galleons
        self.sickles = sickles
        self.knuts = knuts

    def __str__(self):
        return f"{self.galleons} Galleons, {self.sickles} Sickles, {self.knuts} Knuts"

    def __add__(self, other):
        galleons = self.galleons + other.galleons
        sickles = self.sickles + other.sickles
        knuts = self.knuts + other.knuts
        return Vault(galleons, sickles, knuts)


potter = Vault(100, 50, 25)
print(potter)

weasley = Vault(25, 50, 100)
print(weasley)

total = potter + weasley        # 现在能用了！
print(total)
```

**机制（David 讲得很细）：**

当你重载 `+` 这样的运算符时，Python 一看到它，就会**自动调用那个 `__add__` 方法**，并**传入两个参数**：

- **左边的操作数** —— 本例中是 `potter` → 传成 `self`
- **右边的操作数** —— 本例中是 `weasley` → 传成 `other`

> "这意味着我们可以在 `add` 的实现里这样访问它们的内容。"

- `self.galleons` = 本例中 Potter 金库里的 galleons
- `other.galleons` = 本例中 Weasley 金库里的 galleons

**最后必须返回一个新金库：**

> "但归根结底，我需要**返回一个全新的、更大的金库**，它装着所有这些加在一起的内容。而且，既然我们最终想把这个更大的金库赋给左边一个叫 `total` 的变量，我们**最好从这个 add 方法里 return 一个值**。"

所以我们 `return Vault(galleons, sickles, knuts)` —— 调用 Vault 构造函数，把三个和传进去。

运行：

```bash

```

## 本讲易错点

1. **以为 `return name, house` 返回了两个值。** 真相是返回了**一个 tuple**。所以你不能改它里面的元素。

2. **混淆"创建时"和"访问时"的括号。** 创建 list 用 `[]`、创建 tuple 用 `()`；但**访问元素的方括号 `x[0]` 对 list 和 tuple 是一模一样的**。

3. **试图修改 tuple：`student[1] = "Ravenclaw"` → `TypeError: 'tuple' object does not support item assignment`。** 想改就用 list。

4. **f-string 里的引号嵌套。** 外层双引号，内层就不能再用双引号：`f"{student["name"]}"` 会直接 `SyntaxError`（程序根本跑不起来）。内层改用单引号。

5. **忘了 `self`。** 类里的每个方法（包括 `__init__`、`__str__`、你自己写的）**第一个参数都是 `self`**，调用时你不用传，Python 自动传。同理 `@classmethod` 的第一个参数是 `cls`。

6. **以为 `__init__` 能"拒绝"创建对象。** 不能。对象在 `__init__` 被调用时**已经存在**了。所以 `return None` 没用，只能用 `raise` 报错。（真正造对象的是 `__new__`，但一般不用管。）

7. **在 `__init__` 里用了 `self._house = house`（带下划线）。** 这会**绕过 setter**，导致一点错误检查都没有。**只有 setter 函数体里才用 `_house`；`__init__` 里要用 `self.house = house`（不带下划线）**，这样才能触发 setter。

8. **属性名和 property 名撞车。** 有了 `@property def house` 之后，真正的实例变量必须改名（约定加前缀下划线 `_house`），否则 Python 会混淆。

9. **以为加了 `@property` 就安全了。** 不安全——`student._house = "xxx"` 依然能改。Python 没有真正的 private，**下划线只是"君子协定"（honor system）**，靠自觉。

10. **忘了 `import random`。** → `NameError: name 'random' is not defined`。用到库就要在文件顶部 import。

11. **以为有个 `@instancemethod` 装饰器。** 没有。**不写任何装饰器的方法，默认就是实例方法。**

12. **把 `super()` 写错。** 是 `super().__init__(name)`，不是 `super.__init__(name)`；而且传的参数个数要跟**父类的 `__init__` 签名**对上（本例中 Wizard 只收 name，所以只能传一个）。

13. **直接对自定义对象用 `+`。** 不实现 `__add__` 就会 `TypeError: unsupported operand type(s) for +: 'Vault' and 'Vault'`。

14. **`__add__` 忘了 return。** 那样 `total = potter + weasley` 会得到 `None`，因为运算符方法**必须返回**运算结果。

15. **以为 `print(对象)` 会输出内容。** 不定义 `__str__` 就会输出 `<__main__.Student object at 0x...>` 这种内存地址。
