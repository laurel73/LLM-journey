## 1. 什么是库、什么是模块 [00:00]

David 开场就给了定义：**库（library）一般来说就是别人写好的一批代码文件，你可以拿到自己的程序里用**；当然也可以是你自己写的代码——不只是给当前这个程序用，而是给下一个、再下一个程序用。

Python 对这个想法的支持方式，叫做**模块（module）**。在 Python 里，一个模块就是一个库，通常里面装了一个或多个函数，或者别的功能。

**那为什么要搞模块这种东西？核心动机是"复用（reusability）"。** David 给了一个特别好判断的信号：

> 如果你发现自己在反复用同一类函数、同一个功能；如果你发现自己一直在**从老项目里复制粘贴代码到新项目里**——那八成就存在一个机会：把这段你一直在复制粘贴、一直在重用的代码**抽出来（factor out）**，放进一个库里，以后每个程序只要把这个库加载进来就行。不用再复制粘贴，也不用让同一份代码在你的硬盘上散落十几个副本。

这一点其实非常实用。复制粘贴的坏处不只是"麻烦"：万一你后来发现那段代码有 bug，你得把十几个副本全改一遍；放进库里就只需要改一处。

## 2. random 模块：站在别人的肩膀上 [00:01]

### 2.1 Python 自带一大堆模块 [00:02]

Python 自带一个**字面意义上**就叫 `random`（随机）的库。意思是：当你在 Mac、PC 或者云端装好 Python 解释器（interpreter，解释器）的时候，你拿到的不只是一个 Python，你还同时拿到了**一大堆模块**。

这里有一个非常关键的区分，David 特意讲了：

- 像 `print`、`input` 这类函数是**默认就能用**的，它们在 Python 里直接生效。
- 但有些函数被"藏"在了模块里面，你必须**更主动一点**，明确地把它们加载进计算机的内存（memory）才能用。

所以，装完 Python 之后，在你硬盘上的某个地方，其实存在一个文件，名字大概就叫 `random.py`——它可能是某个人在很久以前写的，但你现在可以访问它。而在这个 `random.py` 文件里，有一个或多个函数，能帮你做各种"随机"的事。

**为什么要用别人的？** David 举了两个具体问题：程序里怎么抛硬币？怎么在 1 到 10 之间挑一个随机数？

你当然可以自己从数学上推导、自己写出这样的函数。但**站在前人的肩膀上（stand on the shoulders of others）要容易得多**——别人已经把这个问题解决了，你就可以把精力集中在你自己真正想解决的问题上。

> **怎么查文档？** 几乎所有 Python 模块的官方文档都在 Python 官方文档站上，每个模块有自己的文档地址，进去就能看到这个模块提供了哪些函数、哪些功能。本讲后面遇到的 `random`、`statistics`、`sys`、`json` 都可以这样查。

### 2.2 用 `import` 把模块加载进来 [00:03]

那么，到底怎么把一个模块加载进自己的程序、从而用上里面的函数？需要一个新的 Python 关键字（keyword）：**`import`**。

`import` 的作用就是：把某个模块里的函数内容导入到你的程序中。

David 先从文档里抄了一段函数说明过来，这个函数叫 `choice`（选择）。因为它存在于 `random` 模块里，所以文档里把它完整写成 **`random.choice`**——这就是技术上调用它的写法（不过我们马上会看到别的写法）。

括号里有一个参数叫 `seq`（S-E-Q），是 **sequence（序列）** 的缩写。序列一般指的就是一个列表（list），或者"像列表一样的东西"——比如一串数字、一串字符串，什么都行。

### 2.3 第一个程序：抛硬币 generate.py [00:05]

**为什么写这个程序？** 为了模拟抛硬币：美国的硬币有 heads（正面/人头）和 tails（反面/字），用途就是做一个 50/50 概率的决策。

先在终端（terminal，终端窗口）里输入：

```bash
$ code generate.py
```

> 说明：`code` 是 VS Code 提供的命令，意思是用 VS Code 打开（没有就新建）这个文件。`$` 是命令行提示符（prompt）的符号，代表"在这里输入命令"，你不需要自己打这个 `$`。

文件里写代码。第一版：

```python
import random  # 导入整个 random 模块，从而能用里面的所有函数

coin = random.choice(["heads", "tails"])  # 从列表里等概率随机挑一个
print(coin)
```

**逐句拆解这一行 `coin = random.choice(["heads", "tails"])`：**

- `random.choice` —— 调用 `random` 模块里的 `choice` 函数。注意：和以前我们自己定义的函数不同，这里**必须指明这个函数属于哪个模块**，所以要写 `random.` 前缀。
- `["heads", "tails"]` —— 传给 `choice` 的参数，是一个列表。
  - `"heads"` 和 `"tails"` 用双引号包着，因为它们是字符串（string）。用单引号也行，**只要前后一致**。
  - 中间有个逗号，表示这个列表有两个元素（element）。
  - 左右两端的方括号 `[]`，表示这确实是一个列表——这是 Python 定义列表的语法。
- 最外面还有一层圆括号 `()` —— 那是 `choice` 函数自己的括号，表示参数从这里传进去。

**`random.choice` 的行为**：吃进去一个列表，然后**等概率**地随机返回其中一个值。因为你传了两个元素，所以各有 50% 的概率；如果你传三个元素，那每个就是 33% 的概率，以此类推——**数学部分 Python 帮你算**。

最后把返回值存进变量 `coin`，再 `print` 出来看看结果。

### 2.4 演示现场：概率不是"交替出现" [00:07]

在终端里运行：

```bash
$ python generate.py
heads
```

再跑一次，又是 `heads`。David 还故意逗了一下观众：跑第三次会是什么？你是不是觉得有 bug？

结果第三次是 `tails`，然后再跑，`tails`、`tails`、`tails`、`tails`、`heads`……

**这里 David 特意强调了一个非常常见的误解**：概率不是"交替出现"的。如果你抛**无限多次**，结果确实会趋近 50/50；但如果只抛几次，结果完全可能看起来很不均匀——**概率本来就是这么工作的**。连着出 5 次反面，不代表程序错了。

### 2.5 `from ... import ...`：只导入你要的那个函数 [00:08]

`import random` 这种写法，技术上的含义是：**把这个模块里"所有东西"都导进来**——不只是 `random.choice`，还有好几个别的函数。

这带来一个"代价"：你之后每次调用函数都得写 `random.choice`、`random.这个`、`random.那个`，因为所有被调用的函数都必须和那个模块的作用域（scope，作用域）绑定在一起。

如果你就是想**直接用函数名** `choice` 来调用，也可以。把第一行换成：

```python
from random import choice  # 只把 choice 这一个函数导入当前命名空间

coin = choice(["heads", "tails"])  # 现在不用再写 random. 前缀了
print(coin)
```

**这行代码到底做了什么？** 它把 `choice` 这个函数名**加载进你当前的命名空间（namespace，命名空间）**，也就是加载进你当前这个文件的"作用域 / 本地词汇表"里。这样一来，你就不需要再指明"我要的是哪个 `choice`"，直接写 `choice` 就行。代码更短、更好读。

### 2.6 学生提问：什么时候该用哪种写法？ [00:10]

David 抛给观众一个问题：什么情况下你会想用 `from ... import` 这种显式导入名字的写法，而不是一路写 `random.choice`？

**学生（Mohammed Omar，来自埃及）回答**：如果我自己有一个变量就叫 `choice`，我就得区分清楚我用的到底是哪个 `choice`，所以我可能会选 `random.choice` 这种写法。

David 说这个直觉非常好，并且展开解释了背后的大道理：

- **用 `import random`（第一种写法）的好处**：模块里的所有内容都和 `random` 这个模块绑定 / 限定在 `random` 的作用域里。于是你**可以有你自己的 `choice` 函数，也可以有你自己的 `choice` 变量**，跟模块里那些名字撞了也没关系，**不会冲突（collide，碰撞）**。这是件好事。
- **历史背景**：在一些更老的语言里，如果你导入了某个人的库，你最好祈祷你没有跟他们用同样的函数名或变量名，否则**真的可能发生冲突**。Python 和某些其他语言允许你把这些函数和变量的名字"限定在它们所属的文件 / 模块里"，这就避免了冲突。

**那 `from` 写法什么时候更好？** David 的实话是：像这种特别短的程序，或者你在代码里要调用 `choice` 几十次，`random.choice`、`random.choice`、`random.choice` 一路写下去，代码就越写越长、越写越丑、越写越烦。这时候直接 `import choice` 能把代码收紧一点。

**结论（David 的原话态度）**：跟以往很多决定一样，**没有唯一正确答案，看情况（it depends）**。但出于上面那些理由，他个人**更倾向于第一种**：只导入模块本身，从而保留模块的作用域。

> 这一条是本讲第一个"经验值"，值得记住：**默认写 `import 模块名`，除非你有明确理由才用 `from 模块名 import 函数名`。**

### 2.7 `random.randint(a, b)`：随机整数 [00:12]

`random` 模块里还有个函数叫 **`randint`**（读起来有点拗口），意思就是"给我一个随机的 int（integer，整数）"。

看文档会知道：它返回一个 **a 到 b 之间（含两端，inclusive）** 的随机整数。也就是说传 `1` 和 `10`，你会拿到 1 到 10 之间的数，**1 和 10 本身也可能被取到**，每个数的概率都是 10%。

把 `generate.py` 底部的两行删掉，保留 `import random`，改成：

```python
import random

number = random.randint(1, 10)  # 1 到 10，包含 1 和 10
print(number)
```

运行几次：

```bash
$ python generate.py
4
$ python generate.py
8
```

再跑：9、7、10、2……David 说"我们能玩一整天"，如果把这些结果统计起来，每个数字出现的概率应该都趋向 10%。

**这有什么用？** 比如做一个猜数字游戏，或者给游戏里的角色加点随机行为。用这种非常简单的积木，就能让你的程序**不那么可预测**、更有变化；而具体怎么生成这些随机数，你完全交给 Python 自己的算法和数学去完成。

### 2.8 `random.shuffle(x)`：原地洗牌 [00:15]

第三个函数是 **`shuffle`**（洗牌）。文档说它接收一个列表，然后**把里面打乱**，就像洗一副扑克牌。

```python
import random

cards = ["jack", "queen", "king"]  # 不需要 52 张，三张就够演示
random.shuffle(cards)              # 注意：没有返回值，是直接改 cards 本身
for card in cards:
    print(card)
```

**这里有个非常重要的坑，David 特意强调了：**

> `random.shuffle` 是**"原地（in place）"**打乱的。它**不像**我们见过的大多数函数那样"返回一个值"——它不返回打乱后的牌，而是**直接把它收到的那个列表本身改掉**。

所以正确的用法是：`random.shuffle(cards)`，**不要**写成 `cards = random.shuffle(cards)`（那样 `cards` 会变成 `None`，因为函数没返回值）。

**为什么用 `for` 循环打印，而不是直接 `print(cards)`？** David 解释：如果直接 `print(cards)`，你会看到 Python 自己的列表语法，用逗号之类的符号格式化出来；他觉得一张一张打印看起来更好，所以用上了之前学过的循环：

```python
for card in cards:
    print(card)
```

**执行顺序**：第 3 行定义三张牌，按 jack、queen、king 的顺序；第 4 行把它们洗掉；第 5-6 行用 `for` 循环，每次取出一张打印出来，因为用的是 `print`，所以是一行一张。

### 2.9 演示现场：只有三张牌，"洗了跟没洗一样" [00:17]

运行结果：

```bash
$ python generate.py
queen
king
jack
```

看起来洗了，因为顺序跟定义时不一样。再跑一次：queen、king、jack——**又是这个顺序**。

再跑：jack、queen、king（看起来没洗）；再跑：jack、queen、king（还是没洗）；再跑：jack、queen、king……David 吐槽："这人打牌你肯定愿意跟他玩。"终于跑出一次 queen、jack、king。

**这里的点跟抛硬币那个点一模一样**：只有三张牌，总共就没多少种排列（permutation），所以你经常看到"洗完跟原顺序一样"。跑的次数够多，你总会看到所有排列；如果用的是 13 张甚至 52 张牌，能看到的排列就多得多了。

至此我们有了三种产生随机信息的方式：抛硬币、取 1 到 10 的随机数、把一个列表洗乱。

### 2.10 学生提问：能不能调整概率？ [00:19]

**学生问**：能不能提高或降低某些牌出现的概率？比如现在三张牌，每张 33%，能不能让某张更常见？

**David 回答**：用**这几个**函数做不到。但这些函数本来就被设计得非常"用户友好"、非常简单，给你的就是**等概率**。要倾斜概率，你当然可以：

- 自己实现一些函数，或者

他还顺口开了个玩笑：如果你在做赌博游戏，希望你别真的让某些牌比其他牌更容易出现。

## 3. statistics 模块：求平均值 [00:20]

除了随机，Python 还自带一个 **`statistics`**（统计）库，里面全是做统计类计算的函数：**算平均值（mean）、中位数（median）、众数（mode）**，或者分析数据集的其他方面。

先在终端新建文件：

```bash
$ code average.py
```

代码：

```python
import statistics  # 这次导入的是另一个模块

print(statistics.mean([100, 90]))  # mean 接收一个值的列表，返回平均值
```

**讲解逻辑**：David 拿"算成绩平均分"当例子——第一次考试考了 100 分，第二次考得也不错但没那么好，90 分。他自嘲数学不好，所以想让程序帮他算平均。

- `statistics.mean(...)` —— `mean` 是 `statistics` 模块里的函数，所以要写 `statistics.` 前缀。
- `[100, 90]` —— 传进去的是一个包含两个值（两个 int）的列表。
- 因为这个 `mean` 函数的返回值要交给 `print`，所以外面再套一层 `print(...)`。

运行：

```bash
$ python average.py
95
```

平均是 95 分。

**注意这里的重点**：跟 `random` 那边的区别只是"换了一个模块"——`statistics` 同样是 Python 自带的，但**你得自己 `import` 它**。而且你需要从文档里知道：这个模块里存在一个叫 `mean` 的函数。

## 4. 命令行参数（Command-Line Arguments）[00:21]

### 4.1 为什么需要它 [00:22]

到目前为止，我们程序里用到的所有值，都是**写在程序里的**，或者是运行时用 `input()` 提示用户输入。

但如果想在**命令行**上接收输入呢？David 举的例子特别直观：与其运行 `python average.py`，然后程序里写死 100 和 90；不如直接运行：

```bash
$ python average.py 100 90
```

然后程序自动算出 100 和 90 的平均数。

**命令行参数**这个功能不限于 Python，很多语言都有。它的含义是：你可以在**执行命令的同时**就把参数（也就是输入）提供给程序，而不用等程序启动后再一句一句 `input()` 提示你。

回顾一下：我们一直都是敲 `python 某某.py`，比如 `python hello.py`，从没在文件名后面加过任何词。但其实**在命令行环境里，你可以在你要执行的命令后面跟任意多个词、数字或短语**，这些全都会以某种方式作为输入传给程序本身。

### 4.2 `sys` 模块与 `sys.argv` [00:23]

要用这个功能，需要一个新的模块，名字叫 **`sys`**（system 的缩写，系统）。`sys` 里装了大量跟"系统本身"以及"你我正在敲的命令"相关的功能。

我们需要关注的是其中的**一个变量**：**`argv`**。

- `argv` 是 **argument vector（参数向量）** 的缩写，这是个很花哨的说法，实际意思就是：**人在提示符后面、按回车之前敲下的所有单词组成的列表**。
- 这些词会**像变魔术一样**，由 Python 通过一个叫 `sys.argv` 的变量提供给你。

**`sys.argv` 是一个列表（list）**：第一个元素是你敲的第一个词，第二个元素是第二个词，以此类推。通过这个列表，你就能搞清楚"人到底在提示符后面敲了什么"，并据此改变你自己程序的行为。

新建文件：

```bash
$ code name.py
```

第一版代码：

```python
import sys

print("hello, my name is", sys.argv[1])
```

**设计意图**：以前写"Hello World"程序，都是靠 `input()` 的返回值来知道用户叫什么，让程序打印出来。这次换个思路——**要求用户在运行程序的那一刻就把名字告诉我们**。

现实场景：在美国，大家很习惯在衣服上贴一张贴纸，写着 "Hello, my name is David"。David 想打印出类似这样的文字（也许以后能增强成直接送去打印机，动态生成名牌）。

代码说明：

- `print("hello, my name is", ...)` —— 打印 "hello, my name is"，后面再跟点东西。
- 以前我们会在后面接 `input()` 的返回值；这次直接写 **`sys.argv[1]`**。
- `argv` 是列表，所以中用方括号 `[]` 取其内部元素——这是之前学循环和列表时学过的语法。

运行方式（注意这次文件名后面有东西）：

```bash
$ python name.py David
hello, my name is David
```

### 4.3 `sys.argv[0]` 到底是什么？ [00:25]

只看这个演示，其实已经能推断出 `sys.argv` 的机制了：我访问的是 `sys.argv[1]`，而 `David` 就存在那里。

但等等——**为什么是 1**？以前讲循环和列表时明明说过：列表是**从 0 开始编号（zero-indexed）**的，第一个元素是 0，第二个是 1，第三个是 2……

那么问题是：**`sys.argv[0]` 里装的是什么？**

**学生回答**："我觉得就像 C 语言里一样，是程序的名字。"

**David 确认**：对，跟 C 语言一样，**是程序的名字**。我们来想想我到底敲了什么：

- 我确实敲了 `python`，因为那是解释器的名字——不过这个我们不需要知道，因为我们用的就是 Python 本身。
- 在那之后，我敲了两样东西：`name.py`（跟以往一样，想让 Python 解释器去执行我写的程序）和 `David`。

**按约定，Python 会把"你正在执行 / 解释的那个文件的名字"存进 `sys.argv`，后面再跟着你敲的任意多个词。**

也就是说，`sys.argv` 的内容是：`["name.py", "David"]`。所以：

- `sys.argv[0]` → `"name.py"`（程序自己的文件名，说实话不太有意思）
- `sys.argv[1]` → `"David"`（我们真正想要的）

### 4.4 翻车现场一：IndexError [00:29]

但是——**如果我什么都没敲呢？** David 说自己这么写其实挺天真（naive）的，因为它默认假设 `sys.argv` 的位置 1 上永远有东西。

试一下：

```bash
$ python name.py
```

（我没告诉你我的名字，因为我压根不知道你要我敲名字。）

回车之后——**报错了**：

```
IndexError: list index out of range
```

这是一个新的异常（exception，异常）：**`IndexError`（索引错误）**，详细信息是 **list index out of range（列表索引超出范围）**。

**David 强调**：这其实是编程里最常见的错误之一——不管你用的是 Python 的列表，还是别的语言里的数组（array）或向量（vector），错误本质都一样：**你试图访问一个并不存在的元素**，你在这个"就是一串值的对象"里往左走得太远，或者往右走得太远了。

这里的具体错误是：我假设位置 1 上有东西，但实际上只有位置 0 上有值。

**然后 David 演示了一个"错误修法"**：既然位置 1 没有，那改成 `[0]` 不就行了？

不行——如果改成 `sys.argv[0]`，再不带参数运行，程序会输出：

```
hello, my name is name.py
```

这在给"程序自己"做名牌的情况下倒是没错，但显然不是我们的目的。

**所以正确的问法是**：把 1 改成 0 并不是修复，那该怎么处理这个错误？怎么处理用户**忘了**或者**根本不知道**要在提示符后面敲名字时出现的 `IndexError`？

### 4.5 修法一：`try` / `except` 捕获异常 [00:31]

**学生回答**："我们可以在程序里加个异常处理：如果位置 1 上什么都没有，就直说'我们没有拿到参数'之类的；如果有，就继续往下跑。"

**David 总结并补充了一个重要的学习观**：

> 简言之：**试着执行这行代码，除非（except）出错了，那我们就用别的方式处理。**
> 理想情况下，等我成为足够强的程序员，我**一开始就该预见**到这个问题，并且从写下第一行代码起就写成下面这样。但在**学习阶段**，先看到错误、再"哦，原来我该检测这个"、然后回头改进代码，这**完全合理**。
> 当然，如果你读文档，把过去学到的教训内化，你会慢慢养成习惯，主动去 try、主动去检查这些异常。

第一版修复：

```python
import sys

try:
    print("hello, my name is", sys.argv[1])
except IndexError:
    print("Too few arguments")
```

意思是：**尝试**打印 "hello, my name is" 加 `sys.argv[1]`；**除非**出现了 `IndexError`，那就打印 "Too few arguments"（参数太少）。

运行：

```bash
$ python name.py
Too few arguments
$ python name.py David
hello, my name is David
```

**David 点评**：这个提示信息本来可以写得更详细，但至少——用户不会看到一个晦涩的报错，然后以为是自己把程序搞坏了。虽然名牌还是生成不出来，但用户体验好多了。

### 4.6 修法二：主动检查长度（更防御式） [00:33]

但 David 接着说：**严格来说，我们不必非得 try/except，我们可以写得更"防御"（defensive）一点**——直接检查用户到底有没有提供名字、是不是提供了多个名字，从而给出**更精细的错误提示**。

于是他把 `try/except` 撤掉，改成条件判断：

```python
import sys

if len(sys.argv) < 2:          # 少于 2 个：只有文件名，没名字
    print("Too few arguments")
elif len(sys.argv) > 2:        # 多于 2 个：敲了太多词
    print("Too many arguments")
else:                          # 正好 2 个：文件名 + 人名
    print("hello, my name is", sys.argv[1])
```

**为什么是 2？** David 解释得很清楚：我最终想要的是**两个参数**——位置 0 上是程序的名字，位置 1 上是人的名字，加起来正好 2 个。

（顺带一提：`len(sys.argv) < 2` 也可以等价地写成 `len(sys.argv) == 1`，David 说他选 `< 2` 只是因为他想保留这种写法。）

### 4.7 翻车现场二：SyntaxError（我的错，不是用户的错） [00:35]

现在来跑一下：

```bash
$ python name.py
```

结果——**又是报错，但是完全不同的类型**：

```
SyntaxError: invalid syntax
```

**`SyntaxError`（语法错误）**，我们以前见过。David 的原话是 "**mea culpa**"（拉丁语，我的过错）——这是**我把代码写错了**，我写出了无效的语法（invalid syntax）。

**关键区别，务必记住：**

> **语法错误是"我的错"**——程序根本没跑起来，所以**再多的条件判断、再多的异常处理也抓不住它**。你只能回去把程序改对。

David 往上看：问题在第 4 行。确实，那里有个**未终止的字符串（unterminated string）**——他写 `print("Too few arguments")` 时漏掉了收尾的双引号。补上这个引号就好了。

（这是一个很好的真实示范：讲师也会手滑漏引号。区别在于，语法错误 Python 会直接告诉你行号，而且它属于"必须修"，不是"可以兜底"。）

修好之后重新运行：

```bash
$ python name.py
Too few arguments
$ python name.py David Malan
Too many arguments
$ python name.py David
hello, my name is David
```

**设计上的收获（David 明确强调）**：

> 严格来说，只要我们聪明一点、先检查，就**不一定非要用异常处理**——尤其是当我们想给用户**更精细的建议**时。
> 我们不想只告诉用户"不，出错了"，也不想直接 `pass` 掉；我们想说的是"不，你给少了"或者"不，你给多了"。而**条件（conditional）**已经在我们已有的词汇量里了，我们可以直接用它表达这些。

### 4.8 学生提问：能不能有多个 `else`？全名怎么输？ [00:37]

**问题 A**："能不能用多个 `else` 语句？"

**David**：**不能。** `else` 是最后那个**兜底（catchall）**语句，只能有一个；中间可以有很多个 `elif`，但不能有多个 `else`。

**问题 B**："你刚才提到输全名。以后如果用户想输全名、又有人只想输名，有没有办法区分'这个人是全名'和'这个人只有一个名字'？"

**David**：绝对可以，而且**现在就能支持全名**，方法是——**加引号**：

```bash
$ python name.py "David Malan"
```

**原理**：按 `argv` 的定义，每个词会占据列表里的一个固定位置，所以 `python name.py David Malan` 会被拆成三个参数（`name.py`、`David`、`Malan`），于是报 "too many arguments"。但如果我在命令行上加上引号（单引号双引号都行），Python 就会把它看作**一共两样东西**：文件名，和这个完整的名字。回车后你不会看到引号，整个字符串会作为一个整体传进来。

### 4.9 改进：把错误处理独立出来 [00:38]

现在这个版本逻辑上是对的，但 David 说有件事他不喜欢：

> **我这个程序的本质——就是打印名牌——被塞进了 `else` 分支里。** 逻辑上没错，但一般来说，把**错误处理**和你**真正在乎的代码**分开，是一件很舒服的事：顶部放一堆 `if`/`elif` 检查数据是否符合预期，**然后把真正在乎的代码放在外面**，而不是藏在 `else` 里面。

他想要的理想结构（伪代码）：

```python
# 上面：检查错误
# 下面（左对齐，独立的一块）：打印名牌
```

于是他把代码改成：

```python
import sys

if len(sys.argv) < 2:
    print("Too few arguments")
elif len(sys.argv) > 2:
    print("Too many arguments")

print("hello, my name is", sys.argv[1])   # 注意：这行不再缩进，也不在 else 里
```

**然后 David 问了一个关键问题：我这样改，引入了什么 bug？**

**学生回答**："Name error."

**David 接梗**：巧了，确实跟"名字（name）"有关，但不是 `NameError` 那个异常——是我自己名字的问题（笑）。

**真正的 bug 是**：虽然我在上面检查了 `len(sys.argv)` 小于 2，也检查了大于 2，但**往下走到最后一行时，我仍然是盲目地假设 `sys.argv[1]` 一定存在**。

实际后果：运行 `python name.py`（不带参数）时，终端顶部会先打印我的提示 "Too few arguments"，**然后还是会在第 10 行盲目地去索引列表的位置 1——而那里并不存在**，于是异常照样抛出。

**也就是说：光"打印"错误提示不够，程序还会继续往下跑，然后崩。**

### 4.10 正解：`sys.exit()` 提前退出 [00:40]

**正确的思路是**：如果你在用 Python 写一个"跑一下就结束"的程序，那么当程序**根本没法继续**的时候——用户没给我们想要的数据——我们**干脆提前退出（exit prematurely）**就好了。

`sys` 模块里正好还有一个函数能干这事：**`sys.exit`**。

最终版：

```python
import sys

if len(sys.argv) < 2:
    sys.exit("Too few arguments")     # 打印这句话，然后立刻退出程序
elif len(sys.argv) > 2:
    sys.exit("Too many arguments")    # 同上

print("hello, my name is", sys.argv[1])  # 能走到这里，说明参数一定合法
```

**为什么这样就安全了？**

- 如果用户给的参数太少，我没什么好对他说的了，那就**当场在第 4 行退出**。
- 参数太多也一样，在第 6 行打印提示并退出。
- 于是**走到第 8 行时，所有错误情况都已经被排除**，我可以放心地假设 `sys.argv[1]` 确实存在。

运行验证：

```bash
$ python name.py
Too few arguments
$ python name.py David Malan
Too many arguments
$ python name.py David
hello, my name is David
```

**注意观察**：前两种情况打印完提示就**回到了命令提示符**，没有再发生任何事——这正是 `sys.exit` 的效果。

**关于 `sys.exit` 的两个补充：**

1. 如果传一个**字符串**给它，它会**把这个字符串打印出来，然后就地在那里退出程序**。
2. David 特意澄清：其实**所有 Python 程序跑到底部时都会自动退出**。我们现在用 `sys.exit`，只是为了确保**比原本更早**地退出。

**现在 `sys` 给了我们两种能力**：`sys.argv`（参数向量，给出提示符后面敲的所有词，包括程序自己的文件名）和 `sys.exit`（提前退出程序）。

### 4.11 学生提问：能不能一次取多个位置？ [00:42]

**学生问**：`argv` 能不能一次接受多个元素？比如在命令行敲 `python name.py David Malan 男 20岁`，我只想取名字（第 1 个位置）和年龄（比如第 6 个位置），我能不能分别用 `sys.argv[1]` 和 `sys.argv[6]` 去取？

**David 回答**：简短地说——**可以**。你确实可以在命令后面敲很多词，然后按位置访问任意一个。

**但他立刻给了一个"但是"**：这样写会变得很**脆弱（fragile）**。如果你在提示符后面敲了太多词，**顺序就变得极其重要**，用户稍微记错顺序，程序就废了。

**更好的方向**：现实中有很多程序（Python 里也有相应功能）允许你**按任意顺序**提供这些值——比如名字、年龄或其他任何字段——方法是**在文本里多传一点信息**，告诉程序你想怎么用这些值。（这就是后面会遇到的"命令行参数解析"，本讲先埋个伏笔。）

## 5. `slice` 切片 [00:43]

### 5.1 遍历 `sys.argv`：一次生成多个名牌 [00:43]

接着上面那个问题，David 说："让我先做一个小规模的演示。"

现在的需求变了：**不再有"参数太多"这回事**——我想一次生成多个人的名牌，比如 David、Carter、Rongxin 都要。

于是他把 `elif` 分支删掉（不再限制参数个数的上限），改成遍历提示符后面的每个名字：

```python
import sys

if len(sys.argv) < 2:
    sys.exit("Too few arguments")

for arg in sys.argv:
    print("hello, my name is", arg)
```

**代码解释（David 逐句讲）：**

- 语法跟以前的循环有点不同，但思想一样：**用 `for` 循环遍历一个列表**，这里的列表就是 `sys.argv`。
- `arg` 是**我随手创建的一个变量**：第一次进循环，Python 会保证 `arg` 等于命令行上的第一个词；第二次进循环，`arg` 就变成命令行上的第二个词；以此类推——**`for` 循环会自动帮我们更新这个变量**。
- `arg` 不是必须叫这个名字，叫 `name` 也行，只要两个地方都改。但既然遍历的是"参数（argument）"，叫 `arg` 挺合理。

### 5.2 翻车现场三：多打印了一张名牌 [00:44]

跑一下：

```bash
$ python name.py David Carter Rongxin
```

**会有什么 bug？** 我们想要的明明是 3 张名牌，结果会打印 **4 张**——因为 `sys.argv` 里其实有 4 个元素，第一个是**程序自己的文件名**：

```
hello, my name is name.py     ← 多出来的这张
hello, my name is David
hello, my name is Carter
hello, my name is Rongxin
```

David 的吐槽：也许不算大事，反正名牌够多，浪费一张而已；但**这确实是浪费，而且看起来就是错的**。

**那怎么办？** 我们想要的不是 `argv` 的全部 4 个元素，而是**它的一个切片（slice）**。

> **切片是 Python（以及其他一些语言）里的一个术语**：对一个列表"取切片"，意思就是**取它的一个子集（subset）**——也许从开头取，也许从中间取，也许从结尾取。总之，切片就是列表这类数据结构的一部分。

### 5.3 切片语法：`sys.argv[1:]` [00:45]

在 Python 里取切片非常简单：**在列表名字后面用方括号，括号里指定你想保留的起点和终点。**

```python
import sys

if len(sys.argv) < 2:
    sys.exit("Too few arguments")

for arg in sys.argv[1:]:        # 从位置 1 开始，一直取到结尾
    print("hello, my name is", arg)
```

**语法拆解：**

- 我想**从元素 1 开始**，而不是 0，所以写 `1`。
- 我想**一直取到最后**，所以**第二个数字直接省略**——不写第二个数字也没关系。
- 但**冒号 `:` 必须写**，因为正是这个冒号告诉 Python "我要一个切片"。
- `1:` 的效果等价于：**切掉列表的第一个元素，返回一个新列表**，里面只有那三个人名，没有文件名。

再跑一次：

```bash
$ python name.py David Carter Rongxin
hello, my name is David
hello, my name is Carter
hello, my name is Rongxin
```

正好三个。

**总结（David 原话）**：用 Python 里相对简单的语法，方括号不只是用来取具体某个元素（`[0]`、`[1]`），也可以用来**取列表的子集 / 切片**，写法是 `[某数:某数]`；这两个数字分别是起点和终点，**而且它们都是可选的**，取决于你想要全部还是只要一部分。

### 5.4 学生提问：能不能从末尾开始切？ [00:47]

**学生问**：能不能从参数向量的**末尾**开始切？

**David**：可以，而且这个答案可能有点"烧脑"——用**负数**：

```python
for arg in sys.argv[1:-1]:      # 从位置 1 开始，到倒数第 1 个之前结束
    print("hello, my name is", arg)
```

用同样的命令跑，效果是——**Rongxin 被"取消邀请"了**，拿不到名牌了。

**原理**：如果用负数，它的含义就是**从列表末尾往回数**。所以 `-1` 表示"最后一个"，`[1:-1]` 就是"从第二个元素开始，一直取到最后一个之前"。

### 5.5 学生提问：切片的冒号和 f-string 里的冒号是一回事吗？ [00:48]

**学生问**：我记得很早的时候讲过让浮点数只显示两位小数，用的是 `0.2f` 这种写法，里面也有个 `f`；这跟切片是不是一回事？为什么那个地方要写 `f`，而这里只有数字？

**David**：非常好的问题。简短的回答是——**上下文决定含义（context matters）**。

- 键盘上的按键就那么多，所以**同一个符号在不同场景里有不同含义**，这是常有的事。
- 你说的 `f` 属于 **f-string 里的格式码（format code）**：在 f-string 里用冒号、点号、数字和字母 `f` 来格式化一个数字。那是 **Python 的 f-string 这个特性独有的**。
- 而**这里**的冒号**跟那套语法毫无关系**——这只是"在另一个上下文里用冒号来实现切片"。Python 的作者当初完全可能选另一个符号，但说实话，低头看看键盘，容易敲的符号也没几个可选，所以有时候同一个符号就是会承担不同的含义。

## 6. 包（Packages）与 `pip` [00:49]

### 6.1 为什么 Python 这么火：第三方库 [00:49]

到目前为止，我们用的都是 **Python 自带**的模块（随解释器一起装好的）。现在把视野放大到更一般的**包（package）**。

Python 现在这么流行、这么强大，一大原因就是：**外面存在大量第三方库（third-party libraries）**。

**术语辨析（David 特意讲）：**

- 严格来说，Python 里有个术语叫"包"，指的是**用一个文件夹（folder）而不是单个文件实现的模块**。
- 但更一般地，"包"指的就是**第三方库**——你可以把它装到自己的 Mac、PC 或云服务器上，从而获得别人实现的更多功能。

**去哪儿找？** 有个网站叫 **PyPI（Python Package Index，Python 包索引）**。它是一个可以通过命令行、也可以通过网页搜索的仓库（repository）/ 目录（directory），能让你下载安装各种各样的包。（David 顺口提了一句：连 CS50 自己也有一些包放在这类服务上。）

### 6.2 示例包：`cowsay` [00:50]

举个好玩的例子：**`cowsay`**。这是命令行环境里一个历史悠久的老程序，Python 版的 `cowsay` 包能**让一头牛在屏幕上"说话"**。

它本质上是 **ASCII art（ASCII 艺术）**——只用键盘上的字符，在屏幕上"画"出图形来。David 还补了一刀：在 emoji、GIF、JPEG、PNG 出现之前，我们只有 ASCII art 可用，而 `cowsay` 让它永垂不朽。

### 6.3 `pip`：包管理器 [00:51]

技术上讲，你可以自己去下载文件、解压、再放到 Mac 或 PC 上正确的位置。但现在很多语言（Python 就是其中之一）都有自己的**包管理器（package manager）**，Python 的这个叫 **`pip`**。

`pip` 是一个程序（现在一般随 Python 一起安装），作用是：**你只要跑一条命令，它就能把包装到你的 Mac、PC 或云环境里**。然后"哗"的一下，你就有了一个全新的、Python 原本没自带的库可用。

在终端里执行：

```bash
$ pip install cowsay
```

**命令拆解：`pip` 是命令（包管理器），`install` 是要做的事，`cowsay` 是要安装的包名。** 回车后，输出一些信息，最后告诉你 successfully installed（安装成功）。

### 6.4 用 `cowsay` 写程序 say.py [00:52]

```bash
$ code say.py
```

```python
import cowsay
import sys

if len(sys.argv) == 2:
    cowsay.cow("hello, " + sys.argv[1])
```

**代码讲解：**

- `import cowsay` —— 导入刚装好的包。
- `import sys` —— 因为我还想用命令行参数，这样不用 `input()` 就能立刻拿到用户的名字。
- 这次**主动做错误检查**，但不用"小于/大于"了，直接写：**`if len(sys.argv) == 2`** ——也就是"人只提供了程序名 + 他自己的名字"时才继续。
- `cowsay.cow(...)` —— 调用 `cowsay` 包里的 `cow` 函数。
- 参数只能用**一个字符串**：按它的文档，这个函数不像 `print`，不能传"逗号这个、逗号那个"多个参数，**只能传一个字符串**。所以要先用**字符串拼接（concatenation，拼接）**把 `"hello, "` 和 `sys.argv[1]` 用 `+` 连起来。

运行（David 还特意清屏、把终端窗口调大）：

```bash

         \  (oo)\_______
            (__)\       )\/\

                ||     ||
```

**再改成霸王龙**：`cowsay` 包里还有别的函数，比如 `trex`：

```python
import cowsay

    cowsay.trex("hello, " + sys.argv[1])
```

**David 还演示了一个细节**：先不带参数运行 `python say.py`——**什么都没发生，但也没崩**。为什么？因为我们有那个 `if len(sys.argv) == 2` 条件，**只有等于 2 的时候才做任何事**。这就是提前做错误检查的价值。

然后配合一次：`python say.py David`，屏幕上的不再是牛，而是一只霸王龙（要缩小屏幕才看得全）。

### 6.5 学生提问：跟 Java 比怎么样？命令行参数到底有啥用？ [00:56]

**问题 A**："我们在程序里调用的包，跟 Java 里调用一个 class（类）、一个 Java 文件来用它的函数，是一回事吗？"

**David**：问得很好。**Python 的包类似于 Java 的包**——你在程序顶部写"什么点什么点什么"，从而获得对某个类或其他东西的访问权。Python 本身也支持类（class），这个以后会讲；你在 Python 里能做的事，跟在 Java 里能做的非常相似。这里真正的对应关系就是：**Python 的包 ↔ Java 的包**。

**问题 B**："用命令行参数的**实际目的**是什么？你说它对用户不太友好——用程序的人可能根本不知道程序想要什么。"

**David** 承认这问题问得好，也承认命令行参数**对不在课堂上的普通人确实不那么友好**，但他给出了明确的回答：**效率（productivity）**。

- 随着我们学得越多、对命令行参数越熟，我们会越来越习惯、也会**越来越倾向于**用命令行参数来定制命令。为什么？**因为它让你更快**——你会养成习惯，清楚地知道怎么配置软件，而不用每次手动回答一堆问题。

- **自动化（automation）是大事**：如果你学完这门课后要用 Python 去自动化工作流程、或者做个人项目，**能在一行里把所有输入都指定完，就意味着你能更快地把活干完**。所以答案是：绝对值得。

**David 的补充观点**：命令行参数确实属于系统里比较"古老 / 冷门（arcane）"的特性，因为我们大多数人现在都习惯了 Windows 和 macOS 那种有按钮、图形界面（GUI）和菜单的操作系统，不再熟悉命令行。但**你对编程越熟练，你就越会倾向于使用这些能力，因为它们让你做事更快**。

## 7. API 与 `requests` [00:59]

### 7.1 什么是 API [00:59]

接下来讲另一个包，它非常流行，安装也一样简单，目的是**使用 API**。

**API 不是 Python 特有的概念。** 一般来说，**API = application programming interface（应用程序编程接口）**。它可以指 Python 的文件和函数，但如今 API 更多指的是**第三方服务**——你我可以写代码去跟它们对话。

**很多（但不是全部）API 都活在互联网上**。这意味着：只要你有浏览器，或者你有一点 Python / 任何语言的编程经验，你就可以写一段代码，**假装自己是一个浏览器**，连到服务器上那个第三方 API，**下载一些数据**，然后把它整合进你自己的程序。

### 7.2 `requests` 包 [01:00]

Python 里有个非常流行的包叫 **`requests`**，用 `pip` 安装。它的作用是：**用 Python 代码发起 web 请求 / 网络请求，本质上就像你自己是个浏览器**。于是你可以**自动化地**去获取那些以 `http` 或 `https` 开头的 URL。

安装：

```bash
$ pip install requests
```

输出若干行之后，你会看到 successfully installed。

**David 又强调了一遍 Python 流行的原因**：它是第三方包，但却是最流行、最常用的包之一；Python 之所以火，就是因为**你和我在做项目时遇到的、将来一定会遇到的问题，外面几乎都有现成的解决方案**。这是一个非常活跃的生态、非常活跃的开源社区，而且装起来就是这么容易。

### 7.3 Apple iTunes 的 API 与 URL 构造 [01:01]

Apple 的 iTunes 服务有自己的 API。

先在浏览器（比如 Chrome）里访问这个 URL：

```
https://itunes.apple.com/search?entity=song&limit=1&term=weezer
```

**这个 URL 是怎么来的？** David 是**读了 Apple 的 iTunes API 文档**之后手动拼出来的。文档告诉他：

- `entity=song` —— 我想搜的是他们数据库里的**歌曲**信息，不是专辑（album）、不是艺人（artist）。
- `limit=1` —— 我只想拿回**一首**歌的信息。
- `term=weezer` —— 我想搜的乐队 / 艺人是 **Weezer**。

回车访问后，浏览器会下载一个**文本文件**（在 Mac 上会进 Downloads 文件夹）。打开它，会看到一大堆文字。

### 7.4 浏览器里看到的到底是什么：JSON [01:02]

第一眼看上去这片文字有点晦涩，但**它是有规律的**：

- 开头有个**花括号 `{`**，结尾有个闭合的花括号 `}`。
- 中间有个**方括号 `[`** 和对应的闭合方括号 `]`。
- 在这些语法符号之间，是一大堆字符串和值——准确说，是**一大堆键值对（key-value pairs）**。

**这就是 JSON：JavaScript Object Notation。** 是的，它技术上跟另一种叫 JavaScript 的编程语言有关；但如今 JSON 通常被用作一种**与语言无关（language agnostic）**的数据交换格式。

"与语言无关"的意思是：**你不必用 JavaScript**——你可以用 Python 或任何其他语言来读 JSON、写 JSON。而且它是**完全基于文本（text-based）**的格式，所以用浏览器访问那个 URL 时，下载下来的就是一堆文本；只是这些文本**按标准方式**组织：用花括号、方括号、引号和冒号，最终装满了 Apple 数据库里关于 Weezer 歌曲的全部信息（至少是第一首，因为我们 `limit=1`）。

**这就是 API**：一种机制，让我可以访问别人服务器上的数据，并以某种方式把它整合进我自己的程序。

### 7.5 用 Python 假装成浏览器：itunes.py 第一版 [01:03]

浏览器 Chrome 不是我写的，所以我该写点 Python 代码，让它假装成浏览器去抓同样的数据。

```bash
$ code itunes.py
```

第一版：

```python
import requests
import sys

if len(sys.argv) != 2:
    sys.exit()      # 参数个数不对，直接退出（先不给提示，保持简单）

response = requests.get("https://itunes.apple.com/search?entity=song&limit=1&term=" + sys.argv[1])
print(response.json())
```

**逐行讲解：**

- `import requests` —— 用之前 `pip install` 装好的库，用来发 HTTP 请求。
- `import sys` —— 为了用命令行参数，让用户指定想搜哪个乐队。
- `if len(sys.argv) != 2: sys.exit()` —— 如果用户没有给出"文件名 + 一个乐队名"（也就是长度不是 2），那就直接提前退出。（David 说这里本来可以给更详细的提示，但先保持简单。）**这样保证了后面的代码可以信任 `sys.argv` 里一定有我们要的东西。**
- `requests.get(...)` —— `requests` 包里的函数，作用是**真的去服务器上"get"（获取）一个响应**。URL 跟刚才浏览器里的一模一样，只是**末尾的 `weezer` 换成了 `sys.argv[1]`**——把引号提前闭合，然后用拼接运算符 `+` 把用户在命令行敲的词接上去。这样程序就有了交互性。
- `response = ...` —— 把服务器返回的全部内容存进变量 `response`。
- `print(response.json())` —— 先看看服务器到底返回了什么，好决定下一步怎么走。

运行（David 把终端窗口调大）：

```bash
$ python itunes.py weezer
```

屏幕上出现的，跟刚才浏览器里看到的**几乎一样**的文本，但是——

**一个非常重要的认知点**：Apple 返回的严格来说是 JSON 响应（JavaScript Object Notation），**但 Python 的 `requests` 库已经把它转成了一个 Python 字典（dictionary）**，而巧的是它们的语法几乎一样：

- 用花括号 `{` ... `}` 表示字典。
- 里面的列表用方括号 `[` ... `]` 表示。
- 用引号（这里是单引号，等价于双引号）表示字典的**键（key）**。
- 冒号后面是这个键对应的**值（value）**。

你会看到一个 `resultCount` 键，值是 1；还有一个更有趣的键 `results`，它的值是**一整列表的数据**。

**David 的真心话**：说实话，这一大坨文本太长了，我要想搞明白我在看什么，得花上好一会儿。所以我们临时用另一个 Python 自带的库，把数据**格式化得干净一点**。

### 7.6 用 `json.dumps(..., indent=2)` 漂亮打印 [01:06]

Python 自带一个专门的库叫 **`json`**，可以操作 JSON 数据，甚至可以**"漂亮打印（pretty print）"**——用一种你我都更容易看懂的方式格式化输出。

注意：`json` 是**自带**的，所以**不需要用 `pip` 安装**。

```python
import json          # 新增：Python 自带的 json 库
import requests
import sys

if len(sys.argv) != 2:
    sys.exit()

response = requests.get("https://itunes.apple.com/search?entity=song&limit=1&term=" + sys.argv[1])
print(json.dumps(response.json(), indent=2))
```

**新函数讲解：**

- `json.dumps` —— dumps 可以理解为 "dump string"（转储成字符串）。它的作用就是**漂亮打印**：把同样的信息格式化得好看。这是 David 从文档里知道的。
- **`indent=2`** —— 一个**命名参数（named parameter）**。按文档的说法，传 `indent=2` 就会把所有内容**缩进至少 2 个空格**（你也可以写 4 或者别的）。这么一点缩进就足够帮我们理清眼前的数据了。

再跑：

```bash
$ python itunes.py weezer
```

现在还是有点复杂（毕竟信息量大），但"我的天，这下好读多了"。

### 7.7 读懂返回的数据结构 [01:07]

David 带着大家一层层读这个输出：

- 最外层是**第一个花括号** → 说明这是一个 **Python 字典**，也就是键值对的集合。
- 第一个键叫 **`resultCount`**，它的值是 1。为什么是 1？因为我自己在 URL 里写了 `limit=1`，只让返回一首 Weezer 的歌。如果把 limit 调大，应该能拿到更多。
- 这个响应里真正有意思的部分是数据本身：注意 **`results`** 这个键，它的值非常大，由方括号可知它是一个 **Python 列表**。
- 这个列表里装的是什么？刚才扫过一眼，知道它装了**一个字典**——所以你会看到又一个花括号。

> **一个重要概念**：字典完全可以**套在另一个字典里面**——如果某个键的值本身又是一个字典。这是非常常见的范式（paradigm）。虽然看起来有点晦涩，但它只是让我们能把更多的键关联到更多的值上而已。

大部分信息我可能都不关心。比如 Apple 给 Weezer 的唯一标识符（unique identifier）是 115234——如果我在建自己的数据库、想让它可检索，这可能有用；但今天我关心的只有一件事：**歌曲的名字，也就是键 `trackName`。**

我们拿到的第一首、也是唯一一首（因为 limit=1）歌，就是那首你可能听过的 Weezer 的 **Say It Ain't So**。

### 7.8 最终版：遍历 `results` 打印所有歌名 [01:09]

现在有了线索：目标是写一个 `itunes.py`，**不是**把服务器响应一股脑倒出来（那确实很晦涩），而是**把 iTunes 上这个乐队的所有歌曲名打印出来**。那我大概可以**迭代（iterate）**点什么。

回看结构：键 `trackName` 在一个字典里，而这个字典是 `results` 的值。

最终版：

```python
import json
import requests
import sys

if len(sys.argv) != 2:
    sys.exit()

response = requests.get("https://itunes.apple.com/search?entity=song&limit=50&term=" + sys.argv[1])

o = response.json()                 # o = object，把 JSON 响应存进变量
for result in o["results"]:         # 遍历 results 这个键对应的列表
    print(result["trackName"])      # 打印当前这首歌的 trackName
```

**逐行讲解（David 的复盘）：**

- `o = response.json()` —— 定义一个变量，为了好讨论叫 `o`（object 的首字母），把那份 JSON 响应专门存进去。当然你可以叫任何名字。
- `for result in o["results"]:` —— 对 `o` 里 `results` 这个键里的每一条结果……
- `print(result["trackName"])` —— 打印这条结果的 `trackName`。
- **注意大小写必须完全一致**：`trackName` 的 N 是**大写**，`results` 是**全小写**。
- 第 8 行（`requests.get(...)`）是**用 Python 发 HTTP 请求到服务器**——就像我们人类在浏览器里敲 URL 然后回车一样，这是它的 Python 等价物。
- 第 10 行是从装着服务器响应的变量里，拿出我关心的那个 JSON 对象（也就是最外面那对花括号之间的东西）。
- 因为前面我们"到处戳了戳"，也读了文档，所以我知道这个对象有个叫 `results` 的键，而 `results` 是个列表。
- 此刻这个列表里只有一首歌（Say It Ain't So），因为我把 limit 限制成了 1；**但即便如此，我的循环照样能工作**，只是会迭代一次而已。
- **为了让演示更有趣，把 `limit` 从 1 改成 50**，这样至少能拿到 50 首歌名。

运行：

```bash
$ python itunes.py weezer
Say It Ain't So
Undone - The Sweater Song
Buddy Holly
Say It Ain't So
Buddy Holly
Undone - The Sweater Song
My Name Is Jonas
...
```

一共 50 首。往回翻，第一个确实是 Say It Ain't So；后面还有 Undone — The Sweater Song、Buddy Holly、也许是另一个专辑版本的 Say It Ain't So、另一个 Buddy Holly、另一个 Undone、My Name Is Jonas 等等。

### 7.9 学生提问三连 [01:12]

**问题 A**："能不能用 `break` 代替 `sys.exit`？"

**David**：好问题，但**不行**。`break` 是用来**跳出循环**这类东西的（我们之前见过）；`sys.exit` 是用来**跳出整个程序**的。现阶段记住：**`break` 用于循环，`sys.exit` 用于终止整个程序**。

**问题 B**："`results` 这个键的名字，我们是从哪儿知道的？我们能改这个名字吗？"

**David**：**不能改。** 要搞清楚：JSON 响应里的那些键，来自 `itunes.apple.com`——是某个工程师团队**替我们决定**了这些键叫什么，包括 `trackName`、`results`、`resultCount` 等等。

但是：你和我**完全可以**用 Python 变量把这些值存起来（就像这里用 `o`、用 `result` 一样），**你可以给这些值起任何你想要的变量名**。只是 JSON 响应本身是第三方服务器给的，改不了。

**问题 C**："`cowsay` 这个包能画哪些 ASCII 图形？"

**David**：我建议你去看前面幻灯片里的那个 URL，因为那里讲得更全。它不只有牛，还有霸王龙和另外几种动物。（他还再次强调：**我不觉得你以后会在实际工作中多用这个包**，它只是用来代表"你可以安装的这类包"。）另外补了一句：ASCII art 是 emoji、GIF、JPEG、PNG 出现之前我们唯一的玩具，而 `cowsay` 让它永垂不朽。

## 8. 制作自己的库 [01:13]

### 8.1 为什么要自己做库 [01:13]

最后一件事：**你自己也有能力做自己的库。**

回顾一下走过的路：

- 到目前为止，我们都是把函数写在**同一个文件**里（从 `hello.py` 开始，之后每个程序都是）。
- 然后我们认识了模块（`random`、`statistics`），学会了导入**Python 自带的**模块——但那也是**别人的代码**。
- 然后我们用了 `pip` 这个包管理器，把**第三方包**装到系统里——**还是别人的代码**。

**现在回到起点**：如果你自己发现——

- 你**一遍又一遍**地实现同一类函数，或者
- 你发现自己总是**打开老程序、把以前写的代码复制粘贴到新程序里**，因为又遇到了同样的问题，

那么一个好的做法是：**把这段你一直在重用的代码打包起来，做成你自己的 Python 模块或包**。你可以只放在自己的 Mac、PC 或云服务器上；也可以走完整流程，把它打包成免费的开源软件，放到 PyPI 之类的地方给别人用。

### 8.2 第一步：写 sayings.py [01:14]

这门课里我们写了无数遍 "hello"，那就做一个模块，专门负责说 hello 和 goodbye。

```bash
$ code sayings.py
```

第一版（只有函数）：

```python
def hello(name):
    print(f"hello, {name}")

def goodbye(name):
    print(f"goodbye, {name}")
```

**注意**：这段代码**本身对终端用户什么都不做**——直接运行它，屏幕上什么也没有。但如果某个程序员把这个模块导入他自己的程序，上面这些函数带来的能力就能在他的代码里生效。

**为了验证函数是对的，David 加了一个 `main` 函数做测试：**

```python
def hello(name):
    print(f"hello, {name}")

def goodbye(name):
    print(f"goodbye, {name}")

def main():
    hello("world")      # 测试 1
    goodbye("world")    # 测试 2

main()                  # 像以前一样，在文件底部显式调用 main
```

- `hello(name)` 接收一个 `name` 参数，打印一个 f-string：`hello, {name}`（花括号里代入传入的名字）。
- `goodbye(name)` 同理，打印 `goodbye, {name}`。
- `main()` 里做两个测试：对 "world" 说 hello，再对 "world" 说 goodbye。
- 最后一行跟以前一样：**必须显式调用 `main()`**，函数才会执行。

运行验证：

```bash
$ python sayings.py
hello, world
goodbye, world
```

看起来没问题，可以认为这两个函数（虽然简单）是正确的。

### 8.3 第二步：在 say.py 里导入自己的模块 [01:15]

现在假设我想把这些函数当成**我自己的库 / 我自己的 Python 模块**来用——它对外提供一个 `hello` 函数，或者一个 `goodbye` 函数。

重新打开 `say.py`，这次清掉牛，改成让自己的库来说话：

```python
import sys

from sayings import hello      # 从我自己的模块 sayings（即 sayings.py）导入 hello

if len(sys.argv) == 2:
    hello(sys.argv[1])
```

**关键点：**

- 因为我创建了一个叫 `sayings.py` 的文件，我就可以写 `from sayings import hello`——**Python 会自动推断我说的是 `sayings.py`，至少在当前目录（current directory）下是这样**。
- 这次我只导入其中一个函数，即 `hello`。
- 然后检查 `len(sys.argv) == 2`，如果用户配合、给了两个命令行参数，就调用这个新的 `hello` 函数，传入 `sys.argv[1]`（也就是用户敲在提示符后面的名字）。

运行（David 想让屏幕上出现自己的名字）：

```bash
$ python say.py David
```

### 8.4 翻车现场四：为什么屏幕上先出现了 hello, world？ [01:16]

**实际输出：**

```
hello, world
goodbye, world
hello, David
```

**为什么会这样？**

David 的解释非常关键：

> 原来，尽管我们一直以来的做法就是这样，但在文件底部**盲目地调用 `main()`，并不是正确的做法**。如果我在文件底部无条件调用 `main`，那就意味着：**只要这个文件被 Python 加载，`main` 就会被调用**。
>
> 而不幸的是——**即使我只是从这个文件里导入（import）一个函数**（就像 `say.py` 里做的那样），这也是成立的。

具体到代码：`say.py` 第 3 行 `from sayings import hello`，实际上是在告诉 Python：**去找 `sayings` 这个模块，把它从上到下、从左到右读一遍，然后专门导入 `hello` 这个函数。**

**但不幸的是**：Python 把文件从上到下读完的时候，最后那行代码就是 `main()`——**`main` 无论如何都会被调用**。

### 8.5 正解：`if __name__ == "__main__":` [01:17]

那么，**使用 `main` 函数的正确方式**是什么？

先说明为什么我们还需要 `main`：它解决的问题是——**我们可以按任意顺序排列函数，并且所有函数在被调用时都已经被定义好了**。

问题只出在"调用它的时机"。所以**不应该**在这个文件（或任何文件）底部**无条件**调用 `main`，而应该用这个技巧：

```python
def hello(name):
    print(f"hello, {name}")

def goodbye(name):
    print(f"goodbye, {name}")

def main():
    hello("world")
    goodbye("world")

if __name__ == "__main__":     # 只有被"直接运行"时才调用 main
    main()
```

**原理解释（David 讲得很细）：**

- `__name__` 是 Python 里的一个**特殊变量**。注意：因为 VS Code 的字体问题，屏幕上看起来那两个下划线不太明显，但**左右两边确实各有两个下划线**。
- 当你**从命令行运行**一个文件时（比如 `python sayings.py`），Python 会自动把 `__name__` 的值设为字符串 `"__main__"`。
- 而当你**导入**这个文件时，`__name__` **不会**被设成 `"__main__"`，它会被设成别的值——**技术上说，就是模块的名字**。

于是两种情形就区分开了：

1. **运行 `python sayings.py`**：`__name__` 被自动设为 `"__main__"`，条件成立，`main()` 被调用 → 依然打印 hello, world / goodbye, world，**跟以前一样能测试**。
2. **在 `say.py` 里 `from sayings import hello`**：这一行确实会让 Python 去找 `sayings.py`、从上到下读完，**但这次它会忽略对 `main` 的调用**，因为那个调用被包在了条件里。这种情况下 `__name__` 不等于 `"__main__"`，所以**根据 `__name__` 的值，`main` 不会被调用**。

**最终验证：** 不运行 `python sayings.py`（那是模块），而是运行 `python say.py`（那个导入了 `hello` 的程序）。这次屏幕上只有我们真正想要的那句话。

## 本讲易错点

1. **`random.shuffle` 没有返回值**：它**原地**修改列表，写 `cards = random.shuffle(cards)` 会让 `cards` 变成 `None`。正确写法是 `random.shuffle(cards)`。

2. **`from random import choice` 会污染命名空间**：导入后你自己就不能再用 `choice` 当变量 / 函数名了。默认优先用 `import random`，保留模块作用域，避免冲突。

3. **`sys.argv[0]` 是程序自己的文件名**，用户输入从 `sys.argv[1]` 开始。所以"用户给了一个名字"对应的判断是 `len(sys.argv) == 2`，不是 `== 1`。

4. **`SyntaxError` 抓不住**：语法错误（比如字符串漏了结尾引号）是**写代码的人的错**，程序根本没开始运行，`try/except` 和 `if` 都救不了，只能回去改代码。而 `IndexError` 这类运行时异常才需要用代码去防御。

5. **只 `print` 错误提示但不停下来是不够的**：去掉 `else`、把真正的逻辑放在条件块外面之后，程序会在打印 "Too few arguments" 的同时**继续往下执行并崩溃**。想"提前结束"就必须用 `sys.exit()`。

6. **`break` ≠ `sys.exit`**：`break` 只能跳出**循环**，`sys.exit` 终止**整个程序**。

7. **遍历 `sys.argv` 会连文件名一起遍历**：`for arg in sys.argv` 会多打印一张写着程序名的"名牌"。要切掉它，用 `sys.argv[1:]`。

8. **切片冒号 vs f-string 里的格式码**：同一个符号（`:`、`f`）在不同上下文里含义完全不同。切片是 `list[a:b]`，f-string 格式化是 `{x:.2f}`——不要混为一谈。

9. **JSON 的键名不能改**：`results`、`trackName`、`resultCount` 这些键是**服务端定好的**（来自 Apple 的工程师），你只能顺应它；能改的只有你自己存这些值的**变量名**。而且**大小写必须完全一致**（`trackName` 的 N 大写）。

10. **`json` 是自带的，`requests` 不是**：`json` 直接 `import` 即可；`requests` 和 `cowsay` 必须先 `pip install`。

11. **在自己的模块底部直接写 `main()` 是个 bug**：一旦这个文件被 `import`，`main()` 就会自动执行，导致"莫名其妙多出几行输出"。正确写法是 `if __name__ == "__main__": main()`。

12. **概率不是"交替出现"**：抛硬币连出 5 次反面、洗三张牌洗出跟原顺序一样，都**不是 bug**。样本量小时分布本来就不均匀，跑无限多次才会趋近理论概率。

13. **一个 `if` 只能有一个 `else`**：`else` 是最后的兜底分支；中间想加分支请用多个 `elif`。

14. **命令行里带空格的名字要加引号**：`python name.py David Malan` 是两个参数（会报 too many）；`python name.py "David Malan"` 才是一个整体。
