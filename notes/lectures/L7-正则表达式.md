## 本讲速览

**一句话主题：** 正则表达式（regular expression，常缩写为 regex）就是"一种模式"。它让我们能在代码里定义模式，然后拿这个模式去比对别人（通常是用户）给过来的数据——可以用来**校验（validate）**数据是否合法、可以**清理（clean up）**乱七八糟的输入格式、也可以**提取（extract）**我们想要的那一部分信息。

本讲的知识清单：

1. 为什么需要正则：先用朴素 Python 语法写邮箱校验，一步步撞墙
2. `re` 库与 `re.search(pattern, string, flags=0)` 的函数签名
3. 第一批符号：`.` `*` `+` `?` `{m}` `{m,n}`
4. 有限状态机（finite state machine）视角下正则怎么被"读"
5. 转义字符 `\` 与"点号陷阱"：`.` 是通配符，字面点号要写 `\.`
6. 原始字符串（raw string）`r"..."` 及为什么写正则必须养成用它
7. 锚点符号：`^` 匹配开头，`$` 匹配结尾
8. 字符集 `[]` 与补集 `[^...]`（方括号里的 `^` 意思是"非"）
9. 范围写法 `[a-zA-Z0-9_]` 与内置简写 `\w` `\W` `\d` `\D` `\s` `\S`
10. 分支 `A|B`、分组 `(...)`、非捕获分组 `(?:...)`
11. 标志位（flags）：`re.IGNORECASE`、`re.MULTILINE`、`re.DOTALL`
12. `re.match` 与 `re.fullmatch`：自动锚定开头/结尾
13. 清理用户输入：`format.py`，捕获组 `matches.groups()` / `group(1)` / `group(2)`
14. 海象运算符 `:=`：赋值 + 判断合二为一
15. 提取用户输入：`twitter.py`，`re.sub(pattern, repl, string, count=0, flags=0)`
16. `re.split`、`re.findall` 以及"正则是一门跨语言的通用语言"

## 1. 开场：正则表达式到底是什么 [00:00]

DAVID MALAN 开场就说：这一周我们讲正则表达式。**regular expression，或者干脆叫 regex，本质上就是一个"模式"（pattern）**。

在编程里，有一类需求极其常见：我们想用某个"模式"去匹配某类数据，而这类数据往往是**用户输入**。举个例子，如果用户往你的程序、网站、或者手机 App 里输入一个邮箱地址，你理想情况下应该能判断出"他确实输入了一个邮箱地址"，而不是一串乱七八糟的东西。

有了正则表达式，我们就获得了一项新能力：**在代码里定义模式，然后拿这个模式去比对从别人那里收到的数据**。用途有三种：

- 校验（validate）它是不是符合预期；
- 或者，干脆用来**清理一大堆本来就很脏的数据**（这些数据之所以脏，往往也是因为它们是"人"填的）；
- 再或者，从里面**提取**一部分信息。

这三种用法，本讲后面都会演示到。

不过在正式开始用正则之前，Malan 提议：**先用一些更简单的 Python 语法来解决同样的问题，看看我们会撞上什么样的墙。** 这个"先撞墙再给药"的过程，是本讲最精华的部分。

## 2. 目标：写一个邮箱校验程序 `validate.py` [00:00]

### 2.1 版本一：只要有 `@` 就算有效 [00:00]

在终端里输入 `code validate.py` 创建文件。目标很朴素：用户来到你的 App 或网站，输入邮箱地址，你的程序回答"有效"还是"无效"。

```python
email = input("What's your email? ").strip()

if "@" in email:
    print("Valid")
else:
    print("Invalid")
```

几个细节要记住：

- `input` 的返回值是 `str`（字符串）。`str` 自带很多内置方法（method），其中一个是 `strip`，作用是**去掉左侧的空白和右侧的空白**（leading whitespace 和 trailing whitespace）。
- 为什么要加 `.strip()`？因为用户很可能手抖多敲了一个空格。我们提前把它扔掉，省得后面出问题。这一讲后面每个程序都会这么做，Malan 称之为"至少我能做的最起码的清理"。
- `if "@" in email` 这是 Python 里很地道的写法：问的是"这个字符串 `"@"` 在不在另一个字符串 `email` 里面"，不管 `@` 在开头、中间还是结尾，`in` 会自动帮你把整个字符串搜一遍。

Malan 特意强调：如果用更啰嗦的写法，你得写一个 `for` 循环或者 `while` 循环，逐个字符去看它是不是 `@`。但 Python 的好处就是**用更少的代码做更多的事**（do more with less）。

在终端运行：

```text
$ python validate.py
What's your email? malan@harvard.edu
Valid
```

### 2.2 这个版本是"坏的"：学生的回答 [00:05]

Malan 直接说：这个程序**技术上是坏的，是有 bug 的**。然后向全场提问：谁能举个反例——某个输入会被判为有效，但你我都知道它根本不是邮箱？

**学生回答：** 比如你只输入两个 `@` 符号，别的什么都没有，程序照样说有效——但显然缺了点什么。

Malan 演示：

```text
$ python validate.py
What's your email? @
Valid
```

只输入一个 `@`，没有用户名，没有域名，这怎么看都不像邮箱，但代码认为有效。原因很简单：它只是在找 `@` 而已。**我们把标准定得太低了。**

### 2.3 版本二：同时要求有 `@` 和一个 `.` [00:05]

一个邮箱地址，一般来说会有一个 `@`，以及至少一个点号（通常出现在域名里），比如 `malan@harvard.edu`。

> 注意 Malan 的原话：严格来说点号并不是硬性要求，邮箱不一定非得有点。但这里他先拿自己的邮箱当测试用例。

改代码：

```python
email = input("What's your email? ").strip()

if "@" in email and "." in email:
    print("Valid")
else:
    print("Invalid")
```

这里有两个布尔表达式（Boolean expression），用逻辑上的 `and` 连在一起：**如果 `@` 在 email 里，并且 `.` 也在 email 里**，那就说有效。

```text
$ python validate.py
What's your email? malan@harvard.edu
Valid
```

但同样地，我们还是可以"使坏"（be adversarial），输入 `@.`：

```text
$ python validate.py
What's your email? @.
Valid
```

这又被误判成有效了，可里面依然既没有用户名也没有域名。

### 2.4 版本三：拆成 username 和 domain [00:10]

问题出在哪？`@` 可以在任何位置，`.` 也可以在任何位置。但如果我们假设用户用的是传统域名（比如 `harvard.edu` 或 `gmail.com`），那我们真正想检查的是：**点号在"域名"里**，而不是在整个字符串的某个角落。

于是引入 `split` 方法：

```python
email = input("What's your email? ").strip()

username, domain = email.split("@")

if username and "." in domain:
    print("Valid")
else:
    print("Invalid")
```

要点：

- `email` 是 `str`，`str` 除了 `strip` 还有一个方法叫 `split`。**给它一个（或多个）用来切分的字符，它会把一个字符串切成多个字符串。**
- `email.split("@")` 按理说会返回两部分：用户名和域名。
- `username, domain = ...` 这一行叫**解包（unpack）**——一次性在一行里定义两个变量。当然你也可以先存成一个列表，但既然你已经提前知道会拿到几个值、分别是什么含义，就直接解包更清爽。
- `if username` 这种写法你可能没见过：如果 `username` 是一个字符串，那么只要它不是 `None`（空值）、也不是空字符串 `""`，`if username` 就是"真"。也就是说：**只要用户名里至少有一个字符，就算真；一个字符都没有，就算假。** 这就是所谓的 truthy（真值）判断。

**这里有一个自然语言带来的潜在歧义，Malan 专门停下来讲：**

`if username and "." in domain` 读起来像是"如果用户名和点号都在 domain 里"，但它真正的意思是**两个独立的布尔表达式**：

- `if username`（用户名非空）
- `"." in domain`（点号在域名里）

加上括号会更清楚：`if (username) and ("." in domain)`。所以不要按英语句子的语感去读它。

运行一下：

```text
$ python validate.py
What's your email? malan@harvard.edu
Valid
```

再试 `malan@harvard`（没有顶级域名）：

```text
$ python validate.py
What's your email? malan@harvard
Invalid
```

现在至少能拦住这个了。

### 2.5 版本四：要求域名以 `.edu` 结尾 [00:15]

既然要精确，就精确到底。这一版把范围从"通用邮箱"缩小到"美国大学的 `.edu` 邮箱"。用我们之前见过的 `endswith` 方法：

```python
email = input("What's your email? ").strip()

username, domain = email.split("@")

if username and domain.endswith(".edu"):
    print("Valid")
else:
    print("Invalid")
```

`endswith` 会检查 `domain` 是不是以 `.edu` 结尾。运行：

```text
$ python validate.py
What's your email? malan@harvard.edu
Valid
```

但恶意用户还是能绕过。比如输入 `malan@.edu`——用户名有了，域名也以 `.edu` 结尾，于是被判有效：

```text
$ python validate.py
What's your email? malan@.edu
Valid
```

可现实里 `malan@.edu` 这个地址根本不存在（中间得有域名本体才行）。所以我们还不够严格。

### 2.6 撞墙小结：这条路走不通 [00:15]

Malan 说：我们当然可以继续迭代下去，加更多布尔表达式，用别的 Python 方法去检查"点号左边有没有东西""点号右边有没有东西"，大不了 `split` 用好几次……

**但说实话，这事儿升级得很快（it escalates quickly）。** 你最终会为了表达一个"说起来其实很简单"的需求——"请按邮箱地址的格式来填"——而写出一大堆代码。

那怎么办？答案是：**Python 自带一个专门处理正则的库，名字就叫 `re`。**

## 3. `re` 库与 `re.search` [00:20]

### 3.1 库能干什么 [00:20]

`re` 是 regular expression 的缩写。这个库让你能够：

- **定义**模式（比如一个"邮箱地址模式"）；
- 用库里的内置函数**校验**用户输入是否符合这个模式；
- 甚至用这些模式去**修改**用户输入，或者从里面**提取**部分信息。

Malan 先带大家看了官方文档的网址，然后说：我们把重点放在这个库里**最通用的一个函数**上——`search`。

### 3.2 `re.search` 的函数签名 [00:20]

```python
re.search(pattern, string, flags=0)
```

- `pattern`（模式）：你想找的那个正则表达式；
- `string`（字符串）：你要在这个字符串里搜那个模式，通常就是来自用户的输入；
- `flags`（标志位）：**可选**的第三个参数，是一堆"标志"。

什么是 flag？Malan 解释：**flag 就是你可以传进去、用来改变函数行为的参数**。一开始我们先不用它，只传前两个参数。

### 3.3 初次使用：其实退步了 [00:20]

回到 VS Code，先把大部分代码删掉，在文件顶部 `import re`：

```python
import re

email = input("What's your email? ").strip()

if re.search("@", email):
    print("Valid")
else:
    print("Invalid")
```

Malan 自己承认：**这一版其实一点进步都没有，某种程度上甚至是退步。** 它和最开始那句 `if "@" in email` 完全等价。但现在至少我们开始用这个库了，可以认为 `re.search` 在 `@` 确实存在于 email 里时会返回"真"一样的值。

```text
$ python validate.py
What's your email? malan@harvard.edu
Valid

$ python validate.py
What's your email? @
Valid
```

还是坏的。那要怎么变强？

## 4. 第一批正则符号：`.` `*` `+` `?` `{m}` `{m,n}` [00:20]

### 4.1 我们真正想表达的模式 [00:20]

Malan 说，我们最终想定义的模式其实是：**`@` 左边得有点东西，然后一个 `@`，然后右边得有点东西；而且右边这点东西应该以 `.edu` 结尾，同时在 `.edu` 之前还得有内容**（比如 Harvard、Yale 或者别的学校）。

要做到这点，我们需要更多的"词汇量"。

### 4.2 符号表 [00:20]

在正则的世界里（不只是 Python，很多语言都一样），有一些**特殊符号**可以用来定义模式。到目前为止我们只用过"字面文本"（就是那个 `@`）——技术上说那也算一个正则，只是非常没意思。

第一批符号：

```python
.   any character except a new line          # 任意一个字符，除了换行
*   0 or more repetitions                    # 0 次或多次重复
+   1 or more repetitions                    # 1 次或多次重复
?   0 or 1 repetition                        # 0 次或 1 次重复
{m} m repetitions                            # 恰好 m 次重复
{m,n} m-n repetitions                        # m 到 n 次重复
```

逐个解释（Malan 的口述）：

- **`.`**：一个句点代表"任意一个字符，除了换行"。如果我不在乎用户名里到底是哪些字母，只要"有一个或多个字符"就行，那么 `.` 就能表达 a-z、A-Z 以及其它一堆字符。
- **`*`**：一个星号代表"**0 次或多次**重复"。写成"某物 `*`"意味着我接受 0 次（也就是什么都没有），或者更多次——1 次、2 次、3 次、300 次都行。
- **`+`**：加号代表"**1 次或多次**重复"。也就是说那儿**至少得有一个字符**，后面可以有更多。
- **`?`**：问号代表"**0 次或 1 次**重复"。我要么不要这个字符（0 个），要么只要 1 个，多一个都不行。
- **`{m}`**：用花括号加一个数字（这里记作 m），你可以自己指定重复次数，1 次、2 次、3 次、300 次都随你。
- **`{m,n}`**：花括号里放两个数字 m 和 n，表示一个范围——重复 m 到 n 次。

### 4.3 第一版模式 `.*@.*`——然后翻车 [00:20]

回到 VS Code。我们不光要查 `@`，还要求左右两边都有东西。左边我不在乎用户名是什么字母，所以先用一个 `.`（任意字符）；但我不要只有一个字符（那样用户名只能是 `a@...` 或 `b@...`），所以再加一个 `*`：

```python
import re

email = input("What's your email? ").strip()

if re.search(".*@.*", email):
    print("Valid")
else:
    print("Invalid")
```

`.` `*` 组合起来就是"左边随便给点东西"，右边再写一个 `.*` 就是"右边随便给点东西"。

先测自己的邮箱，没问题。然后输入 `malan@`（完全没有域名）：

```text
$ python validate.py
What's your email? malan@
Valid
```

**它居然还是有效！** 为什么？

**学生回答：** 因为你用的是 `*`，而不是加号。

**Malan：正是。** `*` 的意思是"0 次或多次"，所以 `re.search` 非常乐意接受 `@` 后面什么都没有——那刚好算 0 次重复。

于是改成 `+`：

```python
import re

email = input("What's your email? ").strip()

if re.search(".+@.+", email):
    print("Valid")
else:
    print("Invalid")
```

重新运行：

```text
$ python validate.py
What's your email? malan@harvard.edu
Valid

$ python validate.py
What's your email? malan@
Invalid
```

终于对了。注意 Malan 的总结：**我们不在乎用户名和域名具体是什么，我们在乎的是"模式"。** `.+` 用来判断 `@` 左边有没有东西、右边有没有东西。

### 4.4 学生回答：忘了 `+` 怎么办？用 `..*` 也能实现 [00:20]

Malan 抛出一个问题：假如你忘了 `+` 这个符号的存在，只允许用 `.` 和 `*`，你能不能重新造出"1 次或多次"这个概念？

**学生回答：** 可以，用两个点：`..*`。

**Malan：对。** 因为 `.` 表示任意一个字符，那么第一个 `.` 就表示"这儿必须有一个字符"，后面的 `.*` 表示"零个或多个其它字符"。所以 **`..*` 和 `.+` 是等价的**。

而且他特意澄清一个常见误解：**`..*` 并不要求所有字符都一样**。不是说用户名只能是 `a`、`aa`、`aaa`、`aaaa`——每一个字符都可以不同，`.*` 只是说"零个或多个任意字符，一个接一个"。

两种写法哪个更好？看情况。有人觉得 `..*` 更清楚，因为"一个点 = 一个字符"这件事一目了然；但如果你天天写正则，`+` 这种写法能把代码压缩得更简洁，熟悉之后反而更好读。**和 Python 里的大部分东西一样，同一个问题往往有多种表达方式，至于哪个更好，理性的人也可能意见不同。**

### 4.5 用状态机（state machine）来理解正则 [00:20]

如果上面那些符号让你觉得像天书，Malan 说我们可以画出来看。他先退回到 `.*@.*` 这一版。

`.*@.*` 的意思是：**0 个或多个字符，接着一个字面的 `@`，接着 0 个或多个其它字符**。当你把这个 pattern 作为参数传给 `re.search` 时，它会**从左到右**读这个 pattern，然后拿它去匹配用户输入（这里是 `email`）。

那么 `re.search` 靠什么机制来判断"匹配成功/失败"？答案是：**它其实在运行一台用软件实现的机器——有限状态机（finite state machine），更正式的名字叫"非确定有限自动机"（nondeterministic finite automaton，NFA）。**

`.*@.*` 的状态机可以这么理解（下面用文字描述这个图）：

```text
   起点 start
     |
     v
  +------------------------+
  |                        |
  |   q1（状态一）          |  <-- 箭头从 q1 绕回自己，标注 "."
  |                        |      表示：读到任意字符，就继续待在 q1
  +------------------------+
     |  @
     v
  +------------------------+
  |  (( q2 ))  <-- 双圈 = 接受状态（accept state）
  |   箭头从 q2 绕回自己，标注 "."
  +------------------------+
```

工作过程（以 `malan@harvard.edu` 为例）：

1. 函数从**最左边的 start 状态**开始；
2. 它从左到右读用户的输入，每读一个字符就决定：**是留在当前状态，还是转移到下一个状态**；
3. 在第一个状态 q1 里，它读到 `M`、`A`、`L`、`A`、`N`——每个字符都让它沿着那条"绕回自己"的弧线留在 q1（那条弧线标注的是 `.`，也就是"任意字符"）；
4. 然后它**顺着标着 `@` 的那条边**转移到第二个状态 q2（因为机器里有字面的 `@`，用户的输入里也有）；
5. 在 q2 里继续读剩下的 `H`-`A`-`R`-`V`-`A`-`R`-`D`-`.`-`E`-`D`-`U`，一直绕回自己；
6. 读完之后，计算机检查一个问题：**它现在停在"接受状态"上吗？**

所谓接受状态（accept state / final state），在图上画成**两个同心圆**（一个圆圈套一个圆圈）。如果读完用户输入之后，机器正好停在那个双圈状态里，那么这就是一个合法邮箱。**反之，如果机器卡在第一个状态（单圈，不是接受状态）出不来，那就判定为非法。**

再看 `.+@.+` 这一版的状态机：

```text
  start --> q1 --(.)--> q2 <--(. 绕回自己)
                        |
                       (@)
                        v
                       q3 --(.)--> q4 <--(. 绕回自己)  ((q4 是双圈接受状态))
```

（官方 Notes 的描述：q1 是用户提供的任意字符，q2 表示 1 次或多次重复；接着是 `@`；然后 q3 是用户提供的任意字符，q4 表示 1 次或多次重复。）

用 `malan@harvard.edu` 走一遍：从 start 出发，第一条边标着 `.`，**必须消耗掉一个字符**（`m`）；然后可以在 `@` 之前继续消耗若干字符（`alan`）；然后消耗掉 `@`；接着因为右边是 `.+`，**至少还得消耗一个字符**（`h`）；剩下的 `arvard.edu` 可以随意消耗。最后停在那个双圈的接受状态里 → 有效。

**如果中途某一步没有可走的边（transition），机器卡住了、没法继续从左往右推进，那就只能判定为非法。**

### 4.6 继续加码：要求以 `.edu` 结尾 [00:25]

### 4.7 修复：转义字符 `\` [00:25]

**学生回答：** 可以用转义字符，反斜杠？

**Malan：没错。** 这个所谓的 escape character（转义字符）我们之前见过——在讲换行的时候，`\n` 就是告诉计算机"我要一个换行"，而不是让你真的去敲回车、也不是要在屏幕上显示一个字母 n。

正则用的是同一套思路。在那个点号前面加一个反斜杠：

```python

    print("Valid")
else:
    print("Invalid")
```

在正则的世界里，`\.` 是一个所谓的 **special sequence（特殊序列）**。它表示：**我要匹配的就是一个字面意义上的点号**。不是"任意字符 + edu"，而是"点号 + edu"。

测试：

```text

Valid

$ python validate.py

Invalid
```

完美。

### 4.8 配套必须讲：原始字符串 raw string `r"..."` [00:25]

既然用上了反斜杠，就得顺带讲 raw string。

但我们不想让 **Python** 把这个反斜杠误认为是"转义序列的开头"，比如 `\n` 那种：程序员敲了两个字符 `\` 和 `n`，Python 却把它理解成一个换行符。我们不想出现这种误读。

所以只要你写的正则里用到了反斜杠，就应该再做一件事：**告诉 Python 这个字符串是"原始字符串"（raw string）——在字符串前面写一个 `r`。**

```python
# 普通字符串：\n 是一个换行符（1 个字符）
"\n"

# 原始字符串：\n 就是反斜杠 + n（2 个字符），每个字符都按字面理解
r"\n"
```

Malan 的比喻：这跟在字符串前面写 `f` 是一个道理——`f` 告诉 Python"这是一个格式字符串（format string），请把花括号里的变量插进去"；而 `r` 告诉 Python"这是一个原始字符串，请原封不动地传进去"。

**关于 r 的好习惯，Malan 给了明确建议：** 严格来说，只有当你确实用反斜杠来表达特殊序列（比如 `\.`）时才"必须"加 `r`。但**总体上，养成给所有正则都加 `r` 的习惯是件好事**——因为你以后回过头去改这个正则、往里加东西的时候，很可能顺手加了个反斜杠，然后忘了它会被特殊解释。

## 5. 锚点符号：`^` 和 `$` [00:35]

### 5.1 又一个漏洞：一整句英文也算有效 [00:35]

回到代码。现在虽然要求以 `.edu` 结尾、以用户名开头，但我们还是太宽容了。这对于我自己的邮箱 `malan@harvard.edu` 当然没问题，但如果我输入一整句话呢——比如 `My email address is malan@harvard.edu.`（注意句末还有个英文句号）？

按当前正则分析：

- 有 `@`，通过；
- `@` 左边有一个或多个字符，通过（"My email address is malan" 全是字符）；
- `@` 右边有一个或多个字符，通过；
- `@` 右边有字面的 `.edu`，通过；
- 至于 `.edu` 之后还有个句号？没问题，**因为当前的正则并没有规定"模式必须从用户名开头、必须以 .edu 结尾"**。左边还能有什么、右边还能有什么，都没说。

于是：

```text
$ python validate.py
What's your email? My email address is malan@harvard.edu.
Valid
```

一整句英文被判为有效，显然不是我们要的。

Malan 还给了现实场景：想象你用 Google Forms 或 Office 365 表单收集数据。如果你不校验输入，用户很可能填一整句话或者某个手误的内容进去，而不是真的邮箱。等你把表单里所有结果复制出来、想粘到 Gmail 或别的邮件程序里时，就炸了——**你会不小心把一整句英文当成邮箱地址粘进去**，而你的邮件程序期待的是一个邮箱地址。

### 5.2 新符号 [00:35]

```python
^   matches the start of the string                                  # 匹配字符串开头
$   matches the end of the string or just before the newline at the end of the string
#   $ 匹配字符串结尾，或者结尾换行符之前的位置
```

- **`^`**（caret，那个小尖角符号）：表示"我希望这个模式**专门**匹配字符串的开头"，不是"任意位置"，而是开头。
- **`$`**：表示匹配字符串的结尾，严格说是"字符串结尾的换行符之前"。

Malan 的吐槽：说真的，`^` 和 `$` 这俩符号，我并不觉得它们看起来像一对"反义词"（不像括号那样成双成对）。**但这就是很多年前全世界共同选定的符号，记住就行。**

对初学者而言，简单记：**`^` = 开头，`$` = 结尾。**

### 5.3 改代码 [00:35]

```python
import re

email = input("What's your email? ").strip()

if re.search(r"^.+@.+\.edu$", email):
    print("Valid")
else:
    print("Invalid")
```

虽然这下看起来更"天书"了，但意思很明确：我在开头放了 `^`，结尾放了 `$`。**这不代表我要用户输入一个 `^` 或 `$`**，这是给 `re.search` 看的特殊符号，意思是"只接受与这个模式的**完整精确匹配**"。

测试：

```text
$ python validate.py
What's your email? My email address is malan@harvard.edu.
Invalid

$ python validate.py
What's your email? malan@harvard.edu
Valid
```

### 5.4 学生提问：`$` 前面要不要加反斜杠？`^` 和 `\` 的关系 [00:35]

**问题一：`\.edu` 后面那个 `$` 前面不需要再加反斜杠吗？**

Malan：不需要。在这个语境里，`$` 本身就是特殊符号，意思是"匹配字符串结尾"，**它不代表美元、不代表货币**。反过来讲，如果我真想让用户在输入末尾**字面地**敲一个 `$`，解法也是一样的：在 `$` 前面加一个反斜杠 `\$`。那样的话，用户的邮箱就得长成 `malan@harvard.edu$` 这样——显然也不对。

所以**反斜杠的作用就是：告诉计算机别把这些符号当特殊的看，请按字面处理**。

**问题二（追问前面那个转义）：`\.edu` 里的点号本来是正则符号对吧？**

Malan：本来是。但我特意在点号前加的反斜杠就是转义字符，它告诉 `re.search`：**我这儿不要"任意字符"，我就要一个字面上的句点**。这是区分二者的唯一办法。

如果我把那个斜杠去掉，意思就变成"邮箱必须以任意一个字符 + E + D + U 结尾"。我不要那个，我要的是"句点 + E + D + U"。

Malan 顺势讲了一段编程哲学：**这是编程和技术领域的通用惯例。一旦你和我约定"用键盘上某个字符表示特殊含义"，我们必然给自己埋下一个未来的麻烦——万一哪天我们想按字面使用这个字符怎么办？** 通用的解法就是：**想办法把这个字符"转义"（escape）掉**，好让计算机明白"这不是那个特殊符号，就是它字面上的样子"。

### 5.5 学生提问：为什么用 `+`？`..*` 和 `.+` 又来了 [00:35]

**学生：** 您前面说一个表示"1 个或多个"，另一个又说"1 个 + 什么都没有"……那为什么还要加 `+`？

Malan 倒回去重讲了一遍：

- 最初的写法是 `.*@.*`：**0 个或多个字符 + `@` + 0 个或多个其它字符**；
- 后来进化成 `.+@.+`：**左边 1 个或多个字符 + `@` + 右边 1 个或多个字符**；
- 如果你没用 `+` 或者压根忘了它存在，**你完全可以用两个点加一个星号达到一模一样的效果**：`..*`——第一个点表示"任意一个字符，而且必须在"，第二个 `.*` 表示"零个或多个其它字符"；右边同理。

所以"1 次或多次"既可以写成 `..*`，也可以用更顺手的 `.+`，二者等价。**只是表达同一思想的两种方式而已。**

## 6. 字符集 `[]` 与补集 `[^...]` [00:40]

### 6.1 还有一个漏洞：还是能输入多个 `@` [00:40]

当前版本还有问题：虽然我们从字符串开头开始找用户名、也要求字面的 `.edu` 在结尾，但**那些 `.` 现在太包罗万象了**。

我能输入不止一个 `@`。为什么？因为 `@` 也是一个字符，而 `.` 的意思是"任意字符"。**说实话，我现在想塞几个 `@` 就塞几个。**

```text
$ python validate.py
What's your email? malan@harvard.edu
Valid

$ python validate.py
What's your email? malan@@@harvard.edu
Valid
```

第二个应该无效，但它被认为有效。所以我们必须对那个点号**更严格一点**——不能再甩一句"随便什么字符都行"。

### 6.2 新符号 [00:40]

```python
[]    set of characters              # 字符集
[^]   complementing the set          # 补集（取反）
```

- 你可以在 pattern 里用**方括号 `[]`**，方括号里面放一个或多个你想**具体指定**的字符；
- 或者，你也可以在方括号里放一个 `^`，**在这个语境下它的意思和"匹配字符串开头"完全不同**——它是**补集运算符（complement operator）**，意思是"**你不能匹配这里面的任何字符**"。

### 6.3 改代码：用 `[^@]+` 排除 `@` [00:40]

Malan 先把笨办法演示了一遍：如果不想允许"任意字符"，我可以写 `[abcdefg...]`，把整个字母表敲进去再加数字……

**"哦我的天，这得敲到什么时候。"** 于是他给出了更简单的写法：

```python
import re

email = input("What's your email? ").strip()

if re.search(r"^[^@]+@[^@]+\.edu$", email):
    print("Valid")
else:
    print("Invalid")
```

Malan 承认"事情开始迅速升级了"，所以**我们从左往右一个一个拆**：

- 最开头的 `^`（在方括号**外面**）：和以前一样，意思是"从字符串开头开始匹配"；
- 最末尾的 `$`：意思是"匹配到字符串结尾"；
- 这两个先当作已知项划掉；
- 中间剩下什么？
  - 左边这一段：`[` `^` `@` `]` 然后一个 `+`。`+` 的意思一如既往：**"它左边那个东西，来 1 次或多次"**；
  - 左边那个"东西"是什么？就是新语法：`[^@]`——**方括号里一个 `^` 加一个 `@`，意思是"除了 `@` 之外的任意字符"**。语法是有点怪，但这就是我们表达"键盘上除了 `@` 之外的任意字符（甚至包括键盘上不存在但确实存在的字符）"的方式；
  - 然后是一个**字面的 `@`**；
  - 然后又是同样一套 `[^@]+`：任意个"非 `@`"字符，1 次或多次；
  - 最后是一个字面的 `.edu`。

测试：

```text
$ python validate.py
What's your email? malan@harvard.edu
Valid

$ python validate.py
What's your email? malan@@@harvard.edu
Invalid
```

终于无效了。为什么？**因为我只允许中间出现一个 `@`**：按照新语法，`@` 左边的一切都不能是 `@`（可以是一或多个非 `@` 字符），`@` 右边的一切也都不能是 `@`（一或多个非 `@` 字符），最后以字面的 `.edu` 收尾。

**小结这段新语法：** 方括号让你指定一个字符集——可以直接把你想要的字符敲出来（A、B、C、D、E、F……），也可以用补集 `^` 表示"非"，后面跟上你想排除的那一个（或多个）符号。

### 6.4 学生提问：能不能用 `{m}` 限制只有一个 `@`？ [00:40]

**学生：** `@` 后面能不能用花括号 `{m}`，让 `@` 只重复一次？

Malan：完全可以。他打开 VS Code，把当前正则删掉，退回最初的样子（`.*@.*`），然后演示：

```python
import re

# 用 {m} 也可以精确指定重复次数（示意）
if re.search(r"^.{1,}@.{1,}\.edu$", email):
    print("Valid")
else:
    print("Invalid")
```

也就是说我们前面在幻灯片上看到但还没用过的**花括号语法，确实可以用来指定具体的字符数量**。

**但说实话，这样写比必要的更啰嗦。** 最好、最简单的解法说到底还是直接写 `.+`。**不过这又是一个"同一个问题多种解法"的例子。**

### 6.5 学生提问：能用同样的语法排除"整个字符串中的某个字符"吗？ [00:45]

Malan：可以。你绝对可以用同样的语法把某个字符从整个字符串中排除掉。只是眼下会稍微麻烦一点，因为我们仍然要求结尾是 `.edu`——但答案是肯定的。

### 6.6 学生提问：如果用户输入以 `.edu` 开头会怎样？ [00:45]

**学生：** 如果用户在字符串开头输入 `.edu` 会怎样？

Malan：好问题。我们回到 VS Code 用两种方式来看。

## 7. 收紧字符集：`[a-zA-Z0-9_]` [00:45]

### 7.1 还是太宽容了 [00:45]

回到 VS Code，Malan 说：**我现在还是太宽容了。** 事实上，邮箱地址里的用户名和域名是有规范要求的——世界上有一份官方标准规定邮箱地址能是什么样、里面能有哪些字符。

而我们现在等于"允许世界上除 `@` 之外的所有字符"，这太好说话了。

假设我们只允许"正常出现在单词里的字符"：字母表的字母（a-z，大小写都行）、也许一些数字、甚至还可以允许一个下划线（underscore）——这在邮箱用户名里挺常见的。

### 7.2 范围写法：用连字符 `-` [00:45]

用方括号语法可以这么写字符集。Malan 又演示了一遍笨办法：`abcdefghij`……**"哦我的天，这要敲到什么时候，我得把 26 个字母大小写全敲一遍。"**

更好的办法已经有了：**如果你想在方括号里指定一个字母范围，直接用连字符（hyphen）就行。**

- `[a-z]`：计算机会理解成"a 到 z"，**你不用敲 26 个字母**；
- 想要大写？继续写：`[a-zA-Z]`——小 a  hyphen 小 z，大 A hyphen 大 Z。**中间不要空格，不要逗号**，你就一直往下写范围就行；
- 想要数字？不用敲 `0123456789`，写 `[a-zA-Z0-9]` 就行；
- 还想支持下划线？直接在末尾敲一个 `_`。

完整版：

```python
import re

email = input("What's your email? ").strip()

if re.search(r"^[a-zA-Z0-9_]+@[a-zA-Z0-9_]+\.edu$", email):
    print("Valid")
else:
    print("Invalid")
```

注意这些字符**全部在方括号里面**，意思是"这是我要允许的一组字符"。**这里我没有在开头写 `^`**——因为我不想取补集（注意是 complement 取补集，不是 compliment 夸奖），我是要**明确只接受这些字符**。

右边也照做：如果我也要求域名来自同一组字符（承认这有点过窄，但先熟悉着来），就把同一串字符集粘贴过去。

测试：

```text
$ python validate.py
What's your email? malan@harvard.edu
Valid

$ python validate.py
What's your email? david_malan@harvard.edu
Valid

$ python validate.py
What's your email? malan@@@harvard.edu
Invalid
```

最后一个为什么无效？因为**当前正则只允许中间出现一个 `@`**——左边的一切必须是字母、数字或下划线，右边同理，最后才是 `.edu`。

Malan 的鼓励：**说实话，这就是你在真实世界里可能会习惯性敲出来的那种正则。它看起来是有点天书，但这正是正则的世界。随着时间推移你会越来越习惯这套语法。**

## 8. 内置简写：`\w` `\W` `\d` `\D` `\s` `\S` [00:50]

### 8.1 用 `\w` 取代那一大串 [00:50]

好在，有些模式实在太常用了，于是有了**内置的简写**。也就是说你不必每次都把想包含的符号敲一遍，因为大概率早有别的程序员遇到过同样的问题。

我们可以把 `[a-zA-Z0-9_]` 这一整串删掉，换成一个 **`\w`**：

```python
import re

email = input("What's your email? ").strip()

if re.search(r"^\w+@\w+\.edu$", email):
    print("Valid")
else:
    print("Invalid")
```

**`\w` 代表一个 "word character"（单词字符）**，也就是常说的字母数字符号（alphanumeric）**加上下划线**。它和 `[a-zA-Z0-9_]` 完全等价。

> Malan 在这里说了句：**"Thanks, hard-working programmers!"**（谢了，勤劳的程序员们！）

右边同样处理：把整段方括号替换成一个 `\w`。

现在虽然仍然是"天书"，但比起前几版已经友好多了。来读一遍：

- `^`：从字符串开头开始匹配；
- `\w`：任意单词字符；
- `+`：1 次或多次；
- `@`：字面的 `@`；
- `\w+`：再任意单词字符 1 次或多次；
- `\.`：字面点号；
- `edu`：字面 edu；
- `$`：匹配到字符串结尾。就这些。

### 8.2 完整的简写清单 [00:50]

```python
\d    decimal digit                                # 十进制数字
\D    not a decimal digit                          # 非十进制数字
\s    whitespace characters                        # 空白字符
\S    not a whitespace character                   # 非空白字符
\w    word character, as well as numbers and the underscore   # 单词字符（含数字和下划线）
\W    not a word character                         # 非单词字符
```

逐条解释：

- **`\d`**：任意十进制数字（decimal digit），也就是 0-9；
- **`\D`**：`\d` 的反面/补集——任何**不是**数字的东西，可能是字母、标点或其它符号；
- **`\s`**：空白字符（whitespace），比如敲一下空格键，或者按一下 Tab 键，这些都算空白；
- **`\S`**：`\s` 的反面——任何**不是**空白的字符；
- **`\w`**：单词字符，加上数字和下划线；
- **`\W`**：`\w` 的反面——除了单词字符以外的一切。

Malan 总结：这些也都是"太多人在用、于是被直接烤进正则语法里"的常见模式，好让你更简洁地表达同样的想法。本讲不会把它们全用一遍，但你要知道有这些。

### 8.3 学生提问：`[]` 里面能不能放"列表"？——引出 `|` 和 `()` [00:50]

**学生：** 想问的是上一个方括号的写法……我们能在里面接受"列表"吗？

Malan：可以，而且我们马上就会看到。他顺势演示：假设你不想只接受 `.edu`，还想接受 `.edu` 或 `.com`：

```python
import re

email = input("What's your email? ").strip()

if re.search(r"^\w+@\w+\.(com|edu|gov|net|org)$", email):
    print("Valid")
else:
    print("Invalid")
```

你可以引入**圆括号**，然后把几个选项用"或"连起来：`com`、`edu`、`gov`、`net`、`org`……**这里的每一根竖线 `|` 都有特殊含义：它就是"或"（or）。而圆括号只是把这些东西"分组"（group）在一起。**

正式的语法是这样：

```python
A|B     either A or B        # A 或 B，A 和 B 可以是任意其它模式
(...)   a group              # 一个分组
(?:...) non-capturing version # 非捕获版本（后面会讲）
```

`A|B` 表示"A 必须匹配，或者 B 必须匹配"，其中 A 和 B 可以是任何你想要的模式。括号则用来把若干想法**组合**在一起——**就像数学里一样**，你可以把几个概念合并成一个短语，然后说"要么这个、要么那个"。

### 8.4 学生提问：正则里能放空格吗？ [00:55]

**学生：** 如果我们在表达式里放空格会怎样？

Malan：如果你想要空格，**光用 `\w` 是不行的**，因为 `\w` 只是单词字符，即字母、数字、下划线。但你有两个办法：

**办法一：回到方括号写法**，在方括号里直接敲一个空格：

```python
import re

email = input("What's your email? ").strip()

if re.search(r"^[a-zA-Z0-9_ ]+@[a-zA-Z0-9_]+\.edu$", email):
    print("Valid")
else:
    print("Invalid")
```

注意方括号里那个字面空格——**你可以在方括号里放一个字面的空格**，这样就能识别空格了。

**办法二：仍然用 `\w`，但把它和 `\s` 组合起来**：

```python
import re

email = input("What's your email? ").strip()

if re.search(r"^(\w|\s)+@\w+\.edu$", email):
    print("Valid")
else:
    print("Invalid")
```

回忆一下 `\s` 是空白字符。把它俩放进圆括号里，就表示"**要么匹配左边的东西，要么匹配右边的东西，1 次或多次**"。而且 `\s` 比"一个空格"含义更广，它还可以是 Tab。

### 8.5 学生提问：`\w` 包含点号吗？为什么以前能接受空格现在不行了？ [00:55]

**学生追问 1：** `\w` 里面包含点号吗？

Malan：不包含。**`\w` 只包含字母、数字和下划线，就这些。**

**学生追问 2：** 您开头举过一个带空格的例子，比如 "this is my email, so-and-so"。我觉得我们当前的版本（甚至更早的某个版本）就已经不接受它了——是因为 `^` 吗，还是别的原因？

Malan：不是 `^` 的功劳。原因是这样的：

- 最初我们用的是 `.*` 或 `.+`，也就是**任意字符**——所以空格是能进来的；
- 之后我们改成"除了 `@` 之外的任意字符"——**这里面仍然包括空格**；
- **只有当我们开始用方括号写 `a-z`、`0-9`、下划线之后，我们才终于开始拒绝空白。**

Malan 当场用当前版本（用 `\w` 的那版）跑了一遍验证：

```text
$ python validate.py
What's your email? My email address is malan@harvard.edu.
Invalid
```

现在无效了，因为**空格不是单词字符**。

不过他也主动指出当前的另一个缺陷：**技术地说，我现在也不允许点号。** 你们有些人可能已经在想了——"等等，我的 Gmail 地址里是有点的"。**这一点我们待会儿还得修。所以 `\w` 并不是终极答案，它只是让我们把前一个解法写得更简洁。**

## 9. 大小写敏感性（Case Sensitivity）[01:00]

### 9.1 翻车：`MALAN@HARVARD.EDU` 是无效的 [01:00]

我们还有一件事没处理好：**大写与小写**。

`\w` 技术上说**是**同时处理小写和大写的（因为它等价于之前那串包含 `a-z` 和 `A-Z` 的字符集）。但请看：

```text
$ python validate.py
What's your email? MALAN@HARVARD.EDU
Invalid
```

为什么？我全大写地（"喊着"）输入我的邮箱，结果无效。明明 `\w` 是包含大小写的啊？

**学生回答：** 因为你要求的是小写的 `.edu`，而你输入的是大写。

**Malan：正是。** 我用全大写输入，但我的 pattern 里写的是字面的 `.edu`（小写）。

> Malan 还开了个玩笑：看到大家都戴着 AirPods 和耳机，他很抱歉刚才为了演示"喊"了一声。

### 9.2 三种解法 [01:00]

**解法一：强行把用户输入转成小写。** 在第一行末尾加 `.lower()`：

```python
import re

email = input("What's your email? ").strip().lower()

if re.search(r"^\w+@\w+\.edu$", email):
    print("Valid")
else:
    print("Invalid")
```

**解法二：晚一点再转。** 不是在第一行转，而是在传给 `re.search` 的时候传 `email.lower()`：

```python
import re

email = input("What's your email? ").strip()

if re.search(r"^\w+@\w+\.edu$", email.lower()):
    print("Valid")
else:
    print("Invalid")
```

因为**邮箱地址本来就应该是不区分大小写的**，所以这两种都行得通。

**解法三（本讲重点）：用 `re.search` 的第三个参数——flags（标志位）。**

### 9.3 flags 是什么 [01:00]

回忆一下，`re.search` 是支持第三个参数的，那就是所谓的 flags。**flag 就是配置选项（configuration option）**，通常传给某个函数，用来把它的行为配置得稍微不一样一点。

`re` 这个库自带了几个"内置变量"（可以理解为常量），对 `re.search` 有专门的含义：

```python
re.IGNORECASE    # 忽略大小写
re.MULTILINE     # 多行模式
re.DOTALL        # 让 . 也能匹配换行
```

- **`re.IGNORECASE`**：传给 `re.search` 之后，它会**忽略用户输入的大小写**。大写、小写、混着写都行，一视同仁，按不区分大小写处理。
- **`re.MULTILINE`**：如果你想处理可能跨多行的用户输入——比如用户不是只填了个邮箱，而是填了整整一段文字，你想分别匹配其中的不同行——就用这个。
- **`re.DOTALL`**：用它可以把 `.` 配置成"不只匹配除换行外的任意字符，而是连换行一起匹配"。

本讲只用第一个。

### 9.4 改代码：加上 `re.IGNORECASE` [01:00]

```python
import re

email = input("What's your email? ").strip()

if re.search(r"^\w+@\w+\.edu$", email, re.IGNORECASE):
    print("Valid")
else:
    print("Invalid")
```

测试：

```text
$ python validate.py
What's your email? MALAN@HARVARD.EDU
Valid
```

现在有效了，因为我明确告诉 `re.search`：请忽略输入的大小写。

**为什么选这个方案，而不是 `.lower()`？** Malan 的回答很实在：**如果出于某种原因我并不想真的修改用户的输入，那么这个方案可以在不改变变量本身值的前提下，依然按不区分大小写的方式处理它。**

### 9.5 学生提问：pattern 是字符串，能用 f-string 吗？ [01:00]

**学生：** 这个 pattern 是个字符串对吧？那我们能用 f-string 吗？

Malan：可以。**你当然可以用 f-string**，比如把某个变量的值插进去再传给函数。

### 9.6 学生提问：`\w` 这种能由用户输入吗？ [01:00]

**学生：** `\w` 这种东西，能作为用户的输入吗？

Malan：技术上可以。只是这不是我们现在要解决的问题——我们想让用户提供的是**字面输入**，比如他们的邮箱地址，而不是一个正则表达式。

**但你完全可以想象有这样一种软件**：它面向更高级的用户，会请用户输入一个正则表达式，用来校验别的东西。事实上 Google 就是这么做的——你在 Google Forms 里选了"响应验证 → Regular expression"，Google 就让你我输入自己的正则，这正好就是这种场景。

## 10. 子域问题：`?` 与分组 `()` 的实战 [01:05]

### 10.1 又翻车：`malan@cs50.harvard.edu` 无效 [01:05]

回到上一版（已经加了忽略大小写）。现在 Malan 输入他的另一个邮箱——不是主要用的 `malan@harvard.edu`，而是 `malan@cs50.harvard.edu`（这个地址会自动转发到前者）。

```text
$ python validate.py
What's your email? malan@cs50.harvard.edu
Invalid
```

嗯？无效？可我很确定这确实是我的邮箱啊。**原因是什么？**

**学生回答：** 因为 `@` 后面出现了一个点号。

**Malan：正是。** `cs50` 后面有个点。而我那儿并没有期待任何点号——我只期待单词字符，也就是 a-z、0-9 和下划线。所以得改造。

### 10.2 更一般化：域名里可以有多个点 [01:05]

理论上还可能有更长的地址，比如 `malan@something.cs50.harvard.edu`（虽然这个并不真实存在，但它是可能的）。**域名里当然可以有多个点**，就像这里看到的这样。要是能一并处理就好了。

### 10.3 天真的改法：直接加一段 [01:05]

既然要支持子域，那就再加一段"1 个或多个单词字符 + 一个字面点号"：

```python
import re

email = input("What's your email? ").strip()

if re.search(r"^\w+@\w+\.\w+\.edu$", email, re.IGNORECASE):
    print("Valid")
else:
    print("Invalid")
```

测试：

```text
$ python validate.py
What's your email? malan@cs50.harvard.edu
Valid
```

成功了。**但是——有人看出这要往哪儿发展了吗？**

```text
$ python validate.py
What's your email? malan@harvard.edu
Invalid
```

**我把自己的邮箱给搞坏了。** 一路走来它一直都能用，现在终于崩了。

### 10.4 逻辑上的解法：让这一段变成"可选" [01:05]

怎么办？

- 办法一：用两个正则，一个匹配 `username@domain.tld`，另一个匹配 `username@subdomain.domain.tld`（TLD = Top Level Domain，顶级域名，比如 edu）；
- 办法二（Malan 更喜欢）：**我不想要两个正则，也不想要一个两倍长的正则。为什么不直接告诉 `re.search`：这个模式的某一部分是可选的（optional）？**

那么，我们前面见过哪个符号可以表示"它前面的东西是可选的"？

- **学生 A：** 竖线？我们之前用竖线来做"可选"。
- **Malan：** 也可以。我们可以用竖线加圆括号说"要么这儿有点东西，要么这儿什么都没有"。但我觉得有更简单的办法。
- **学生 B：** 其实是问号。

**Malan：没错，问号！** 回想第一批符号表：除了 `.`、`*`、`+`，还有一个 `?`，意思是**"0 次或 1 次重复"**，也就是说——**可选**。要么在（1 次），要么不在（0 次）。

### 10.5 正确的改法：`(\w+\.)?` [01:05]

第一步，先用圆括号把这一段包起来。**注意：这不代表我要用户真的输入一个括号**，我只是想把这几个字符组合在一起。

```python
import re

email = input("What's your email? ").strip()

if re.search(r"^\w+@(\w+\.)?\w+\.edu$", email, re.IGNORECASE):
    print("Valid")
else:
    print("Invalid")
```

逐步测试：

```text
$ python validate.py
What's your email? malan@cs50.harvard.edu
Valid

$ python validate.py
What's your email? malan@harvard.edu
Invalid     # 还没加 ? 之前

$ python validate.py
What's your email? malan@harvard.edu
Valid       # 加了 ? 之后

$ python validate.py
What's your email? malan@cs50.harvard.edu
Valid       # 依然有效
```

**关键理解：** 括号后面那个 `?`，告诉 `re.search`——**括号里这一整块，要么出现一次，要么干脆不出现（0 次）**。

Malan 逐段解读最终版（把 `@` 之后、`$` 之前的部分划出来）：

- 右边这部分 `\w+\.edu` 和以前一样：`\w+` 就是 Harvard 或 Yale 之类的名字，`\.edu` 是字面的 `.edu`；
- **新增的部分**是：圆括号里有一段 `\w+` 加 `\.`，也就是 `(\w+\.)`；
- 后面紧跟一个 `?`，意思是"**括号里这一整块可以在，也可以不在**"，两者都可接受；
- **所以 `?` 的本质作用就是"让某个东西变成可选"。**

**这里有个极易犯的错误：** 如果把圆括号去掉，写成 `\w+\.?\w+\.edu`，那意思就变成了"**只有那个点号是可选的**"，这可不是我们想表达的。**我们要的是"子域 cs50 加上那个多余的点号"这个整体，要么都在、要么都不在。**

### 10.6 学生提问：如果要多于一个子域呢？ [01:05]

**学生：** 您说 `?` 是"0 次或 1 次重复"。如果我有更多呢？

### 10.7 用户名里带点：用 `|` 或字符集 [01:05]

**学生：** 这个能用在用户名上吗？

Malan：完全可以。我们还有别的问题没解决——**现在我们不允许用户名里出现句点**。而你们有 Gmail 或其它账号的人，用户名里可能不只有下划线、数字和字母，**还可能有句点**。

有了圆括号之后，可以这么做：用圆括号把 `\w` 包起来（"任意单词字符"，也就是字母/数字/下划线），**再用竖线"或"上一个别的东西，比如一个字面点号**：

```python
import re

email = input("What's your email? ").strip()

if re.search(r"^(\w|\.)+@(\w+\.)?\w+\.edu$", email, re.IGNORECASE):
    print("Valid")
else:
    print("Invalid")
```

**那个字面点号必须转义**，否则它就代表"任意字符"，那就是倒退（regression）了。现在的意思变成：你的用户名必须是"一个单词字符（a-z 大小写、0-9、下划线）**或者**一个字面点号"。

**另一种写法：不用圆括号和竖线，改用字符集：**

```python
import re

email = input("What's your email? ").strip()

if re.search(r"^[a-z0-9_\.]+@(\w+\.)?\w+\.edu$", email, re.IGNORECASE):
    print("Valid")
else:
    print("Invalid")
```

这里手写 `a-z`、`0-9`、下划线，再加一个转义的点号 `\.`。而且**技术上说我已经不需要大写 `A-Z` 了**，因为我本来就告诉计算机忽略大小写，二选一即可。

**哪个更好？这取决于你自己。你觉得哪个更易读，哪个通常就是更好的设计。**

## 12. `re.match` 与 `re.fullmatch` [01:10]

除了正则本身，`re` 库里还有别的函数。其中两个是 `re.match` 和 `re.fullmatch`。

- **`re.match`**：和 `re.search` 非常像，**唯一的区别是：如果你希望"从字符串开头开始匹配"，你不需要自己写 `^`。** `re.match` 按设计就会自动从字符串开头开始匹配。
- **`re.fullmatch`**：精神类似，但它**不只从开头匹配，还要求匹配到结尾**——所以你连 `^` 和 `$` 都不用写了。

```python
import re

email = input("What's your email? ").strip()

# 用 re.match：不用写 ^
if re.match(r"\w+@\w+\.edu", email, re.IGNORECASE):
    print("Valid")

# 用 re.fullmatch：^ 和 $ 都不用写
if re.fullmatch(r"\w+@\w+\.edu", email, re.IGNORECASE):
    print("Valid")
```

想了解更多，去看 Python 官方文档里关于 `re` 的部分。

## 13. 清理用户输入（Cleaning Up User Input）· `format.py` [01:15]

### 13.1 场景：用户永远不按你说的填 [01:15]

Malan 说：这一节换一类问题。前面我们只是**校验**用户的输入，看它长得对不对。现在假设**用户根本不会按我们想要的方式输入**，所以我们必须去**清理**它。

这在使用 Google 表单、Office 365 表单或任何收集用户输入的工具时**极其常见**。**不管你的表单问题写得多么清楚，用户都不一定照做**，他们可能按另一种格式填进来。

你当然可以把结果下载成 CSV、或者打开 Google 电子表格 / Excel，**手动**把所有数据清理一遍。但如果你有成堆的提交——几十行、几百行、几千行——手动做可就一点都不好玩了。**更有效的做法是写一段 Python 代码，让它帮你清理这批数据，以及未来的任何一批数据。**

### 13.2 目标：把 "Malan, David" 规范化成 "David Malan" [01:15]

关掉 `validate.py`，新建一个 `format.py`。这次要重新格式化的数据是**用户的姓名**。

我们希望用户好好填，比如 `David Malan`。但有些用户出于习惯会把名字"倒过来"填，中间加个逗号，比如 `Malan, David`。两种写法人类都读得懂，但如果你想**标准化（standardize / canonicalize）**数据在你系统里的存储格式（数据库也好、CSV 文件也好），那就应该保证：无论用户怎么填，你打出来的名字格式永远一致——比如永远是 `David Malan`，没有逗号、没有颠倒。

### 13.3 版本一：原样打印 [01:15]

```python
name = input("What's your name? ").strip()
print(f"hello, {name}")
```

这基本上就是一个 "hello world" 程序。照例先 `.strip()` 掉首尾空白——万一用户不小心敲了空格，我们不想让它进到数据集里。

测试：

```text
$ python format.py

hello, David Malan

$ python format.py
What's your name? Malan, David
hello, Malan, David
```

第二种明显不对（至少语法上不对），应该输出 `hello, David Malan` 才对。

### 13.4 版本二：用 `split(", ")` 拆开 [01:15]

你当然可以加一些 `if` 条件，在用户填了逗号或者把名字填反的时候**拒绝**他的输入。但那就**太少也太晚了**——如果用户已经在线提交了表单、数据已经在你手里，你现在需要去清理它。而跑到 Google 表格、Apple Numbers 或 Microsoft Excel 里手动修一堆人的名字（去掉逗号、按美国习惯把名字挪到姓前面）一点也不好玩。

于是先来个朴素写法（Malan 承认它有点脆弱 fragile）：

```python
name = input("What's your name? ").strip()
if "," in name:
    last, first = name.split(", ")
    name = f"{first} {last}"
print(f"hello, {name}")
```

要点：

- `if "," in name` 是很 Pythonic 的问法："这个短字符串在不在那个长字符串里？"
- 如果有逗号，就用 `split(", ")` 切——**注意切的不只是逗号，还有逗号后面那个空格**（假设人类会在逗号后敲一个空格）；
- `last, first = ...` 同样是解包，把 "Malan, David" 拆成两个变量；
- 然后**强行把用户的名字改成我们期望的格式**：`name = f"{first} {last}"`，也就是用 f-string 把名和姓用一个空格拼起来，**覆盖**掉原来的 `name` 变量。

测试：

```text
$ python format.py
What's your name? David Malan
hello, David Malan

$ python format.py
What's your name? Malan, David
hello, David Malan
```

搞定。虽然事情很小，**但清理用户输入这种需求实在太常见了**，这里就演示了至少一种简单的做法。

> Malan 的补充：现在这个程序是交互式的，是用户（比如他自己）在往里敲名字。但想象一下，数据本来就已经在一个 CSV 文件里了，来自 Google 表单或某个线上流程。你可以写非常类似的代码，只是先去把那个文件读进内存——也许是通过 `csv` 的 reader 或 DictReader——然后遍历每一个名字。这里我们保持简单，一次处理一个名字。

**翻车二：逗号后面没空格 —— 直接抛异常。**

```text
    ^^^^^^^^^^^

```

**为什么会有 `ValueError`（一个真正的异常）？**

因为 `split` 的本职工作是：靠寻找"逗号 + 空格"把一个字符串切成**两个**字符串。可是如果输入里**根本没有"逗号 + 空格"**，它就切不出两个东西来。**而左边我写了两个变量，右边只回来一个值，于是就炸了。**

### 13.6 用正则让它变结实 [01:20]

**Malan 的感叹：** 这写法确实是脆弱的，但要是能改进一下就好了。比如说，我们刚学了正则语法，**要是我想让那个空格变成"可选"的，该怎么办？**

我可以用新学的正则语法加一个 `?`——**`?` 的意思是"它左边那个东西出现 0 次或 1 次"**。这里的"左边那个东西"就是一个字面的空格。因为只有一个字符，我连括号都不用加。于是模式就变成：**必须有一个逗号，然后那个空格可有可无（0 个或 1 个空格）**。

**但问题是：`str` 自带的那个 `split` 版本并不支持正则表达式。** 想要正则，就得去用那个库。

### 13.7 版本三：改用 `re.search` + 捕获组 [01:20]

```python
import re

name = input("What's your name? ").strip()
matches = re.search(r"^(.+), (.+)$", name)
if matches:
    last, first = matches.groups()
    name = first + " " + last
print(f"hello, {name}")
```

逐行拆解 Malan 的思路：

1. 顶部 `import re`；
2. 用 `re.search` 去找一个"姓, 名"这样的模式。怎么表达 `Malan, 空格, David`？
   - 先有"某个东西" → `.+`；
   - 然后一个逗号 `,`；
   - 然后一个空格；
   - 然后"某个东西" → `.+`；
3. **提前加固**：我希望这整个模式**从用户输入的开头开始匹配**，所以立刻加上 `^`；我也希望**匹配到用户输入的结尾**，所以加上 `$`。于是整体意思是：任意字符 1 次或多次，然后一个逗号，然后一个空格，然后任意其它字符 1 次或多次，**然后就没有了**；
4. 第二个参数照旧传 `name` 变量。

**这里出现了一个关键的新概念：捕获（capture）。**

前面我们用 `re.search` 只是拿它来回答一个是/否的问题（用户的输入匹配不匹配这个模式，本质上是 True/False）。**但 `re.search` 其实比这强得多——你能拿回更多信息。**

具体做法是：指定一个变量加一个赋值运算符，接住返回值，然后得到更精确的答案。

**那你想拿回什么呢？** 这就要说到正则的另一个特性：**圆括号除了"分组"，还可以用来"捕获"。**

> 事实上，**当你在正则里写圆括号时，在我们还不知情的情况下，括号里的所有内容都会被作为返回值从 `re.search` 交还给你。** 这让你可以从用户自己的输入里**提取**特定的信息。
>
> 你也可以反向操作，使用**非捕获版本**：写圆括号，然后紧接着一个 `?` 和一个 `:`，再写别的内容。这就表示"别捕获这个，我只是想分组"。**不过这一节我们先只用普通圆括号。**

所以，如果我想拿回用户的姓和名，我要捕获的就是逗号左边的 `.+` 和逗号右边的 `.+`。**我特意给这两个 `.+` 都加上了圆括号——不是为了分组（我既没加 `?` 也没加 `+` 或 `*`），而是为了捕获。**

接着：

```python
if matches:
    last, first = matches.groups()
```

- 依然问一个布尔问题："如果有匹配（matches）的话，就做这些"；
- 如果 `matches` 不是假值（不是 `None`），说明我确实拿到了一些匹配；
- 然后 `last, first = matches.groups()`——**把所有被括号捕获到的"组"（groups）一次性取回来**；
- 再像以前一样用 f-string 更新 `name`；
- 最后照旧 `print(f"hello, {name}")`。

**怎么取到这些返回值？** 你让那个接住返回值的变量（`matches`）交出它所有的 **groups**，也就是所有被圆括号捕获到的分组。

测试：

```text
$ python format.py
What's your name? David Malan
hello, David Malan
```

这种情况下 `if` 里什么都不执行——**因为我没有输入逗号，`re.search` 找不到逗号，所以没有匹配（matches 是 `None`）**，于是直接打印 `hello, name`，没什么新鲜的。（对应锚点 [01:25] "so there are no matches."）

```text
$ python format.py
What's your name? Malan, David
hello, David Malan
```

这下名字被重新格式化了。

### 13.8 更明确：`matches.group(1)` 与 `matches.group(2)` [01:25]

其实我没必要只说 `matches.groups()`，**我可以明确指定要哪几个组**：

```python
import re

name = input("What's your name? ").strip()
matches = re.search(r"^(.+), (.+)$", name)
if matches:
    last = matches.group(1)
    first = matches.group(2)
    name = f"{first} {last}"
print(f"hello, {name}")
```

**注意这里的 `group` 是单数（没有 `s`）。**

**为什么是 1 和 2？** 因为这是**逗号左边第一组圆括号**，和**逗号右边第二组圆括号**。按照输入：

- 第一组 = 用户的姓（本例中是 `Malan`）；
- 第二组 = 用户的名（本例中是 `David`）。

所以我用 `group(1)` 取姓、`group(2)` 取名。

### 13.9 再精简：直接拼接 [01:25]

既然这两个变量我马上就要用掉，就没必要单独存了，直接收紧：

```python
import re

name = input("What's your name? ").strip()
matches = re.search(r"^(.+), (.+)$", name)
if matches:
    name = matches.group(2) + " " + matches.group(1)
print(f"hello, {name}")
```

`group(2)` 和 `group(1)` 用一个空格**拼接（concatenate）**起来。第一组是逗号左边的东西，第二组是逗号右边的东西。**所以如果我想把它们翻过来更新 `name`，我就先取 `group(2)`、加一个空格、再拼上 `group(1)`。**

### 13.10 学生提问：为什么是 1 和 2，而不是 0 和 1？ [01:25]

**学生：** 为什么这里我们用 1 和 2 来捕获，而不是从 0 和 1 开始？

Malan：非常好的问题，很好的观察。**在几乎所有其它场合，我们都是从 0 开始数的（0 和 1），而不是 1 和 2。**

**原因是：`re.search` 返回的东西里，位置 0 上还有别的内容，它跟字符串本身有关。** 所以**仅就这个函数的文档而言**：`1` 是第一个圆括号，`2` 是第二个圆括号，往后以此类推。**这里只是换了一套约定而已。**

### 13.11 学生提问：如果输入是"空白 + 逗号 + 空白"怎么办？ [01:25]

**学生：** 如果我们什么都不写，比如"空白、逗号、空白"，怎么判断条件真假？

Malan 先不直接回答，而是**先跑一遍确认没把东西改坏**：

然后他说：我觉得下面这种情况**还是会崩**。跑第三次，输入 `Malan,David`（逗号后无空格）——确实还是崩的。**为什么？因为我还在找"逗号 + 空格"。**

**怎么修？** 一种办法是加一个 `?`，它表示"它左边的东西 0 个或 1 个"。如果我写"空格 + `?`"（因为只有一个字符，不需要括号），那我就**同时容忍** `Malan, David`（有空格）和 `Malan,David`（无空格）：

### 13.12 空格敲多了怎么办：`*` 上场 [01:25]

再试一次：这次我手抖多敲了好几下空格，两个词隔得特别开。这还是不行——因为 `.+` 会把那些空白全吃掉（变成名字的一部分）。

两种处理办法：

- 对结果再做一次左右 `.strip()`，去掉首尾空白；
- 或者，**把 `?` 换成 `*`：**

```python
import re

name = input("What's your name? ").strip()
matches = re.search(r"^(.+), *(.+)$", name)
if matches:
    name = matches.group(2) + " " + matches.group(1)
print(f"hello, {name}")
```

**注意正则里新增的那个 `*`。** 这段代码现在：

- 能接受并正确处理 `Malan,David`（无空格）；
- 也能处理 `Malan,     David`（David 前面有一堆空格）。

> 这是官方 Notes 的最终版（用 `*`，而不是 `?`）。

**Malan 的总结：** 你可以想象，**你正在清理的数据有多脏，你的正则就得有多复杂。这完全取决于你想一次解决多少个问题。**

### 13.13 海象运算符 `:=` [01:30]

Malan 说：在使用正则时，像我们前面这样写是**极其常见的**——用带捕获括号的 `re.search` 调一次，把返回值接到一个我叫做 `matches` 的变量里（你当然可以叫别的名字，但默认我叫它 `matches`），然后**下一行**再写 `if matches`。

**要是能把它们收紧到同一行，岂不美哉？** 是可以的。

先看看"错误"的尝试。Malan 说：我先把那个 `if` 删掉，试图写成这样——

```python
if matches = re.search(r"^(.+), *(.+)$", name):   # 语法错误！
```

**这在 Python 里是不行的。** 他解释：在 C、C++ 或 Java 里，你确实可以这么干——把整个赋值表达式用括号包起来（有时还要套两层括号来消除警告）——**如果你想同时做两件事**：既把 `re.search` 的返回值赋值给 `matches`，又紧接着问一个布尔问题"它本质上是真还是假"。

而这正是我们刚才在做的事（先是接住返回值赋给 `matches`，然后再提问）。**看起来，需要写两行代码这件事困扰大家太久了，于是 Python 现在允许你把这两类行合并成一行。**

**但你需要一个新的运算符。** 你不能写 `if matches = re.search(...)` 然后以冒号结尾，**你必须写成 `:=`**——当且仅当你想同时做两件事：**从右往左赋值**，并且**在同一行上问一个 `if` 或 `elif` 的问题**。

```python
import re

name = input("What's your name? ").strip()
if matches := re.search(r"^(.+), *(.+)$", name):
    name = matches.group(2) + " " + matches.group(1)
print(f"hello, {name}")
```

**这个运算符被亲切地称为"海象运算符"（walrus operator）**，是 Python 近几年才有的新特性。它既允许你像上面这样**从右往左赋值**，又允许你**对它提一个布尔问题**（用 `if`，或者等价的 `elif`）。

**为什么叫海象运算符？** 你把头侧过来看看 `:=` ——如果你熟悉海象的样子，它多少有点像一只海象（两个点是眼睛，冒号是两颗牙）。

Malan 的评价：这是个次要细节，也是 Python 相对较新的特性，但说实话，既然它已经存在了，**你在网上、源码里、教科书里见到它的频率只会越来越高。它不改变任何逻辑。**

```text
$ python format.py
What's your name? Malan, David
hello, David Malan
```

照样能修好，只是把代码收紧了一点。

### 14.7 版本三：`removeprefix` [01:40]

怎么改进、一个一个把这些问题解决掉？

```python
url = input("URL: ").strip()
```

### 14.8 引入 `re.sub` [01:45]

**Malan 的推进：** 事实上，**正则就是能让我们更精确地表达模式。** 我们可以花一整天用 `removeprefix`、`remove`、`strip` 等等各种 Python 函数慢慢逼近正确答案，**但一个正则能让你（ admittedly 更天书地）更简洁地表达这类模式和目标。**

而且我们现在已经有了圆括号这个工具——**它不只是能把符号分组，还能捕获信息**——这可是我们工具箱里非常强大的一件武器。

于是回到文件，顶部 `import re`，然后用一个新函数：**不是 `re.search`，也不是 `re.match` / `re.fullmatch`，而是 `re.sub`**——`sub` 就是 **substitute（替换）**。

它的参数更多一些，但都很直白：

```python
re.sub(pattern, repl, string, count=0, flags=0)
```

- `pattern`：你要找的正则，也就是那个模式；
- `repl`：replacement string（替换串）——你想把那个模式换成什么；
- `string`：你想在哪个字符串上做这个替换；
- 后面还有几个参数，Malan 说"我先挥挥手带过"——其中包括那些**同样的 flags**，还有一个 **`count`**：你想做几次查找替换？全部？还是只做一次？就像在 Google Docs 或 Microsoft Word 里那样，你可以进一步控制。

### 14.9 版本四：最简单的 `re.sub` [01:45]

```python
import re

url = input("URL: ").strip()

username = re.sub(r"https://twitter.com/", "", url)
print(f"Username: {username}")
```

- 第一个参数：正则 `"https://twitter.com/"`；
- 第二个参数：想把它换成什么？和之前简单 `str.replace` 一样——换成"什么都没有"，也就是干脆删掉；
- 第三个参数：在哪个字符串上做？用户给的那个 `url`；
- 把 `re.sub` 的返回值赋给变量 `username`。

**`re.sub` 的"人生目标"就是：把某个值替换成某个正则所匹配的内容，做若干次。** 本质上它就是**用正则实现的"查找并替换"**，并且它会把替换完成之后的字符串返回给你。

```text

```

### 14.10 逐个解决问题（一）：加 `^`，但不加 `$` [01:45]

它还是有点脆弱。Malan 又请学生来提：现在该先解决哪个问题？

**学生：** 协议，还有域名前缀。

Malan：好。**协议（HTTP vs HTTPS）**，还有**子域 www（可能有没有）**。另外还有几个错误我们也要处理。

**学生：** 如果我们像你之前那样输入一整句话，问题还是一样，因为它没有考虑开头那部分文本。

Malan：对。**我可能还是允许 URL 左边出现一些英文单词，因为我没有用 `^`。** 这个我来修。

**学生：** 可能是 `http`，或者斜杠少于两个。

Malan：好的。可能是 `http`（这个前面在协议那条里提过了）。**至于"斜杠少于两个"——这个我不管。如果用户给我一个斜杠而不是两个，那是真正的用户错误（user error）。** 我当然可以容忍它，但说真的，到那个程度我更愿意甩一条错误信息给用户说"请修正你的输入"。**否则我们可能在这儿待一整天去处理所有可能的拼写错误。** 我认为，出于可用性（usability）或者说用户体验（user experience，UX）的考虑，**我们至少要容忍所有"可能合法的输入"或者"合理的输入"。**

于是开始动手。**第一个要解决的问题：从字符串开头开始匹配。** 在开头加 `^`。

**但末尾不要加 `$`**，为什么？因为我不想一直匹配到最后——我要在后面留出纳用户名的位置。所以我们只需要 `^`：

```python
import re

url = input("URL: ").strip()

username = re.sub(r"^https://twitter.com/", "", url)
print(f"Username: {username}")
```

### 14.11 逐个解决问题（二）：一个没人提到的隐蔽 bug [01:45]

Malan 说：**这里有一个还没人提到的隐蔽 bug（subtle bug）。** 我把它高亮出来，看你能不能一眼看出来。

**他把 `twitter.com` 里的那个点号高亮了。为什么我要高亮 `twitter.com` 里那个明明应该存在的点号？**

**学生：** 因为没加反斜杠的点号表示"除换行外的任意字符"。

**Malan：对，就是这个意思。** 所以我可以输入 `twitter?com`、`twitterXcom` 之类的，全都会被容忍。**其实也没那么糟**（用户干嘛要这么填呢），**但如果我想写对、想能正确地测试自己的代码，我就该把这个细节弄对。**

这个修复很容易，**但它是个非常常见的错误**：**任何时候你在写正则，而它恰好涉及特殊符号——比如 URL 或域名里的点号、涉及货币时的 `$` 符号——记住你很可能确实需要用反斜杠把它转义掉。**

```python
import re

url = input("URL: ").strip()

username = re.sub(r"^https://twitter\.com/", "", url)
print(f"Username: {username}")
```

### 14.12 逐个解决问题（三）：协议 `http` 还是 `https` [01:45]

HTTPS 是好事，意味着安全、有加密，你当然喜欢看到 HTTPS。但人们还是会输入或复制 `http`。

**最简单的修法是什么，才能同时容忍 `http` 和 `https`？** Malan 先给出一个可行的写法：`http|https`（`|` 表示 A 或 B）。**但他说我觉得可以更聪明一点，让代码更简洁。** 于是问学生有什么建议。

**学生：** 我们可以在 S 后面加个问号。

**Malan：完美，就用问号。**

> 注意这里同学说的是"在 S 后面加问号"，即 `https?`——`?` 作用在它前面的 `s` 上，让 `s` 变成可选，于是 `http` 和 `https` 都能匹配。

两种写法都可行：

```python
# 写法一：显式（更啰嗦）
r"^(http|https)://twitter\.com/"

# 写法二：让 s 可选（更简洁）
r"^https?://twitter\.com/"
```

Malan 的取舍建议：如果你想在代码里超级明确，没问题，用括号写 `http` 或 `https`，好让你、你的读者、你的老板、你的老师都一眼看懂你在干什么。**但如果你一直采用更啰嗦的写法，它反而可能变得不好读——尤其当你的正则从"这么大"变成"这么大"的时候。**

**所以能在省地方的地方就省地方。** 而且他论证道：只要你养成了读正则的习惯、知道问号**不是**字面问号、而是"它前面那个东西 0 次或 1 次"，那么 `https?` 这种写法是相当合理的——**我们相当于让那个 S 变成了可选。**

### 14.13 逐个解决问题（四）：`www.` 也要可选 [01:50]

接下来，假设我们想容忍 `www.`——它可能有也可能没有，但你真的在浏览器里访问是能用的。我可以写 `www\.`（**注意这次我在点号前加了反斜杠，免得重犯刚才那个错**）。

**但这样写也不行**——因为我现在等于**要求**它必须存在。

**怎么让 `www.` 变成可选？**（Malan 说这个问题要"hammer this home"，也就是反复敲打、务必讲透）

**学生（Maria）：** 我们可以分组——加个方括号……再加个问号。

**Malan：完美。答案还是问号，但这次我们要更聪明一点。** 正如 Maria 指出的，**我们需要圆括号**。因为：

- 如果我只是在点号后面加个问号（`www\.?`），那**只有那个点号**变成可选；
- 这是错的——我们不想让用户输入 `WWWTWITTER`，我们要的是"要么 `www.` 整个都在，要么连 `www` 都没有"。

所以必须**把这一整块分组**，左括号放在前面，右括号**放在点号之后**（不是放在第三个 W 之后），这样整块才是"要么在、要么不在"：

```python
r"^https?://(www\.)?twitter\.com/"
```

### 14.14 逐个解决问题（五）：连协议本身都可不要 [01:50]

还有一件事我们也该容忍，之前有人提过，Malan 说"我把这条摘出来"——**协议怎么办？如果用户压根没输入或没复制 `http://` 或 `https://` 呢？**

说实话，现在你我和大多数人**早就没有输入协议的习惯了**——我们让浏览器自己去猜、自动帮我们补上。

于是这个改动看起来"有点拗口"（more of a mouthful），**但如果我想让高亮的这一整块变成可选，解法其实和 Maria 刚才给的一模一样**：在前面加个左括号，在两个斜杠之后加个右括号，然后再加一个问号，让整块都变成可选。

```python
import re

url = input("URL: ").strip()

username = re.sub(r"^(https?://)?(www\.)?twitter\.com/", "", url)
print(f"Username: {username}")
```

**这完全是可以的。** 把整块变成可选、或者在它内部再把那个 `s` 变成可选，**都没问题。只要你在反复应用同样的原则**——不论是在小尺度上还是大尺度上——**把一个嵌套在另一个里面也完全 OK。**

官方 Notes 对这一版的完整解读：

- 加了 `^` 表示从开头匹配；
- `.` 可能被解释器误读，所以用 `\` 转义成 `\.`；
- 为了同时容忍 `http` 和 `https`，在 `https` 的 `s` 后面加 `?`，让 `s` 变成可选；
- 为了兼顾 `www`，加上 `(www\.)?`；
- 最后，万一用户干脆不写协议，`http://` 或 `https://` 用 `(https?://)?` 变成可选。

### 14.15 学生提问：能用 `|` 代替 `?` 吗？括号能嵌套吗？ [01:50]

**问题一：能不能在 `www.` 那里用竖线？**

Malan：可以。我们也可以这么写——不用问号，而是写 `www\.` **或** "什么都没有"，然后留着那个括号。这也完全可以。**但我个人不太喜欢这么写**，因为对我来说它不够明显——我会怀疑："等等，那是有意为之，还是我走神了、忘了在竖线后面把话说完？"

**问题二：如果括号里套括号、再套括号，会互相干扰吗？**

Malan：**如果你在括号里放括号，那也完全没问题。而且这恰恰应该是今天最让人安心的一课。**

**尽管这些正则已经变得公认地复杂，但我在做的，不过是一遍又一遍地应用完全相同的原则和完全相同的语法。** 只要每一层括号各自在解决不同的问题，括号套括号就完全 OK。

### 14.17 最后一个问题：别盲目相信 `re.sub` 的结果 [01:55]

这个方案**仍然存在至少一个问题**：虽然我调用 `re.sub` 把 URL 替换成了"什么都没有"，但我在最后一行（第 6 行）**盲目地假设它一定成功了**，然后就去打印用户名。

### 14.18 版本五：改用 `re.search` + 捕获 —— 然后翻车 [01:55]

```python
import re

url = input("URL: ").strip()

matches = re.search(r"^https?://(www\.)?twitter\.com/(.+)$", url, re.IGNORECASE)
if matches:
    print(f"Username:", matches.group(1))
```

Malan 的思路复述：

- 从字符串开头开始匹配 `^`；
- `https` 加 `?` 让 `s` 可选；
- `://`；
- 用括号把 `www\.` 包起来加 `?`，让它可选；
- 然后 `twitter\.com`（点号要转义）；
- 然后一个 `/`；
- 然后——**`davidjmalan` 应该在这儿。怎么检测它？** 我想我就"容忍 URL 末尾的任意内容"吧，用 `.+`，再加 `$` 收尾。
- 顺便说明：目前我们**约定不操心末尾的问号或井号**（比如 URL 里的片段标识符 fragment ID），为简单起见，假设 URL 就以用户名结尾。
- 第三个参数传 `re.IGNORECASE`，应用前面学到的教训。
- `re.search` **会把它捕获到的匹配返回给你**。我想捕获什么？**`twitter.com/` 右边的一切**。于是用圆括号把用户名那一段围起来——**不是为了让它可选，而是说"请捕获这一组字符"**。
- 如果 `matches` 不是 `None`、确实装着某个匹配，那么**且仅在此刻**才打印用户名。

**翻车现场开始了：**


好，至少我们解决了刚才那个"盲目假设代码一定成功"的错误——现在会先确认找到了 Twitter 的 URL 前缀。

**嗯？`None`？出什么问题了？**

Malan 说：这个错误**稍微隐蔽一点**。为什么 `matches.group(1)` 里什么都没有？

他先自我怀疑：等等，也许是我写错了？也许……**也许我们需要 `www`？** 那就再跑一次：

**嗬，嗬，嗬。到底怎么回事？**

**学生：你得用 group 2。**

**Malan：我得用 group 2？** 哦——对！**因为子域是可选的，而为了让子域可选，我必须在这里用圆括号。于是我在 `(www\.)?` 上用了一次括号，表示 0 次或 1 次——这就意味着我"无意中、但确实按设计地"捕获了 `www.`（如果它存在的话；如果不存在就捕获到空）。**

**而因为我有了第二组圆括号（用户名那组），所以用户名其实是第二个匹配。**

### 14.19 用海象运算符收紧 [01:55]

既然喜欢我们的新朋友（很难不喜欢），那就用海象运算符把两行并成一行：

```python
import re

url = input("URL: ").strip()

if matches := re.search(r"^https?://(www\.)?twitter\.com/(.+)$", url, re.IGNORECASE):
    print(f"Username:", matches.group(2))
```

### 14.20 更好的方案：非捕获分组 `(?:...)` [02:00]

Malan 说：**但我敢打赌，还有另一个解法。** 事实上，我们可以回到最后那批语法：

```python
A|B     either A or B
(...)   a group
(?:...) non-capturing version
```

回忆一下，我们引入圆括号是为了能用 `|` 做 A 或 B（还能连着用好几个竖线）；我们也用分组来把 `www\.` 这样的想法组合起来。**而最下面这个到目前为止还没用过的、 admittedly 有点怪的语法，就是"非捕获版本"的括号**——**如果你出于逻辑需要必须用括号，但又不想费事去捕获它的结果，就用它。**

**在这个例子里，这可以说是更好的解法。** 因为：

- 是的，回到 VS Code，**我确实需要用圆括号把 `www\.` 包起来**（至少按我现在写的这个正则是这样），因为我需要在它后面加问号；
- **但我并不需要把 `www.` 取回来。**

**事实上，让我们只提取我们真正关心的数据，免得日后给我、我的同事、我的老师造成困惑。**

**语法（按幻灯片）是：在左括号之后立刻写一个问号和一个冒号。** 看起来确实怪。有编程经验的人可能会觉得眼熟——这语法来自三元运算符（ternary operator），那种把 if/else 写在一行里的写法。**括号开头的 `?` `:` 意思是：是的，我在用圆括号把这些东西分组；不，你不需要捕获它们。**

于是我们可以把 `matches.group(2)` **改回** `matches.group(1)`：

```python
import re

url = input("URL: ").strip()

if matches := re.search(r"^https?://(?:www\.)?twitter\.com/(.+)$", url, re.IGNORECASE):
    print(f"Username:", matches.group(1))
```

```text
$ python twitter.py
URL: https://twitter.com/davidjmalan
Username: davidjmalan

$ python twitter.py
URL: https://www.twitter.com/davidjmalan
Username: davidjmalan
```

加不加 `www` 都能拿到用户名。

### 14.21 学生提问：把 `^` 挪到 `twitter.com` 前面行不行？TLD 怎么灵活处理？ [02:00]

**学生：** 首先，我们能不能把 `^` 直接放在 `twitter` 前面、从那儿开始读，然后把前面那些（协议、www）全扔掉？第二个问题：怎么用列表或字典来处理 `.com`、`.co.uk` 这类后缀，怎么把它弄进 `re` 函数里？

**Malan 的回答（第一个问题）：好问题，但不行。** 如果我把 `^` 挪到 `twitter.com` 前面、并且把协议和 www 都扔掉，那么**用户就必须字面地输入 `twitter.com/用户名`**，连那些别的东西都不能填了。**那将是一次倒退（regression），是退步。**

**第二个问题（`.com` / `.org` / `.edu` 等等）：** 简短的回答是——**解法有很多。**

- 如果我想对 `.com` 严格一点（假设 Twitter 也许还拥有别的域名，尽管他们一般只用这一个，比如可能还有 `.org`），**我可以用更多括号，写成 `com|org`**。而且我大概会想**加一个 `?:` 让它变成非捕获**，因为我不在乎到底是哪个，我只想两者都容忍：

  ```python
  if matches := re.search(r"^https?://(?:www\.)?twitter\.(?:com|org)/(.+)$", url, re.IGNORECASE):
      print(f"Username:", matches.group(1))
  ```

- **或者，我们也可以捕获它。** 写成 `twitter\.(.+)` 之类的，把 TLD 捕获下来，然后：**如果 `matches.group(1) == "com"` 就支持它，等等。** 也就是说，**你可以把逻辑"分解"出去——先把顶级域名（TLD）提取出来，然后用纯 Python 代码（也许是个列表，也许是个字典）在正则之外去校验它是不是你期望的那个。**

- **不过现在我们保持简单，本例只关注 `.com`。**

### 14.22 最后一改：用户名只接受 `[a-z0-9_]` [02:00]

最后再对这个程序做一处修改，好让我们对"Twitter 用户名"的定义更精确一点。

**我们现在在末尾有点太慷慨了**——我们接受"任意字符 1 次或多次"。但我查了 Twitter 的文档，**Twitter 只支持字母（a-z）、数字（0-9）和下划线**，而不是"任意字符"。

而且我还想做到：**不仅容忍这些符号出现 1 次或多次，还容忍 URL 末尾可能还有别的东西**——我现在打算接受 URL 末尾出现斜杠、问号或井号，**它们在 URL 里都是合法符号，但根据 Twitter 的文档，它们不属于用户名的一部分。**

```python
import re

url = input("URL: ").strip()

if matches := re.search(r"^https?://(?:www\.)?twitter\.com/([a-z0-9_]+)", url, re.IGNORECASE):
    print(f"Username:", matches.group(1))
```

- `[a-z0-9_]` 告诉解释器：只接受 a-z、0-9 和 `_`；
- `+` 表示我们期待 1 个或多个这样的字符；
- **我不需要同时写大写 `A` 和小写 `z`**，因为我们已经用了 `re.IGNORECASE`。

最终测试：

```text
$ python twitter.py
URL: https://twitter.com/davidjmalan
Username: davidjmalan

$ python twitter.py
URL: https://twitter.com/davidjmalan/
Username: davidjmalan
```

带不带末尾斜杠都能正确提取出 `davidjmalan`。

## 15. 收尾：`re` 库还有别的函数 & 正则是一门跨语言的语言 [02:00]

Malan 收尾说：正则的世界和这个库里还有什么呢？除了 `re.search` 和 `re.sub`，还有别的函数：

- **`re.split`**：可以用它来切分字符串，**而且切的依据不是某个（或某几个）具体字符（比如逗号和空格），而是多个字符**；
- **`re.findall`**：它可以让你在一个字符串的不同位置**找出同一个模式的多份匹配**，方便你操作不止一处。

**所以说到头来，你真的学会了一门全新的语言——正则表达式这门语言；而我们是在 Python 里用它。但这些正则其实也存在于非常多的其它语言中**，比如 JavaScript、Java、Ruby 等等。

**因此，借助这门新语言——尽管第一次用它时它公认地天书——你获得了一项新能力：表达模式。** 而如前所述，你可以用这些模式去**校验数据、清理数据、甚至提取数据**，对象则是你手上的任何数据集。

## 本讲易错点

1. **`.` 是通配符，不是点号。** 这是本讲出现频率最高的坑。`.+@.+.edu` 会接受 `malan@harvard?edu`；要匹配字面点号必须写 `\.`。凡是在正则里出现 URL、域名、货币符号，都要想想"这个符号要不要转义"。

2. **忘了用原始字符串 `r"..."`。** `\.` 在普通字符串里可能被 Python 当成转义序列的开头。虽然只有在用反斜杠时才"必须"加 `r`，但 Malan 建议**所有正则都加 `r`**，因为以后回头改的时候很容易顺手加个反斜杠然后忘了这回事。

3. **`*` 和 `+` 选错。** `*` 是"0 次或多次"，所以 `.*@.*` 会接受 `malan@`（`@` 后面 0 个字符也算通过）。要求"至少有东西"必须用 `+`。（`..*` 是 `.+` 的等价写法。）

4. **忘了 `^` 和 `$`。** 没有这两个锚点，`re.search` 会在字符串里"任意位置"找匹配，于是 `My email address is malan@harvard.edu.` 这种整句英文也会被判为有效。相反，处理 URL 时如果只想锚定开头，就只加 `^` 不要加 `$`（后面要留位置给用户名）。

5. **括号放错位置导致"可选"的对象错了。** 想让 `www.` 整体可选，必须写 `(www\.)?`；写成 `www\.?` 就变成"只有点号可选"。同理，`(\w+\.)?` 去掉括号就变成"只有点号可选"。**`?` 只作用于紧邻它左边的那一个"东西"，想作用于一组就必须先分组。**

6. **`matches.group()` 从 1 开始数，不是 0。** 这和其它几乎所有 Python 场合都不一样——`re.search` 返回对象的第 0 号位置放的是跟整个字符串本身有关的内容。所以第一个圆括号是 `group(1)`，第二个是 `group(2)`。

7. **多写了一组括号，就会多占一个组号。** `twitter.py` 里最经典的翻车：为了让 `www.` 可选而写了 `(www\.)?`，结果用户名变成了 `group(2)`，`group(1)` 打印出来是 `None`。**解决办法是用非捕获分组 `(?:www\.)?`，这样组号不会被占用，用户名仍是 `group(1)`。**

8. **`re.sub` 不检查是否匹配成功。** 它会老老实实返回一个字符串（可能什么都没替换），然后你的代码如果盲目使用这个结果，就会把 `https://google.com/` 这样的输入也当成有效数据。需要判断"到底匹配上没有"时，应该换回 `re.search`。

9. **`str.split` 和 `str.replace` 不支持正则。** 想在切分/替换里用 `?`、`*`、字符集这些语法，就必须 `import re`，用 `re.sub` / `re.split`。另外 `split(", ")` 在输入是 `Malan,David`（逗号后无空格）时会直接抛 `ValueError: not enough values to unpack`。

10. **不要试图一口气写出一条复杂正则。** Malan 反复强调：即便对他这样写了多年代码的人来说，那些长正则也依然是天书。正确做法是**增量式推进**——做一点、确认能跑、再加一点、再确认。想校验邮箱这类"有官方定义的常规数据"时，**优先去找现成的流行库，不要自己发明轮子。**

11. **`\w` 只包含字母、数字、下划线，既不包含点号也不包含空格。** 所以用了 `\w` 之后，带空格的整句英文和带点的 Gmail 用户名都会被拒绝。需要空格时可以写成 `(\w|\s)+`，或者直接在字符集里敲一个空格 `[a-zA-Z0-9_ ]`。

12. **正则默认是大小写敏感的。** `\w` 虽然同时匹配大小写字母，但 pattern 里字面的 `.edu` 只匹配小写，所以 `MALAN@HARVARD.EDU` 会无效。解决办法要么 `.lower()`，要么传 `re.IGNORECASE`（后者不会改变用户输入的原值）。
