## 2. `set`：自带去重的数据类型 [00:05]

### 2.1 先看没有 `set` 的时候怎么写 [00:05]

问题背景：有一份 `houses.py`，里面是一个很大的 list（列表），每个元素是一个 dict（字典），代表一个学生的名字和学院（house）：

```python
# houses.py —— 手写去重的版本（第一版）
students = [
    {"name": "Hermione", "house": "Gryffindor"},
    {"name": "Harry", "house": "Gryffindor"},
    {"name": "Ron", "house": "Gryffindor"},
    {"name": "Draco", "house": "Slytherin"},
    {"name": "Padma", "house": "Ravenclaw"},
]

# 准备一个空列表，用来"攒"住不重复的学院名
houses = []
for student in students:
    # 注意：student 是一个 dict，所以要用 ["house"] 索引进去
    if student["house"] not in houses:
        houses.append(student["house"])

# 攒完之后排序再打印，让输出好看一点
for house in sorted(houses):
    print(house)
```

终端运行：

```text
$ python houses.py
Gryffindor
Ravenclaw
Slytherin
```

作为人类，我一眼就能看出答案是 Gryffindor、Slytherin、Ravenclaw；但我们要的是**程序化**地做这件事。

讲师强调的一个细节：为什么最后要用 `sorted(houses)` 而不是直接 `print(houses)`？如果直接打印列表，那"攒"这个动作就白做了，不如一开始就在循环里直接打印。用 `sorted` 至少把结果按字母序整理出来，输出顺序是 Gryffindor、Ravenclaw、Slytherin，而原始列表里的出现顺序其实是 Gryffindor、Gryffindor、Gryffindor、Slytherin、Ravenclaw——确实过滤掉了重复项。

这个写法完全正确，但有个问题：**你在重新发明轮子**。去重这件事，Python 已经替你做好了。

### 2.2 用 `set` 重写 [00:07]

数学里的集合（set）就是"一堆值，且没有重复"。Python 里真的有这么个数据类型。改法只有两处：

```python
# houses.py —— 用 set 的版本（第二版）
students = [
    {"name": "Hermione", "house": "Gryffindor"},
    {"name": "Harry", "house": "Gryffindor"},
    {"name": "Ron", "house": "Gryffindor"},
    {"name": "Draco", "house": "Slytherin"},
    {"name": "Padma", "house": "Ravenclaw"},
]

# 注意：这里不再是 []，而是 set()，创建一个空集合
houses = set()
for student in students:
    # set 的方法叫 add，不叫 append！
    houses.add(student["house"])

for house in sorted(houses):
    print(house)
```

运行结果一模一样。

讲师在这里的特意提醒：

- 空列表既可以写 `houses = []`，也可以啰嗦地写成 `houses = list()`；空集合则是调用 `set()` 函数，它会返回一个代表集合的对象。
- 往列表里加东西是 `append`，往集合里加东西是 **`add`**。这是文档里规定的，别串。
- 最关键的一点：`if ... not in houses` 那个判断**整个删掉了**。我们可以闭着眼睛 `add`、`add`、`add`，重复的会自动被 Python 消化掉。代码少了一层缩进，逻辑少了一个分支。

### 2.3 学生提问两则 [00:09]

**问题一：怎么在 set 里查找某个元素？比如找 Gryffindor 在不在里面？**

答：语法和列表里一模一样，用 `in`：

```python
if "Gryffindor" in houses:
    ...
```

`in`、`not in` 以及相关的函数在 set 上都能用。

**问题二：如果学院名相似但有出入呢？比如 Slytherin 拼成了 Slytheron（i 变成了 o）？for 循环会逐个字母去比吗？**

答：不会逐字母比，Python 是拿**整个字符串**去比较。所以一旦拼写不一致（或者大小写不一致），它们就是两个不同的字符串，结果里会**同时出现两个版本**的 Slytherin。

讲师接着补充了一个很实用的态度：数据脏不脏，取决于它是从哪来的。如果数据是用 ` input()` 从用户那儿收来的，那你确实有风险，可以用我们前面学过的办法先清洗一遍——`upper()` 全转大写、`lower()` 全转小写、`capitalize()`（首字母大写，Python 里 `str` 自带的方法）、或者 `title()`（每个词首字母大写）。而本例中数据是我自己提前写死在代码里的，不是用户输入，所以姑且相信我自己没拼错。

> 想了解 `set` 的全部能力，去查 Python 官方文档里 set 的部分。

## 3. 全局变量与 `global` 关键字 [00:10]

### 3.1 背景：别的语言里司空见惯的东西 [00:10]

在很多语言里有所谓**全局变量（global variable）**的概念：写在所有函数之外的变量（通常放在文件顶部），任何函数都能访问。Python 里也有这回事。严格讲，在 Python 里它其实是"模块级（module-level）"的变量——如果你写的是一个库而不是一个程序，那它是属于这个模块的；但对一个具体的程序来说，表现上就是全局的。

然而，等你的程序变大、函数变多，你会发现：**这个变量并没有你以为的那么好改**。

### 3.2 第一版：只读，一切正常 [00:11]

新建 `bank.py`，实现一个极简的银行，只记录余额（balance）：

```python
# bank.py —— 第一版：只读全局变量，没问题
balance = 0   # 全局变量，写在所有函数之外、文件的最顶部


def main():
    print("Balance:", balance)


if __name__ == "__main__":
    main()
```

这里讲师刻意演示了两个习惯：

- 变量 `balance` 放在第 1 行，类型是 `int`，初值 0；
- `print("Balance:", balance)` 给 `print` 传了两个参数，因为之前讲过，多个参数之间会被 `print` 自动用一个空格分隔；
- 老规矩，既然有 `main`，就配上 `if __name__ == "__main__":` 再调用 `main()`。

运行 `python bank.py`，输出 `Balance: 0`。

结论：**读**全局变量是没问题的。虽然 `balance` 定义在第 1 行，在第 5 行的 `main` 里依然能打印出来，尽管它并不是在 `main` 里定义的。

### 3.3 第二版：想改它？直接崩 [00:12]

让程序有点用：能存钱（deposit）、能取钱（withdraw）。

```python
# bank.py —— 第二版：试图在函数里修改全局变量，报错！
balance = 0


def main():
    print("Balance:", balance)
    deposit(100)
    withdraw(50)
    print("Balance:", balance)


def deposit(n):
    balance += n          # 等价于 balance = balance + n，只是写法短一点


def withdraw(n):
    balance -= n


if __name__ == "__main__":
    main()
```

讲师的想法很朴素：开头余额是 0，存 100，取 50，第二行 `print` 应该输出 50。

结果跑 `python bank.py`，炸了：

```text
UnboundLocalError: local variable 'balance' referenced before assignment
```

**这是本讲第一个重点"翻车现场"，而且错误信息本身有误导性。** 讲师特意停下来分析：

- 它说 "referenced before assignment"（在赋值之前就被引用了）——可我明明在最上面赋值了 `balance = 0` 啊！代码没丢，滚上去看还在那儿。
- 出错位置指向第 12 行附近，也就是 `deposit` 里试图操作的那一句。

请学生回答时，学员 Elena 说：全局变量是不可改的；如果你想改这个值，它得是函数内部的局部变量。

讲师认可并总结成一句很好记的话：

> **全局变量可以读（read），不可以写（write）。** 读包括打印它、取出它的值；但想在函数里重新给它赋值，不好意思，Python 不允许。

### 3.4 第三版（错误尝试）：把变量挪进 `main` 也没用 [00:13]

那我把全局变量删掉，改成写在 `main` 里面试试？

```python
# bank.py —— 第三版（错误尝试）：把 balance 放进 main，依然报错
def main():
    balance = 0           # 现在是 main 的局部变量
    print("Balance:", balance)
    deposit(100)
    withdraw(50)
    print("Balance:", balance)


def deposit(n):
    balance += n


def withdraw(n):
    balance -= n


if __name__ == "__main__":
    main()
```

再跑，还是 `UnboundLocalError`，只不过这次是**因为另一个原因**。这里必须搞清楚一对概念：

- **局部变量（local variable）**：在某个函数内部出现、只活在这个函数上下文里的变量。本例中写在 `main` 里第 2 行的 `balance` 就是 `main` 的局部变量。
- **全局变量（global variable）**：不属于任何函数、通常写在文件顶部的变量。

`deposit` 和 `withdraw` 访问不到 `main` 里的 `balance`，因为它属于 `main`。于是我们陷入一个死循环：放外面（全局）→ 不能改；放里面（`main`）→ 别的函数看不见。

### 3.5 第四版（正确）：`global` 关键字 [00:15]

解决方案就是 Python 里的 `global` 这个关键字。它可能跟你在别的语言里见过的写法不一样，但作用很直白：**告诉这个函数——这个变量不是你自己的局部变量，我指的就是外面那个全局变量，请改它。**

```python
# bank.py —— 第四版（正确）：用 global 关键字
balance = 0


def main():
    print("Balance:", balance)
    deposit(100)
    withdraw(50)
    print("Balance:", balance)


def deposit(n):
    global balance        # 声明：下面用到的 balance 是全局那个
    balance += n


def withdraw(n):
    global balance        # 每个要改它的函数都得声明一次
    balance -= n


if __name__ == "__main__":
    main()
```

运行结果：

```text
$ python bank.py
Balance: 0
Balance: 50
```

讲师的解说很到位：`global balance` 这一行是给 Python 的一个"线索"（clue）。有了它，Python 就知道"哦，这不是你手滑写出的 bug，你是真的有意要改外面那个变量"。注意 `balance` 的值依然由第 13 行、第 18 行的 `+=` / `-=` 来改变，`global` 只是解除禁令，不改变业务逻辑。

### 3.6 学生提问三则 [00:18]

**问题一：如果我在外面声明了一个全局变量，又在函数内部声明了一个同名变量，会怎样？**

答：这位同学很会琢磨边界情况（corner case）。结果是：里面的那个会**遮蔽（shadow）**外面的那个。你在这个函数里用的、改的都是局部变量，对全局变量**毫无影响**；在函数的执行期间，Python 只认局部那个。

所以经验法则是：**别这么干。** 一来你自己都可能改错对象，埋下 bug；二来对读你代码的人来说也很费解。

**问题二：那我把 `balance` 当成参数传给各个函数呢？**

答：直觉很好，但同样解决不了。因为把变量传进函数之后，函数里改的只是这份**局部副本**（local copy），外面那个值不会变。所以我们确实需要一种更好的办法。

### 3.7 更好的办法：用类重写 [00:20]

这就接上了上一讲（第 8 讲）的面向对象。现实世界里有"银行账户"这么个实体，我们可以用类来建模，把余额**封装（encapsulate）**进去。

讲师在写这段代码时的几个现场操作，值得留意：

- 先把全局变量整个删掉，从零开始；
- 定义 `class Account`，写 `__init__`，按惯例第一个参数是 `self`；
- 初始化余额为 0：`self._balance = 0`。注意这里**提前**用了第 8 讲学到的教训：因为马上要写一个同名的 property（名叫 `balance`），如果实例变量也叫 `balance` 就会重名打架，所以先主动把实例变量改名成 `_balance`，用一个下划线表示"这是私有的，外面的代码别碰"——虽然 Python 并不强制执行，这只是个视觉提示；
- 写一个名为 `balance` 的方法并加上 `@property` 装饰器，作用是返回 `self._balance`。

```python
# bank.py —— 最终版：用面向对象彻底干掉全局变量
class Account:
    def __init__(self):
        # 下划线开头，表示"私有"，这只是一个约定
        self._balance = 0

    @property
    def balance(self):
        # getter：只读属性，取值用
        return self._balance

    def deposit(self, n):
        self._balance += n

    def withdraw(self, n):
        self._balance -= n


def main():
    account = Account()               # 构造函数：类名加两括号，没参数也别漏了括号
    print("Balance:", account.balance)  # 访问的是 property，不是实例变量
    account.deposit(100)
    account.withdraw(50)
    print("Balance:", account.balance)


if __name__ == "__main__":
    main()
```

输出同样是 `Balance: 0` / `Balance: 50`。

讲师的感慨很真实：一开始目标很小（就做个银行），结果代码"升级得很快"。用 `global` 确实能通过依次告诉每个函数"这是全局的"来实现功能，但那不是我们手上最好的封装手段。既然我们在建模一个真实世界的实体（银行账户），**类就是干这个用的**。而且随着方法越来越多，类的优势会越来越明显——因为在 Python 的类里，实例变量天生就能被所有方法访问，因为大家都通过那个特殊的参数 `self` 去够它。

**学生提问：`@property` 到底是干什么的？**

答（回顾第 8 讲）：property 是一种"受保护的"实例变量，让你能控制它怎么被读、怎么被写。本例只有通常说的 **getter（取值器）**，没有 setter（赋值器）——虽然代码里并没出现 "getter" 这个词，`@property` 的意思就是：名为 `balance` 的这个函数，让你能用 `account.balance` 这种语法，装作 `balance` 就是一个不带下划线的实例变量。

同时，正因为没有定义 setter，`main` 里的代码没法写 `account.balance = 1000` 来凭空给自己变出 1000 个币。这就是 property 带来的** finer-grained control（更细粒度的控制）**。

**最终态度**：小脚本里偶尔用一下 `global` 无所谓；但一般经验是 **sparingly（尽量少用）**，最好完全不用。因为在很多语言里（Python 也在一定程度上如此），频繁使用全局变量容易把事情搞乱——你的信息一会儿在上面，一会儿在函数里，很快就搞不清数据到底存在哪儿了。

## 4. 常量：全大写只是"君子协定" [00:25]

### 4.1 问题：魔法数字 [00:25]

有些语言允许你定义**常量（constant）**：一旦赋值就改不了。这是好事，它让你能"防御式编程（program defensively）"——万一你不小心、或者别人不小心想改这个值，语言会拦住你。

Python 没有这个机制，Python 又是靠**君子协定（honor system）**。但约定照样非常有用。

新建 `meows.py`，让猫叫三声：

```python
# meows.py —— 第 0 版：硬编码一个 3
for i in range(3):
    print("meow")
```

先收拾一下：`i` 根本没用到，按 Python 的惯例把它改名成 `_`。

```python
# meows.py —— 第 1 版：循环变量用下划线
for _ in range(3):
    print("meow")
```

现在关键问题来了：这个 `3` 是**硬编码（hardcoded）**、明明白白打在代码里的。代码只有两行时这当然无所谓。但想象一下这个程序有几十行甚至几百行，其中某一行里孤零零地躺着个 `3`——你以后**根本找不到它**，而且无论是你还是同事都很容易忽略"这里硬塞了个魔法值"。

所以在 Python 以及别的语言里，最佳实践都是：只要你手上本质上是个常量（比如这个不该变的 3），就把它**冒泡到代码顶部**，让所有人一眼看到你的常量有哪些。

### 4.2 约定：全大写 [00:27]

```python
# meows.py —— 第 2 版：常量提到顶部，全大写命名
MEOWS = 3

for _ in range(MEOWS):
    print("meow")
```

好处：以后想改成叫四声，只需要改文件最上面这一行，不用到处去捞、去猜"改了会不会弄坏别的地方"。

**但是，这是本讲第二个重点提醒**：

> Python 里的所谓常量，只是个约定，**语言层面完全没有阻止你去改它**。大写是你在向全世界宣告"别碰我"。可你要是哪天心血来潮写一句 `MEOWS = 4`，它照样跑得通。别的语言通常会有一个关键字或语法机制，让这行代码在运行时直接报错；Python 则把这些都留给了约定。

### 4.3 类常量 [00:30]

还有一类"带引号的常量"，体现在类里面。回顾第 8 讲：类里不仅有实例变量，还可以有**类变量（class variable）**——它在类里面、但不在 `self` 里面，所有方法都能访问。同样地，如果想表示"这个东西不该被改"，约定就是**把名字全大写**。

```python
# meows.py —— 第 3 版：类常量
class Cat:
    MEOWS = 3          # 类变量，在所有方法之外，按约定应视为常量

    def meow(self):
        for _ in range(Cat.MEOWS):   # 通过类名访问，写清楚这是 Cat 的 MEOWS
            print("meow")


cat = Cat()            # 类名大写 Cat，变量名小写 cat
cat.meow()
```

运行 `python meows.py`，输出三声 meow。

讲师强调的命名习惯：按 OOP 的约定，**类名首字母大写**（`Cat`），而它造出来的对象变量名小写（`cat`，当然你也可以叫 `c`）。讲师个人喜欢这种对称写法——大 Cat 和小 cat。`cat.meow()` 这个方法会通过第 5 行访问到那个"类常量"。

再说一遍：它之所以是常量，**仅仅因为你不该碰它**，而不是语言真的强制你不能碰。

## 5. 类型注解（type hints）与 `mypy` [00:30]

### 5.1 为什么需要 [00:30]

Python 是**动态类型语言（dynamically typed）**，也就是不强类型：你想要个 `int`，不需要告诉程序它是 `int`；`str`、`float`、`set` 同理。我们迄今为止写变量都是给个名字、用等号赋个值，Python 自己会动态推断类型——`"hello, world"` 就是 `str`，`50` 就是 `int`。

而在 C、C++、Java 等语言里，**程序员有义务**指定类型。这么做的好处是**更容易发现 bug**：如果你本想存字符串却存了整数，语言可以直接在你运行程序时报错，而不是等真实用户倒霉地撞上。

Python 的做法是折中的：你可以给 Python 提供**提示（hint）**，告诉它变量应该是什么类型，但语言本身**不强制**。真正把这些 hint 用起来的是**工具**——作为程序员，你在把代码发布出去之前，手动跑一遍这个工具；或者把这件事挂到自动化流程里（就像你可能会用别的程序给代码排版、做 lint 一样）。

这个工具就是 **`mypy`**。它只是众多选择之一，但特别流行，安装方式也很常规：

```text
$ pip install mypy
```

### 5.2 起点：一个有类型 bug 的 `meows.py` [00:32]

清空 `meows.py`，写一个带 `meow` 函数的版本。为了聚焦新东西，讲师这次**故意不写 `main`**：

```python
# meows.py —— 第 1 版：藏着一个类型 bug
def meow(n):
    for _ in range(n):
        print("meow")


number = input("Number: ")
meow(number)
```

在终端里跑 `python meows.py`，输入 `3`，期望叫三声，结果：

```text
TypeError: 'str' object cannot be interpreted as an integer
```

学生立刻答对了原因：`input` 函数返回的是字符串（`str`），不是整数（`int`）。我们过去的修法是拿 `int()` 转换一下。现在讲师要演示的是：**如何更防御式地写代码，让自己压根不落到这一步。**

### 5.3 加类型注解（但 Python 依然不管） [00:33]

```python
# meows.py —— 第 2 版：给参数加类型注解
def meow(n: int):          # 冒号 + 空格 + int，这就是一个 type hint
    for _ in range(n):
        print("meow")


number = input("Number: ")
meow(number)
```

注意 `n: int` 这段语法的含义：写个冒号、一个空格、再加类型名 `int`，**并没有创建另一个 int 或任何东西**，它只是一个 hint、一个 annotation（注解），告诉别人（和工具）：这个叫 `n` 的变量**应该**是 int。

**第三个重点提醒**：

> Python 本身不在乎这些类型注解。这是**刻意的设计**：Python 社区希望 Python 保持动态类型，而不是强类型到必须满足这些约束。所以你再跑 `python meows.py` 输入 3，那个 TypeError **依然在那儿**。

### 5.4 让 `mypy` 在代码运行之前就抓到它 [00:35]

现在登场的是 `mypy`——一个能读懂类型注解的程序：

```text
$ mypy meows.py
error: Argument 1 to "meow" has incompatible type "str"; expected "int"
```

注意这一步的关键差异：**我们跑的是 `mypy`，不是 Python**。讲师说得很清楚，`mypy` 不是给最终用户用的，它是给**你我这样的程序员**用的。在把程序发布给世界之前先跑一下，就能在代码真正被调用之前发现"哦，我把参数类型搞错了"。这比你或者用户撞上一个含义隐晦的 TypeError 要好得多。

### 5.5 给变量也加上注解，错误定位会更早 [00:36]

不光函数的参数可以注解，普通变量也可以。既然第 6 行的 `number` 是我们自己创建的，而且我们知道右边是 `input` 的返回值，那就再给工具一个 hint：`number` 也应该是 `int`。

```python
# meows.py —— 第 3 版：给变量也加注解，让 mypy 更早报错
def meow(n: int):
    for _ in range(n):
        print("meow")


number: int = input("Number: ")
meow(number)
```

再跑：

```text
$ mypy meows.py
error: Incompatible types in assignment (expression has type "str", variable has type "int")
```

这次报错指向第 6 行，而不是第 7 行。**错误被提前了一步**：还没到调用 `meow` 那一步，`mypy` 就指出"你在给一个声明为 int 的变量赋一个 str"。

讲师的建议是：养成给**所有**变量和参数写注解的习惯，那么 `mypy` 这类工具就能在你还没敲 `python` 之前就把问题挖出来。

### 5.6 修好它 [00:38]

终于到了这几周以来你一直在想的那一步——把 `input` 的返回值转成整数。（本讲不处理异常，假设用户乖乖输入数字。）

```python
# meows.py —— 第 4 版：真正修好，mypy 通过
def meow(n: int):
    for _ in range(n):
        print("meow")


number: int = int(input("Number: "))
meow(number)
```

```text
$ mypy meows.py
Success: no issues found in 1 source file
```

现在再跑 `python meows.py` 输入 3，就有充分的理由相信不会再撞类型错误了——因为写代码的当下我们就写好了注解，而这些注解让 `mypy` 能验证"我的意图"和"代码实际行为"是否一致。

**学生提问：类型注解到底常不常见？是不是只用在复杂代码里？**

答：这是个好问题，但也相当主观。Python 在设计上对这些细节更灵活（versatile），一部分是为了**writeability（写代码的顺手程度）**——写起来更快；一部分是为了性能——解释器不用费劲做这些检查，直接开跑。

但现实是：**强类型检查确实有利于提高代码的正确性（correctness）**，因为像 `mypy` 这样的程序能在代码运行之前发现已知错误，这对防御式编程是好事。

现状总结：

- 在 Python 生态里，你可以这样注解类型，也可以用工具去消费这些注解；
- 但迄今为止，Python 本身**不强制**，也不打算强制这些约定；
- 在更大的代码库、专业代码库、商业代码库里，要不要用往往取决于项目经理或工程团队——因为只要它能降低出 bug 的概率，他们通常就愿意用。

### 5.7 注解返回值：`-> None` [00:40]

再引入一个新的错误场景。回想我们讲**单元测试**时的那个原则：函数**返回值**通常比**副作用**（side effect）好——因为返回值的函数可以被 `assert` 断言。

假设我还沉浸在那个思维里，**误以为** `meow` 会返回一大串 "meow" 给我，让我自己拿去打印（这样也更好写单测）。于是我不小心写成这样：

```python
# meows.py —— 第 5 版：误以为 meow 有返回值
def meow(n: int):
    for _ in range(n):
        print("meow")


number: int = int(input("Number: "))
meows: str = meow(number)      # 我假设这里会拿到一个字符串
print(meows)
```

跑 `python meows.py`，输入 3，输出很诡异：

```text
meow
meow
meow
None
```

**这是本讲第四个重点。为什么会打印 `None`？**

- 当前的 `meow` 只有副作用，它自己把 meow 打印出来了，**没有 `return`**；
- 在 Python 里，函数如果没有显式返回值，它的**隐式返回值就是 `None`**；
- 所以第 7 行赋值给 `meows` 的其实是 `None`；第 3 行照旧打印了三声 meow，而第 8 行多余地把 `None` 打了出来。

用类型注解怎么抓住这种错误？给返回值加注解：

```python
# meows.py —— 第 6 版：用 -> None 注解返回值
def meow(n: int) -> None:      # 箭头语法：这个函数不返回值
    for _ in range(n):
        print("meow")


number: int = int(input("Number: "))
meows: str = meow(number)
print(meows)
```

语法说明（讲师口头描述得很细）：hint 返回值时，在参数列表的右括号之后写一个空格、一个连字符、一个大于号（看起来像箭头 `->`）、再一个空格，然后是返回值的类型。这里是 `None`。

```text
$ mypy meows.py
error: "meow" does not return a value
```

`mypy` 之所以知道这一点，正是因为我在第 1 行主动注解了 `meow` 的返回值是 `None`。于是 `mypy` 立刻发现第 7 行在把一个没有返回值的函数的结果存进变量——"哦，我犯傻了，`meow` 明显不返回值。"

### 5.8 干脆让它真的返回字符串 [00:45]

错误抓到了，那就按我们在单测那讲宣扬的原则改：`meow` 不要副作用，改为返回真正的字符串。

```python
# meows.py —— 最终版：返回 str，mypy 零错误
def meow(n: int) -> str:
    return "meow\n" * n        # 利用字符串支持乘法（运算符重载）


number: int = int(input("Number: "))
meows: str = meow(number)
print(meows, end="")           # 每个 meow 自带换行，别再多打一个空行
```

这里的一行小技巧：`"meow\n" * n` 就是"把 meow 加换行重复 n 次"，比写循环干净得多。因为每个 meow 自带一个 `\n`，最后 `print` 时加上 `end=""` 抑制 `print` 自己追加的那个多余换行——纯属美观考虑。

```text
$ mypy meows.py
Success: no issues found in 1 source file
$ python meows.py
Number: 3
meow
meow
meow
```

注意：`None` 不再出现，因为现在 `meow` **真的**返回 `str` 了，`meows: str` 这个注解也名副其实。

**学生提问一：`return "meow\n" * n` 里的引号和 `\n`，为什么程序不把它当成普通字符串处理？**

答：回顾课程早期，加号 `+` 是字符串的连接符（左侧拼右侧）。而**乘法是被重载（overloaded）过的运算符**：字符串在左、整数在右时，它会把这个字符串重复连接那么多次。这既是 Python 的功能，也是我们在第 8 讲看到的**运算符重载（operator overloading）**的实例。

**学生提问二：我们不能不做类型转换、直接指定变量类型吗？**

答：不能，而且先纠正一下术语——在这个语境里不叫 **typecast（类型转换）**，那更像 C / C++ 里类型之间存在某种等价关系的说法；在 Python 里你做的是 **convert（转换）**：把 `str` 转成 `int`。

你必须显式调用 `int()`。`mypy` 会因为你把右边的 str 赋给左边的 int 而报警。另外注意区分同一个词 `int` 的两种身份：

- `int(...)` 仍然是那个**函数调用**，跟它一直以来是同一个东西；
- 而变量左边那个 `int`（如 `number: int`）则是类型注解里的用法。

两者互不相干，转换这一步你得自己走。

## 6. docstring：文档字符串 [00:50]

### 6.1 由来：又一个 PEP [00:50]

在 Python 的世界里，给函数写文档有一套**标准化**的做法，出自另一份 **PEP（Python Enhancement Proposal，Python 增强提案）**——这次是 **PEP 257**，它基本上规定了你应该怎么给函数（以及代码其它部分）写文档。

### 6.2 基本写法 [00:51]

回到 `meows.py`，给 `meow` 加文档。关键规则是：文档不是写在函数**上面**，而是写在函数**里面**（缩进的函数体第一行）。而且用的不是平时的 `#` 井号注释，而是**三引号**：

```python
# meows.py —— 单行 docstring
def meow(n):
    """Meow n times."""          # 三个双引号开始，三个双引号结束
    return "meow\n" * n


number = int(input("Number: "))
meows = meow(number)
print(meows, end="")
```

讲师口述的要点：

- 三引号可以是**三个双引号**，也可以是**三个单引号**（开头结尾保持一致即可）；
- Python 内置了某些工具和假设：一旦检测到"用三引号包起来的这段注释"，它就认定这是该函数的文档；
- 于是 Python 生态里就涌现出一大批工具，能自动分析你的代码、把所有 docstring 抽取出来，甚至生成网页或 PDF 形式的文档。

好处显而易见：**只要你遵循这些约定，你的文档就能自动生成**，而不用再另外手写一遍。

### 6.3 多行标准格式 [00:53]

如果函数有参数、行为更复杂，可以采用更丰富的约定。注意这套语法需要用多行形式：

```python
# meows.py —— 多行 docstring，遵循 reStructuredText 风格
def meow(n):
    """
    Meow n times.

    :param n: Number of times to meow
    :type n: int
    :raise TypeError: If n is not an int
    :return: A string of n meows, one per line
    :rtype: str
    """
    return "meow\n" * n


number = int(input("Number: "))
meows = meow(number)
print(meows, end="")
```

逐项解释：

- 开头先用一句话说明函数干什么（`Meow n times.`）。按某些风格的用法，这句话紧跟在三引号之后；也有风格要求它单独占第一行、下面空一行。讲师这里选择**整体统一缩进**的写法。
- `:param n:` 描述参数 `n` 是什么 —— "叫几声"。
- `:type n: int` 说明参数类型。
- `:raise TypeError: If n is not an int` 声明它可能抛出的异常。讲师坦言**这算是他自己的失误默认剧本**：虽然第 1 行的注解暗示你应该传 int，但 Python 不强制；假如有人传进来一个 float 或 str，`"meow\n" * n` 里的乘法是跑不通的，凭经验可知会触发 `TypeError`。既然可能会发生，就主动写进文档里。
- `:return:` 用自然语言描述返回值 —— "由 n 个 meow 组成的字符串，每行一个"。
- `:rtype: str` 返回值的类型。

**第五个重点提醒**：

> 上面这些 `:xxx:` 语法**并不是 Python 本身的东西**。它是一种叫 **reStructuredText** 的约定 —— 一种类似 Markdown 的标记语言，用于文档、网站、博客等等。它是 Python 世界里比较流行的一种文档约定。
>
> 所以：**类型注解（type hints）是 Python 的语言特性；而 docstring 里写什么格式纯属第三方约定。** 两者互不相干，我只是按规矩在三引号之间塞了标准内容，好让第三方工具能从头到尾分析我的代码并生成文档（PDF、网页等），这样我和同事就不必既写代码又手工维护一份文档。

像 **Sphinx** 这类成熟工具就能解析这些 docstring，自动生成网页和 PDF 文档供你发布和分享。

### 6.4 学生提问两则 [00:57]

**问题一：把这些做成 PDF 发出去，目的是让别人能用你的函数吗？**

答：绝对是。回想我们几周前安装过的第三方库，比如 `cowsay`——讲师当时给大家看过它有哪些函数；而如果你去读它的文档，会发现那正是作者写好的说明文档（虽然多半不是用本讲这套语法）。对你我来说，能读到一个网页或 PDF 告诉你这库怎么用，**远胜于**通读别人的源码、去猜有哪些函数、该怎么调用。为自己写的代码或库提供像样的文档，对开发者友好得多。

**问题二：生成 PDF 的时候会不会连代码一起包含进来？如果注释里引用了代码，脱离代码看不懂怎么办？**

答：简短回答——**可以做到**，但不是讲师此刻用的这套约定。事实上更巧妙的做法是：在 docstring 里写上函数的**样例输入**和**样例输出**；然后用某个工具（本讲没讲过）跑你的代码，用样例输入去喂它，检查实际输出是否和样例输出一致；不一致就报警说"你某处有 bug"。

也就是说，docstring 不止能用来写文档，还能**顺手帮你抓错误**。

## 7. 命令行参数：先用 `sys.argv` 手写 [00:55]

### 7.1 目标 [00:55]

我们想把 `meows` 程序改成：不用 `input()` 那个闪烁的光标来问，而是从**命令行参数**读输入。回顾"库"那一讲：你可以用 `sys.argv` 拿到人类运行程序时敲进去的命令行参数。

需求设定：

- 用户什么都不敲 → 就喵一声（至少有点视觉效果）；
- 用户想指定叫几声 → 用 `-n` 这样的开关。

### 7.2 第一小步：没有参数就喵一声 [00:57]

```python
# meows.py —— sys.argv 手写版（第一步）
import sys

if len(sys.argv) == 1:
    print("meow")
else:
    print("usage: meows.py [-n NUMBER]")
```

说明一个容易被忽略的事实：`python` 这个词**永远不会**出现在 `sys.argv` 里；但文件名 `meows.py` 会，并且排在 `sys.argv[0]`。所以当你只敲了 `python meows.py`，`sys.argv` 里只有一个元素，长度为 1。

```text
$ python meows.py
meow
$ python meows.py 3
usage: meows.py [-n NUMBER]
```

这里出现了另一个通用约定：**出问题时打印一行 usage（用法）**——字面写上 "usage"、一个冒号、程序名，也许再补点解释。讲师故意写得很简单。

### 7.3 正式支持 `-n 3` [01:00]

在命令行里控制程序时，提供所谓的 **switch（开关）或 flag（标志）** 是非常普遍的：写成 `-n`（语义是 number 次数），然后一个空格，然后是数字 `3`。

这么做的好处：**我的程序明确知道这个 3 是什么意思**。如果你只敲 `meows.py 3`，我怎么知道这个 3 是次数、是音量还是别的什么？而 `-n 3` 只要你读过这个程序的文档（`-n` = number of times），意思一目了然。换句话说，这是给两个参数之间建立了"关系"。

```python
# meows.py —— sys.argv 手写版（完整）
import sys

if len(sys.argv) == 1:
    print("meow")
elif len(sys.argv) == 3 and sys.argv[1] == "-n":
    n = int(sys.argv[2])
    for _ in range(n):
        print("meow")
else:
    print("usage: meows.py [-n NUMBER]")
```

逻辑讲清楚：

- `sys.argv` 的下标是 0、1、2，一共三个东西（程序名、`-n`、数字），所以用空格分隔后一共三项，`len(sys.argv) == 3`；
- 保险起见还要检查 `sys.argv[1] == "-n"`，确认第一个额外参数的确是 `-n`；
- 然后才敢假设 `sys.argv[2]` 是个整数，把它转成 `int` 存进 `n`；
- 最后用一个循环打印那么多次 meow。

讲师承认这里有两处 `print("meow")` 可以合并（默认情况和 `-n` 情况），但故意先不合并，好把两个思路讲清楚。

测试：

```text
$ python meows.py -n 3
meow
meow
meow
$ python meows.py -n 2
meow
meow
$ python meows.py -n 1
meow
$ python meows.py
meow
```

### 7.4 这个方案的死穴 [01:03]

现在假设程序要变复杂：我不只想支持 `-n`，还想支持 `-a`、`-b`、`-c`、`-d`……一堆开关；或者干脆用单词 `--number`。

补充一下约定：

> 在计算领域，惯例是**单字母用单短横线**（`-n`），**整个单词用双短横线**（`--number`）。

麻烦立刻来了：

- 你得在代码里到处检查这些参数；
- 更要命的是**顺序问题**：如果用户把参数顺序打乱了呢？你得检查 `-n` 是第一个、第二个、第三个还是第四个？传进来两个 `-n` 怎么办？
- 明明只是"让用户传几个命令行参数"这么简单的事，代码却很快变得痛苦不堪。

这就是库存在的理由。

## 8. `argparse`：把参数解析外包出去 [01:05]

`argparse` 是 Python 自带的库。讲师现身说法：他自己以及 CS50 团队写的很多 Python 工具，只要复杂到不再是课堂演示级别、需要用户在命令行配置选项，就会频繁使用 `argparse`。它的文档说明写得很直白：帮你搞定**所有命令行参数的解析（parsing）**——"parse" 就是读取、拆解、分析的意思。于是你可以把精力集中到程序有意思的那部分。

### 8.1 第一版：最小可用（并且有坑） [01:05]

```python
# meows.py —— argparse 第一版（不完整）
import argparse

parser = argparse.ArgumentParser()     # 从 ArgumentParser 类造一个 parser 对象
parser.add_argument("-n")              # 告诉它：我要支持一个 -n 参数
args = parser.parse_args()             # 让它去解析命令行（它自己会去查 sys.argv）

for _ in range(int(args.n)):
    print("meow")
```

逐行解释：

- `import argparse`：注意这里**不再 import sys**了。
- `parser = argparse.ArgumentParser()`：类名是 `ArgumentParser`，首字母大写 A 和 P，这是它的构造函数。`parser` 这个名字可以随便取。这里终于用上了 OOP——因为这就是在造对象。
- `parser.add_argument("-n")`：这是 `parser` 对象上的一个**方法**，用来告诉 argparse 我期望用户能提供什么参数。
- `args = parser.parse_args()`：调用解析方法。**默认它会自己去查 `sys.argv`**，你不用 import sys，`ArgumentParser` 自己的代码会处理，并找出 `-n` 或其它参数在哪儿。
- 这行执行完之后，`args` 这个变量里就装着所有命令行参数的值，**无论用户以什么顺序敲的**。只有一个参数时无所谓；如果有 `-n`、`-a`、`-b`、`-c`，用户可以按任意顺序敲（不必按字母序），这对可用性来说更好——而 argparse 帮你搞定这一切。
- 最后 `int(args.n)`：用点号访问 `args` 对象里的 `n` 属性。之所以要手动 `int()`，是因为第一版还没告诉 argparse 它该是整数。

演示 + 讲师的"翻车"：

```text
$ python meows.py
Traceback (most recent call last):
  ...
TypeError: int() argument must be a string, a bytes-like object or a real number, not 'NoneType'
```

讲师自己跑的时候就出错了（他原话是 "I did make a mistake"）。他本意是演示什么都不传的默认情况，结果直接崩了。原因：用户没给 `-n`，于是 `args.n` 是 `None`，`int(None)` 就 TypeError 了。

补上参数就正常：

```text
$ python meows.py -n 3
meow
meow
meow
```

讲师的评价是：眼下这个版本反而**比手写 `sys.argv` 那版更糟**（手写版至少会打印 usage）。但别急，这个库远比这灵活——它能给使用者提供真正的文档。

### 8.2 `--help` / `-h` [01:08]

怎么知道一个命令行程序怎么用？在 Python 以及很多编程环境里，惯例是传一个特殊参数 `-h` 或 `--help`：

```text
$ python meows.py -h
usage: meows.py [-h] [-n N]

options:
  -h, --help  show this help message and exit
  -n N
```

```text
$ python meows.py --help
（输出同上）
```

注意这段输出里的通用约定：

- `usage:` 后面是程序名 `meows.py`；
- **方括号在文档里几乎总是表示"可选"**：`-h` 可选，`-n` 加一个值也可选；
- 下面的 options 区会更啰嗦地列出每个选项，还能看到 `-h` 有长形式 `--help`。

但目前这份帮助信息**太通用了**，跟我的程序毫无关系，发布出去也帮不上用户什么忙。

### 8.3 第二版：加 `description` 和 `help` [01:10]

```python
# meows.py —— argparse 第二版：带说明文档
import argparse

parser = argparse.ArgumentParser(description="Meow like a cat")
parser.add_argument("-n", help="number of times to meow")
args = parser.parse_args()

for _ in range(int(args.n)):
    print("meow")
```

两处新增都叫 named parameter（命名参数）：

- `description="Meow like a cat"`：放在 `ArgumentParser` 里，是**给人类看的**一句话描述；
- `help="number of times to meow"`：放在 `add_argument` 里，解释 `-n` 到底什么意思。

```text
$ python meows.py --help
usage: meows.py [-h] [-n N]

Meow like a cat

options:
  -h, --help  show this help message and exit
  -n N        number of times to meow
```

现在友好多了：上面多了一句"这个程序像猫一样叫"，选项区也告诉你 `-n` 是叫几声。而那个大写的 `N`（args.N 里的 mental variable，形式参数名）是在暗示：小写的 `-n` 之后，按惯例要跟一个数字。

### 8.4 第三版：`default` 和 `type` [01:15]

还剩一个问题：什么都不传的时候程序依然会崩。理想情况下它应该像我们手写 `sys.argv` 那版一样，默认叫一声。查一下文档就知道，`add_argument` 还支持 `default`：

```python
# meows.py —— argparse 最终版
import argparse

parser = argparse.ArgumentParser(description="Meow like a cat")
parser.add_argument("-n", default=1, help="number of times to meow", type=int)
args = parser.parse_args()

for _ in range(args.n):
    print("meow")
```

两个新参数的作用：

- `default=1`：用户没给 `-n` 时，它的值就是 1；
- `type=int`：告诉 argparse "请帮我确保 `-n` 的值是 int"。**这样一来第 7 行就不用自己 `int()` 转换了**——直接信任 `args.n` 已经是整数。

这就是库的价值：脏活累活它干了，你回去专心写自己关心的逻辑（本例中就是"像猫一样叫"）。

```text
$ python meows.py
meow
$ python meows.py -n 3
meow
meow
meow
```

### 8.5 学生提问两则 [01:18]

**问题一：`args.n` 里面装的到底是什么？**

答：装的是**人类在 `-n` 后面加个空格打进来的那个整数**。

**问题二：指定 `type` 之后，如果用户输的是字符串，它会帮你处理异常吗？**

答：非常好的问题，那就试试看：

```text
$ python meows.py -n dog
usage: meows.py [-h] [-n N]
meows.py: error: argument -n: invalid int value: 'dog'
```

argparse 会**自动生成**错误信息（承认有点晦涩），先帮你温习一下 usage，再简单说明哪里不合法。这正是"让库把这类事情自动化，我只管写真正关心的代码"的好处。

## 9. 解包（Unpacking）[01:15]

### 9.1 我们早就见过的一次解包 [01:15]

新建一个 `unpack.py`。先复习：假设程序问用户叫什么名字，比如 "David Malan"，我们能不能把这一个输入拆成两个变量？以前我们用过的办法之一，就是把返回值（一个列表或别的数据结构）**直接拆到两个变量里**：

```python
# unpack.py —— 最朴素的解包（复习）
first, _ = input("What's your name? ").split(" ")
print(f"hello, {first}")
```

```text
$ python unpack.py
What's your name? David Malan
hello, David
```

细节：

- 这里很天真地**按单个空格 split**，潜台词是用户都像讲师一样只有两段名字：没有中间名、没有复姓，正好拆成两个。对别的用户这当然会出 bug，但现在刻意保持简单。
- `_`（下划线）这个变量：按 Python 的惯例，某个值我拿到了但**用不到**，就取名 `_`。但它必须占个位，因为你一次要接两个值。

其实除了这种，Python 还提供了别的解包方式，尤其在**函数参数的传递**上。这算是稍进阶的功能，但一旦你熟悉了这类语法，代码能写得更优雅、更有表现力。

### 9.2 场景：魔法世界的货币换算 [01:16]

别再玩 hello 了，换成《哈利·波特》里的货币：**galleons（加隆）、sickles（西可）、knuts（纳特）**，它们之间有固定的换算关系。写个 `total` 函数算算一个巫师在古灵阁（Gringotts）金库里总共有多少钱。

```python
# unpack.py —— 第 1 版：最普通的位置参数调用
def total(galleons, sickles, knuts):
    return (galleons * 17 + sickles) * 29 + knuts


print(total(100, 50, 25), "Knuts")
```

换算公式是讲师自己查的：加隆 ×17 加西可，整体再 ×29，最后加上零散的纳特。（原书原电影里有没有这细节不好说，总之这是"官方公式"。）

```text
$ python unpack.py
50775 Knuts
```

给 `print` 传了两个参数：算出来的整数, 和字符串 `"Knuts"`，这样输出最后是带单位的。

### 9.3 如果钱存在一个 list 里 [01:17]

假设出于某种原因，我手上的钱都存在一个 list 里，顺序是 100、50、25（相当于一个钱包）。

```python
# unpack.py —— 第 2 版：老老实实用下标索引
def total(galleons, sickles, knuts):
    return (galleons * 17 + sickles) * 29 + knuts


coins = [100, 50, 25]

print(total(coins[0], coins[1], coins[2]), "Knuts")
```

列表的下标从 0 开始，三个元素就是 0、1、2，分别对应 galleons、sickles、knuts，顺序与 `total` 的签名一致。能跑通，数学结果也对。

但——**太啰嗦了（verbose）**。难道就不能直接把这整个列表丢给 `total` 吗？比如写成 `total(coins)`？

讲师当场提问：为什么这样写不行？学生 Eric 答：因为你把一整个列表传给了 `galleons`，`sickles` 和 `knuts` 什么都没收到。

讲师补充两点：

- 这个函数签名里**没有默认值**（第一行没有等号），所以 Python 不知道该假设什么值；
- 而且类型也不对——传进去的是 list，不是当初那个 int。

跑一下这个错误版本：

```text
$ python unpack.py
TypeError: total() missing 2 required positional arguments: 'sickles' and 'knuts'
```

只看错误信息会觉得"我们都知道那里其实有三个东西"，问题是你给错了位置。

如果唯一的出路就是 `coins[0]`、`coins[1]`、`coins[2]`，想象一下函数参数再多一些的时候会有多啰嗦、多容易打错字。

### 9.4 用 `*` 解包列表 [01:20]

现在这个列表是被"打包（packed）"起来的——三个值挤在一个 list 里。能不能像之前把 `split` 的返回值拆成多个变量那样，把它**解包（unpack）**开？

可以，就加一个星号：

```python
# unpack.py —— 第 3 版：用 * 解包列表
def total(galleons, sickles, knuts):
    return (galleons * 17 + sickles) * 29 + knuts


coins = [100, 50, 25]

print(total(*coins), "Knuts")        # 一个星号
```

这里的 `*coins` 会把 `coins` 这个大小为三的序列"炸开"、解包成三个独立的参数传进去。**不需要写逗号**，Python 全包了。效果等价于传 `100, 50, 25`，正好对应 `galleons, sickles, knuts`。

```text
$ python unpack.py
50775 Knuts
```

讲师感叹：仅仅引入了一个符号（这个符号我们在别的语境里当乘号用过），就把代码收拾干净了。虽然只是个单目运算符，但威力不小——它让我们可以把一个数据结构拆开、逐个传进去。

### 9.5 学生提问三则 [01:22]

**问题一：tuple、set、dict 也能这么解包吗？**

答：**tuple 可以**。set 嘛……讲师现场"口头谷歌"了一下（还不小心跟台下自言自语确认了半天），结论是：**set 不行**，因为 set **不保证顺序**——这很容易理解，因为你要解包成有顺序的位置参数，顺序不保就毫无意义。总结一句话：**凡是保序的枚举类型（比如现在的 dict 也保序）都可以用**，而且接下来马上就会看到 dict 用另一种方式（`**`）解包。

**问题二：能不能用解包来取代 for 循环求和，比如直接得到 100+50+25？**

答：简短回答——不行。如果你关心的是**单个值**，那就老实去索引到具体位置。解包的语义是"返回多个值，等价于一个逗号分隔的列表"，不是求和。

**问题三：如果函数参数有默认值，而我们解包的列表元素个数不一样会怎样？**

答：这个问题要先分两种情况。先测元素**多于**参数个数的情形，比如给 `coins` 加一个值：

```python
# 故意多给一个值
coins = [100, 50, 25, 5]
print(total(*coins), "Knuts")
```

```text
$ python unpack.py
TypeError: total() takes 3 positional arguments but 4 were given
```

责任在程序员自己，别这么干。（只要你控制得住这个列表的内容，这事儿是可避免的。）

而如果函数参数**有默认值**，比如 `def total(galleons=0, sickles=0, knuts=0)`，好处就是你不必把三个都传进来，它们会取 0。因此解包列表或字典时可以**少传几个**。讲师特意先**没有**加默认值，就是为了让我们先撞上上面那个错误。

### 9.6 换一种玩法：命名参数 [01:24]

上面都是**位置参数（positional argument）**：默认第一个是 galleons、第二个是 sickles、第三个是 knuts。我们也可以像 Python 允许的那样，把名字一起写进去——这样顺序就不重要了，Python 会按名字对上号。

```python
# unpack.py —— 第 4 版：命名参数调用
def total(galleons, sickles, knuts):
    return (galleons * 17 + sickles) * 29 + knuts


print(total(galleons=100, sickles=50, knuts=25), "Knuts")
```

结果照旧是 50775。这就是最传统的"带名的参数传递"：不再是位置式的，而是明确写清每个参数的名字——名字当然必须和 `total` 里的形参名一致。

### 9.7 一旦有"名字 + 值"，就该想到字典 [01:25]

名字和值、名字和值……这自然会让我们想到 Python（以及别的语言里）最多才多艺的数据结构之一：**dict（字典）**。字典就是键值对的集合，正好"名字 + 各自的值"。

于是把 `coins` 改成字典：

```python
# unpack.py —— 第 5 版：改用字典，老老实实按 key 索引
def total(galleons, sickles, knuts):
    return (galleons * 17 + sickles) * 29 + knuts


coins = {"galleons": 100, "sickles": 50, "knuts": 25}

print(total(coins["galleons"], coins["sickles"], coins["knuts"]), "Knuts")
```

改动点：

- `coins` 现在是字典，所以外层是**花括号**而不是方括号；
- 索引不再用数字，而用**字符串 key**：`coins["galleons"]` 这样。

能跑，结果一样，但**又变啰嗦了**。

### 9.8 用 `**` 解包字典 [01:28]

如果你手上本来就用一个字典来存某人的钱包（每种币各有多少），那用字典是再合理不过的。可当你想算总额时，`total` 又偏偏不收字典——前面演示过，直接传 `coins` 会报错：

```text
$ python unpack.py
TypeError: total() missing 2 required positional arguments: 'sickles' and 'knuts'
```

数据结构（dict）和函数期待的东西（三个整数）就撞上了。解决办法：解包字典，用**两个星号**。

```python
# unpack.py —— 第 6 版（最终）：用 ** 解包字典
def total(galleons, sickles, knuts):
    return (galleons * 17 + sickles) * 29 + knuts


coins = {"galleons": 100, "sickles": 50, "knuts": 25}

print(total(**coins), "Knuts")
```

`**coins` 的效果是：**把三个带名字的值传进去**，等价于写：

```python
total(galleons=100, sickles=50, knuts=25)
```

也就是说，解包字典时，传进去的既有 key 也有 value，概念上用等号连起来，正如明写命名参数时那样。

对比一下两种解包：

- `*coins`（一个星号，作用于 list）：只传值，等价于 `100, 50, 25`；
- `**coins`（两个星号，作用于 dict）：连同键一起传，等价于 `galleons=100, sickles=50, knuts=25`。

**学生提问：字典里能不能是可变数量的键值对？**

答：简短回答，可以有多个键值对（不像这儿只有三对）。但**如果 `total` 只收三个参数，解包就跑不通**。讲师现场往字典里加一枚"pennies（便士）"：

```python
coins = {"galleons": 100, "sickles": 50, "knuts": 25, "pennies": 1}
print(total(**coins), "Knuts")
```

```text
$ python unpack.py
TypeError: total() got an unexpected keyword argument 'pennies'
```

因为在 `total` 眼里根本没有 `pennies` 这个参数。别急，**过一会儿就会看到解决这个问题的漂亮办法**（也就是下一节的 `**kwargs`）。

## 10. `*args` 与 `**kwargs`：数量不定的参数 [01:30]

### 10.1 同一个符号，另一种身份 [01:30]

刚才那个单星号 / 双星号，**不只**用在"解包"这个语境里。同样的语法在 Python 里还有一层含义：作为**视觉标志**，表示"这个函数可以接收数量不定的参数"。

也就是说，函数可以是 **variadic（可变参数的）**：它不必死板地规定"必须收三个参数"，而是可以收零个、一个、两个、三个……实现这个想法的语法，精神上和前面非常相似。

### 10.2 定义一个可变参数函数 [01:30]

清空代码，不再玩加隆西可纳特，写个最通用的东西来看清语法。

```python
# unpack.py —— *args 版：接收任意多个位置参数
def f(*args, **kwargs):
    print("Positional:", args)


f(100, 50, 25)
```

```text
$ python unpack.py
Positional: (100, 50, 25)
```

解读：

- `def f(*args, **kwargs)`：`*args` 表示"我要接收任意数量的**位置参数**（positional argument，通常从左到右排）"，具体几个我暂时不知道；
- `**kwargs` 表示"另外还支持任意数量的**关键字参数**（keyword argument / named parameter）"，调用方可选地按名字一个个给出；
- **`args` 和 `kwargs` 这两个名字可以随便改**，它们只是全世界约定俗成的习惯叫法；你在 Python 官方文档里会频繁看到这两个占位名。为了和"asser（主张）"区分，读的时候通常重音在后面。

讲师特意在函数里只做最朴素的事——把参数打印出来。他不厌其烦地强调：你平常**不会**写这种"不管收到什么都打印出来"的函数，这里纯粹是为了**诊断（diagnostically）**、把语法的效果展示清楚。

### 10.3 数量随便变 [01:32]

过去如果往只接受三个参数的 `total` 里传四个值，会立刻撞 TypeError（某处明明白白告诉你不能多也不多少）。但现在：

```python
f(100, 50, 25, 5)     # 四个也没问题
```

```text
$ python unpack.py
Positional: (100, 50, 25, 5)
```

甚至只剩一个值：

```python
f(100)
```

```text
$ python unpack.py
Positional: (100,)
```

注意这个输出：`(100,)`——**逗号后面明明什么都没有**。这是 Python 表示**只有一个元素的 tuple（元组）**的写法，那个逗号就是"这确实是个序列，只是里面只有一个元素"的标志。

### 10.4 `**kwargs`：自动变成字典 [01:33]

现在改成打印 `kwargs`。位置参数在前（args）、命名参数在后（kwargs），这是 Python 规定的顺序。

```python
# unpack.py —— **kwargs 版：接收任意多个命名参数
def f(*args, **kwargs):
    print("Named:", kwargs)


f(galleons=100, sickles=50, knuts=25)
```

```text
$ python unpack.py
Named: {'galleons': 100, 'sickles': 50, 'knuts': 25}
```

妙处在于：**`kwargs` 自动就是一个字典**，装着所有传给这个函数的命名参数。

所以设计自己的函数时，只要你想支持"不止一两个、也许是任意多个"的参数，你完全可以同时支持：

- 数量不定的**位置参数**（值, 值, 值 这种）；
- 数量不定的**命名参数**（参数名=值, 参数名=值 这种）。

### 10.5 回头看 `print` 的官方文档 [01:35]

其实我们早就在"野外"见过这种写法，只不过当时文档里不叫 `args`、也不叫 `kwargs`。回想我们的老朋友 `print`：

```python
print(*objects, sep=' ', end='\n', file=sys.stdout, flush=False)
```

- 第一个参数是 `*objects`。刚开课时讲师曾对这个星号一笔带过；现在你该能推断出来了：**这是 Python 文档的约定，表示 print 接收数量可变的参数**。
- 后面的 `sep`（separator，分隔符，默认是空格）、`end`（默认是换行 `\n`）等是命名参数。（还有 `file`、`flush` 这些我们当时也没细看。）
- 如果去看 print 的真实实现，它大概长这样：

```python
def print(*objects, sep=' ', end='\n', file=sys.stdout, flush=False):
    for object in objects:        # 遍历那堆数量不定的对象，逐个打印
        ...
```

（上面这段代码只是**示意**，不是真实源码。）

这就解释了一件我们做了好几周却没深究的事：为什么你可以

- `print()` —— 括号里什么都不放；
- `print("hello, world")` —— 放一个字符串；
- `print("hello", "world")` —— 放两个甚至更多字符串。

我们一直都在用**可变参数函数（variadic function）**。而现在，通过今天学的 `*args` / `**kwargs`（名字不必叫这个），你自己也能写出这种函数了。讲师那会儿写的 `f` 函数确实没干什么正经事，但它示范了：将来如果你有这种需求，该怎么接收零个、一个或多个任意类型的参数。

**学生提问一：如果打印的是 kwargs，而传进来的参数本身是个列表，会怎样？**

答：讲师把历史代码回滚到那个 `f` 函数解释：传 `f(100, 50, 25)` 时，这三个值自动被收集到 `args` 里；跑 `python unpack.py` 你就能看到那一整串值——它们体现在**同一个变量**里。这只是为了演示语法效果，程序本身毫无美感也毫无用处，但它展示了"如何访问这一整串值"。

**学生提问二：能不能把 kwargs 传给另一个函数？**

答：当然可以。两种（args 或 kwargs）都能往下传。典型场景是你**包装（wrap）**另一个函数：外面套一层、加点自己的功能，同时把原本应该支持的全部参数原封不动地传给底层那个函数。

## 11. 三种编程范式与 `map` [01:40]

### 11.1 先梳理一下范式 [01:38]

接下来要补充的工具，关系到 Python 支持的**编程模型（programming model / paradigm）**：

- **procedural programming（过程式编程）**：我们一开始就是这样——从上到下、从左到右写代码，途中定义一些函数（也就是 procedure，过程）、定义变量、产生副作用、按需赋值。
- **object-oriented programming（面向对象编程）**：后来我们揭开的真相：Python 其实也很面向对象。我们用了好几周的那些变量和类型其实都是对象，来自某个类；类是某种模板或蓝图，可以把数据和功能一起封装进去。
- **functional programming（函数式编程）**：第三种范式，Python 在一定程度上也支持。在它里面函数的地位更高——**倾向于没有副作用**（不打印、不改全局状态），而是完全自包含：接收输入、返回输出。

其实这条路我们早就踩过一脚：讲**排序**的时候，我们把一个函数（或 lambda）当作 `key` 传给 `sorted`，让它决定排序依据——那就是函数式风格。

现在再把这套思路往前推一步。

### 11.2 `yell.py` 第 1 版：只能喊一个词 [01:40]

关掉 `unpack.py`，新建 `yell.py`。目标：用户输入一句话，程序把它全部转成大写"喊"出来。（讲师特意向戴耳机的同学道歉，并答应收敛音量。）

```python
# yell.py —— 第 1 版：只收一个短语
def main():
    yell("This is CS50")


def yell(phrase):
    print(phrase.upper())      # str 的 upper 方法：全部转大写


if __name__ == "__main__":
    main()
```

```text
$ python yell.py
THIS IS CS50
```

### 11.3 第 2 版：改成接收一个列表 [01:41]

只收一句话不好，最好像 `print` 那样能收好几个词。先尝试让 `yell` 收一个**列表**：

```python
# yell.py —— 第 2 版：接收列表（第一小步：错的）
def main():
    yell(["This", "is", "CS50"])


def yell(words):
    for word in words:
        print(word, end="")     # 还没转大写，显然不对


if __name__ == "__main__":
    main()
```

跑一下发现：**我没有把任何东西转成大写**。那就修：

```python
# yell.py —— 第 2 版：先攒一个空列表
def main():
    yell(["This", "is", "CS50"])


def yell(words):
    uppercased = []                        # 空列表，也可以写成 list()
    for word in words:
        uppercased.append(word.upper())    # 逐个转大写再 append 进去
    print(uppercased)                      # 先直接打印，看看长啥样


if __name__ == "__main__":
    main()
```

```text
$ python yell.py
['THIS', 'IS', 'CS50']
```

**又一个"翻车点"**：输出不是人话，带着 Python 语法的痕迹——引号、逗号、方括号。因为你在打印一个**列表**。

这时候前文的解包就派上用场了：思路不用改，只要加一个星号：

```python
# yell.py —— 第 2 版修好：用 * 解包再交给 print
def main():
    yell(["This", "is", "CS50"])


def yell(words):
    uppercased = []
    for word in words:
        uppercased.append(word.upper())
    print(*uppercased)     # 把列表拆成三个独立的参数给 print


if __name__ == "__main__":
    main()
```

```text
$ python yell.py
THIS IS CS50
```

现在输出是正常英文了，没有引号逗号方括号——三个大写词被当成三个独立参数交给 `print`，由它用空格分隔。解包技术第一次展现出它的实用价值。

### 11.4 第 3 版：别逼用户传列表了 [01:43]

不过让用户必须传一个列表还是别扭。你写的时候得多敲方括号，而且不符合大家习惯——`print` 明明允许你传零个、一个、两个乃至任意多个参数，凭什么你的 `yell` 只收一个列表？

改进办法就是把方括号去掉，直接传三个参数；函数定义处也不要写 `word1, word2`（那没法扩展、没法应对不同数量的词），而是用我们刚学到的星号：

```python
# yell.py —— 第 3 版：用 *words 接收任意多个词
def main():
    yell("This", "is", "CS50")


def yell(*words):                          # 不用 args，起个更清楚的名字 words
    uppercased = []
    for word in words:
        uppercased.append(word.upper())
    print(*uppercased)


if __name__ == "__main__":
    main()
```

```text
$ python yell.py
THIS IS CS50
```

讲师的评价是"边际改善（marginal improvement）"，但对用户友好多了：现在 `yell` 和 `print` 一样，爱传几个传几个，而且还顺带把一切都转成了大写。

### 11.5 `map`：把一个函数映射到序列的每个元素上 [01:45]

Python 自带的 **`map`** 函数，干的就是这件事：把一个函数"映射（map）"到某个序列（比如列表）的每一个元素上。

```python
# yell.py —— 第 4 版：用 map
def main():
    yell("This", "is", "CS50")


def yell(*words):
    uppercased = map(str.upper, words)
    print(*uppercased)


if __name__ == "__main__":
    main()
```

```text
$ python yell.py
THIS IS CS50
```

三行循环缩成一行。语法细节至关重要：

- `map` 收**两个**参数；
- 第一个是"我想应用到每个元素上的那个**函数**"。由于我们已经懂了 OOP，就知道 `str` 这个类里有个叫 `upper` 的函数——我们平时的写法是 `变量.upper()`，而在 `str` 类的文档里，这个函数写作 **`str.upper`**；
- **注意这里 `str.upper` 后面没有括号！** 因为我不想现在调用它，我是要把这个函数**交给** `map`，让 `map` 在需要的时候替我给每个元素"补上括号"去调用；
- 第二个参数是那个序列本身，本例是 `words`；
- 这就是**函数式编程的实例**：我把一个函数当作值传给另一个函数，只是"按引用（by a reference）"交出去，并没有调用它；
- `map` 会替你遍历 `words`、对每个词调用 `str.upper`，最后返回一个装着全部结果的新列表。手动造列表、`append`、`append` 那套全免了；
- 最后还是用 `*uppercased` 解包交给 `print`，一次打印出来。

## 12. 列表推导式（List Comprehensions）[01:45]

还有一个更 Pythonic、或者说更常见的写法：**列表推导式**。

名字听起来挺吓人，但它指的是：不用循环、不用 `append`，而是在**一行之内**临时构造出一个列表的能力。

```python
# yell.py —— 最终版：列表推导式
def main():
    yell("This", "is", "CS50")


def yell(*words):
    uppercased = [word.upper() for word in words]
    print(*uppercased)


if __name__ == "__main__":
    main()
```

语法读法（官方 Notes 里写的是 `[arg.upper() for arg in words]`，讲师口述时用的是 `word`）：在一对方括号里写一个 Python 表达式，它会按你写的逻辑**动态生成**一个全新的列表。从左往右读就是：**"对 words 里的每个 word，给我它的大写版本"**。

讲师坦言这确实有点绕口（mouthful），需要适应：左边是要塞进结果的值（连着一次函数调用），方括号里面还嵌着一个循环。但一旦习惯这种从左到右的读法，Python 程序员会非常喜欢这个能力——过去要两三行甚至更多、要反复 append 才能造出来的列表，现在一句话搞定。

**学生提问：里面能加 if / else 条件吗？**

答：可以，马上就给你看（下一节）。眼下我们先只是把列表里每个词都转成大写。

**学生提问：这算函数式编程吗？**

答：未必。讲师认为这更像 Python 自己的一个特性。真正的函数式 incarnation（具体体现）是刚才的 `map`；另外当初把 lambda 当 `key` 传给 `sorted` 也是一例；而且马上我们还会看到一例（`filter`）。

## 13. 带条件的列表推导式：筛出 Gryffindor [01:50]

### 13.1 先写传统版本 [01:50]

关掉 `yell.py`，新建 `gryffindors.py`：还是那份学生名单（Hermione、Harry、Ron、Draco），目标是只挑出 Gryffindor 学院的学生。

```python
# gryffindors.py —— 第 1 版：老式循环 + 条件
students = [
    {"name": "Hermione", "house": "Gryffindor"},
    {"name": "Harry", "house": "Gryffindor"},
    {"name": "Ron", "house": "Gryffindor"},
    {"name": "Draco", "house": "Slytherin"},
]

gryffindors = []
for student in students:
    if student["house"] == "Gryffindor":
        gryffindors.append(student["name"])

for gryffindor in sorted(gryffindors):
    print(gryffindor)
```

```text
$ python gryffindors.py

Hermione
Ron
```

看过书或电影的就知道，这四个里只有三个是 Gryffindor；`sorted` 又顺手把名字按字母排好了。

### 13.2 压缩成一行 [01:52]

```python
# gryffindors.py —— 第 2 版：带条件的列表推导式
students = [
    {"name": "Hermione", "house": "Gryffindor"},
    {"name": "Harry", "house": "Gryffindor"},
    {"name": "Ron", "house": "Gryffindor"},
    {"name": "Draco", "house": "Slytherin"},
]

gryffindors = [
    student["name"] for student in students if student["house"] == "Gryffindor"
]

for gryffindor in sorted(gryffindors):
    print(gryffindor)
```

读法是：**"对 students 里的每个 student，如果他的 house 是 Gryffindor，就把他的 name 放进这个新列表。"**

讲师的讲解逻辑很清楚：这和刚才给 `yell` 造列表的推导式如出一辙，只是这里**带条件**。我们从"循环"借鉴了想法，从"条件"借鉴了想法，再把它们塞进同一个方括号语法里。所以 `gryffindors` 最终是零个或多个学生的名字——具体是哪些，取决于遍历时谁的 house 恰好是 Gryffindor。

顺便一个现场小插曲：讲师第一次跑的时候**屏幕上什么都没出现**——因为他还没把程序写完（没写打印的部分）。这也是课堂演示常见的"半截代码"状态。

## 14. `filter`：函数式的筛选 [01:55]

同一道题还有别的解法，这就回到 Python 的函数式特性：除了 `map`，还有一个叫 **`filter`** 的函数，能用更函数式的思路达到同样效果。

### 14.1 写一个返回布尔值的函数 [01:55]

```python
# gryffindors.py —— filter 版
students = [
    {"name": "Hermione", "house": "Gryffindor"},
    {"name": "Harry", "house": "Gryffindor"},
    {"name": "Ron", "house": "Gryffindor"},
    {"name": "Draco", "house": "Slytherin"},
]


def is_gryffindor(s):
    return s["house"] == "Gryffindor"


gryffindors = filter(is_gryffindor, students)

for gryffindor in sorted(gryffindors, key=lambda s: s["name"]):
    print(gryffindor["name"])
```

讲师写 `is_gryffindor` 的过程很值得学：他**先**口述了一个啰嗦版本——

```python
# 冗余版：明明已经在问布尔问题了，还非要 if / return True / return False
def is_gryffindor(s):
    if s["house"] == "Gryffindor":
        return True
    else:
        return False
```

然后立刻自我纠正：这种条件判断写得没必要地啰嗦了（unnecessarily verbose）。既然上面就是在问一个是非题，那直接把这个布尔值 `return` 出去就行——要么相等为 `True`，否则为 `False`，不必显式地 return True / False。

### 14.2 `filter` 与 `map` 的区别 [01:56]

`filter` 同样收两个参数：

- 第一个是要应用到每个元素上的**函数**；
- 第二个是被处理的**序列**。

它和 `map` 的精神一样（都在"把函数交给另一个函数"），但结果不同：

- `map`：**每个元素都产出一个对应的新值**（所以能用来把所有词转成大写）；
- `filter`：它期待的那个函数返回的不是新值，而是 **True / False**——用来回答"这个元素要不要留在结果里"。本例中问的就是"他住不住在 Gryffindor？"，答案从字典的 `house` 键里取。

### 14.3 排序这块要注意 [01:57]

`filter` 返回的是**原来的那些字典**，不是名字字符串。所以打印时得取 `gryffindor["name"]`；而且不能像上一节那样直接 `sorted(gryffindors)`——那是拿一堆字典在比大小。要给 `sorted` 一个 `key`：一个匿名函数，也就是 **lambda 函数**，它接收一个学生 `s`，返回 `s["name"]`，表示"按学生自己的名字排序"。

```text
$ python gryffindors.py
Harry
Hermione
Ron
```

讲师先跑的版本**没加 key**，所以输出是 Hermione、Harry、Ron（未排序），然后再补上 key 变成排序好的。

### 14.4 学生提问三则 [01:58]

**问题一：如果把代码全塞在一行里，做代码风格检查（比如 Black）不会报错吗？可读性不是更差吗？**

答：讲师把代码回滚到那个较长的列表推导式版本，然后跑 `black gryffindors.py`，结果 Black **只是微调了格式**。讲师坦白说：他是提前自己手动排好版的——因为他知道如果自己写成一行，Black 八成不喜欢，会帮他重排。为了避免被工具改，他干脆在写的时候就排好了。

**问题二：能不能不定义 `is_gryffindor`，直接把判断写在 `filter` 里面？**

答：讲师先反问了一下，确认同学的意思。对方补充说：能不能直接把 `house == "Gryffindor"` 这个 return 写进去。答案是**当然可以**——回顾几周前学过的 lambda 函数，那正是为了"临时把一个匿名的小函数传给 `sorted` 的 key"。这里也可以：

```python
# gryffindors.py —— filter + lambda 版（无需单独定义函数）
students = [
    {"name": "Hermione", "house": "Gryffindor"},
    {"name": "Harry", "house": "Gryffindor"},
    {"name": "Ron", "house": "Gryffindor"},
    {"name": "Draco", "house": "Slytherin"},
]

gryffindors = filter(lambda s: s["house"] == "Gryffindor", students)

for gryffindor in sorted(gryffindors, key=lambda s: s["name"]):
    print(gryffindor["name"])
```

lambda、`filter` 接收到的 `s` 就是当前学生，返回 `s["house"] == "Gryffindor"` 这个布尔值。于是**可以把 `is_gryffindor` 整个删掉**——不必为了只用一次而专门定义一个函数。输出结果不变。

注意传给 `filter` 的是"函数的**名字**"（或者是 lambda 这个匿名函数本身），而不是调用它——所以要让 `filter` 替你去调用这个判断函数。

## 15. 字典推导式（Dictionary Comprehensions）[02:00]

最后再装备一个工具：字典推导式。讲师承认语法已经开始变得愈发奇怪了，但随着你对这些基础构件越来越熟，它们就是你解决未来问题的可选武器。

有了字典推导式，你就不必"造一个空字典 → 写个 for 循环 → 一次次往里塞键值对"，而可以**一次搞定**。

### 15.1 先回到最土的办法 [02:00]

问题掉个个儿：这回**只知道学生的名字**，要把"每个学生的信息字典"重新搭出来。

```python
# gryffindors.py —— 第 1 版：最老实的写法，先攒一个列表
students = ["Hermione", "Harry", "Ron"]

gryffindors = []

for student in students:
    gryffindors.append({"name": student, "house": "Gryffindor"})

print(gryffindors)
```

```text
$ python gryffindors.py
[{'name': 'Hermione', 'house': 'Gryffindor'}, {'name': 'Harry', 'house': 'Gryffindor'}, {'name': 'Ron', 'house': 'Gryffindor'}]
```

讲师带着大家读这段输出：

- 最外层的方括号说明这是**一个列表**；
- 里面有一堆花括号，每个花括号是一个字典；
- 花括号里带引号的是 key（`print` 一个字典时按惯例用单引号包裹 key，这只是视觉指示），后面跟它的值：`'name': 'Hermione'`、`'house': 'Gryffindor'`；
- 逗号分隔相邻的字典对象；越过 Harry 那一组之后，还有第二个逗号把 Harry 组和 Ron 组分开。

### 15.2 压缩成列表推导式 [02:03]

```python
# gryffindors.py —— 第 2 版：列表推导式（列表里装字典）
students = ["Hermione", "Harry", "Ron"]

gryffindors = [{"name": student, "house": "Gryffindor"} for student in students]

print(gryffindors)
```

输出和上面完全相同。三行变一行。

读法（讲师的说法）：

- 最外层方括号 = 我要造一个列表；
- 方括号里第一个东西 = 我要在这个列表里放的**对象**，这里是花括号包着的字典；
- 每个字典有两个 key：`name` 和 `house`，值分别是"某个学生"和固定的 `"Gryffindor"`；
- 从哪些名字造这些字典呢？`for student in students`；
- 所以**左边是"结果长什么样"，右边是"循环"**，这次没有条件。

### 15.3 真正的字典推导式 [02:05]

可我不想要"装着三个字典的列表"，我想要**一个更大的字典**：key 是学生名，value 是所属学院——`Hermione: Gryffindor`、`Harry: Gryffindor`、`Ron: Gryffindor`。不需要列表，也不需要每个学生一个对象。（暂时假设这个世界里没有重名。）

```python
# gryffindors.py —— 第 3 版：真正的字典推导式
students = ["Hermione", "Harry", "Ron"]

gryffindors = {student: "Gryffindor" for student in students}

print(gryffindors)
```

```text
$ python gryffindors.py
{'Hermione': 'Gryffindor', 'Harry': 'Gryffindor', 'Ron': 'Gryffindor'}
```

**唯一的形式差别：最外层从方括号变成花括号。** 内部依然保持"左边是结果、右边是循环"的结构：

- 每个 key 是**某个学生的名字**；
- 每个 value 是 `Gryffindor`；
- 从哪儿来？从这个名单里一个一个来。

讲师又一次感慨：某种视角下 Python 真的很"从左到右可读"。当然这需要练习和熟悉度，但它确实又是一种解决同类问题的武器。注意这次输出不再有方括号和多个字典，只有**一个大字典**。

## 16. `enumerate`：同时拿到下标和值 [02:05]

再补一个 Python 自带的函数。回到最简单的名单：Hermione、Harry、Ron。假如我们想给每个人排个名次（1、2、3）。

最朴素的循环只能打印名字：

```python
students = ["Hermione", "Harry", "Ron"]

for student in students:
    print(student)
```

```text
$ python gryffindors.py
Hermione
Harry
Ron
```

没有任何数字序号。于是换个循环写法，用 `range(len(...))`：

```python
# enumerate —— 第 1 版：range + len + 索引
students = ["Hermione", "Harry", "Ron"]

for i in range(len(students)):
    print(i + 1, students[i])
```

```text
$ python gryffindors.py
1 Hermione
2 Harry
3 Ron
```

注意这里的 `i + 1`：讲师特意演示了**先写 `print(i, students[i])` 的版本**，输出是 0 Hermione、1 Harry、2 Ron——"这几位又不是程序员，他们可不认为自己是从 0 开始编号的，Hermione 肯定想排第一而不是第零"。所以补一点算术：`i + 1`。

但其实 Python 一直有一个内置函数能更简洁地解决这件事：**`enumerate`**。它会遍历某个序列，但每次给你的不是"值"，而是**值和它的下标，两个答案一起**：

```python
# enumerate —— 第 2 版：enumerate
students = ["Hermione", "Harry", "Ron"]

for i, student in enumerate(students):
    print(i + 1, student)
```

```text
$ python gryffindors.py
1 Hermione
2 Harry
3 Ron
```

好处一目了然：

- 不用再写那个啰嗦的 `range` / `len` / 到处出现的 `i`；
- 不用再用 `students[i]` 这种下标索引把值捞出来；
- `i + 1` 那点小算术还是照旧（`enumerate` 给的下标仍然是 0、1、2）。

讲师点题：**这一讲的主题就是"解决和过去几周一样的问题，但用手上更多的工具把代码收紧。"**

## 17. 生成器（Generators）与迭代器（Iterators）[02:10]

### 17.1 问题场景：数据量太大怎么办 [02:10]

如果你写的函数要读取或生成**大量**数据，你的函数、程序乃至整台电脑都可能把内存耗尽，程序就跑不下去了。这个问题我们之前没专门遇到过，但只要你离开这门课开始做真实的数据处理，迟早会碰上。

在美国有个习俗：睡不着的时候就在脑子里**数羊（count sheep）**——卡通片里常见：一只羊跳过栅栏，然后两只，然后三只……数到无聊你就睡着了。我们就用这个写个 `sleep.py`。

### 17.2 第 1 版：直接写在顶层 [02:10]

```python
# sleep.py —— 第 1 版：全写在顶层
n = int(input("What's n? "))
for i in range(n):
    print("🐑" * i)          # 字符串乘整数：i 只羊
```

```text
$ python sleep.py
What's n? 3

🐑
🐑🐑
```

注意是从 0 开始数的：第一次循环打印 0 只羊（空行/什么都不显示），然后是 1 只、2 只……一直到 n-1 只。把终端窗口拉大一点就能看到更多羊。

### 17.3 第 2 版：加个 `main` [02:11]

践行我们一直宣扬的设计习惯：

```python
# sleep.py —— 第 2 版：包进 main
def main():
    n = int(input("What's n? "))
    for i in range(n):
        print("🐑" * i)


if __name__ == "__main__":
    main()
```

功能几乎没变，输入 3 依然是 0 只、1 只、2 只羊。

### 17.4 第 3 版：抽出 `sheep` 函数 [02:12]

我们一直在"抽象（abstract away）"代码：把生成羊的功能拆成单独的函数——一来确实被抽象了，不用再关心实现细节；二来可以在别的项目或库里复用；三来也方便写单元测试。

所以别把所有逻辑都堆在 `main` 里：

```python
# sleep.py —— 第 3 版：抽出 sheep 函数（一次只造一行）
def main():
    n = int(input("What's n? "))
    for i in range(n):
        print(sheep(i))       # 由 sheep 负责返回这一行羊


def sheep(n):
    return "🐑" * n           # 返回值而不是打印，方便写单测


if __name__ == "__main__":
    main()
```

这里的关键改动：`sheep` 不再打印（副作用），而是**返回**一整串该数量的羊字符串，交给 `main` 打印。函数单一职责，好测试。

### 17.5 第 4 版：一次返回整群羊（灾难的开始） [02:13]

不过还有点不优雅：**迭代还得由 `main` 负责**。能不能让 `sheep` 负责生成全部数据、一次性返回？

```python
# sleep.py —— 第 4 版：攒一个巨大的列表再一次性返回
def main():
    n = int(input("What's n? "))
    for s in sheep(n):        # sheep 现在是复数意义上的一群羊
        print(s)


def sheep(n):
    flock = []                # 一群羊，从空列表开始
    for i in range(n):
        flock.append("🐑" * i)
    return flock              # 整个列表一次性交出去


if __name__ == "__main__":
    main()
```

小提示：`main` 里的循环变量写作 `s` 而不是 `sheep`，因为 sheep 单复数同形，用 `for sheep in sheep(n)` 会把自己覆盖掉。

小规模测试都正常：输入 3 正常；输入 10 行，正常；输入 100，开始有点丑但刷刷就过去了；输入 1000，依然飞快，只是屏幕上比较乱；输入 10000，**开始明显变慢、屏幕闪烁**（据讲师说是大约慢了 10 倍），但还是能全部打印出来。

### 17.6 一百万只羊：挂了 [02:15]

那就再冒险一点：**一百万只羊**。

```text
$ python sleep.py
What's n? 1000000
```

然后——**什么都没有了**。

讲师一边等着一边问：有人有直觉吗，为什么我的程序突然不打印羊了？在这个不断生成巨大列表的版本里，到底哪里出错了？

学生答：可能是内存（memory）或算力（computation power）耗尽了。

讲师确认：我们大概是顶到了这台 Mac / PC / 云服务器的**内存或 CPU（计算机的大脑）上限**。它正在试图生成一份又一份巨大无比的巨大列表——一百万行羊，而且每行羊的数量还在增长。这台电脑显然吃不住了。

更糟的结果是：过一会儿程序被 **`Killed`**——也就是说，电脑实在受不了你占用这么多内存和 CPU，直接宣布"不许你再跑了"。

（讲师还幽了一默：这时候连风扇声都听得见了。）

**这里藏着本讲最深刻的反思**：这个程序对 1000 只羊、10000 只羊明明都跑得好好的，一过某个阈值就彻底不能用；或者慢到毫无实用价值。可这实在有点蠢——理论上我明明可以"先打印一只，马上打印两只，再打印三只"这样按顺序来啊。

问题的根结（回到代码看）：恰恰是我为了践行"最佳实践"（把逻辑模块化、拆出辅助函数），导致 `sheep` 的职责是"生成所有羊、然后一次性全部返回"。那就问一句：**一次返回一点点，会不会更好？**

可如果真把打印塞回一个个地方，那又是**倒退**：这就和过去几周学到的教训相矛盾——一般来说，不要把什么都塞进 `main`；一般来说，多抽一个函数出来、能单独写单测，是好事。难道为了减少几只羊的内存占用，就要把这些最佳实践全扔掉？

### 17.7 解法：生成器（generator）与 `yield` [02:20]

Python 的答案是**生成器（generator）**。你可以把函数定义成生成器：它照样能为调用者生成海量数据，但可以**一次只返回一点点**。你自己要写的代码几乎没变，也不必担心一次性返回太多。

官方文档里都有。而这一切归根结底就是一个关键字：**`yield`**。

过去我们写函数，返回值（如果有）一律用 `return`；前面那个倒霉版本里，我们一直在 `return flock`——等回来的时候，整群羊都在手上，而电脑已经累死了。

```python
# sleep.py —— 最终版：用 yield 变成生成器
def main():
    n = int(input("What's n? "))
    for s in sheep(n):
        print(s)


def sheep(n):
    for i in range(n):
        yield "🐑" * i       # 不是 return！一次交一条


if __name__ == "__main__":
    main()
```

先用 `return` 做反例，讲师讲得非常清楚：**在这个循环里用 `return` 是不行的**。因为如果你要一百万只羊，写个 `for i in range(1000000)` 并在循环体里 `return`，那你会立刻 return 掉第 0 只羊，整个函数就到此为止了——循环只跑一次，后面的迭代根本轮不到。

而 `yield` 的含义是：**"一次返回一个值"**，然后"再返回一个值"，"再返回一个值"……**for 循环会继续往下走**，i 继续从 0、1、2 一路数到一百万；只是每次函数都只把一小份数据递出来（一次只 generate 一点点，而不是全部）。

为什么这样就不爆？因为这台电脑的内存虽然装不下一百万行羊，但**装一行羊绰绰有余**。

```text
$ python sleep.py
What's n? 3

🐑
🐑🐑
```

再试一百万：

```text
$ python sleep.py
What's n? 1000000
🐑
🐑🐑
...（屏幕上羊在飞快地刷）
```

屏幕上的变化立竿见影：**程序不再是"卡住（hang）"**——不是在那儿干等、思考、试图一次性生成整群羊；它一行一行地生成，屏幕上因为量太大而闪烁。（讲师说我们就不等它数完了，否则**在座的各位就真的要睡着了**。一台流淌着羊的屏幕。）

### 17.8 术语：迭代器（iterator） [02:22]

再补一个术语，好让你之后听到时不陌生：上面这套东西返回的是我们称为 **iterator（迭代器）** 的东西。`yield` 返回的就是一个 iterator，它让你的代码——本例中 `main` 里的那个 for 循环——能够逐个迭代这些被生成出来的值。

### 17.9 学生提问两则 [02:23]

**问题一：`yield` 在底层到底是怎么工作的？是用多线程（multithreading）吗？**

答：你可以把它的实现理解为"某种意义上的异步（asynchronous）"——函数先立刻返回一个值，随后再给你一个又一个。

底层真正发生的事情是：**生成器替你保留了状态（retaining state）**。它不会把整个循环从头跑到底再返回值；它跑一次迭代、yield 一个结果，然后 Python 会**把这个函数挂起（suspend）**，但记住它当时跑到了第几次迭代。于是你下次再迭代它（就像 `main` 里那个 for 循环会一次又一次地迭代），就又会拿到下一个值，周而复始。

所以 `yield` 返回的就是一个叫做**迭代器（iterator）**的东西，这个迭代器可以在循环里被一个元素一个元素地"踏"过去。而 Python 替你处理了这些底层的管道（plumbing），你不必自己动手。

**问题二：是不是每次迭代，程序都会把那部分内存还给系统，所以不会崩？**

答：对。每次迭代只返回当前 i 对应的那一串羊，它不会试图一次返回全部一百万行。因此它用到的内存大约是原来的百万分之一（讲师承认这个说法有点简化）。

最后讲师提醒：像过去遇到无限循环时那样，用键盘 **Ctrl-C** 可以中断这个程序（虽然它并非死循环，只是真的很长），把电脑的控制权拿回来。

- **exceptions（异常）**：事情总会出错。异常处理不仅让你抓住错误，还能让你**主动 raise 自己的异常**——当你打算写给别人用的代码（比如库）时，这点尤其重要。
- **libraries（库）**：你现在不仅能用库，还能自己写，无论是一个小模块还是一整个想分享给全世界的 package（包）。
- **unit tests（单元测试）**：你能为自己的代码、自己的库、甚至别人的代码写测试。这样你不仅对"今天的代码是对的"更有信心，而且明天改动代码之后，只要测试继续通过，你就没把东西弄坏。
- **file I/O（文件读写）**：把所有数据存在**磁盘**上而不仅仅是内存里（就像刚才那些羊）——可以是 CSV，也可以是更偏二进制的东西比如图片。
- **regular expressions（正则表达式）**：用模式去表达、去校验、去抽取数据。在数据规模不断膨胀、而且源头往往很脏的今天，这尤其管用。
- **object-oriented programming（面向对象）**：换一种视角解决同类问题，用代码去封装和刻画真实世界的实体。
- **et cetera（其它内容）**：也就是今天——那些不属于上面任何一把大伞、但值得塞进你口袋的工具：函数、数据类型、各种技巧，都是你解决问题的又一手段。

## 本讲易错点

1. **`set` 的方法名是 `add` 不是 `append`**：造空集合用 `set()`（不是 `{}`，那是空字典的写法），往里加东西用 `add`。用 `set` 之后就别再手写 `if x not in list` 去重了，重复它自动帮你吃掉。
2. **全局变量能读不能写**：在函数里只是打印/读取全局变量完全没问题；一旦尝试 `balance += n` 就会得到 `UnboundLocalError: local variable 'balance' referenced before assignment`——注意**这个错误信息有误导性**，明明你在文件顶部赋过值。修法是在函数内写一行 `global balance`（每个要改它的函数都要写）。
3. **同名局部变量会遮蔽全局变量**：函数内外同名，函数里改的是局部那个，全局变量纹丝不动。看不清这一点很容易埋 bug，所以干脆别这么写。
4. **把变量当参数传进去也救不了你**：函数里改的只是局部副本，外面那个值不会变。真正干净的替代方案是**用类**（`self._balance` + `@property`）。
5. **Python 的常量只是"君子协定"**：`MEOWS = 3` 靠全大写 + 放文件顶部表达意图，语言层面**不阻止**你改它。同理，类变量 `Cat.MEOWS` 也是"不鼓励改"而不是"改不了"。
6. **类型注解不会被 Python 执行**：写了 `n: int` 之后 `python meows.py` 照样报 TypeError。注解是给 `mypy` 这类工具看的。想提前抓 bug 要手动跑 `mypy meows.py`。
7. **没有 `return` 的函数返回值是 `None`**：所以 `meows: str = meow(number)` 会拿到 `None` 并打印出来。用 `-> None` 注解返回值，`mypy` 会报 `"meow" does not return a value` 提醒你。
8. **`int(...)` 是函数调用，注解里的 `int` 是类型**：两者同名但身份不同；类型转换这一步必须你自己做（`number: int = int(input(...))`），`mypy` 不会因为你有注解就替你转。顺带术语纠正：在 Python 里这叫 convert（转换），不叫 typecast。
9. **`argparse` 第一版不带 `default` 会崩**：不传 `-n` 时 `args.n` 是 `None`，`int(None)` 直接 TypeError。加上 `default=1, type=int` 之后既不怕漏传、也不用自己 `int()` 转换了。
10. **解包元素个数必须和参数个数对得上**：`*coins` 少传或多传都会 TypeError（`takes 3 positional arguments but 4 were given`）；`**coins` 里多一个 key 会报 `unexpected keyword argument 'pennies'`。另外 `set` 不能解包（不保序），tuple 和 dict 可以。
11. **给 `map` 传函数时不要加括号**：写 `map(str.upper, words)`——加括号就变成"现在调用它"了，你要的是把函数当值交出去。同理，`filter(is_gryffindor, students)` 传的是函数名，`is_gryffindor(student)` 是错的。
12. **`print(列表)` 会带出 Python 语法痕迹**：想要干净的英文输出就用 `print(*列表)` 解包。
13. **`filter` 返回的是原字典，不是字符串**：所以排序要 `key=lambda s: s["name"]`，打印要 `gryffindor["name"]`。用列表推导式那种写法时取出来的是字符串，两者别混。
14. **`enumerate` 的下标依然从 0 开始**：想显示人类习惯的 1、2、3，别忘了 `i + 1`。
15. **别在循环里用 `return` 想"分批返回"**：第一次迭代就返回，循环直接终止。要分批返回请用 `yield`，它返回的是一个**迭代器（iterator）**，每次迭代生成一小份数据、保留当时的状态，避免一次性把百万行数据塞进内存把程序跑挂（Killed）。
