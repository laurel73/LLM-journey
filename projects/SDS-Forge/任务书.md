## 一、题目（一句话）

**把几百份格式互不相同的化学品安全技术说明书（SDS / MSDS）PDF，自动解析成可校验、可查询的结构化台账，并用一套可复现的评测脚本，证明它比人工快多少、准多少，以及在哪些情况下会失败。**

简称 SDS-Forge。仓库名建议 `sds-forge`。

---

## 二、为什么是这道题

不是拍脑袋选的，四条依据：

**1. 痛点真实且是法定要求，不需要你去找工厂要数据。**
SDS（中国叫「化学品安全技术说明书」，旧称 MSDS）是《危险化学品安全管理条例》要求企业必须提供和持有的文件，结构由 **GB/T 16483-2008 / GHS 统一规定为 16 节**（标识、危险性概述、成分组成、急救、消防、泄漏、操作储存、接触防护、理化特性、稳定性、毒理、生态、废弃、运输、法规、其他）。任何化工厂、化工贸易商、仓储方都要维护 SDS 台账。现实流程是：供应商发来 PDF → 人工打开 → 把关键字段敲进 Excel/ERP → 每年版本更新重来一遍。**每份人工录入约 8–15 分钟**，几百种物料就是一个人几周的活。

**2. 它现在是真实的研究前沿，你已经有可对标的公开基线。**
不是「做个玩具」，是有人在正经发论文的问题：

- TNO（荷兰国家应用科学院）2026 年发表在 *Annals of Work Exposures and Health* 的流水线，用 LLM 自动抽取 SDS 多字段入库，**平均准确率 0.83**。
- Wiley 2025 年一篇对比研究更有意思：**纯文本模式** GPT-4o 准确率只有 50.59%、召回率 17.16%；**图像（多模态）模式** 同样文档准确率 98.54%、召回 99.14%。结论是 SDS 这种复杂版式，靠文本层几乎做不动，必须看图。
- 2025 IEEE CogInfoCom 有篇抽 SDS 成分表的，准确率 97.4%。

这意味着你做完可以直接写一句：「我的规则基线是 X%，接入视觉模型后到 Y%，论文里同类系统是 83%/98.5%」。**这是面试官最想听的对照叙事，而不是「我做了一个小工具」。**

**3. 它精准命中 2026 年招聘方筛简历的那几个信号。**
今年多篇面向 AI/Python 岗位的招聘分析指向同一件事：**大家都会做 demo，几乎没人做评测**。「你怎么知道它是对的？改动之后你怎么发现它变差了？」——这两个问题答不上来，项目就只是玩具。这道题天然逼着你做：黄金集、指标定义、回归门禁、失败案例复盘。同时它还自带错误处理（PDF 损坏、字段缺失）、数据结构化（清洗、校验、入库）、系统集成（外部 API 交叉校验）。

**4. 你有别人没有的优势。**
化工本科 + 在工厂环境长大。CAS 号、闪点、GHS 象形图、H/P 短语这些对你不是黑话，你一眼能看出「这个闪点抽错了」。别人的作品集是股票分析、是通用 RAG 聊天机器人；你的是**垂直行业的真实文档工程**。之前定的方向就是：卖点是「懂化工还会写代码」，不是 Python 本身。

## 三、数据源清单（全部公开、已核实可访问）

| 用途 | 来源 | 备注 |
|---|---|---|
| 主语料 + 黄金集 | `github.com/MisbahKhan789/SDS-dataset` | 500 份 SDS PDF（约 103 MB）+ `multiple_information_fields.csv` 人工标注（产品名、产品代码、制造商、供应商、修订日期 5 个字段）。**仓库没有开源许可证** |
| GHS 短语校验 | `github.com/mhchem/hpstatements` | H/P 短语 JSON，24 种语言，CC BY 4.0，2026-07 仍在更新 |
| GHS 代码表 | Zenodo DOI `10.5281/zenodo.20171153` | UN GHS Rev.10：9 个象形图 + ~80 H 码 + ~90 P 码，CC BY 4.0 |
| 外部真值交叉校验 | PubChem PUG REST API | 用 CAS 号反查物质与 GHS 分类，验证你抽出来的对不对 |
| 官方分类查询（进阶） | `codeberg.org/OpenTools/ECHA-GHS-Client` | 逆向 ECHA 接口，CAS → 协调分类 H 码，纯标准库实现 |
| 中文 SDS 来源 | 国家危险化学品安全公共服务互联网平台 `whpdj.mem.gov.cn` | 中文语料，做中文解析的加分项；注意对方可能有反爬，爬之前先确认 robots 与用途合规 |
| 结构标准 | GB/T 16483-2008（国家标准全文公开系统 `openstd.samr.gov.cn` 可免费下载） | 16 节顺序的权威依据，就是你解析器的 schema |

**关于许可证，这是本题的第一个考点，别跳过**：SDS-dataset 无开源许可证，含义是「可以本地研究使用，但你不能把那 500 个 PDF 跟着你的仓库一起分发」。正确做法是写一个 `scripts/fetch_corpus.py` 负责下载，仓库里只提交代码、指标和（可选的）自己标的标注。**顺手在 README 里写清数据来源与许可证边界**——这本身就是 2026 年招聘方明确看的「数据责任」意识。

## 四、交付物与阶段验收

按 v0 → v3 推进。**v0 和 v1 是本次结课的硬性要求，v2 是加分，v3 属于下一阶段（AI 应用）不纳入本次验收。**

### v0：能跑通的最小闭环（约 8–12 小时）

1. 下载 SDS-dataset，跑通 `pdfplumber`（或 `pypdf`）提取单份 PDF 的文本层，把原始文本落盘成 `.txt`。
2. 针对黄金集的 5 个字段写抽取逻辑（正则 + 关键词 + 位置启发式都行）。
3. 写 `evaluate.py`：读取标注 CSV，与你的抽取结果逐字段比对，输出 **每个字段的 precision / recall / F1 以及整体字段覆盖率**。
4. 输出 `report.md`：一张指标表 + 5 个典型失败案例（截图或原文片段 + 你抽成了什么 + 应该是什么）。

**验收标准**：`python evaluate.py` 一条命令出指标表；5 个字段里至少 3 个 F1 > 0.7；失败案例是真实分析不是敷衍。

### v1：真正的解析器（约 20–30 小时）

1. **16 节切分**：按 GHS/GB 标准的 16 个章节标题切分文档（标题写法各家不同：「Section 9. Physical and chemical properties」「9. 理化特性」「SECTION 9 — PHYSICAL & CHEMICAL PROPERTIES」，你要能都认出来）。输出每节的文本范围与置信度。
2. **成分表抽取**（第 3 节）：抽出「化学名 / CAS 号 / 浓度或浓度范围」，多行、跨页、百分比与范围写法都要处理。
3. **理化特性抽取**（第 9 节）：闪点、沸点、熔点、密度、pH、蒸气压、溶解性，含**单位归一化**（`>100 °C`、`>212 °F`、`not applicable`、`无资料`、`N.A.` 要统一成可比较的结构）。
4. **GHS 危险性抽取**（第 2 节）：象形图代码（GHS01–GHS09）、信号词（Danger/Warning）、H 短语码、P 短语码。
5. **校验层**：
   - **CAS 号校验位算法**（从右往左，第 1 位×1、第 2 位×2…… 求和 mod 10）。这是化工人该有的杀手锏，能直接识别出解析错误和 OCR 错误。
   - H/P 码必须落在 GHS 官方码表里，不在就是抽错了。
   - 数值合法性（闪点 -100~300 °C 之外的标为可疑；浓度合计不等于 100% 时告警）。
6. **输出**：每份 SDS 一个 JSON（带 schema 版本、源文件哈希、每字段的抽取方法与置信度）+ 汇总 CSV + SQLite 库。
7. **CLI**：`python -m sds_forge parse <dir> --out out/`、`validate`、`report`、`query --cas 64-17-5` 四个子命令，`--help` 齐全。
8. **测试**：`pytest`，覆盖 CAS 校验、单位归一化、章节切分、表解析、边界与异常输入，覆盖率 ≥ 70%。
9. **自建黄金集扩充**：从 500 份里挑 50 份，人工标注化学字段（CAS、浓度、闪点、H 码），存成 `data/golden/chemical_fields.csv` 并在 README 说明标注规则。

**验收标准**：500 份全量跑完不崩（失败的记进 error 表而不是中断）；自建 50 份黄金集上，CAS 号与 H 码的 F1 ≥ 0.85；`pytest` 全绿；README 能让人 3 分钟内跑起来。

### v2：加分项（选做 1–2 个）

- **外部交叉校验**：抽出的 CAS 号拿 PubChem API 反查名称与 GHS 分类，与 SDS 原文比对，输出「文档内部不一致」和「与外部权威源不一致」两类冲突报告。这一项最能体现工程判断力。
- **中文 SDS 支持**：从官方平台取中文 SDS，做中文 16 节切分（GB/T 16483）。
- **增量与版本追踪**：同一产品多次修订，识别新旧版本并 diff 出变化字段（真实台账管理需求）。
- **台账报表**：输出「本库共 N 种物质，其中 M 种闪点 < 60 °C，K 种带致癌性 H350」这类统计。

### v3：下一阶段（本次不做，作为延伸）

接入视觉模型（你用过的 qwen3-vl-flash）处理扫描件与文本层错乱的 PDF，走论文里「图像模式」的路线，与 v1 规则基线做同集对比。这是你 AI 应用阶段的主线项目之一，现在先留好接口。

## 五、指标怎么定（这道题的灵魂，别省）

**评测集分层**：

- L1（现成）：SDS-dataset 的 500 份 × 5 字段，零成本，先用它跑通流程。
- L2（自建）：50 份 × 化学字段（CAS、浓度、闪点、H 码），你自己标。**README 里必须写清标注规则与歧义处理**，否则别人无法复现。
- L3（回归门禁）：从 L2 里挑 20 份做「改动前后必测」子集，每次改解析器都跑，指标掉超过阈值就报警。

**指标定义**（写进 README）：

- 字段级 **精确匹配**：大小写、空白、全半角标点归一化后字符串完全相等。
- **归一化匹配**：数值 + 单位统一后比较（`>100 °C` vs `>212 °F` 算对）。
- **部分匹配**：成分表用集合 F1（抽对多少行、漏了多少行）。
- 每个字段都要报 **覆盖率**（有多少比例的文档抽出了该字段）——只报准确率不报覆盖率是耍流氓，抽 5 份全对、另外 495 份全空，准确率也是 100%。

**对照基线（写进结论）**：规则基线 X% → 改进后 Y% → 文献同类系统 83%（LLM 文本）/ 98.5%（多模态）。

## 六、硬性工程要求

- 目录结构：`sds_forge/`（包）、`tests/`、`data/`（不提交 PDF）、`scripts/fetch_corpus.py`、`reports/`、`README.md`、`requirements.txt`、`.gitignore`。
- 所有路径与参数走 CLI 或配置文件，不硬编码绝对路径。
- 每个抽取字段记录 `method`（regex/table/llm）与 `confidence`，便于后续定位问题。
- 单份文档解析失败不影响批次，错误写进 `errors.jsonl`（含文件名、异常类型、堆栈摘要）。
- README 必须包含：解决什么问题、数据从哪来（含许可证说明）、怎么一键跑通、指标表、已知局限与失败模式。
- 全程 git 提交，commit 信息说清改动原因。**仓库要干净，别把 100 MB PDF 提交上去。**

## 七、明确不要做的事

- 不要一上来就接大模型。**先有规则基线才有对比**，直接上 LLM 你既不知道它好不好，也练不到 Python。
- 不要做 Web 界面/Docker/前端。那是加分项的加分项，优先级最低，做不完反而显得虎头蛇尾。
- 不要追求 500 份全对。这题的价值在于**诚实呈现失败模式**，不在于刷高准确率。
- 不要自己造 PDF 解析轮子，用 `pdfplumber` / `pypdf`。

## 八、你会遇到的真实难点（提示，解法自己想）

1. 同一个字段在不同厂商的 PDF 里叫法、位置完全不同（这是核心难点，不是 bug）。
2. 两栏排版、页眉页脚、页码混进正文，导致文本层顺序错乱。
3. 成分表跨页、合并单元格、浓度写成 `10 - 30%`、`≤ 5%`、`trade secret`。
4. 单位与「无数据」写法五花八门（`N.A.` / `not available` / `无资料` / `未测定`）。
5. 修订日期格式（`2023-05-01` / `01/05/2023` / `May 1, 2023`）——注意美欧日月顺序陷阱。
6. 一份 SDS 里出现多个产品、多个供应商（一个 PDF 对应多个 SKU）。
7. 扫描件 PDF 完全没有文本层（v1 阶段允许直接标记为 `needs_ocr` 跳过）。
